# PromptCut 统一 Python 卡片管线制作提示词

请基于 PromptCut 现有代码，实现一套 Python 定义的统一卡片管线。

目标是让 Agent 能直接写代码实现原本没有的功能，不必为每种新效果提前增加专门封装。统一支持动画效果、音频效果、转场、滤镜和强调。

先检查现有架构，尽量复用已有能力，并保持旧项目可用。完成实际实现，不只提供设计方案。

## 1. 卡片接口

卡片用 Python class 定义：

```python
class ExampleCard:
    need_prerendering = False

    def __init__(self, style=None):
        self.style = style

    def card(self, source, time):
        ...
        return result
```

`source` 是可按时间查询的输入节点，可以是原始素材，也可以是另一张卡片的输出。

通过 `source.time(t)` 获取指定时间的结果：

```python
frame = source.time(time)
```

查询不能改变共享播放位置。结果可以是帧、纹理或待执行的绘制描述，不必每次都把像素传回 Python。

支持多输入，例如转场的 A、B 两路素材。音频沿用相同卡片体系，但按音频块处理，具体类型与访问方式根据现有项目设计。

## 2. GLSL 与自由代码

提供 GLSL 对象，让 Agent 能在 Python 卡片中编写和使用着色器：

```python
class ExampleCard:
    need_prerendering = False

    def __init__(self, style=None):
        self.shader = GLSL("GLSL 源码")

    def card(self, source, time):
        frame = source.time(time)
        return self.shader(frame, time=time)
```

软件运行时负责注册和执行 GLSL。能够注册为实时绘制的部分，尽量在前端 GPU 路径执行，避免每帧往返传输完整图像。

卡片内部也可以使用其他 Python 算法或获准的库，不局限于 GLSL。不要假设任意 Python 代码都能自动转成 GLSL 或 React。

## 3. 旧动画卡片处理

为现有动画卡片也增加 `need_prerendering` 项，接入统一调度，不要求将已有 React/HTML 实现全部重写成 Python。

能够改写为通过 `t` 直接求出当前画面的卡片，采用 React 按时间求值，实现随机访问。这类卡片设置 `need_prerendering = False`；不能仅因为使用了 React 就认为它已经支持随机访问。

必须依靠历史状态逐帧推进的卡片，设置 `need_prerendering = True`，保留 HTML/Chrome 顺序推帧能力，将生成结果缓存，供后续随机访问。

将现有 MOV 预渲染管线调整为：对能够独立渲染的控件分别生成 MOV，使用控件自身的局部帧时间，并与时间轴建立准确映射。根据合成需要保留透明通道，选择支持所需随机访问性能的编码与索引方式。

不能把所有 Chrome 卡片都默认拆成独立 MOV。毛玻璃等效果会读取下方画面；其他卡片也可能依赖完整的浏览器合成环境。

对于依赖背景或尚未确认能够独立渲染的 Chrome 卡片，保留在最终合成场景中由 Chrome 截图渲染的路径，确保所需背景和图层上下文存在。需要推帧的仍按其状态推进要求执行。

`need_prerendering` 与“能否独立缓存”分别判断。不要为生成独立缓存而改变原有视觉效果，也不要仅凭静态代码特征认定卡片没有背景依赖。

## 4. 后台预渲染、占位与缓存读取

后台预渲染按以下优先级执行：

### 第一优先级：必须预渲染的卡片

- 优先处理 `need_prerendering = True` 的卡片实例。
- 缓存尚未生成时，编辑台在素材对应的位置和范围绘制方框，并显示动态漏斗占位画面。
- 不因这些卡片尚未就绪而阻塞用户播放、拖动时间轴或即时预览。

### 第二优先级：各控件的 MOV 缓存

- 必须预渲染的任务完成后，后台逐步为视频中的各个可独立渲染控件生成 MOV 缓存，包括原本可以按 `t` 实时访问的控件。
- 使用控件自身的局部帧时间，正确映射到时间轴。
- 沿用旧卡片处理规则：毛玻璃等依赖背景的控件不能脱离合成上下文单独缓存；这类内容保留到有完整上下文的合成阶段处理。

### 第三优先级：整片 MOV 缓存

- 控件缓存阶段完成后，后台继续生成整个视频的 MOV 缓存。
- 整片缓存需要包含真实的最终合成效果，包括依赖背景的 Chrome 卡片。
- 不得将编辑台的方框或漏斗占位画面当作真实内容写入最终缓存。

后台任务不能阻塞即时预览。产生新的必须预渲染任务时，应优先调度，并在可行的任务边界暂停较低优先级工作。

### see_frames 读取顺序

`see_frames` 按以下顺序获取画面：

1. 优先从覆盖请求时间、且与当前项目版本一致的整片 MOV 缓存取帧。
2. 没有可用整片缓存时，使用已有的控件 MOV 缓存参与合成。
3. 缺少控件缓存时，对支持按时间直接求值的卡片，通过 `t` 获取结果。
4. 对其他卡片，优先复用已有 HTML 渲染实例或渲染入口；如果它不能直接定位到目标时间，则恢复或初始化状态后推帧到目标位置。

同一帧可以混用有效控件缓存与现场渲染结果，不要求所有控件都已缓存。最终仍需按正确图层顺序和背景依赖关系合成。

是否能够通过 `t` 随机访问，以卡片实际能力为准，不能只依据是否使用 React；存在 HTML 也不意味着可以省略必要的推帧。

源码、素材、参数、风格或时间轴变化后，使受影响的控件缓存和整片缓存失效，保留不受影响的可复用结果。旧任务完成时，不得覆盖较新的版本。

如果 `see_frames` 仍有内容只能显示占位，应明确返回哪些内容尚未就绪，不能把占位图作为已经完整渲染的真实画面。正式导出必须使用真实结果。

## 5. 全局风格

全局 `style` 通过构造函数传入。

Agent 写卡片时可以选择全部适配、部分适配或完全不适配，不强制使用全局风格。风格变化后，使用它的卡片应能更新。

## 6. Rust 运行器与并行渲染

使用独立 Rust 运行器管理多个常驻 Python 工作进程，支持独立轨道或卡片并行渲染，最后统一合成。

不要每帧重新启动 Python。存在上游依赖的卡片按依赖关系执行，同一合成结果使用一致的时间与版本。合理控制并发并支持取消任务。

## 7. Python 权限隔离

优先使用 [rappct](https://github.com/cpjet64/rappct)。

如果存在确认无法解决的阻塞，再使用 [Sandy](https://github.com/ahrvoje/sandy_cli)。

复用它们提供的 Windows 隔离能力，不从零制造沙箱。Rust 包装器本身不等于权限隔离。

卡片只能读取授权输入、写入本次任务的输出和临时目录，不能修改用户原文件或软件代码。卡片从导入、初始化到执行，都必须在受限环境中运行。

使用实际打包的 Python 和依赖验证权限与兼容性。隔离无法建立时明确报错，不回退到不受限执行。

## 8. Agent 创建与编辑

沿用或扩展 `create_card`、`get_card_source`、`edit_card` 等工具。

Agent 通过 JSON 参数向 `create_card` 提交卡片信息和 Python 源码；JSON 负责传输，效果逻辑由源码实现。

区分卡片定义与使用实例，同一张卡可以应用到不同素材。卡片源码和必要配置随项目保存。

## 9. 接入与交付

让新卡片接入编辑台预览、最终导出和 Agent 看帧；音频也要覆盖预览与导出。

用实际示例验证实时 GLSL、Python 预渲染、多输入转场、音频、全局风格和多轨并行。确认能创建、编辑、应用、保存并重新打开项目。

旧卡片额外验证：

- 通过 `t` 直接求值的 React 卡片能够正确随机访问。
- 必须推帧的卡片能够生成缓存，并按控件局部帧时间读取。
- 独立 MOV 的透明度、时间映射与合成结果正确。
- 毛玻璃等背景依赖效果在最终 Chrome 场景中保持正确。

验证后台任务按“必须预渲染 → 控件 MOV → 整片 MOV”的顺序调度；缺少结果时编辑台正确显示方框与动态漏斗且不阻塞交互；`see_frames` 按缓存层级逐步回退，并正确处理缓存失效、混合合成与尚未就绪的内容。

其余实现细节根据现有项目合理决定，避免为了统一接口建设过大的框架。交付时说明完成情况、测试结果和实际限制。

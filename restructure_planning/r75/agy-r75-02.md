## 2. 阻塞项

### 阻塞 1 · C4：「要改三处白名单」漏掉页面侧的发送闸门，`wanted` 在播放和拖动中一条都发不出去

- **任务书行号与原句（L134）**：「（要改三处白名单：`mirror-store.mjs:127` 的 `setPlayhead(session, t, playing)` 加第四参 `wanted`、`vite-plugin-mirror.ts:232` 的调用与 `:234` 的转发体都只传 `{ session, t, playing }`，不改就静默丢掉）」；同段还要求「由页面的 `dataMirror` 用 `fetch(..., { keepalive: true })` 打编辑器进程、不等回复、每 100 ms 至多一条」。
- **证据**（`src/editor/dataMirror.ts`，逐字）：
  - `:149` `  if (s.t === pushedT && s.playing === pushedPlaying) return;` —— `t` 没变就整条不发，`wanted` 变了也发不出去。
  - `:184` `    if (!s.playing && (lastPlaying || s.t !== pushedT)) {` —— **播放中根本不进这个分支**。
  - `:185` `      // 播放中不推 t;停下来(或暂停时拖了播放头)才推一次`
  - `:186` `      schedulePlayhead(400);` —— 节流 400 ms，不是 100 ms；`:156` `  if (headTimer) clearTimeout(headTimer);` 是可重入防抖，连续拖动期间一次都不会触发。
  - `:151` `  const res = await post("/api/data/playhead", { session, t, playing });` —— 等回复。
  - `:78` `    const res = await fetch(path, {`、`:82` `      signal: AbortSignal.timeout(10000),`、`:85` `    await res.json().catch(() => null);` —— `post` 没有 `keepalive`，而且读完响应体才返回。
- **为什么阻塞**：`wanted` 是 C2「每批开始前读镜像插件的 `latestPlayhead().wanted`」的唯一输入。照 L134 只改它点名的三处，播放中恒为空、拖动中要停满 400 ms 才有一条，C2 的播放头优先调度等于没接上。
- **建议改法**：L134 那个括号里的「要改三处白名单」改成「要改四处」，第四处写明：`src/editor/dataMirror.ts` 的播放头路径——`:184` 的 `!s.playing` 闸门要放开（播放中也要报 `wanted`）、`:149` 的早退条件要加上「`wanted` 变了也发」、`:186` 的 400 ms 改成 100 ms 且改成固定节流而不是可重入防抖、并为这条请求单开一个 `keepalive: true` 且不读响应体的发送函数（不要复用 `:76` 的 `post`，它带 10 秒超时并读完 body）。

### 阻塞 2 · F5：只扫磁盘目录重建不出 C3 的 `readyIndex`——目录名里没有 clipId

- **任务书行号与原句（L207）**：「预渲染进程起来先扫 `controls-html/<共享键>/index.json`、`controls-local/<entry.key>/<共享键>/index.json` 和轨道流目录的分段清单，重建 C3 的 `readyIndex`」。
- **冲突的另一处任务书原句（L133）**：「`{ type: 'layer', clipId, kind: 'html' | 'local' | 'stream', key, ranges: [[from, to], …] }`」、「页面侧 `readyIndex: Map<clipId, Map<kind, { key, ranges }>>`」。
- **证据**：`server/card-identity.mjs:105` `  const { id: _id, inputs: _inputs, definitionId: _definitionId, clipId: _clipId, ...stripped } = node ?? {};` —— 共享键刻意剥掉 `clipId`；目录形状里也只有键（`server/snapshot-store.mjs:74` `  if (tier === 'shared') return path.join(root, SHARED_DIR, key);`、`:77` `    return path.join(root, LOCAL_DIR, entryKey, key);`）。
- **为什么阻塞**：`layer` 消息的必填字段 `clipId` 和 `readyIndex` 的键都拿不到，F5 的验收「页面的就绪索引条数与磁盘一致」跑不出来。
- **建议改法**：L207「先扫 …… 重建 C3 的 `readyIndex`」后面补一句：「扫盘只得到『共享键 → ranges』；`clipId` 要先按 `ensureMirror` / `repushMirror` 拿回项目、重算一次 card plan，用 plan 里的 `control.clipId` 与 `control.snapshotKey`（`server/card-cache.mjs:92-93`）反查；项目还没到位时先不发 `layer`，等项目到了再发 `reset` + 全量 `layer`。」

### 阻塞 3 · C3 要的 SSE 代理端点不在 D5 的编辑器进程保留清单里

- **任务书行号与原句（L133）**：「SSE 由预渲染进程产生、经编辑器进程代理」、「端点 `GET /api/frames/ready?session=&localRev=`（SSE）」。
- **冲突的另一处任务书原句（L146）**：「`/api/frames/*` 保留 `archive`、`import`、`status`、GET 文件路由；`/api/frames/yield` 删除」——没有 `ready`。
- **证据**：`server/vite-plugin-frames.ts:122` `    server.middlewares.use("/api/frames", (req, res, next) => {` —— 这个插件在编辑器进程和预渲染进程**都挂**；GET 分支（`:127`–`:156`）只认几条定长正则，不匹配的一律 `return next()`（`:140` `        if (!final && !track) return next();`）。照 L146 的保留清单做，编辑器进程上的 `/api/frames/ready` 既不会被代理、也不会被本地应答。
- **建议改法**：二选一并写死——(a) L146 的保留清单改成「保留 `archive`、`import`、`status`、`ready`（**只做反向代理到预渲染进程的 SSE，不本地应答**）、GET 文件路由」；或 (b) L133 改成「SSE 由页面直接打预渲染进程的 `/api/frames/ready`，和快照字节同源、同走 `PROMPTCUT_CORS_ORIGINS`，编辑器进程不代理」。

# 0.4.0 之后的计划

0.4.0(构建自 3e48941)已经交付:导出换成 beginFrame 后端,Agent 能读改所有卡片源码,并能只读查看 DOM 树。
这份文档列出之后要做的事,每条写清来源、要做什么、做完怎么验收。改建计划本身的实施状态见
[render-rebuild-plan.md](render-rebuild-plan.md) 开头的状态表。

分三档:

- **P0**:已知的错,或会让用户丢数据的风险,尽快做;
- **P1**:计划里还没做完的部分;
- **P2**:可选的优化和清理。

## P0:已知问题与风险

### 1. 安装版里 Agent 改过的内置卡,打补丁后会被覆盖

> **0.5.0 已解决**:装机版改卡写进 `<数据目录>/card-overrides/`,仓库那份当只读底版,补丁只换底版(`server/card-overrides.mjs`,见 [decoupling-plan.md](decoupling-plan.md)「实施记录」阶段 5)。

- **来源**:`edit_card` 写入的是 dev server 根目录下的 `src/cards/…`,在安装版里就是 `runtime/app`。而更新补丁会整个覆盖 `runtime/app`(make-patch 只打这一部分)。
- **后果**:用户让 Agent 改好的内置卡,升一次级就回到原样。改前备份在 `out/card-edits/`,但没有任何东西会把它恢复回去。
- **要做**:
  1. 先实测确认:在安装版里改一张内置卡,装一次补丁,看改动还在不在。
  2. 确认会丢之后,二选一:
     - 改动写进覆盖层目录(例如 `userdata/card-overrides/`),加载时优先用它;
     - 打补丁前扫 `out/card-edits/`,列出被改过的文件,提示用户。
- **验收**:改内置卡 → 装补丁 → 改动仍在,或者用户在装补丁前明确收到提示。

### 2. `--workers` 的默认值,代码和文档不一致

> **0.5.0 已解决**:命令行默认单进程,`--workers` 真正被解析了(以前命令行根本不认这个参数,一律 `auto` 开 4 个分片),`/api/export` 也显式传 `--workers 1`(见 [decoupling-plan.md](decoupling-plan.md) 阶段 6)。

- **来源**:`scripts/export-frames.mjs` 的命令行默认是 `workers: 'auto'`(最多 4 个进程),但 `server/bakery/bake.mjs`、`server/bakery/shards.mjs` 的注释和 `scripts/README.md:25` 都写默认单进程。
- **要做**:按文档改成默认 1。实测 4 个进程只快约 18%(54.8 → 44.8 秒),却要占 4 份内存和 CPU,不值得作为默认。
- **验收**:不带参数运行时只起 1 个 headless-shell。

### 3. 三张卡换了时间轴位置,画面就变

- **来源**:`scripts/card-audit.mjs` 第一次实跑,结果在 `out/card-audit.json`。

  | 卡片 | 最大通道差 | 不通过的片内帧 |
  |---|---|---|
  | `mu-word-rotate` | 250 | 1/4 |
  | `versus-card` | 40 | 1/4 |
  | `lottie-bodymovin` | 42 | 1/4 |

- **影响**:渲染缓存的键不含片段位置;`inspect_card_dom` 会把片段挪到 0.5 秒处再渲。这两处都默认卡片画面和它在时间轴上的绝对位置无关,这三张卡不满足,就可能缓存到错的画面、看到错的 DOM。
- **要做**:逐张查画面读的是哪个时钟。可能是用了绝对时间 `t` 而不是片内时间,可能是 Lottie 的起始帧和绝对时间挂钩,也可能是 Motion 动画的起点受第 0 帧预热影响。`out/card-audit/<id>/` 下 a/b 两组 PNG 都留着,可以直接比。
- **验收**:重跑 `node scripts/card-audit.mjs`,位置无关一项 89/89 全过,退出码 0。

### 4. `particles-nasa` 挂载时去外网拉图

- **来源**:同一次审计。这张卡加载 `upload.wikimedia.org` 上的 NASA logo,http 和 https 各请求一次。
- **后果**:导出时"等网络请求"那一步要等它。没网就只能等到 30 秒超时报错;网慢时每次导出都被拖慢。
- **要做**:把图下载进 `catalog/`,改成本地路径。顺便给审计加一项:挂载时出现非本地请求就告警。
- **验收**:断网导出这张卡能成功;审计里它的挂载请求只剩那 7 个本地依赖分包。

## P1:计划里没做完的部分

### 5. 实测打补丁升级到 0.4 的路径

- **来源**:0.4 的导出依赖 chrome-headless-shell。完整安装包自带它;从 0.3.x 打补丁升上来的用户手里没有,第一次导出时由 `openBakery` 调 `@puppeteer/browsers` 自动下载安装(约 100 MB)。**这条下载路径没有真实跑过。**
- **要做**:在一台装着 0.3.1、从没装过 headless-shell 的机器(或者清空了 `PUPPETEER_CACHE_DIR` 的环境)上:
  1. 装 `PromptCut-patch-0.4.0.exe`,导出一次:确认能自动下载,下载完导出成功;
  2. 断网再导出一次:确认报错写清楚了"请用完整安装包重装",而不是卡住或报一句含糊的错。
- **注意**:装补丁会让正在跑的会话集体卡住好几分钟(补丁会覆盖 `runtime/app`)。要挑没有会话在跑的时候测。

### 6. 结构不稳定的两张卡

- **来源**:审计第 3 项,只提示,不影响退出码。`chapter-bar` 在片内出现 2 种 DOM 结构,`terminal-3d` 出现 3 种。
- **影响**:HTML 采样缓存(`--dom-cache`)假定"一棵树 + 逐帧数值表"。结构一变,这个假定就不成立,但逐帧冻结整棵树的做法照样能用。只有以后要做"只存数值、不存树"的压缩时,才会被它们挡住。
- **要做**:暂不改卡。等 P2 的第 10 条确定要做时,再决定是改卡(比如用 `visibility` 代替条件渲染),还是让这两张卡退回逐帧整树。

### 7. 字体随包分发(计划阶段 0 第 3 条)

- **来源**:计划状态表里标着"等设计决定"。
- **现状**:主题字体栈已经写全,`font-audit` 零告警。但成片仍然依赖系统里装的字体,比如 Microsoft YaHei、Consolas。换一台没装这些字体的机器(比如 macOS、精简版 Windows),像素层就会不一致。
- **需要你决定**:
  - **A. 不分发**:保持现状,只保证 Windows 上一致;
  - **B. 分发开源替代**:比如思源黑体 / Noto Sans CJK 加 JetBrains Mono,换上后成片观感会变;
  - **C. 两层都要**:编辑台用系统字体,导出用随包字体。代价是预览和成片的字不一样。
- **选定之后**:做字体子集化,估算包体增量,再重跑 `font-audit` 和 `verify-determinism`。

### 8. 画布层单独出帧(计划阶段 6,可选)

- **来源**:计划状态表"没做"。
- **思路**:把 canvas / WebGL 卡(62 张粒子卡、`scene-3d`)单独出帧再合成,DOM 层就能全走 HTML 采样缓存。
- **前提**:毛玻璃这类 `backdrop-filter` 叠在画布上时,两层拆不开。要先统计有多少项目里出现这种叠法,再决定值不值得做。

## P2:优化与清理

### 9. 分片并行换个思路

- **来源**:实测 1/4/8 个进程耗时 54.8/44.8/62.4 秒。每个分片都得从第 0 帧推起,推进这部分省不掉;几个软件光栅化进程又互相抢 CPU。
- **可试**:单进程顺推一遍,同时开 `--dom-cache` 冻结;然后开 N 个进程,用 `scripts/replay-frames.mjs` 从缓存乱序重截,重截可以并行。
- **待解**:重放和实时截图之间有边缘残差,同一次交付只能走其中一条路。所以要先量清楚:冻结一遍(每帧多约 56 ms)加并行重放,总耗时到底能不能低于单进程直出(26.9 ms/帧)。

### 10. HTML 采样缓存的压缩存储

- 对结构稳定的卡,只存第一帧的树加上逐帧变化的数值,体积能小一个数量级。依赖第 6 条。

### 11. 测试脚本跟上现状

- `server/test/mcp-smoke.mjs` 还写着 5195 端口,并且打开的是 `/`。现在 `/` 是开始页,编辑器不挂载,MCP 桥永远连不上。
- **要做**:改成可配端口,打开 `/?editor`;把这次会话里写的端到端检查也并进去,包括 `get_card_source`、`inspect_card_dom`、`edit_card` 的拒绝路径、大 props 项目。
- **验收**:`PROMPTCUT_PORT=5197 node server/test/mcp-smoke.mjs` 全绿。

### 12. agy 全局允许清单(安全,需要你决定)

- **现状**:agy 的全局允许清单里有 91 条 `mcp(promptcut/*)` 规则。任何 agy 会话都能不经审批调用 promptcut 的全部工具,包括 `edit_card`、`create_card`、`send_message`。这些规则早就在,不是 0.4 加的。
- **可选**:
  - 清掉,每次委派 agy 时按需临时批准;
  - 保留,但只放行只读工具,比如 `get_*`、`list_*`、`inspect_card_dom`、`see_frames`。

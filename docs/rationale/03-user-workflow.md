# 用户工作流程：为什么这样定

对应 `docs/semantics/03-user-workflow.md` 和 `docs/semantics/workflow/`。这里只写理由和取舍，不是规范。

## 为什么只有两种工作方式

曾经有三种：传统式、对话式、SKILL。传统式的左栏和时间轴可以收起，收起后就是对话式的布局，对话式因此没有单独存在的必要。

## 为什么 SKILL 也是协作，而不是托管

桌面 APP 里的 Agent 经 MCP 接入，拿到的权限和 AI 栏里的 Agent 相同；用户手动修改时，它和 AI 栏里的 Agent 一样收到通知。它只是另一个从别处接入的协作者。

旧的做法是把项目快照进独立任务目录，让一份无头实例改副本，最后三方合并回来，期间锁住用户的 AI 栏。这让用户和 Agent 各改一份，违背了架构里「人和 Agent 改的是同一份项目」的硬要求，所以改掉。

桌面 APP 拿不到文字输出，就用 SKILL 提示词约定结构化的汇报方法。AI 栏里的 Agent 本来也不直接显示文字回复，两边对用户是同一个口径。

## 为什么关闭界面转入后台运行

SKILL 下主要是桌面 APP 在干活，编辑界面不必一直开着；但软件一退出，外部 Agent 就断了。所以关闭界面只是收起，软件留在托盘和悬浮窗里继续运行，右键明确选择关闭才退出。浏览器没有托盘，这条只在桌面应用里成立，SKILL 也因此只在桌面应用中提供。

## 为什么创造力等级是三档、默认高

用户要能在「稳定」和「探索」之间选：低档只套现有模板、只改参数，结果稳定；中档允许在模板基础上改代码；高档放开，可以新建任意卡片。默认高，是为了让 Agent 写代码的能力默认就能发挥出来。

等级同时管卡片、效果和测量，因为写滤镜表达式、写测量代码和写卡片代码是同一类能力。低档下 Agent 不能新建滤镜或写测量代码。

等级有项目默认值、每个对话可以单独改：桌面 APP 的对话在它自己的窗口里，本软件的 AI 栏够不着，只能让它跟随项目的等级。

## 为什么分工模式并入多 Agent

分工模式是几个角色按固定顺序接力，它只是多 Agent 的一个特例。让主 Agent 按需拉起其它 Agent、分派任务、附加预设的角色，覆盖了分工模式能做的事，也更灵活。「角色」不叫「角色卡」，是为了不和特效卡片撞名。

## 为什么「用户正在编辑」是提示，不是禁止

要防的情况是：Agent 覆盖了用户正在改的东西，还给出一个看似合理的理由。所以系统要在 Agent 看或改那张卡时直接告诉它用户正在编辑。但用户可能正是在这个位置给 Agent 下指令，一律禁止会挡住正当的用法，所以只提示。

## 为什么功能清单写成「至少提供」

清单一旦读起来像封闭的枚举，就会被误读成限制。整理时出现过两次：库类效果读起来像「必须共用一个定义」，音频测量读起来像「只能测响度」。统一写明「是至少要提供的能力，不是封闭的清单」，逐条补「也可以」就不需要了。

## 为什么分成指导层和分册两层

第一版把工作方式、跨步骤的规则、功能清单写在一份里，功能清单占了大半，Agent 分不清哪句是必须守的原则、哪句只是当前有这个功能；功能每加一个，指导文档就要改一次。拆开之后，规则只在指导层写一次，分册只列能力，引用规则而不重复。判断一句话放哪一层的标准是：它变了会不会迫使别处的设计跟着变。

## 几条归类的理由

- **转场归效果**：它在时间轴上显示，但不属于任何序列。
- **一键配特效放在主线之外**：它只是入门时的测试和展示功能，不是核心功能。
- **接入方式分 CLI、API、桌面 APP 三类**：前两类在 AI 栏里对话，桌面 APP 在自己的窗口里对话、经 SKILL 接入，两者的界面和汇报方式不同。

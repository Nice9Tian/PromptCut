# 主会话交接（PC ⇄ 笔记本）

同一时刻只有一个主会话。切换时先给现主钉交接 goal，再给新主发接手段，再让新主那台的辅助待命、旧主那台的辅助报到，最后重钉 goal。

## 一、给现主钉的 goal（覆盖它原来的）

```text
目标：把主会话交接给「〔新主标题〕」，然后待命。完成条件：
1. 不再派新任务；在途子 Agent 提交完，所有 worktree 分支已推到 origin。
2. docs/reports/HANDOFF-〔日期〕.md 已写好（按 PAUSE-2026-09-26.md 的格式：阶段与步骤、在途分支及最后提交、信箱两队列已处理到的 seq、待跨机复核项、待用户项、阿里云现状、已发未回执的指令；不含令牌），已提交推到 origin/main，release 已按 git_and_release.md 判过。
3. 已用 ListAgents 按标题找到「〔新主标题〕」并用列表里的句柄发消息通知它接手（找不到则报告用户，由用户转）。
4. 交接文件路径和提交号已贴在对话里。
之后进入待命：不派子 Agent、不合并、不往信箱写指令、不接任务，直到用户明确说恢复主会话。待命不算未完成。
```

## 二、给新主发的接手段

```text
接手主会话。pull main 到最新，读 docs/reports/HANDOFF-〔日期〕.md，按主计划第 0.4 节自检，检查信箱两队列的 seq 与交接文件一致。都过了就从交接文件写的那一步继续。接手后第一件事：把主计划 6.1 节的角色改成当前分工，标〔裁〕注明是用户定的交接。
原主会话「〔旧主标题〕」现在待命，不派活；〔旧主那台〕的辅助节点会向你报到，报到后回执。自检结果和报到贴给我，我再钉 goal。
```

## 三、辅助节点

- 新主那一台的辅助会话：发「你待命，不接任务，直到我说恢复」。
- 旧主那一台的辅助会话：按它模板里的「准备（握手）」重新报到，主会话标题换成新主。

## 四、重钉 goal

新主用它模板里的 goal（加「从 HANDOFF-〔日期〕.md 接着做」）；旧主那台的辅助用它模板里的 goal，主会话标题换成新主。云端的 goal 只在主会话标题变了时重钉。

## 五、恢复原主

对现主钉第一节的交接 goal（新主标题填原主），原主按第二节接手，其余同上。

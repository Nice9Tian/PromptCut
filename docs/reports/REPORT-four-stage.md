## 第二段：在线执行用户卡与图卡（2026-10-07 合入集成分支，`21b02329`）

### 做了什么

- **转译与加载**：在线页面用 Sucrase 3.35.1（MIT，唯一新增依赖，按需载入约 124 KB）转译同步来的用户卡与图卡；写法预检拦下 `namespace`、装饰器、顶层 await 等；包白名单与桌面相同；转译结果按内容哈希缓存；运行状态十种，参数面板按状态说明原因。
- **隔离**：画面只在跨源舞台里执行，声音只在舞台源起的后台线程里执行，编辑页面与导出页都不执行卡片代码。舞台源带全套内容安全策略与 `Connection-Allowlist: (response-origin)`（Chrome 152、154 实测能拦 WebRTC），iframe 加 `sandbox`，脚本加固作第二道；素材票据换成 HttpOnly cookie，舞台地址里不再带 `?t=`；舞台启动自检，不生效就不执行；托管方可用站点配置 `onlineCardExec: false` 整体关掉。
- **图卡**：在隔离舞台里执行，素材经 `/media-s/<会话号>/` 按 Range 取；图形能力不够判 `gpu`、输入解不了判 `media`，退回原做法。
- **轻重判定**：本页能运行的卡走内置卡那一套；**有声动效卡的画面自动即时补测、不默认判重**（用户 2026-10-06 指示）。
- **浏览器节点**：认领当前登录用户自己发出的用户卡任务，用带在线运行时版本的环境指纹；内置卡的结果键一个字不变。
- **在线导出**：同步来的用户卡用预渲染原尺寸；修了「导出页不挂同步卡的包裹层，成片里整张缺失」的缺陷。
- 语义与契约已落稿（`product/platforms.md`、`product/rendering.md`、`product/cards.md`、`glossary.md`、`mechanism/rendering.md`、`mechanism/platforms.md`、`mechanism/cards.md`；`c10-contract.md`、`m7-contract.md`、`render-queue-contract.md`、`online-card-exec-contract.md`）。

## 第三段：云节点渲染服务常驻（2026-10-07 合入集成分支，`48b223d9`）

### 做了什么

- **托管方服务身份**（决定 D）：每个服务一对 Ed25519 密钥，文档服务只存公钥；握手只认真正从节点本机发起的连接，集群令牌不参与；带 `service` 字段的连接走「缺省拒绝」的消息白名单。渲染服务只能报到、认领、交付、读项目与内容库、写预渲染清单、取素材票据（只许写 `snap`、`px`）。通用骨架同时给第四段的 `agent` 服务用。
- **自动为节点上所有项目服务**：目录模块推「项目、开关、是否活跃」，建、删、改开关 5 秒内生效；没有成员在线、只有别的托管方服务声明「有活要渲」时也连着接活。
- **项目开关**：项目设置里「托管方的渲染节点」，缺省开，创建者可关；关掉后连接断开、认领放回、素材票据当场失效；成员列表里显示为单独一行、不计入成员数。
- **常驻形态**：PM2 应用 `promptcut-render`，管理进程持私钥、工作进程只拿短期票据；并发 2；背压（可用内存、文档服务自检、负载线按核数）；内存看护按不重复计共享页的口径量（Linux：独立 cgroup 的 `memory.current` 或按进程的 `Pss`；Windows：私有工作集）；结束时带走整棵进程树；启动自检（Node、私钥、数据目录、中文字体、ffmpeg、`chrome-frame`：走到真正开页出一帧）；root 或容器下 Chrome 自动带 `--no-sandbox`；没有 systemd 时退到进程内看护。
- **用户卡按项目隔离**（用户 2026-10-06 要求重开）：常驻工作进程不装、不执行任何项目带来的卡；有 `card-source` 的项目由隔离工作进程做（同时最多一个、一轮一个项目、每轮口令现生成、数据目录每轮清空）；渲染页过页面请求闸（实测只放行一种接口），出网两层限制（只通向本工作进程的出口代理，加 `Connection-Allowlist`）；同步来的样式与脚本装卡前过白名单预检。
- 容量记账（上限 `min(20 GiB, 盘的四分之一)`，到上限只拦渲染服务的写入）、部署模板与远端子命令（`install-render`、`deploy-render`、`status-render`、`stop-render`、`rollback-render`、`keygen-render`）、`hosting-migration.md` 的重建步骤。

### 过程中查出并修掉的

- 被杀的工作进程留下孤儿 vite 占端口，之后每次重启都失败（Linux 演练查出）。
- 启动自检说 Chrome 没问题、实际开不了页：预渲染必须用 `chrome-headless-shell`（puppeteer 25.10.0 配 152.0.7977.75），完整版 Chrome / Chromium 不行。
- 内存看护累加工作集、重复计共享页，Linux 上常驻树空着也量出 6.8 GB，隔离工作进程一就绪就被误杀。
- 渲染页能请求工作进程的本机接口；同步来的样式写法能读项目根以外的文件，`@plugin`、`@config` 能把同步来的脚本在 Node 里执行。两处都实测成立并已堵上。
- 现有鉴权的几处口子（渲染角色的连接能给自己换可改项目的票据等）由白名单拦住，各有拒绝用例。

### 残余面与没做到的

- **按哈希读素材**（待用户判）：越权探测卡若已知别的项目某块素材的哈希，经工作进程读得到；这是素材服务「按哈希读」的既有规则，成员本人凭自己的票据同样读得到，渲染服务没有增加能力，页面一侧列举不了哈希。主会话判为不算第 23 条不过，记为残余面。
- 产物「按最久没人在线淘汰」没交付（前提不成立：清单列着、块稳定 404 时在线页面不会重新发补渲），另立专项。
- 图卡：能力位照旧 `graphCards: false`；服务端分不出图卡，含图卡的片段照样被认领并求值，画面对不对没验。
- 渲染变慢：渲染页多经一跳出口代理（同一步约 36 秒 → 58～90 秒，噪声大，未在安静的机器上对比）；Linux 上每 30 帧的快照任务 31～50 秒。
- 卡片引用的远程图片、字体在渲染节点上取不到（出口限制）。
- 只能在新节点上验的：真 PM2、systemd slice 与 cgroup 那一支量法、非 root 用户下的 Chrome 沙箱、节点重启后自动起来、`limits` 与 `load` 两步、满载时文档服务与素材下载的前后对比。

## 第一段的核心项补修：打字卡 10 帧像素差异（2026-10-07，`claude/typing-timeline-fix` 已合入集成分支）

- **根因**：两条导出路径挂载卡片的时刻不同。带轨道的项目格式在片段起点才挂卡；演示项目走的平铺片段格式按 `CARD_MOUNT_LEAD`（0.05 秒）提前挂，30 fps 下早一帧。main 的旧打字卡从挂载那一帧计时，重写后的卡从片段起点计时，于是平铺格式下每个字晚一帧。
- **改法**：`src/render/Stage.tsx` 加 `mountClock`（只在导出页的平铺时间轴分支打开），在起点之前挂上的卡收到 `CardProps.mountClockMs`，算式与旧实现相同；`mu-typing` 收到它就按它取字。预览、带轨道项目的导出、预渲染都不传，行为不变；字素计时、停顿参数、从中间接着打都没动。
- **验证**：默认演示项目全长 1800 帧对 main（`044f767f`）逐字节相同 1800/1800；`typing-card-compare` 带轨道格式 9 个与平铺格式 6 个应当相同的用例差异帧全为 0，应当不同的用例与第一段验收时的数字逐项相同；`npx tsc -b --force` 退出码 0；`npm test` 4681 项、4680 过、0 失败、1 跳过；`sound-effects-probe --node-only --av` 48 项全过。
- **残余**：平铺格式下带源偏移的打字片段会在挂载帧（片段起点前一帧）早一帧露字；真实项目是带轨道的格式，不走这条路径。
- 顺带：`online-stage-watch-probe`、`online-stale-layer-probe`、`online-nav-stress-probe` 三个在 main 上因「探针建的项目是空的」而不过的探针已修（只改探针）。

## 第一段：声音（2026-10-06 合入集成分支，`755fba9e`）

### 做了什么

- `origin/Doger` 的 0.5 期声音实现 `--no-ff` 合入（无冲突）：合成提示音与键盘声、动效卡内嵌声音、片段独立静音与时间轴「已静音」标记、声音 WAV 入库、Agent 生成与调参。
- **决定 A：导出时自动生成声音。** 导出开始时先把未生成、缺失、过期的声音生成好再出画面；生成进度算进导出进度（界面显示「生成声音 n / N 段」）；取消导出同时取消生成、不留半截产物；某段生成不出来时导出失败并报出片段名。桌面与在线导出都照此办。语义 `product/rendering.md`「有声动效卡」已改写。
- **决定 B：在线浏览器合成内置声音。** 内置提示音、键盘声、内置有声卡按轻重区分：判轻的在浏览器里合成，判重的用已有产物；测量时不出声；数字写在 `mechanism/rendering.md`「声音的轻重」〔裁〕。语义 `product/platforms.md`「卡片声音的平台边界」已改写。
- 浏览器端验收：声音探针完整版、预览探针（桌面形态与在线模式）、打字卡逐帧比对、样本导出、与打包保存和协作的组合。
- 修了四处缺陷（各有单测）：
  1. 打字动画默认参数的普通文字在整帧边界上少显示一个字（帧时刻相减的浮点误差），加 1 纳秒容差；
  2. 本机发素材文件「先查文件再另开读流」的竞态：文件在两步之间被删时编辑器进程以未捕获的错误退出；
  3. 起播后舞台第一拍到之前声音已经放出去；卡顿要等晚到的那一拍来了才判——改成第一拍到之前不起声、看门狗当场掐住；
  4. 放到素材尽头的声音元素被从头重播。
  另修：在线页面原来把写了 `audio()` 的内置卡当成图卡，画面成了「需要本地 PC 渲染辅助」。

子 Agent 报告：`AGENT-sound-ab.md`、`AGENT-sound-verify.md`、`AGENT-sound-fix.md`、`sound-effects-phase-half.md`（Doger 的实现报告）。

## 第二段：在线执行用户卡与图卡（2026-10-07 合入集成分支，`21b02329`）

### 做了什么

- **转译与加载**：在线页面用 Sucrase 3.35.1（MIT，唯一新增依赖，按需载入约 124 KB）转译同步来的用户卡与图卡；写法预检拦下 `namespace`、装饰器、顶层 await 等；包白名单与桌面相同；转译结果按内容哈希缓存；运行状态十种，参数面板按状态说明原因。
- **隔离**：画面只在跨源舞台里执行，声音只在舞台源起的后台线程里执行，编辑页面与导出页都不执行卡片代码。舞台源带全套内容安全策略与 `Connection-Allowlist: (response-origin)`（Chrome 152、154 实测能拦 WebRTC），iframe 加 `sandbox`，脚本加固作第二道；素材票据换成 HttpOnly cookie，舞台地址里不再带 `?t=`；舞台启动自检，不生效就不执行；托管方可用站点配置 `onlineCardExec: false` 整体关掉。
- **图卡**：在隔离舞台里执行，素材经 `/media-s/<会话号>/` 按 Range 取；图形能力不够判 `gpu`、输入解不了判 `media`，退回原做法。
- **轻重判定**：本页能运行的卡走内置卡那一套；**有声动效卡的画面自动即时补测、不默认判重**（用户 2026-10-06 指示）。
- **浏览器节点**：认领当前登录用户自己发出的用户卡任务，用带在线运行时版本的环境指纹；内置卡的结果键一个字不变。
- **在线导出**：同步来的用户卡用预渲染原尺寸；修了「导出页不挂同步卡的包裹层，成片里整张缺失」的缺陷。
- 语义与契约已落稿（`product/platforms.md`、`product/rendering.md`、`product/cards.md`、`glossary.md`、`mechanism/rendering.md`、`mechanism/platforms.md`、`mechanism/cards.md`；`c10-contract.md`、`m7-contract.md`、`render-queue-contract.md`、`online-card-exec-contract.md`）。

### 合入前要有结论的两件事

1. **`m7-node-probe` 在隔离摆法下曾卡住 16 分钟：产品问题，已被 `abb2f56e` 修掉，探针不是原因。** 把那次提交的改动撤掉重新构建能稳定复现（节点就绪后清单计划发了两版，但没有细任务可认领，认领数一直是 0）；其中两处各自都足以引发：没有同步卡时也起声音线程、声音状态没变也换宿主。修后连跑 5 遍都过。更深一层的机制没查（怀疑是声音状态反复变动牵动编辑页面一侧的重算）。
2. **同一张仓库用户卡「成员甲活渲、成员乙贴快照」：不是缺陷。** 对乙连续采样：0.015 秒贴已有的层，约 0.9 秒测量完成，3.36 秒切到活渲；全程只有这两种状态，没有占位、没有「需要本地 PC 渲染辅助」、没有空窗。没声明 `direct` 的卡在测量完成前按重，是既有规则。

### 旧探针按新语义改的断言

- `online-user-cards-probe`：「仓库用户卡 u 贴预渲染快照」改成「测完判轻后直接活渲」；「清单计划含 u」改成「稳定后不含」；同步卡的旧断言挪到一张故意运行不了的卡上。
- `c10-browser-probe --user-card --only-a4`：舞台读素材改认 `/media-s/`；用户卡那一层可由成员页自己的浏览器节点产出；用户卡按在不在清单计划里分流断言。
- `m7-browser-probe`、`c10-ui-probe`：断言没改。

### 做不全的（记清范围）

- **图卡任务浏览器节点不认领**：整屏快照实测 2～6.5 MB 一帧，上限 300 KB / 1 MB，没放宽（主会话裁定）。判轻的图卡在浏览器里活渲，判重的交给 PC 或云节点。
- **没进审阅表的用户卡出不了浏览器那一份**：审阅表是合成方式的唯一权威，不随源码同步；另立专项。
- 读素材采样的音频图卡不在线合成；同步来的卡引用外链资源在隔离舞台里加载不出来；内置粒子预设 `nasa` 在在线页面里不带背景图（NASA 徽标不随构建）。
- 放本机的项目没有 nginx 的策略头，在线页面自检不过、自动不执行，退回原做法。
- `c10-browser-probe` 完整版的 A5（独立渲染主机认领清单计划）在第二段之前就不稳，没修。

### 主会话的裁定（待用户合入前审）

不认 `Connection-Allowlist` 的浏览器不执行卡片的画面那一半（声音照常）；图卡任务不放宽体积上限；内置卡的外链资源不许因隔离悄悄退步；编辑器页只加 `frame-src` 一条；声音产物的键不带在线运行时版本；托管方总开关。

## 1. 做了什么

### 1.1 在线页面读（`src/render/snapshotSource.ts`，只动这一个产品文件）

- `parseLayerStreams` 认 `kind: below` 的行（只认「一个成员、`plane: stage`」的；形状不对的跳过）；`OnlineStream.kind`、流清单头的 `kind` 加 `below`。
- 就绪消息（`streamMessage`）给这种流另带 `streamKind: "below"` 和层表那一行的 `inputSig`，形状与桌面预渲染进程发的那一层相同（`server/frame-stream.mjs` 的 `belowLayerMark`）。父页（`snapshotFeed.ts` 的 `streamLayers`，上一块做的）据此发 `plane: "stage"` 的流平面；给舞台的清单 `kind` 是 `below`、`plane` 是 `stage`，播放器的 `planeFits` 对得上。
- 过期两道：在线来源按行里的 `kind` 算签名（现成的 `streamStale`，`streamInputSig` 认 `below`），过期的行不发、不取清单和字节；父页另按 store 里当前的项目比消息带来的签名（项目一改当场撤，不等在线来源收到新项目）。
- 占解码器预算、有流不读快照、暂停和拖动贴流、追到精确活渲以后撤：都是父页和舞台现成的同一套，没有改；单测和端到端探针核过对这种流也成立。
- 低内存档不消费流（`streamsNow` 只在普通档），没动。

### 1.2 清单计划那条路产这种流

「下层一」报告说要改 `local-node.mjs` 和 `frame-pipeline.mjs` 的 `streamPicked`；那以后「甲三」已经把清单计划里切分方自己的那一份做成了另一条路（`listStreamSpecs` 现算，不经 `streamPicked`），所以这次是接在「甲三」的路上，`streamPicked` 没有动：

- `server/render-node/local-node.mjs` 的 `listPlanOverrides`：依赖下层的流（一个成员、舞台坐标）照单卡流同一套开关——`ownListStreams` 为真（本机此刻能产流；渲染主机另要这个项目的「生成轨道流」开着）出切分方自己的那一份；只有 `ownListSparseStreams`（渲染主机、这一项关着）时标 `ownSparseOnly`，只出稀疏流任务；都不为真标 `browserOnly`，等于不出。浏览器那一份 `splitPlan` 本来就不出，所以这种流只按切分方自己的指纹出键、由它自己产。稀疏、满密度两种任务都有，稀疏在前（`splitPlan` 现成的规矩）。
- `server/prerender-executor.mjs` 的 `matchStream`：清单计划切出的流任务回来时，按任务的片段现算一条来对，原来只认单卡流，现在也认这种流（它的内容键只由目标卡和下层决定，与清单里还有哪些片段无关；单测钉了「只列目标卡一张 / 连别的卡一起列 / 整版全算」三样键相同）。任务说的种类对不上照旧不产。
- `server/frame-pipeline.mjs` 的 `issuedStreamSpecs`：层表按切分候选记录另列的流，原来只列单卡流，现在也列这种流（清单里的卡本机多半没判重，不从这里列层表里就没有这一行）。行的形状（`kind: below`、`plane: stage`、`inputSig`）是「下层一」的 `layerStreamsOf` 现成写的。
- `server/frame-stream.mjs` 只改了 `planListStreams` 上面的一段注释。

没动：`BELOW_STREAM_RULES.frame3d`（依赖下层又带三维外框的卡照旧没有流）；手机身份；`split.mjs`、`filter.mjs`（浏览器节点认领不了这种任务是「下层一」做的规则 7，这次只加了核对）。

## 7. 〔裁〕

都是三级。没有建解法表。

1. 渲染主机上这个项目的「生成轨道流」关着时，这种流照单卡流的规矩只出稀疏流任务（派活指令只说了开着时同样）。理由：语义写的是打开项目时给每张重卡产一套稀疏的；不出的话这种卡在这类项目里一直是占位符。
2. 在线来源的就绪消息带上层表那一行的 `inputSig`，父页再比一次。在线来源自己已经会撤过期的行；多这一道是为了项目一改当场撤（上一块做的那个 effect 在线页面同样走）。
3. 探针里「与同一帧的精确活渲相符」的阈值定为 7，只对入场动画放完以后的帧判（第 3 节第 2、3 条）。

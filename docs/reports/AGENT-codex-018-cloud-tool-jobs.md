## Implementation and verification

- Added the standalone `createToolJobs` SQLite provider. It requires a configured path and explicit asynchronous `authorize(context, 'read' | 'write')` and `verifyFence(context, revision)` callbacks. Writes re-check both authorization and the exact fence around the transaction; current conversation authorization governs reads; writes bind to the complete run/grant/instance context. `cancelForFence` accepts only the trusted matching fence and changes only its queued/running rows.
- The durable ledger stores validated scope, a hashed request idempotency key, input digest, revision/fence/state/progress, validated output references, safe error code, and timestamps. It does not store the raw request id, request body, credential, model text, or user path. On POSIX it creates new DB parent directories as `0700`, refuses an existing parent or database file with group/other access, and makes a new database file `0600` without chmodding an existing shared directory. Reopen marks running rows interrupted, keeps queued and terminal rows, and never resumes work. `close()` drains accepted ledger operations and only closes SQLite.
- Added ten focused tests covering mandatory authorization/path configuration, exact idempotency, scope/revision/transitions/output validation, current conversation reads and cross-scope denial, read-only denial, authorization/fence changes across async gaps, exact-fence cancellation, restart recovery, stored-data minimization, and close behavior. All temporary SQLite data is created under OS temp and removed by the test fixture.

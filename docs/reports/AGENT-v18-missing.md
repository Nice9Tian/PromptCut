### 3. 谁认定「确认缺失」（提交 `9de16f81`、`5159cd71`）

main 上本来就有打开本机项目后的后台检查（`src/editor/io/mediaUpload.ts` 的 `ingestUnhashedMedia`、`checkHashedMedia`），只认编辑器进程明确的否定回答，共享项目里不判。它原来的做法是清空地址、名字前加「(缺失) 」。我在这上面接：

- 认定时写记录（形状没改，仍是分支上的 `MediaAsset.missingMaterial`），名字照旧加「(缺失) 」，**地址不再清空**。原因：ChatGPT 做的占位要求记录里的地址与素材现在的地址逐字相同，而时间轴的出声清单（`src/kernel/audioPlan.mjs`）不收空地址的素材，清空了人声就出不来。

## 第 5 条：节点上怎么登记墓碑，删完怎么验

节点上的事我没做。下面是给主会话的步骤（第二轮按审查意见重排过：**先停旧服务、备份，再登记**）。

**为什么顺序要紧**：墓碑一登记，客户端打开对应的文件就会转成本地项目，不管旧服务上那个项目是不是还开着（打开文件时先问证明、后连接）。脚本查不了旧服务停没停，只能要你明说。

**前提**：这条分支的文档服务已经部署到节点（否则没有 `gone` 入口）；文档服务配了签名钥匙（`PROMPTCUT_ACCOUNT_SIGNING_KEY_FILE`、`PROMPTCUT_ACCOUNT_SIGNING_KEY_ID`，没配时入口回 503 `gone-proof-unavailable`）。

1. **确认旧服务已经停掉**（pm2 里的 `promptcut-hosted`，交接计划书记的是已停，动手那天再核一次），并且没有别的进程在读旧托管数据目录。
2. **确认旧数据的备份在、能恢复**（用户已有清单；备份本身不删）。
3. **备份账本**：文档服务数据目录下的 `account-v2.sqlite`（连同 `-wal`、`-shm`）。
4. **列清单**：要清的旧项目号写进一个文本文件，一行一个（`sp_` 开头），`#` 开头的是注释。
5. **空跑**：`node server/hosted/deploy/legacy-tombstones.mjs plan --ledger <账本绝对路径> --authority-id <签发方标识> --ids <清单> --legacy-data <旧托管数据目录>`。
   - 账本以只读方式打开，不写任何东西；给的文件不是这个签发方的账本就报错退出。
   - 逐个号报 `new` / `already` / `conflict-account-project`（与账号项目撞号）/ `invalid` / `not-in-legacy-data`（旧数据目录里没有这个项目的登记文件）。后三种退出码 2，先改清单。
   - 另报一行：旧数据里还有几个项目不在清单里、也没登记过墓碑（核对有没有漏）。
6. **真写**：同一条命令把 `plan` 换成 `apply`，加 `--source "<一句来源说明>" --old-service-stopped yes`。`--legacy-data` 必给。清单里有一个不能登记的就整份拒绝、一个都不写；已登记过的原样不动。
7. **取公钥**：`… print-public-key --signing-key-file <签名私钥文件>`，打印 43 个字符的公钥（不是秘密）。
8. **从公网核对**：`… verify --origin https://visuhive.com --authority-id <标识> --kid <钥匙号> --public-key <公钥> --service <旧文件里记的服务地址> --ids <清单> --absent <一份不该有墓碑的号>`。最后一行 `# 全部对上：N/N`，退出码 0。
9. **填信任表**（要改代码、要发版）：`server/recovery/gone-proof.mjs` 的 `TRUSTED_GONE_AUTHORITIES` 填一条 `{ authorityId, origin: 'https://visuhive.com', services: [...], keys: { '<钥匙号>': '<公钥>' } }`。守门测试要求 `origin` 是 https、条目里没有测试用的地址。`services` 怎么填见文末「查清的几件事」第 3 条。
10. 节点上删旧项目数据（要用户点头，不归这一块）。墓碑在账本里，不在旧托管数据目录里，删旧数据不会带走它。

**登记错了怎么办**：`… revoke --ledger … --authority-id … --ids <清单> --source "<原因>"` 把号从墓碑里拿掉（留一条撤销记录，`list` 看得到），之后文档服务不再为它签证明。证明本身没有有效期，但客户端从不保存证明，每次打开文件都现问一次，所以撤销之后再打开那份文件就不转换了。撤销之前已经转换过的：用户那边多了一个本地项目，原文件没有被改（转换后的第一次保存一定是另存），再打开原文件照常连回原云端项目；已经另存出去的本地副本收不回，也不需要收回。

**删完以后的真实旧文件验收（第 19 行）**，在装了带信任表的那一版的电脑上：

1. 从公网再跑一遍第 8 步，确认证明拿得到。
2. 双击（或软件里打开）一份真实旧 `.proc`：出现「云端项目已不存在」的提示；顶栏没有协作状态条；项目设置里多用户协作是关的；片段、参数、卡片都在。
3. 素材：内容库里有的照常放；没有的弹「找不到素材」窗口列出来，预览里画面占位加文件名，播放时人声放一次；导出一次，成片里占位和人声都在。分别记内容结果和素材结果。
4. 保存：弹另存为（不覆盖原文件）；核对原文件的修改时间和哈希没变。
5. 关掉软件，打开刚存的新文件：直接是本地项目，不提示，不连旧云端。
6. 再打开原文件一次：会再转换、再提示一次（原文件没被改，这是预期）。
7. `.procp` 包同样走一遍：包里带着的素材不该出占位。
8. 反例：断网时打开原文件，不该转换，状态条是等待或要认证；用另一份号没登记墓碑的旧文件，不该转换。

## 没做成的及原因

1. **账号项目的文件不带云端关联，第 7 行对账号项目没做**。现在进入账号项目时关联被置空（`syncManager.ts` 的 `enterAccountProject`），存出来的 `.proc` 就是一份普通的本地文件，重开得到一个本地副本：不会盖掉云端，但也不会连回原项目。要做得给账号项目加一种新的关联（项目号、签发方），重开时走登录再进项目，被删时走带登录的 `status` 拿证明。这不在「旧云端文件」的范围里，量也不小，我没有做。对旧项目，第 7 行走的是原有的恢复流程，这次只在前面加了「先问一次证明」，状态机单测里验了「没有墓碑就照常连接」。
2. **「没过期且连得上原项目」「没有权限」两格没有在真应用里验**，只有状态机单测。要一台活着的旧云端服务。
3. **真实旧文件验收（第 19 行）没做**，等部署和删除之后。我手上也没有真实旧文件，所以矩阵全是合成的。
4. **「桌面版」验的是开发服务器上的编辑器页面**（无头 Chrome），不是装好的桌面壳。双击文件关联、安装包里那段人声文件有没有带上，都没验。
5. **人声「放得出来」的证据是间接的**：`<audio>` 元素在播且播放头在走、字节哈希一致、浏览器解得开、导出音轨里那一段有 -21～-24 dB 的声音。没有人用耳朵听过。
6. **在线页面里把旧文件转成本地项目没验**。在线页面没有本机空间，转换后只是断开；能不能在在线页面里打开旧 `.proc` 我也没查。
7. **连着的时候项目被删**（会话中收到 4004）这条路没改：仍弹原来的「已删除」阻断窗，不转换；下次打开文件才走证明。旧项目的服务已经停了，这条路现在走不到。
8. **建了但没摆上时间轴的定制卡**：定制卡的归属按项目号记，转换换了项目号，这类卡再保存时不会被打进新文件（时间轴上用到的卡不受影响）。没处理。
9. **Linux 没跑**。
10. （已做）`scripts/probes/cross-machine-proc-probe.mjs` 的第 3、4 步原来断言「地址清空」「缺失的老视频导出时跳过」，和新做法相反，我照新做法改了，见「验证结果」。

## 4. 拿不准、请用户定的

下面几条的阈值是时间，但判的不是「这台机器有多快」。这次都**保留为通过条件**，没有动。

1. **声音对齐**（`sound-preview-probe`，任务书点名的一条）：元素位置与时间轴相差 0.15 秒以内的拍占比 ≥ 90%；播放中才挂上的元素起声偏差的中位数在 −0.25～+0.05 秒、90% 的拍离中位数不超过 0.08 秒；时间轴相对墙钟的速率低于 0.9 时这一遍不作数、重量至多 3 遍。
2. **可见舞台的空白**（`online-stage-handshake-probe`）：出画面之后（含换回双舞台那一下）可见舞台空白不超过 1 秒。它和「黑帧数」是一类事，只是用时间量的。
3. **去掉时间门槛之后少了一层保护的**：`cloud-agent-run-probe` 的 E1 原来靠「耗时 < 500 毫秒」证明工具没有干等；现在只剩「回的话是发起方不在线、不要等待」这一条。「2 秒内停下」「5 秒内停下」「5 秒内断开」同理：现在只判最终停了、断了，慢到几十秒也算过，只在耗时记录里看得出来。这是照规则改的；如果其中某条其实是产品承诺（例如撤销后必须多久之内停），需要另定一个不随机器快慢变的判法。
4. **产品计时器的下界**保留为通过条件：退回不早于 20 秒的握手 / 重载时限、保持期 ≥ 30 秒才断开、死循环不早于合成时限被掐。机器慢不会让它们不过，早了才是缺陷。
5. **`m7-node-probe` 的长任务数**（P-m7-node）现在只记不判，注释写的理由是「带耗时门槛的项在笔记本判」。按新规则长任务数是通过条件；这一处原来就不是断言，这次没有改成判，只把注释改了。要不要改成判，请定。

# AGENT-v18-cardsync：账号云端项目里的用户卡源码同步、卡片声音上传、Agent 一侧旧绑定

分支 `claude/v18-cardsync`，从 main `5c286289` 起。派活指令共五条（第 6 条渲染节点不做也没碰）。

名词：**账号项目** = 走网站账号的云端项目；**编辑器进程** = 桌面版里跑 vite 的那个 Node 进程（卡片文件、改动层、卡片源码同步都在它里面）；**票据** = 文档服务给一条连接用的一次性短凭证；**访问令牌** = 账号服务发给一次登录的短凭证（寿命 120 秒，到期前客户端自己续）。

| 条 | 结果 |

## 开工核对（读代码，和派活指令里的描述对照）

- 三处 `!account` 挡掉绑定、`auth.ticket` 在账号连接上被拒、`generatedAudioUpload.ts` 签旧票据、进账号项目不解 Agent 绑定：都属实。
- 账号闸（`server/docservice/account-hosted.mjs` 的 `gate`）对内容库本来就放行：`instanceMessageAction` 把 `content.put` 归「写」、`content.list/get/watch` 归「读」，再问成员权限。所以第 2 条不需要改闸。
- 桌面外壳的账号桥路径白名单（`desktop/src-tauri/src/account_vault.rs`）本来就放行 `/hosted/shared/account/session`，「页面多取一份会话」不需要改外壳。
- 派活指令没提到、做的时候才撞上的两件事：
  - **接续不能带票据**。文档服务规定接续项旁边不能有鉴权项（`server/docservice/session.mjs` 的 `parseSessionItem`），带了握手回 400。所以卡片同步只在建新会话时出示票据。
  - **账号连接有寿命**。连接上每条消息都过闸，闸拿建连时那张票据背后的访问令牌去问账号服务；令牌 120 秒到期后，这条连接还开着，但每条消息都回 `credential-revoked`（再晚是 `authorization-expired`），续令牌也救不回这条连接。实验（真服务）：建连 100 秒时读写正常，130 秒、145 秒读写都被拒。「票据到期要续」因此不是「接续时带新票据」，而是「到期前换一个会话」。

## 做了什么

### 1、2、3 卡片源码同步

路：照建议的走，页面凭自己的登录向 `/hosted/shared/account/session` 另取一份会话，把其中的连接票据交给编辑器进程。角色仍是 page，没有新角色，没有放宽「不许自报角色」，`account-hosted.mjs` 一行没动。

- `server/account-card-link.mjs`（新）：账号项目用的端点 `accountCardEndpoint`。只在建新会话时出示票据；按票据的到期时刻提前 8 秒结束这个会话、凭新票据建下一个；万一没赶上，收到 `credential-revoked` / `authorization-expired` 的回包也当场换。换的那一下对同步规则来说就是一次断线重连：在途的上传留在待上传里，新会话建成后重新订阅、重新对账。`cardSyncConnect` 按绑定选端点：账号项目用它，本机项目和旧共享项目与原来的缺省端点一模一样。
- `server/vite-plugin-cards.ts`：`/api/cards/sync/bind` 多认一种 `mode: 'account'`；页面交回票据时可以带 `expiresAt`；`createCardSync` 的 `connect` 换成 `cardSyncConnect`。
- `src/editor/sync/accountCardSync.ts`（新）：页面答票据请求。已经不在这个项目里（换了项目、换了账号）就不取并解绑；会话接口回 401 / 403 / 404 解绑；断网、503 只抛，编辑器进程退避后再要。
- `src/editor/sync/cardSync.ts`：绑定多一个 `account` 标记；票据可以带到期时刻。
- `src/editor/sync/syncManager.ts`：见下面「改了哪几行」。
- `server/card-sync.mjs`、`server/render-node/session-link.mjs` 没动（都在不许碰的那一带）：换会话是在它们外面包了一层端点做的。

停：服务端在退出登录、被踢、项目被删时会把这个登录或这个项目的连接全关掉（原有行为）；之后编辑器进程建新会话要票据，页面取不到，解绑，编辑器进程回本机空间，不再重试。页面自己判出失效（`enterAccountProject` 的 `fail`）时也直接解绑。

### 4 卡片声音上传

`src/editor/io/generatedAudioUpload.ts`：账号项目里写票据改用 `remoteAssetTicketInfo`（进项目时已经接好的那套，401 时强制换一张），不再发 `auth.ticket`；请求带 `credentials: 'omit'`（素材服务见到网站 Cookie 就拒）；上传途中换了账号项目也取消。`src/editor/media/assetTiers.ts` 加了一个只读的 `remoteAccountProjectId()`。旧共享项目和本机项目的路没变。这个改动对在线页面同样生效。

### 5 Agent 一侧旧绑定

`src/editor/sync/agentSideBinding.ts`（新）：原来写在 `syncManager.ts` 里的 `bindAgentSide` 原样搬出来，加 `releaseAgentSide`。进账号项目时不管页面记不记得绑过都发解绑（服务端的绑定是编辑器进程里的状态，页面整页重载后自己不记得）；绑与解排同一条队，解绑不会被一条还在路上的旧绑定盖回去。账号项目里本机 Agent 仍走「页面代做」，正式绑定没做。

## 发现的三个现状问题（都不在这次清单里，没改，要主会话决定）

1. **账号项目里，页面自己那条连接进项目约两分钟后写不进云端。** 和上面「账号连接有寿命」是同一个原因，但页面的连接没有换会话这一步。探针实测：甲登录 161 秒后在页面里放一个片段，服务端的项目版本没动（10 → 10），乙看不到；甲的页面仍显示在线、未确认数是 0、片段还在本地、没有任何提示。裸连接实验同样：130 秒起读写都回 `credential-revoked`。用户看到的就是「改了半天，别人那边没有，自己也不知道」。我的探针因此把甲页面写项目的几步都排在登录后 100 秒内。
2. **账号项目里，在线页面不执行用户卡。** 编辑器页把素材票据交给舞台源那一步（`src/online/stagePolicy.mjs` 的 `TICKET_PATTERN`，线上 nginx 的 `nginx-site-promptcut-stages.conf` 第 17 行由它生成）只认旧票据的形状 `v1.<…>.<…>`；账号会话签发的素材票据是 43 个字符的随机串，交接回 400。结果：`cardExec` 是 `grant-failed`，用户卡显示「需要本地 PC 渲染辅助」。这和语义 `product/platforms.md`「在线浏览器执行经文档服务同步来的用户卡」对不上。要改的是那个正则加上 nginx 重新部署。
3. **页面的账号连接断一次传输后，接续会一直失败。** `enterAccountProject` 给接续也配了带票据的子协议，文档服务对「接续项旁边有鉴权项」回 400。这条是读代码加端点一级的实测（我的同步端点最初也这么写，日志里是连续的 `Unexpected server response: 400`，直到 60 秒保留期过完才重建会话），没有在页面上单独测。

另有两处小的、看到了没查：账号项目里提示气泡把写入者显示成 `account:acc_…@设备号`（成员名单在账号项目里是空的，`writerLabel` 对不上名字）；乙进项目时甲的页面弹过一次「你的近期修改已被 … 覆盖」。

- `2-c-online-as-is.png`（现状）拍到的是「正在测量卡片」遮罩：现状下这个遮罩等了 60 秒没退，没查原因。

## 裁定〔裁〕

- 〔裁一〕接续不带票据。原因：文档服务的现有规定（带了回 400），不是我选的；接续时服务端按会话里的身份重新核对（`resumeGate`）。用户看不出区别，三级。
- 〔裁二〕账号连接到期前 8 秒换会话，而不是等被拒。8 秒是为了比页面续访问令牌的提前量（10 秒）小，这样要票据时页面已经续过令牌，拿到的是满寿命的票据。三级。
- 〔裁三〕换会话用「先关旧的再建新的」，中间有几百毫秒没有连接；期间的上传留在待上传里、别人的版本靠新会话的对账补上。没做「先建新的再关旧的」，因为要改 `card-sync.mjs`。三级。

## 对任务书或语义的更正建议

- `docs/semantics/product/platforms.md`「在线浏览器执行经文档服务同步来的用户卡」在账号项目里目前不成立，建议在修好之前记进待办。

## 1 页面的账号连接约两分钟后写不进云端

**做法**：和卡片同步同一个思路（到期前换会话），但页面这边是「先建好新的再切」，不是先断再连：

- `src/editor/sync/accountLinkLife.ts`（新）：什么时候换。每 3 秒看一次墙上时钟，离票据到期不到 30 秒就换；取票据时要求访问令牌至少还剩 60 秒（`src/account/client.ts` 第 102～104、208 行给 `session()` 加了 `minRemainingMs`）。回到前台、网络恢复、睡眠醒来时不等定时器，当场看一次。
- `src/editor/sync/link.ts` 的 `renew()`（第 203～260 行一带）：新会话建成后，最多等 8 秒让旧会话上没确认的提交落定，然后切过去；旧会话再留 5 秒只为收完已发请求的回包。
- `src/store/docsync.ts` 的 `handover()`（第 463～481 行）：切的那一刻不记成离线，没确认的提交在新会话上补发，文档服务按提交号去重；所以别人恰好这时改了项目也不会弹离线对话框。切的这一下没有新版本时，手里的项目对象原样留着，界面不重算（第 554～558 行）。换连接后确认先后颠倒不再触发整份重取（第 677～679 行）。
- `src/editor/sync/syncManager.ts` 的 `enterAccountProject`：接上寿命模块；重新建成会话时不再把进项目的整套流程重跑一遍（原来每次重连都会再弹一次「已进入云端项目」）。

**换不成时**（都用现有的状态和文案，没有新字）：

| 情况 | 页面 |
|---|---|
| 账号服务一时不通 | 到期之前一直重试，页面照常；到期那一刻还没换成 → 按断线处理，状态变「离线」，改动进离线队列；通了之后照现有的离线重连补发 |
| 退出登录 | 现有的 `fail`：停连接，气泡「登录已失效，请重新登录。」 |
| 被踢 | 现有的被踢弹窗 +「你已被禁止加入这个项目。」 |
| 项目被删 | 气泡「这个云端项目已不存在。」（客户端里已有的句子，原来对不上服务端的错误码，现在接上了） |
| 连接已经过期才发现（睡眠醒来） | 文档服务回「凭证到期」时当场换，没确认的改动在新会话上补发；换不成转离线 |

**第 2 条修好后露出来的一件事，一并处理了**：创建者把成员从可写改成只读时，服务端会关掉这位成员的旧连接，用的关闭码和「被踢」是同一个（4003）。原来接续一直失败，页面歪打正着地重新连上了；接续修好后页面会把它当成被踢。现在账号项目里关闭码不当终局，重连时取票据的接口回 401 / 403 / 404 才收场（`link.ts` 的 `isFatalClose`）。反过来只读改回可写时服务端不关旧连接，旧连接一直是只读，所以页面读到自己的权限变了就换一个会话（`accountLinkLife.ts` 的 `accessSeen`）。

## 2 接续带了票据一直回 400

- 页面上复现：探针里乙（桌面页面）`cut()` 断一次传输，改之前 **90 秒**才收到甲之后的改动（接续一直失败，等 60 秒保留期过完才重建会话）；真服务测试第 1b 步改之前 60.4 秒。
- 改动：`syncManager.ts` 的 `enterAccountProject` 不再给 `resumeProtocols`（一行）。接续只带会话项，服务端按会话里记下的身份重新核对登录与成员资格。
- 改之后：探针 **614 毫秒**接回、943 毫秒收到之后的改动；测试第 1b 步 230 毫秒接回，会话没断。
- `src/editor/sync/reconnect.test.mjs` 里原来有一条测试把「接续带票据」钉成了预期，改成「接续只带会话项」，并用文档服务自己的握手判定核对（旧写法被判成写法不对）。

### 主会话部署时要做的

线上文件 `/etc/nginx/sites-available/promptcut-stages`（s1、s2 两个舞台源），两处，都在文件开头的 `map` 块里：

1. `map $http_authorization $pc_grant_ticket` 里那一行，换成：
   `"~^Bearer (?<pc_gt>(?:v1\.[A-Za-z0-9_-]{1,1600}\.[A-Za-z0-9_-]{1,200}|[A-Za-z0-9_-]{43}))$" $pc_gt;`
2. `map "$request_method|$pc_grant_origin_ok|$pc_grant_ticket" $pc_grant_cookie` 里那一行的开头，从 `"~^POST\|1\|(?<pc_gt2>v1\..+)$"` 换成 `"~^POST\|1\|(?<pc_gt2>.+)$"`，后面的 cookie 串不动。

也可以直接拿仓库里的模板替换 `{{DOMAIN}}`、`{{BIND_ADDR}}` 后整份换上。主站的配置、两个策略头片段不用动。顺序：先备份原文件，改完 `nginx -t`，通过后 `systemctl reload nginx`（不用重启任何服务，也不用先换页面：旧页面发的仍是旧票据，照样认）。

验证（把域名换成线上的）：

- `curl -i -X POST https://s1.<域名>/media-s/<32 位十六进制>/_grant -H "Origin: https://<域名>" -H "Authorization: Bearer <43 个字母数字>"` 应回 **204** 且带 `Set-Cookie: pc_rt=…`（改之前回 400）。票据是随便编的也行，这一步只看形状；
- 同一条命令把票据改成 42 个字符，应回 **400**；把 `Origin` 改成别的站，应回 **403**；
- 然后在线页面进一个账号项目、放一张用户卡，舞台上画得出来（不再是「需要本地 PC 渲染辅助」）。

回退：把备份的文件放回去，`nginx -t && systemctl reload nginx`。回退后账号项目里在线页面退回不执行用户卡，别的不受影响。

## 4 两处小的

**提示气泡把写入者显示成 `account:acc_…@设备号`**。原因：非账号项目里，气泡按成员名单把写入身份换成显示名；账号项目的成员名单不走那条路，页面手里是空的。改法照非账号项目的做法：进项目时取一次账号成员名单（之后成员有变化再取），按账号查名字（`src/editor/sync/labels.ts` 第 91～96、132～133 行；`syncManager.ts` 的 `displayNames`）。探针截图 `3-b-desktop-v2.png` 里现在是「已同步为 dualUser0 的版本」。涉及给用户看的字的两点见下「要用户定的事」。

**乙进项目时甲页面弹「你的近期修改已被…覆盖」**。是误报，和账号无关，旧共享项目里同样会有。探针抓到的原始消息：被覆盖的是 `/meta/duration`（项目总时长），覆盖它的是乙页面的一次 `set /duration`。甲放片段时自己写过一次总时长；乙进来收到这个片段后，乙的页面也照自己手里的时间轴重算了一遍总时长并写回去；文档服务看到「甲刚写过的东西被乙写了」就通知甲。总时长是每个页面都会自动重算的派生值，内容没丢。没改（不在这次范围里，改法也要定：别人的改动引起的重算不写回，或者这个字段不发覆盖通知）。

## 这一轮看到、没处理的

- **新用户卡偶尔画不到对方桌面的舞台上**：四次整跑里有一次，乙的改动层和页面注册表都有了这张卡，但两个舞台窗口里的注册表没有（`known: false`），90 秒没画出来；那一次两个编辑器进程起得特别慢。像是开发服务器给舞台窗口推热更新的时序问题，和账号无关。没查。
- **账号服务不通时气泡重复弹**：每次重连取票据失败都弹一条「云端服务暂时不可用，请稍后重试。」，探针里同时挂着两条。原有行为。
- **文档服务对账号连接落提交很慢**：每条提交都要问账号服务，这台机器上一秒落两三条。测试里两个人各 0.5 秒改一次就有积压。没查线上是不是也这样。
- **每换一次会话要重新取一遍整份项目**（约 90 秒一次）。换的这一下没有新版本时界面不重算，但服务端照样要发一份。项目很大时是个开销。更省的办法是让文档服务支持「在原连接上换票据」，那要改协议和服务端，这次没做。
- 第 3 条修好后在线页面的截图 `2-c-online-as-is.png` 已不再生成，旧文件删了。

## 没做成的

- 真的桌面外壳仍没参与验证；云端 Agent 仍是模拟的（同上一轮）。
- 「睡眠醒来」在页面上是用冻结在线页面模拟的；桌面这两页是开发服务器给的，冻结后热更新通道断开、醒来会整页重载，所以桌面的这一条只有真服务测试里「计时器停着」的那一步，没有页面级的。
- `2f8f51ba` 里混了第 4 条取成员名单的那几行（和第 1 条的补丁在同一个文件的同一段里）。

## 要用户定的事

1. **账号项目里成员名字显示什么**。现在显示账号名（例如「已同步为 dualUser0 的版本」）。非账号项目里同名的人会带上设备名来区分；账号项目里同一个账号在两台设备上，现在两边都只显示账号名。要不要带设备名，请定。名单还没取到的头一两秒里，气泡仍会显示内部标识；要不要改成一句固定的话（比如「别人」），也请定。
2. **项目被删时的气泡**。现在用的是客户端里原有的「这个云端项目已不存在。」，原来因为错误码对不上，实际显示的是「请求失败（no-project）。」。如果这句不合适请给原文。
3. **账号服务一时不通时页面显示「离线」**。用的是现有的离线状态和离线对话框，没有单独的说法。要不要单独告诉用户「账号服务连不上」，请定。
4. **「你的近期修改已被…覆盖」的误报**要不要修、怎么修（见上第 4 条）。

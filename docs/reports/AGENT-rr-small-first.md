# rr-small-first：素材上传先传小尺寸、再传原尺寸

用户 2026-10-13 另加的一条（`docs/plan/user-decisions-2026-10-13.md` 第 1 节第 3 条）：「素材在上传素材云端的时候，强制先上传小尺寸，然后上传大尺寸，这样就解决没有小尺寸素材的问题了。」分支 `claude/rr-small-first`，从 main df7511a3 分出。

## 1. 各条上传路径的现状（改之前）

「小尺寸」只对视频有：桌面版的编辑器进程用 ffmpeg 转（`server/media-tiers.mjs` 的 `makeSmallVersion`，800×600 以内的 H.264）。图片、音频从来只有原尺寸一档，哪条路径都一样。

| 路径 | 谁产小尺寸 | 两档什么时候传 | 有没有「原尺寸先到或只有原尺寸」的窗口 | 多个素材的先后 |
|---|---|---|---|---|
| 桌面版导入（连着远程素材服务时） | 编辑器进程，导入后在后台转 | 小尺寸转完（或确定转不出）才把这个素材交给上传队列（`media-tiers.mjs` 的 `buildSmall` → `handToQueue`），队列里先小后大 | 没有先到的窗口。转码失败、没有视频轨的，只传原尺寸一档 | 改之前：逐个素材先小后大（A 小、A 原、B 小、B 原）。所以 A 的原尺寸很大时，B 的小尺寸要等它传完 |

## 2. 改了什么

只改了一处：`server/upload-queue.mjs` 的派活顺序。桌面版所有往远程素材服务传素材的路径都经它，所以上表前三行一起变。

- 队里只要还有哪个素材的小尺寸没传完，就先传它（按进队先后）；所有小尺寸都在素材服务上 `complete` 了，才按进队先后传原尺寸。
- 传原尺寸期间新进队的素材、或给已在队里的素材后补上的小尺寸，排在剩下的原尺寸前面；正在传的那一档传完才让（不打断）。
- 小尺寸传失败在退避时，任何原尺寸都不传（照旧「严格按序」，只是序变了）。
- 只有原尺寸一档的素材（图片、音频、转不出小尺寸的视频）排在所有小尺寸之后。
- 出队条件不变：这个素材传过的档都在素材服务上 `complete`。队列文件的格式不变；哪一档传过只记在内存里，重启后从小尺寸重新问起，已传完的档问一次 `chunks` 就过，不重传。
- 原尺寸传完之前成员看到什么，没动。

查过会不会破坏别的承诺：带宽闸（预渲染产物优先）照旧每片都取；断点续传照旧；项目归属的核对照旧每档、每片都做。没有发现依赖「一个素材两档连着传」的地方。

## 3. 在线浏览器导入：没做，评估如下

现状见第 1 节：在线页面根本不能导入素材，所以现在不存在「在线浏览器只传了原尺寸」的窗口。而 `product/asset-service.md`「上传」和 `mechanism/asset-service.md`「逐个素材上传」已经写着「在线浏览器导入素材时在页面里转出素材小尺寸，先传它，再传原尺寸」——语义走在代码前面，要做的是一个新功能，不是改顺序，这次没硬做。

要补的三块，从便宜到贵：

1. **页面往素材服务传素材**（分片、断点续传、算 sha256、带票据、登记进项目）。页面里现成的只有传预渲染产物的 `src/online/snapUploader.ts`，可以照它写。几个 G 的文件要流式算哈希。
2. **图片、音频**：本来就没有小尺寸一档，有了第 1 块就能直接传，不涉及先后。
3. **视频的小尺寸**。页面里现成的：WebCodecs 编码（`src/render/streamEncode.ts`）、MP4 封装（`src/export/mp4Mux.ts`）。缺的：任意用户视频的解封装（仓库里没有 mp4box 一类的库，不许新增依赖）、音轨的转码与封装。三种做法：
   - 甲：用 `<video>` 元素播放加 `requestVideoFrameCallback` 逐帧截，喂现成的编码与封装。不用解封装，浏览器能播的都能转；代价是按播放速度转（十分钟的视频转十分钟，页面要一直开着），音轨要另走 `captureStream` 或 `decodeAudioData`，掉帧时时间戳要自己对。
   - 乙：自己写 MP4 解封装加 `VideoDecoder`，比实时快；只认 MP4/MOV，要处理 B 帧、可变帧率、旋转、HDR，工作量和风险都最大。
   - 丙：页面不转，原尺寸传完后由云端的渲染节点（有 ffmpeg 的那台）补转小尺寸。和现在的语义「素材服务不转码、由上传方转」冲突（二级），而且做不到「小尺寸先到」。
   - 建议：先做第 1、2 块加甲，转不出来的（浏览器播不了的编码）照语义只传原尺寸一档；转的时候给进度并允许用户跳过。在那之前保持「导入媒体」置灰就不会有只有原尺寸的窗口。

### Linux 两用户自检怎么跑

`sudo node scripts/probes/account-tools-perms-linux.mjs`

只在 Linux 上、以 root 跑（别处直接退出，退出码 2）。把这一版的检出放到节点上别的用户读得到的位置（只要 `server/` 和这支脚本，不要 `node_modules`；不要放在 `/root` 下面），Node 用产品用的那一个。它不建系统账号：挑两个没登记的数字用户号、一个没登记的数字组号，每一步起一个子进程，子进程先降成那个用户（补充组、主组、用户号、umask 0007）再调产品自己的模块。只碰它自己建的临时目录，跑完删掉。可选 `--tmp <目录>`、`--repo <检出>`、`--keep`。

期望输出：每项一行 `PERMS OK …`，一行不计数的 `PERMS INFO …`，末行 **`PASS 22/22`**（有没过的是 `FAIL k/n`，退出码 1；哪一步自己出错会多记一项没过）。22 项：降权生效 2；用量 5；浏览器目录与记号 11（其中 2 项是在任务用户下建一份真的工具提供者）；删对话 3；收尾 1。那一行 `PERMS INFO` 请主会话务必看，见下面「顺带发现」。

### 追加：删对话的接缝（块五合进 main 之后）

块五把账号模式的删对话做成了真的删，并留了 `onConversationDeleted`。我接上的是：文档服务确认删掉以后，这个对话的**云端浏览器目录**和**对话目录**（`tenants/<项目>/conversations/<对话>/`，里面 `tools/` 下是作业账本、追踪结果、委托记录）全清。

- 做法和转私有一样：主服务先把这个对话**记进待清的单子**、给浏览器目录留记号，再尽力删一次。单子记下了就算办妥；单子都记不下、东西又还在，才报没办成（页面得到 503，块五的对账会再来）。幂等。
- **这个对话再也没有任务也清得掉**：任何一条任务的进程开工时都会照单子清；主服务每 60 秒那一趟对账里也顺手再删一遍单子上还没清掉的。**清不到的一种**：节点上一条云端任务都不再起，那时要手工以任务用户删；README 写了。

### 顺带发现（不是我这一块的文件，没改，请主会话定）

**块五的清理器在两个用户的生产上多半删不动对话目录，删对话会回 503。** `conversation-purge.mjs` 由主服务执行、先于我的接缝跑，它要删 `tenants/<项目>/conversations/<对话>/`。这个目录是任务进程建的，`account-runner.mjs` 用的是 `mkdirSync(…, { recursive: true, mode: 0o700 })`，连上面几级一起都是 0700、属任务用户——主服务连 `tenants/` 都进不去。照代码推：`rmSync` 抛没有权限，清理器抛 `purge-failed`，`DELETE` 回 503，重试也一样；我的接缝排在它后面，轮不到。Windows 单用户的测试和探针验不出。

这是**照代码推出来的，没有实测**。Linux 自检里那一行 `PERMS INFO` 就是拿真的清理器在这种目录上跑一遍的结果：`"ok":false` 加 `purge-failed` 就是坐实了。坐实的话改法有现成的：对话目录我的单子已经会由任务用户一侧删掉，清理器只要把「够不到」当成「交给任务用户一侧」而不是失败，并把接缝挪到它前面。这是块五的行为（用户定的是「清干净」），由主会话定。

`docs/semantics/product/agent.md`：前面建议加的四句里，第三句（代下）和第四句后半（关 Agent 清浏览器状态）**撤回**，改成：**「采集遇到要登录的站点时，云端按未登录的画质下载（请发起人的电脑代下的做法已经做好但没有开放）。」「对话转成私有时，这个对话在云端浏览器里攒下的状态清掉；创建者关掉云端 Agent 时不清。」**

### 要用户定的事（这次更新的三条）

1. **云端 Agent 请你的电脑代为下载时，要不要提示你、提示什么字。** 是什么：有的视频站登录后才给高画质，登录信息只留在你自己的电脑上，所以做了一条路——云端让你的电脑用你的登录去下、下好直接传进共有项目。现状：这条路**做好了但关着**，云端一律按未登录的画质下；Agent 仍然可以在你的桌面上弹出登录窗口帮你登录，那个你看得见。选项：（甲）一直关着；（乙）打开，并在桌面版显示一行提示，字要你给；（丙）打开，每次弹确认框，你点了才下。后果：甲没有高画质；乙要一句新的界面文字；丙你不在电脑前会卡到超时再退回低画质。建议乙。定了以后部署上把 `PROMPTCUT_AGENT_COLLECT_DELEGATE` 写成 1，并且要先补上「撤回已经在传的文件」那个接口。
2. **Agent 说完话、后台作业还在做的那段时间，页面上显示什么。** 是什么：云端一条任务一个进程，进程收了作业就没了，所以 Agent 回完话以后任务进程还要等转写、镜头识别这些作业做完。现状：这段时间页面显示的是现成的那句「执行已结束，等待云端确认关闭与结算。」，**没有说是在等后台作业**；你在同一个对话里发的下一条会排在后面。选项：（甲）照旧用这一句；（乙）换一句说清楚在等什么，字要你给。建议乙。
3. **等满一小时作业还没做完会怎样。** 现状：到一小时任务进程不再等，作业被中断，这一轮仍然记「完成」，**不另外通知你**；之后让 Agent 查那个作业，看到的是「被中断」。选项：（甲）就这样；（乙）这种情况把这一轮记成别的结果或在对话里留一句话，字和记法要你给。没有建议。

原来的第 3 条（关 Agent 时要不要清浏览器状态）不用定了：照网页操作原来的规矩，不清。

## 做了什么

### 进程分工

| 东西 | 在哪个进程 | 文件 |
|---|---|---|
| 八个包的提供者、作业账本、追踪结果、代下的委托记录 | 任务进程，一条任务一份，随任务建、随任务收 | `server/agent/service/account-tools.mjs`（新） |
| 反向通道的登记表（哪张页面在线、哪条请求在等、请求状态落盘） | 主服务 | `account-master-assembly.mjs` 里建 `page-bridge.mjs` 的桥 |
| 任务进程里的反向通道 | 一个薄客户端，形状同桥（`requestPage`、`initiator`、`limits`、`extraTools`） | `server/agent-service/worker-page-client.mjs`（新） |
| 任务进程 → 主服务「向发起人页面要一件事」 | 主服务那个只绑回环、双向 TLS 的内部口上的新路径 | `server/agent-service/worker-page-internal.mjs`（新） |
| 代下的委托逻辑（核回执、核素材、登记） | 任务进程（它要用这条任务的「项目素材」和写权限）；经薄客户端问主服务 | `collect-bridge.mjs` 原样用 |
| 对话转私有、关 Agent 时清云端浏览器数据 | 主服务当场清；有任务进程占着就留记号，那个进程自己清 | `account-master-assembly.mjs`、`account-tools.mjs` |

采用的是派活指令第 3 条的默认做法（W2 报告的甲案），C1 报告建议的「委托逻辑放任务进程、经内部请求转主服务」与它不冲突，两样都照做了。

**内部请求的鉴权**（不比交事件的那条弱，逐样相同）：连过来的证书指纹必须是文档服务此刻说的那一代任务证书；请求带任务进程内存里那把钥匙的签名，签的是固定的域名与路径、权威号、root 的槽与代、任务绑定的摘要、任务的八个字段、请求号、请求体哈希、这条 TLS 连接的导出值、一次性随机数；每个请求都现问文档服务（主身份的 `workerEventSource`）。派活指令的五条要求：

| 要求 | 怎么做的 | 证据 |
|---|---|---|
| 鉴权不比现有内部通道弱 | 见上；签名方法加在任务进程的实例会话里（`agent-instance-session.mjs` 的 `workerPageEnvelopeFor`、`workerPageProofFor`），和交事件用同一把钥匙 | 单测 WIRE-PAGE 五条（别的证书、别的钥匙、换连接、签完改请求体、重放、任务已收回、换了一代进程都拒） |
| 项目、对话、任务、发起人取自可信上下文 | 主服务拼运行上下文用的是文档服务的回答（`source.runGrant`），请求体里的只用来找到那一条；发起人账号根本不在请求体里；发起页号取文档服务里那条消息的选区快照 | WIRE-PAGE「上下文取自文档服务的回答」；探针隔离段 |
| 任务进程取消传到主服务 | 一次请求是一条长挂的 HTTP 请求；取消就是断开连接（登记器的信号、调用方的信号、`cancelRun`、`close`、进程被杀都一样），主服务看到连接没了把等待作废 | WIRE-PAGE「连接断掉收到取消信号」 |
| 主服务重启后在等的请求如实回 | 任务进程得到连接断开或超时，回 `{ delivered: false, offline: true, why: 'master-unavailable' }`，工具回「发起方不在线」；登记表重开时把还在等的标成被中断（W2 原有） | 探针「主服务关闭」段 |
| 页面晚到的回答拒掉 | 桥原有的重核一行没改；任务进程收到「页面交回了」之后自己再向文档服务核一次授权、栅栏版本、页面号 | 探针「这一轮结束之后页面再交被拒」（409） |

### 工具表怎么翻的

`cloud-tools.mjs` 没有改任何一个工具的 `mode`。每个可以由提供者接的工具多了一个 `provider: '<族>'`；一个工具算不算可用，看的是**这个进程里有没有真的建出它的提供者**（`account-tools.mjs` 把建出来的工具名交给实例）：

- `checkCloudTool(tool, provided)`：`provided` 里有就可用，否则按原来的 `mode` 答。
- `cloudOpenTools({ look, provided })`：交给模型的清单 = 原来的两张表之一，加上建出来的。
- `cloudSystemNote({ look, provided })`：给模型看的那一段按接上了哪几族来写。
- 不给 `provided`（旧托管档、桌面）时三样都逐字是原来的（单测 WIRE-TABLE 第二条；另用脚本拿 main 的旧文件逐项比过：128 个工具的回答、两张清单、系统提示词全部相同）。

一族建不出来（缺依赖、两边工具名对不上）只是那一族不算接上，日志记 `agent.account-tools.skipped`；节点没装 Python、ffmpeg、浏览器不算建不出来，提供者照样建、工具照样交给模型。没有到主服务的内部通道时反向通道那三族（页面控制、网页接管、采集登录）不建，工具照旧回「发起方不在线」。

### 收场到底靠什么

| 事件 | 任务进程名下的子进程、浏览器 | 浏览器用户数据目录 | 作业账本 | 在等发起页的请求 |
|---|---|---|---|---|
| 停止 | root 关任务进程；浏览器随管道断开自己退 | **留着**（W1 的裁 2：登录态保留） | 下一次打开账本时标成被中断 | 连接断开，主服务作废 |
| 转私有（别人的那一轮被收回） | 同上 | 主服务删（那个进程还没被关完就隔两秒再来，最多两分钟） | 同上 | 同上 |
| 转私有（发起人自己正在跑的对话，那一轮保留） | 不动 | 主服务留记号；任务进程在下一次网页操作前关浏览器并删，或收尾时删 | 不受影响 | 桥原有：正在途中的那一次拒收 |
| 关 Agent | root 关任务进程 | 主服务从「强制终态」里看到原因是 Agent 被关，把这个项目各对话的都删 | 标成被中断 | 作废 |
| 删对话 | — | 备好了 `purgeConversationBrowser`（整个目录删掉）。**账号模式的删对话接口本身还没开放**（回 503 `deletion-pending`），所以没有调用方 | — | — |
| 任务进程被杀 | 浏览器随管道断开自己退 | 留着 | 标成被中断 | 作废 |
| 主服务重启 | 不影响任务进程里的子进程 | — | — | 任务进程得到连接断开，回不在线 |
| 任务正常结束 | 提供者逐个 `close`，回执里任何一族没关干净就不形成收尾记录 | 留着 | 关 | — |

任务进程里的 `fence` 钩子（账本标取消、请求作废、关浏览器并按原因删目录）接在 `drainControl` 里，在进程内执行器那条老路上会跑到；在一条任务一个进程的生产形态里它不是保证，只是多一层。

## 部署要新配什么

工具在任务进程里跑，而任务进程的配置不来自环境变量，来自 root 入口每开一代写的那份设置文件。所以新配置进的是 **root 入口的配置 `agent-root.json` 的 `worker` 一节**，不是主服务的环境变量（和派活指令写的「环境变量」不一样，以代码为准，见「更正建议」）：

- `worker.runAssets`：写了才会建这些提供者。
- `worker.tools`：键值表，键名沿用各包报告里起的环境变量名，值是节点上的绝对路径。都可选；写了但路径不在，任务进程拒绝启动。键的清单与「不写的后果」、节点上要装什么（ffmpeg、Python、各种权重、chrome-headless-shell、`puppeteer-core`、yt-dlp，哪些可选）两张表在 `server/hosted/deploy/README.md`「工具要的节点依赖」。
- 主服务不用新加任何变量：登记表放在它原有的数据目录里（`page-requests.sqlite`）；nginx 不用改。

我没有安装任何东西。

### 顺带发现（不在这一块的文件里，没改）

**一位成员的页面连接登录过期后，全项目的在场表查询都失败。** `server/docservice/modules/selection.mjs` 的 `querySelections` 逐条核每条在线连接的登录，核不过时只有「没权限（403）」会把那一条拿掉，别的（登录过期是 401）整次查询回 `authority-unavailable`。后果：只要有一位成员的页面连着而登录过期了，这个项目里所有任务的 `get_selection` 与页面工具（`seek` 等）都按「取不到 / 不在线」答，直到那条连接断开。探针里复现得出来：乙的连接留着不管，约三四分钟后甲的 `seek` 开始回不在线，任务进程日志是 `agent.page.presence selection-authority-unavailable`；把乙的连接关掉就好了。建议把 401 也按「这一条不算在线」处理。


### 探针里哪些不是产品接线（不冒充）

- **模型**是模拟模型，没有用真模型。
- **root 看操作系统的那一半**在 Windows 上是夹具受控的（没有 systemd）：进程被关用「这个子进程真的退出了」代替。
- **发起人页面那一段**：页面是本工作区 dev server 的真编辑器（无头 Chrome），执行请求的是产品自己的 `accountPage.ts` 加本机的播放头实现，改的是编辑器自己的 store；主服务一侧（事件流挂登记表、内部通道、交回）全是产品接线。但页面里「开事件流、把请求交给执行器、交回答案」是探针注入的一小段，替的是 `useCloud.ts` / `session.ts` 的会话接线——那一段要走账号登录界面，探针没有走。发起页的在场页面号是夹具里这位成员在 Node 里连文档服务时报的那一个。`session.ts` 的账号模式接线另有单测 CAU-WIRE-01～04。
- **出网闸**开了测试例外，只放行本机假站一个地址。
- **删对话**只验了备好的收场函数，接口本身没开放。
- **主服务重启**验的是「主服务关闭时在等的请求」：任务进程如实得到不在线、登记表里那一行不是「在等」。主服务再起来之后登记表把残留的「在等」标成被中断是 W2 包内的测试（W2-RESTART）验的，这里没有真的把主服务再起一遍。
- **隔离**：夹具只有一个项目，所以验的是两个账号、两个对话（作业号查不到、页面请求到不了别人的页面、账本与浏览器目录各是各的）。**两个项目之间**没有在这条链上验，靠的是各包包内的测试（可信上下文之外的项目一律取不到）和已有的素材隔离探针。

## 没做成的与原因

1. **Python 系的四族没有真跑出结果**（语音转写、主体识别、运动追踪、镜头识别的模型档）。探针没给任务进程配这些解释器与权重，只验到如实回「没配」。各包自己的探针在各自准备的环境里真跑过；接线之后「真跑」这一步要在配了依赖的机器或节点上补。
2. **Linux 没验**。任务进程被 root 关掉时子进程树的收法在 Linux 上靠 systemd 单元的进程组；Windows 上任务进程被强杀时，探针只验了浏览器会自己退，没有专门验感知的 Python、ffmpeg 子进程（本机只有秒级跑完的 scdet，抓不到「在跑」的窗口；各包包内用替身脚本验过取消时杀进程树）。
3. **任务进程里的收场钩子在生产形态下跑不到**（root 先关了进程）。后果：被收回的任务名下的作业在账本里记成「被中断」而不是「已取消」；别的由进程退出、主服务清理兜住。见「收场到底靠什么」。
4. （已改，见返工：关 Agent 不再清浏览器数据，这个缺口作废）**关 Agent 时没有任务在跑的项目**：主服务是从「强制终态」里得知 Agent 被关的；当时没有任务在跑就没有这条信号，这个项目各对话留着的云端浏览器数据不会被清，直到某个对话下一次被转私有。文档服务回给主服务的「Agent 已关」不带项目号（票据在文档服务那边才解得开），我没有找到不改文档服务就能补上的办法。解法表见下。
5. （已改，见返工：删对话已经接上；删项目仍没有通知）**删对话、删项目的收场没有调用方**。删对话接口没开放；删项目时主服务得不到通知。函数备好了。
6. **桌面版一侧没有真跑**：`collectLocal.ts`（本机采集、上传、登录窗口的适配）和 `useCloud.ts` 里网页接管的钩子只过了类型检查与单测里的假实现，没有桌面版安装包去点。
7. （见返工：代下现在缺省不开）**代下的整条链没有在探针里走**（同上，要桌面版）。
8. **一键流程的「发布预渲染任务」没配**（指令如此）；**重复点一键配特效会叠出第二份**（P5 留给用户定的去重，我没有实现，行为与桌面版一致）。
9. **切剪辑三个工具在账号模式下仍按播放头 0 记**：它们读的「发起方在不在线」在账号模式下一直是假（原有行为）。`seek` 做成后我把对话记着的播放头改了，但那三个工具没有用上。没在这一期的三十个里，没动。
10. **素材拼图、自定义测量、可视记录、开子 Agent** 不在这一期。
11. **用量**没有计量后台作业的时长与网页操作的流量（见零碎一表）。成员查用量在生产装配下原来回 503，这次接通了。
12. **真模型**没有用。

## 要用户定的事

（第 1、2、3 条已经更新，以「复审之后的返工」里的三条为准。）

1. **云端 Agent 请你的电脑代为下载时，要不要提示你。** 背景：有些视频站登录后才给高画质，而登录信息只能留在你自己的电脑上。这一版接上以后，你在桌面版里让云端 Agent 采集哔哩哔哩的链接、你的电脑上又登录着，云端就会让你的电脑去下载，用的是你的登录身份、你的带宽和磁盘，下好的文件直接传进项目。现在这个过程桌面版上没有任何提示。选项：（甲）不提示；（乙）在采集面板或聊天栏显示一行「云端 Agent 正在用这台电脑的登录下载……」，文字要你给；（丙）每次弹确认框，点了才下（人不在电脑前会卡到超时，再退回云端按未登录的画质下）。后果：甲最省事但你可能不知道电脑在替云端干活；乙要一句新的界面文字。我的建议是乙；在你定之前，主会话可以先不开放代下。
2. **Agent 说完话以后，后台作业没做完，这个对话要不要先让出来。** 背景：云端每条任务一个进程，进程收了作业就没了。我现在让它等作业做完（最多一小时）再收，所以你会看到 Agent 已经回完话，但你在同一个对话里发的下一条要等前面的转写或镜头识别做完才开始。选项：（甲）等（现在的做法）；（乙）不等，Agent 一说完就收，没做完的作业记成被中断，Agent 得在一轮里自己守着作业做完再回话。后果：甲不丢作业但下一条会排队；乙下一条不排队但作业容易白做。我的建议是甲。
3. **创建者关掉云端 Agent 时，要不要把各对话在云端浏览器里攒下的状态清掉。** 背景：云端浏览器按对话各有一份数据（这一版里实际只有匿名的 cookie，因为云端不代填密码）。网页操作那个包原来定的是「留着」，主会话这次让我改成「删」。现在的实际情况是：关的时候有任务在跑就删得掉，没有任务在跑就删不掉（缺一条通知）。选项：（甲）要删，那就得再补一条通知（要动文档服务）；（乙）不删，和停止一样留着。我的建议是乙，简单且这一版里面没有敏感的东西；等「把网页交给本人登录」真的能让云端浏览器登录上的那一天再改成甲。
4. **各包报告里原来就等你定的几条**现在因为接上而生效了，原样转述：只读成员能不能让云端 Agent 上网（现在能）；云端同时开着的浏览器数缺省 2 个；云端一键配特效里镜头识别、主体识别没就绪时是停下还是跳过（现在停下）；重复点一键配特效会不会叠出第二份字幕（现在会，和桌面版一样）；`web_handoff` 在云端的做法（请你在自己电脑上打开同一个网址，云端那个浏览器并不会因此登录）；给模型看的那些话的措辞。详见各包报告的「要用户定的事」。

## 当前代码核实与最小调整理由

1. 当前 Codex 的本地探测和服务商列表确实各有缓存，运行认证失败没有负向状态反馈。新增按 CLI home 隔离的后端权威状态，在两层缓存查询结果上合成失效优先级，并阻挡迟到探测。
2. 当前 Codex 路由并未接审核环路，审核环路实际供 agy 使用。保留现有接入，仅修复通用审核封装的错误透传和不可重试处理，并用 Codex 认证事件验证该封装；没有替 Codex 新增审核功能。
3. 通用进程封装原来的终态可能早于进程退出，权限回退可能把认证错误当成拒绝权限后再执行。Codex 采用终态后停止自己进程树的选项，Promise 等待实际 close；认证错误优先于文本协议回退。其他 runner 保持已有停止策略。
4. 聊天入口在 runner 之前会探测额度，这也可能启动 Codex app-server。已知失效的拦截提前到聊天入口，并在额度模块本身增加防护，避免任意客户端绕过。
5. 前端原本各聊天实例独立取列表，没有适合直接复用的跨编辑器认证推送。采用同一编辑器共享状态和有界、不重叠的轻量认证轮询：本页收到 SSE 即刻同步，其他编辑器每轮间隔 2 秒读取非敏感状态；失效先发布，再进行可能较慢的服务商探测。
6. 认证代次只在新登录成功验证后更换，另用状态修订号和登录尝试票据阻挡旧结果。点击重新登录不能让仍在运行的任务失去报告当前凭据撤销的资格，失败或取消的新登录也不能屏蔽该证据。

上述调整遵循现有接入与工作流程，均在已授权的登录失效、事件、缓存、持久记录、恢复入口、启动拦截和测试范围内。

## 改法

### 1. 停下时播放态补跑立即让路（`src/editor/stageSwap.ts`）

- `runSettleSwap` 撞上正在跑的**播放态**互换、且 store 已不在播放、它还没进互换那一步时：当场 `abort` 它的 `AbortController`、接过 `running`（`owner` 记是哪一次），暂停态第二路马上把自己的补跑排进后台队列（`stageJobs` 的 `catchup` 档，单飞、先来后到）。
- 播放态那一路的补跑不再等 `render` 回包（`untilAborted` 与中止信号赛跑）：一中止就把那次 `render` 记成「孤儿」、从后台队列里退出来，排在它后面的暂停态补跑立刻开工。退出之后清掉额外抑制，不碰 `running`、不做 R5-15 的交接（`running` 已归暂停态那一路）。
- 孤儿 `render` 怎么掐：暂停态补跑第 (1) 步本来就是 `pushProject('back', 当前项目, { reset: true })`，舞台下一次让出时就把在飞的 `render` 回成 `'project'`（`job: 'catchup'` 期间一律丢弃）。停下那一拍不用补跑时（例如播放到头、卡都出场了），另排一个 `catchup` 活只做这一步（`abortOrphanRender`），免得它在后台白推十几秒。
- 不抢的情形照旧走 R5-15：它已进了 `swapAndDress`（新 `front` 换到一半）、或 settle 来时 store 仍在播放——只记下，收手时交给暂停态那一路（C10-A4 的修法保留）。
- 武装停等帧、续推 `render`、`mediaReady` 等待也都和中止信号赛跑；武装停等完若已不在播放就不再换成播放态（以前停下后等 5 秒超时会照样 `play(T)`）。

### 2. 播放态互换按整场景估时，追不上不发起（`src/render/catchUpEstimate.mjs`、`stageSwap.ts`）

- 新纯函数 `sceneCatchUpCost(片段, t, fps)`：后台补跑是整台戏从「此刻活跃的卡里最早的入点」逐帧推到目标拍，后台舞台没有分派表、判重的卡也活渲，所以**积压** = 场上每张卡从 max(入点, 起推点) 推到 min(出点, t) 的代价之和（每张仍按原来的 `catchUpEstimateMs`：帧数 × 单帧、封顶整段）；**速率** = 此刻活跃的卡单帧代价之和 × fps（每多推 1 秒时间线要多花的墙钟）。单帧和积压用同一个数（`stepMaxMs`，没有才 `stepMs`，都没有按整段 `catchUpMs` 均摊）。
- `guessCatchUpMs` 改为整场景积压（只有目标卡一张时与以前相同）。
- 新 `planPlayingSwap`：目标拍领先 L 要满足 L = 积压 + 速率 × L，即 **L = 积压 ÷ (1 − 速率 / 1000)**（以前是 L = 目标卡自己的积压，没算「边补边被可见舞台追」那一截）。**不发起**的两种：速率 ≥ 1000 ms/秒（后台推 1 秒时间线要 1 秒以上，永远追不上）；解出的目标拍落在目标卡全部出场之后。不发起时什么都不做：不抑制、不排后台任务、不占 `running`。
- Preview 诊断 `__pcPreviewDiag().swapPlaying`：最近一次发起判断（领先量、积压、速率或不发起的原因）、让路次数、有没有孤儿 `render`。

### 桌面与在线

两条都在桌面与在线共用的 `stageSwap.ts` 里。行为变化只有两处，都是「更快到精确、不白占」：
- 停下时不再等播放态补跑推完（在线舞台每帧让出一次，掐断要等一帧；桌面舞台每 8 帧让出一次，最多等 8 帧——这是舞台现有的让出节奏，没动）；
- 估出来追不上的播放态互换不再发起。那张 (b) 档 `vtOk = false` 的轻卡在这一轮播放里就照可见舞台的节拍活渲（和别的轻卡一样），不进额外抑制、不显示占位；停下那一刻暂停态第二路照常把它补成精确活渲。以前这种情况会先占位十几秒、再「武装停已过」两次、最后降级为重卡（K6）——现在不降级。这一点请主会话确认（见「需要主会话定的事」）。
- 能追上的播放态互换照旧发起，只是目标拍更远（算上了同场的推帧与被追的那一截），少白补一趟「武装停已过 → 翻倍续推」。

## 没做的与观察

1. **播放态互换在自然进入时本来就不必要**：探针里那张轻卡（`probe-typewriter`，入点 2 秒）是在连续播放中自然进场的——可见舞台按全局时钟逐帧推，它在自己的挂载帧挂上，状态就是对的（和导出一样）；只有跳进它中间（从片段中间开始播放）时它的状态才是错的、才需要整场景补跑。现在 `Preview.tsx` 只要播放头落在这类卡上就发起一次，不区分自然进场与跳入。本任务按任务书只改了估时与不发起，没动发起条件；建议主会话另立一条看是否只在「这一轮播放从它中间开始」时才发起。
2. 停下那一拍不用补跑时掐孤儿用的是「整份重灌当前项目」，会让后台舞台重渲一遍整棵树（一次 React 提交）。没有新增 RPC（加一个「中止补跑」的 RPC 属于改对外接口，按规矩要〔裁〕，没必要）。
3. 在线后台活可能被父页判忙而暂停（`setBackWork`），估时没建模这一截；追不上时只会让「武装停已过 → 翻倍续推 → 降级」照旧兜底。
4. 诊断：`swapTrace` 新增 `preempt`、`catchup-preempted`、`orphan-abort`、`playing` 的 `skip-rate / skip-past-end` 与估时数字；`__pcPreviewDiag().swapPlaying`。都只记内存，集成时要撤可以一起撤。
5. 探针 `c10-browser-probe` 的 `a4.timing` 与 `settleTiming` 是新加的输出，判据没改。
6. 没跑的：stream-produce-probe、ready-index-probe、verify-unified-frames（任务书没点名；改动只在父页的补跑调度，不碰导出与预渲染）。带耗时门槛的项一律没在 PC 上判。

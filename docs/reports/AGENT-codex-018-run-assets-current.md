## 当前实例登记的只读机制（尚未接生产入口）

根和 Astra 审定的第三层字段落实在新 `run-assets-current-registry.mjs`。root-owned `registry` 的完整 exact-shape 对象是 `{v:1,authorityId,serviceId:'asset',epoch,state,instance,previous}`；`state` 只允许 `preparing|active|closed`，读入口只接受 `active`。`instance` 完整包含 `instanceId,bootId,pid,pidBirth:{bootId,startTicks},uid,unit,unitInvocationId,cgroup:{v2Path,dev,ino,bootId},serviceIdentity,clientFingerprint256,serverFingerprint256`。`pidBirth.startTicks` 是 Linux `/proc/<pid>/stat` 第 22 字段的十进制字符串，与真实 boot ID 组成不可混淆标识，不能取应用时钟。`unitInvocationId` 为 systemd invocation ID，cgroup dev/ino/boot 同时绑定，部署预期仅固定 path/UID/unit/pin，dev/ino 随实例更新。`epoch` 正安全整数，生产未接受更高 epoch 时同步读必拒。

首实例还需同目录 root-owned `anchor`：`{v:1,protocol:'promptcut.asset-root-anchor.v1',authorityId,firstEpoch:1,firstRegistryDigest,serviceIdentity,uid,unit,cgroupPath,clientFingerprint256,serverFingerprint256}`。doc 自有持久 checkpoint exact `{v:1,authorityId,epoch,recordDigest,anchorDigest}`；首次缺 checkpoint 不会凭当前登记自建信任。后继 `previous` exact `{epoch,registryDigest,instance,closureWitnessDigest}`；同目录 root-owned witness exact `{v:1,protocol:'promptcut.asset-os-closure.v1',witnessId,authorityId,fromEpoch,toEpoch,previousRegistry,observed:{kind:'cgroup-empty',closed:true,at,bootId,cgroup,unitInvocationId,pidBirth}}`。校验读取 **完整** 旧 registry 与 witness，核旧 registry 摘要、旧 instance、前后 epoch、旧 cgroup/出生信息、观察 boot/时点和 witness 全文摘要；摘要形状本身不作通过凭据。全部 digest 用现有 `server/account/ledger.mjs` 的 `digestOf`/`canonicalJson` 对 exact-shape 完整对象求 SHA-256；证书 pin 为无冒号小写 SHA-256。Linux 只读入口逐层拒非 root 拥有或可组/其他写祖先、符号链接及非普通/多硬链接文件，打开 `O_NOFOLLOW` 后核实际 FD 的 dev/ino/uid/mode/size。当前包**没有** `acceptCurrent`、root writer 或部署见证生成；后续需先核 root 旧树 closure witness、耐久写 doc checkpoint，才可把新 epoch 暴露给 RAM。未证明时一律 503。

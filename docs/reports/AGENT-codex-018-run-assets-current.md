# 当前主线的云端运行素材闭环

开工基点 `eb8228a4a93d9283f23507a7a826fa7b9fcc0358`，分支 `codex/018-run-assets-current`。本包在当前主线既有的账号严格证书 pin、独立素材服务和关闭屏障之上，移入旧私有包经过验证且仍缺失的文档权威媒体 selector、双 head、私有元数据及独立素材读取接缝。只逐项移植所需语义，不用旧文件覆盖已收主线实现。

租约起初限于 hosted run-assets 新模块、media-selector、doc/asset assembly、asset-runtime、asset-run-access、files、Agent project-assets、专属测试和本报告；根随后精确扩租 combo、asset-main、main 的运行素材接线。本阶段仅动 combo、asset-main，不改 main 入口、账号/运行授权底层、素材既有 handler/lease、节点或 release。运行中的服务及用户数据不碰。

已移入并定向验证的独立部分：文档同 coordinator 锁内媒体历史 selector、撤权夹缝重核、小档私有元数据读取、独立素材实际文件/stat、双持久 head 比对、run consumer 参与原 human ACK、关闭见证私有查询与受控 run-assets 内部挂载。doc 仍使用原同一 ledger、runProvider 与 RAM instanceAuthority；asset 的数据口使用 B 的原 handler/lease，未改其关闭/LP/socket 竞态实现。combo 仅在可信 `runAssets` 选项齐备时挂载；当前生产 main 没有提供该选项，内部 `/internal/v2/run-assets/` 保持 503。独立素材 `PROMPTCUT_ASSET_RUN_ENABLED` 未设置时不启动 run consumer/data handler，三角色账号基本路径保持原行为。

实测记录：初始六个纯目标 `%TEMP%/pc-run-assets-current-pure-first.log` 为 11/11；首次 TLS `%TEMP%/pc-run-assets-current-tls-first.log` 为 3/3，但夹具误用 listen(0) 分配了租约外端口 5853、5858、5859、5860，均在结束时关闭。修正到独占 6440–6449 后，`%TEMP%/pc-run-assets-current-tls-bounded.log` 为 2/2、实际端口 6440/6441/6442 与 6445/6446，结束 sockets 0、监听 0。当前可选挂载首测 `%TEMP%/pc-run-assets-current-mount-first.log` 为 0/1，受控 fixture 缺 `authorizePrincipal` 导致 `conversation-configuration`；只修 fixture 后 `%TEMP%/pc-run-assets-current-mount-second.log` 为 1/1、6447 实际 TLS 与关闭 0。当前三角色账号路径 `%TEMP%/pc-run-assets-current-account-baseline-first.log` 为 5/5，doc/asset/account 子进程都退出，6440–6449 监听 0。强制类型 `%TEMP%/pc-run-assets-current-type-after-wiring.log` exit 0；stage/head 定向 `%TEMP%/pc-run-assets-current-head-stage-after.log` 2/2。没有全量/G0/C10。本报告不把受控 registry 的 TLS 挂载目标称作生产当前实例证明。

当前生产阻断是“此 asset mTLS observer 属于目前登记、仍活着的那一个 asset OS 实例”的同步可信来源。`currentAsset({socket})` 每次回调必须来自真实当前服务登记与单调实例代际，不能用新连接的 `/status` 或 `/run/identity` 结果回填旧 socket WeakMap；这会把仍活着的旧 socket 冒认为新实例。`/status` 还可能 human consumer.sync → run consumer → doc observer → status 回查形成锁环，因此同步 observer 身份核验不得调用它。现有 `asset-lifecycle` 的 root-owned cgroup-empty 恢复文件虽绑定旧 instanceId/PID/cert pin/scope，尚无 UID、PID 出生标识及代际证明，不能在此包推导所有旧 socket 已关闭。A 的旧 lease/控制回执跨新实例恢复也缺独立外部见证。根另审该接缝前，生产 `currentAsset` 不提供、run 数据口不宣布 ready，未知旧实例保持 503/receipt pending；不能用空 Map、静态环境实例号或 `complete:true` 代替。最小三角色账号服务无需 Agent/run-assets，因此不受这个未完成模块阻断。

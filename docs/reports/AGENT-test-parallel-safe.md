# AGENT 报告：test-parallel-safe

分支 `claude/test-parallel-safe`，从 main `7d90218` 起，中途合入 main `19f1dec`（含坏端口并行修复与 T9 修复）。
任务：同一台机器上几份 `npm test` 并行跑（不同 worktree 的子 Agent 常这样）时不互相撞。
只改测试与测试辅助文件，没改产品代码，没连 5190～5192。

## 做了什么

### A. 固定端口

**A1 `sp-hosted.test.mjs` + `sp-kit.mjs`（托管组合子进程，原固定 5490～5495）**

- 原来：6 个固定端口起 `server/hosted/main.mjs` 子进程；就绪只看端口答不答 HTTP。两份并行时会连到对方的实例、用对方的数据（报「共享项目 from 2 / to 1」、`ECONNRESET`）；SPC1-5 两条期望「非零退出」的用例还可能因为端口被占这个错误原因通过。
- 现在：
  - `sp-kit` 新增 `freePorts(n)` / `hostedPorts()`：`listen(0)` 向系统要空端口，记下后放掉、传给子进程。本机 TCP 动态端口段从 1024 起，`listen(0)` 可能给到 fetch 拒连的坏端口或 5190～5192，这些号占着不放、另要一个。
  - `hostedFor` 不给端口时自动要；子进程报 `config.error` `listen`（放掉到占上之间被别人抢了）就换一对重起，最多 5 次。
  - 就绪判据加上「自己的子进程打出了 `listen` 事件行」，排除「自己没占到、别人的进程恰好在答」。
  - `runHosted` 不给实际端口就直接抛错，SPC1-5、SPC1-7 期望失败的子进程也拿真实空端口，失败只能是数据目录或布局的原因。
  - SPC7-1 新实例的公网地址按它实际拿到的素材端口算（`assetPublicUrl` 可以给函数）。
- 放掉端口到子进程占上之间的小窗口没有消掉，靠「被占就换一对重起」兜住。没改成传 `PROMPTCUT_*_PORT=0` 再读实际端口，原因：托管组合绑 0.0.0.0 时必须在启动前给 `PROMPTCUT_ASSET_PUBLIC_URL`，这个地址经 `service.endpoints` 下发给成员；SPC7-1、SPC7-2 的 `migrate-check` 探针就是从这里拿素材地址的，端口得在启动前知道。改成绑 127.0.0.1 又会让 SPC1-2、SPC1-3、SPC2-1 这些「非回环来源」的用例失效。
- 核对过：先占住一个端口再让 `runHosted` 用它，子进程退出码 1、`addrInUse()` 为真；`hostedFor` 不给端口照常起来、有 `listen` 行。

**A2 `sp-lan.test.mjs`（局域网发现，原固定 UDP 5496/5497）**

- 原来：主机绑 5496，客户端绑 5497。`discovery.mjs` 用 `reuseAddr: true`，两份都能绑 5496，单播只到其中一个；SPC4-8 固定的项目名 `Found-Me`，「主机停了就找不到」会被另一份打破；客户端 5497 会 `EADDRINUSE`。
- 现在：主机绑 0，查询发往 `host.port()`（实现本来支持）；客户端也绑 0。

**A3 其它**：`skill-gate` 写 `PROMPTCUT_SKILL_DIR/lock-test.proc`，缺省跳过，不用管。临时文件都用 mkdtemp 或随机名；`agent-c65*` 用 middleware 模式，不监听端口。没再发现别的固定端口。

### B. 压着 CPU 时会误判的计时

每一处都写明原判据、新判据，以及为什么没削弱。

| 位置 | 原判据 | 新判据 | 为什么没削弱 |
|---|---|---|---|
| `queue-node-wiring.test.mjs` J5 真 sink 的 `drive` | 每步等 5 ms 真时间、假时钟推 250 ms，超过 400 步判失败 | 带真 I/O 时，假时钟按每步实际经过的真时间推进，到 20 s 真时间才判失败；纯内存的 `drive` 不变。B 等内容库清单的窗口从 3 s 放到 15 s（按条件等） | 要验的 `task.done` 内容、只渲一次、去重不渲这些断言全都没动。假时钟跟着真时间走，租约（30 s）、停滞（120 s）不会因为「步数多了」提前触发。本机实测 A 约 300 ms、B 约 100 ms 就满足条件 |
| `src/render/changedClips.test.mjs` 三级缓存 | 单次 `projectHash` ≤ 2 ms，量一次 | 不达标就重拖一次再量（每次都是新拖出来的一条轨道，工作量与第一次相同，并核对只重算 1 段 1 轨），最多 8 次、间隔 120 ms，任一次 ≤ 2 ms 即过 | 门槛不变，第一次就是原来那一次；缓存失效时每一次都要重算很多，每次都超 |
| `docservice-backpressure.test.mjs` I3 | 正常节点投递延迟 p95 < 50 ms，一轮 | 整轮场景（新服务、200 条连接、慢连接积压并被 1013 关闭、堆增长 < 50 MB 等全部断言）最多跑 3 轮，任一轮 p95 < 50 ms 即停，取最好的一轮判 | 每一轮都是完整场景，门槛不变；背压真失效（慢连接拖住正常节点）时每一轮都超 |
| `asset-client.test.mjs` 4xx 不重试 | 整个 `put` 调用（含真 HTTP 往返和核票）< 150 ms | 总耗时减去花在 fetch 里的时间 < 150 ms；「只发一次请求」的断言照旧 | 要证明的是「不睡重试间隔」。第一次重试间隔是 200 ms，客户端要是睡了，fetch 之外的时间至少 200 ms，照样拦得住；机器忙时变慢的是往返，不是重试间隔 |
| `media-pull.test.mjs` 117、192、195 行 | 最多 50 或 200 次 × 20 ms 轮询后断言文件在 | 按 10 s 截止时间等（`waitLocal`），然后断言 | 「最终会进库」没放宽，只是等的上限从 1～4 s 变成 10 s；不进库照样失败 |
| `media-pull.test.mjs` T5-pull-3 | Range 回包 < 800 ms（全件约 1.3 s，约六成） | Range 回包 < 整件进库用时 × 0.6，并保留「回包时整件还没进库」 | 比例与原来相同，机器忙时两边一起变慢。真退化成「等整件下完才答」时，回包用时 ≥ 整件用时，而且回包时文件已经进库，两条都会挂 |
| `c65-ops.test.mjs` C65-V8-01 | 50 次（深拷贝那项 20 次）的中位数 ≤ 5 ms，量一批 | 分批量，最多 8 批、间隔 100 ms，任一批中位数 ≤ 5 ms 即过（同 `diffProject.test.mjs` 的 `timeIt`） | 门槛不变，第一批就是原来那一批；代码真退化时每一批都超 |
| `src/store/docsync.test.mjs` V8 | 40 次提交一侧耗时的中位数 ≤ 5 ms，量一批 | 同上，最多 8 批，每批 40 次提交；A、B 与服务端一致照旧核对 | 同上 |
| `render-node-ws.test.mjs` case 8 | hang 与回环 good2 共用 `timeoutMs: 1000`，整次解析 < 3 s | hang 照旧 1000 ms 超时、要判成 `timeout`，只算 hang 这次探活要 < 3 s；注入的 fetch 对 good2 不传探活的 abort 信号，好的那个不受 1 s 限制 | case 8 要证明的是「慢的按超时判掉、然后继续试下一项」。慢的那一半一点没放宽，还多断言了 `reason === 'timeout'`；放宽的只有「好的那个 1 s 内要答」，而这不是本用例要验的 |

## 顺带看到、没改的

- 每一次全量（单跑也一样）都会打出约 17 行 `WebSocket server error: Port 24678 is already in use`：几个测试以中间件模式起 Vite，Vite 的 HMR WebSocket 缺省用固定端口 24678，同一轮里几个文件互相抢。单跑也有，从没让用例失败，所以只记在这里。要消掉，就在这些测试起 Vite 时关掉 HMR 或给端口 0，属于另一件事。
- RHC12 与 T2-2 两次失败的根因都没复现出来（分别单独并发 24 次、52 次）。现在的改法是按「最终会发生」等，并把判据改成看完整过程；RHC12 再挂时报错里会带诊断日志。

## A：导出时自动生成声音

做法：页面在把项目交给导出之前先跑一步「生成声音」。

- `src/editor/io/exportSounds.ts`（新）：
  - `listExportSoundNeeds` 列出这次导出要先生成的声音，认三种原因：未生成（有声卡没有声音记录）、过期（参数、源码、输入变了，或产物盖不住当前范围）、缺失（项目里没有素材记录，或素材服务里没有它的文件）。口径与混音计划相同：隐藏或静音的序列、静音的片段不算。
  - `prepareExportSounds` 逐段生成，进度按「段数」报（一段之内带小数）；取消抛 `{ cancelled: true }`；某一段生成不出来抛 `ExportSoundError`，信息形如「片段「声画提示脉冲」(c-xxx)的声音生成不出来:原因」，带 `clipId`。
- 管两种声音：独立音效（提示音、键盘声，按片段里存的配方重新合成，`soundGeneration.ts` 新增 `restoreSoundEffectAsset`）和有声动效卡（沿用 `generateCardAudio`）。音频图卡没有持久产物，导出混音时当场合成，不在这一步。
- 桌面：`src/editor/io/index.ts` 的 `exportVideo` 先调这一步，再取项目快照、交给预渲染进程。生成阶段有自己的任务 id（`sound-prep-…`），`cancelExport` 认它；交给预渲染进程之后 `onStart` 再回一次导出任务的 id。没有要生成的声音时这一步不出现，流程与原来完全相同。
- 在线：`src/export/onlineExport.ts` 的 `exportVideoOnline` 在打开落点文件之前先调这一步。
- 进度：`onProgress` 的阶段多了 `sound`；`src/editor/ExportDialog.tsx` 显示「生成声音 n / N 段」。
- 不留半截产物：每一段是「合成 → 入库 → 一次提交」，取消或失败都在提交之前，项目不动；取消之前已经做完的那几段是完整的声音，留着。
- 补回独立音效时：项目里素材记录还在、哈希相同，只把字节补回素材服务，项目不动；记录没了才提交一次（不进撤销栈、不改选区，`commitSoundEffect` 加了 `silent`）。
- 预览时未生成的声音仍然提示（桌面没改这条路）。

## B：在线浏览器可以合成声音

- 放开的范围（`src/online/soundPolicy.ts`，新）：在线页面只执行**内置**卡的 `audio()`；用户卡仍然不执行。第二段的接口留好了：`setOnlineUserCardAudioGate`。带素材输入的图卡原有的那道闸（在线取不到素材采样块）没动。
- 轻重（`src/audio/soundCost.ts`，新）：测量、判据、记录。沿用画面的 `robustStep`、可调系数和「预算 = 时长 × 70%」，数字见 `mechanism/rendering.md`「声音的轻重」。
- 判定（`src/editor/io/onlineSoundJudge.ts`，新）：桌面运行环境恒合成；在线页面里跑不了的（用户卡、图卡）、低内存档、判重的不合成，各有说明文字。记录存页面内快照库 L2 的成本表（`onlineSoundBoot.ts` 接上）。
- 预览（`src/editor/io/onlineSoundSource.ts`、`src/editor/preview/MediaLayers.tsx`）：在线页面里没有有效产物、或产物的文件取不到时，判轻的由浏览器合成一份临时声音当播放源（不入库、不改项目）；有了有效产物就改用产物。
- 「生成声音」按钮（`CardAudioForm.tsx`）在线对内置有声卡可用；在线新加提示音、键盘声在合成前先判轻重。
- 测量不出声：测量只调纯合成函数、把采样当场丢掉，不建音频上下文、媒体元素或可播放地址。

### 〔裁〕清单

只有一处，三级：`docs/semantics/mechanism/rendering.md` 新增「声音的轻重」一节（标了〔裁〕）。它不是按现有语义做不下去才改的，是任务书 B 明写「数字写进 mechanism，标〔裁〕」，所以没有建解法表。本节新设的数字与做法：

| 项 | 值 | 依据 |
|---|---|---|
| 测量的块长 | 4096 采样帧（48 kHz 约 85.3 ms） | 与独立音效的合成块相同 |
| 最少块数、取第几百分位 | 16 块、第 90 百分位，不足取最大 | 与画面同一个函数、同一组可调系数 |
| 预算 | 一块的时长 × 70%（约 59.7 ms） | 与画面预算 B 的 70% 同一个数 |
| 一次测量的封顶 | 累计 500 ms | 与画面计时趟的封顶相同 |
| 设备串 | 浏览器标识、CPU 核数、运行模式、百分位、最少块数 | 合成只吃 CPU，不带 GPU 与渲染路线 |
| 什么时候测 | 第一次要用这段声音时，不盖遮罩 | 测一次约几毫秒到几十毫秒 |
| 记录放哪 | 页面内快照库的成本表，不写共享成本记录 | 共享记录是低内存档界限搜索的输入，混进去会打乱它 |
| 判轻时预览用临时声音，不入库 | — | 预览不该自动改项目 |
| 低内存档一律按重 | — | 沿用它现有的规则，不是新规则 |

实测（这台 PC，无头 Chrome）：内置有声卡每块 0.5～3.2 ms，预算 59.7 ms，判轻。

### 低内存档的表现（探针 L1～L3）

没有改它的任何规则。查到的表现：

- **不测、不合成**。判定直接回「低内存档」，测量次数不变。理由是它现有的两条规则：播放不活渲；没有成本记录的按重。声音没有共享成本记录，所以全按重。
- **预览**：只播已经同步的声音产物（实测能播，素材服务的地址）。有声卡没有产物时不出声，预览里写「这台设备(低内存档)不合成声音,只用已经同步的声音;请在电脑上的 PromptCut 里生成后同步」。独立音效的文件取不到时这一段没有声音（这是原来就有的表现，没有提示）。
- **导出**：声音齐全就成功，不出现生成阶段，成片有声且对齐（起音误差 1.3、1.1 ms）；缺声音就失败并指出片段，不在这台设备上合成。
- 没有遇到「必须动低内存档现有规则才能做」的情况。

## 没做成的

**判重、又没有产物时交给渲染节点**（B 的一部分，验收第 5 条「判重的走产物或渲染节点」的后一半）。现状：判重有产物时走产物，已验；没有产物时预览提示、导出失败并指出片段。留了接口 `setSoundBackfillHandler`（`onlineSoundJudge.ts`），预览和导出遇到这种情况都会调它，现在没有接收方。

没做的原因：

- 要让渲染节点接声音的活，得在任务队列里加一种任务、让节点认领并合成、再定一个「节点做出来的声音登记在哪」的办法。这些在 `server/render-queue/`、`server/render-node/`、`server/docservice/`，不在我的文件清单里。
- 还卡着一个没定的问题：现在声音产物是靠改项目（片段上的声音记录）登记的，而渲染节点按第三段的 D 只有渲染身份、不能改项目内容。要么声音产物改成像画面那样按身份登记在内容库里，要么另想办法，这是二级的决定。
- 实际影响小：内置声音的合成比预算快一个数量级以上，正常设备上不会判重。

## 发现（不在本任务范围内，没有改）

1. **在线页面把内置有声动效卡当成图卡**（已改，见上表）。`needsLocalPc` 原来把凡是写了 `audio()` 的都当图卡，Doger 让动效卡可以同时写画面组件和 `audio()` 之后，内置有声卡的画面在在线页面里成了「需要本地 PC 渲染辅助」。
2. **有声动效卡没有成本身份，画面永远按重卡**（没改）。`src/kernel/cardGraph.mjs` 给它合成的节点没有 `clipId`，`clipCostIndex` 因此不给它身份，它从不被测量、在桌面和在线都落在「按声明兜底判重」。用夹具核对过：同样写 `frameMode: 'direct'`，普通 DOM 卡判轻，带 `audio()` 的进了预渲染集合。这是画面路径，要改得跑渲染附加项，留给主会话决定。
3. **在线普通档导出在没有层表时会一直等**（没改，main 上就这样）。没有渲染节点写过层表时，页面把分派表里判重的片段都算「缺预渲染原尺寸」，素材段（`cardId` 是空串也被当成卡片段）和没测过的卡都在里面。探针里是替渲染节点写了一张空层表才导得出来。第三段云节点常驻之后这种情况会少，但素材段被算进去这一点值得看一下。
4. **`online-user-cards-probe.mjs` 在 main 上跑不过**（没改）。它让在线页面加入一个刚建好、还没有内容的共享项目，而现在在线页面加入空项目会被拒（界面显示「连不上服务器」，实际是项目没有内容）。在 main `3da0aa0e`、`e7d18340`、本分支三处都试了，都卡在加入那一步。任务书第二段第 17 条要求这个探针仍过，需要先修探针（加入前替创建者写一份项目内容，`sound-ab-probe.mjs` 里有现成写法）。

# AGENT-v18-guard

分支 `claude/v18-guard`，从 main `162a72be` 起。三件互不相干的事：舞台端口来的请求只放行白名单、全项目读选区时单个成员的失败怎么算、`move-guard.test.mjs` 一条偶发失败的测试。端口只用 29000～29049。

名词：**舞台** = 桌面版里跑卡片代码的两个 iframe；**舞台端口** = 编辑器端口 +1、+2 上的两个反向代理，舞台 iframe 开在它们上面，请求由代理转给编辑器进程；**编辑器进程** = 桌面版里跑 vite 的那个 Node 进程，本机接口（`/api/**`）都在它里面。

## 第一件：舞台端口来的请求缺省全拒，只放行白名单

### 做了什么

- `server/stage-gate.mjs`（新）：白名单 `STAGE_ALLOW` 和判据 `stageRequestAllowed(method, url, { upgrade, headers })`。白名单只写在这一处，每条带「谁用、为什么要」。
- `server/vite-plugin-stage-ports.ts`：闸放在舞台端口的反向代理里，**转给编辑器进程之前**判：不在白名单里的普通请求当场回 403（请求体不读、不转），WebSocket 升级回 403 后断开。这是最靠前的统一入口，也是唯一能同时管住普通请求和升级的地方（升级不经过 vite 的中间件）。同一个插件在编辑器进程一侧另注册了一个中间件，按代理写的头（`http-guard.mjs` 的 `viaStagePort`）用同一个函数再判一次，是第二道。
- 原来 `vite-plugin-cards.ts` 那三个口的单独拦截没动，现在是第三道。各插件的业务逻辑没改；`server/frame-*.mjs`、`server/bakery/` 等一个字没碰。
- 排障用：编辑器进程设了 `PROMPTCUT_STAGE_PORT_LOG=<文件>` 时，代理把舞台端口的每个请求记一行（方法、地址、放没放行）。只记不判，不设时什么都不做。探针靠它核「正当请求一个没被拒」。

闸管的是**全部路径**，不只 `/api/**`：开发服务器的静态服务会把项目根下的文件按路径发出去（改之前舞台里 `fetch('/package.json')`、`/@fs/<任意工作区内文件>` 都读得到），WebSocket 上还挂着文档服务。

### 白名单是怎么定的

读代码之后起真的编辑器把舞台端口实际发出的请求全记下来（两趟：`stage-gate-probe.mjs` 的用户卡、内置卡、视频、声音、播放、卡片声音；`scrub-stream-probe.mjs` 的重卡、轨道流、按住标尺拖、暂停起播）。两趟各约 2050 个请求，归类后只有下面这些：

| 方法 | 路径 | 谁用 | 为什么要 |
|---|---|---|---|
| GET/HEAD | `/`（整条） | 舞台 iframe | 舞台文档 `/?stage=1&id=…`；热更新客户端探活 |
| GET/HEAD | `/src/**` | 舞台 iframe | 页面脚本、样式、卡片与部件源码（改动层里的用户卡映射在 `/src/cards/user/` 下） |
| GET/HEAD | `/server/**` | 舞台 iframe | 页面脚本引用的两端共用模块、动效素材目录索引（随包发的代码，没有数据） |
| GET/HEAD | `/node_modules/**` | 舞台 iframe | 预构建好的依赖 |
| GET/HEAD | `/@fs/**`，路径里必须带 `/node_modules/` | 舞台 iframe | 不在项目根下的依赖；别的文件不给 |
| GET/HEAD | `/@vite/**`、`/@react-refresh` | 舞台 iframe | 热更新客户端与运行时 |
| 升级 | `/`，子协议必须是 `vite-hmr` 或 `vite-ping` | 舞台 iframe | 热更新的 WebSocket（改卡后舞台跟着换） |
| GET/HEAD | `/@media/**` | 舞台里的 `<video>`、`<img>`、音频图卡、素材效果卡 | 本机内容库里的素材字节（含 `/@media/<哈希>/pcm`） |
| GET/HEAD | `/api/media/file`（整条） | 舞台里的 `<video>`、`<img>` | 迁移期老项目按路径取素材；接口自己只给素材目录里的文件 |
| GET/HEAD | `/catalog/**` | Lottie 卡、粒子卡 | 动效素材目录里登记过的 JSON |
| GET/HEAD | `/api/cards/scopes`（整条） | 舞台里的卡片注册表 | 定制卡的归属表，只读；改档位的 POST 不放行 |
| GET/HEAD | `/api/prerender/info`（整条） | 舞台里取生成快照与轨道流的那一层 | 问预渲染进程在哪个端口，只读 |

全部只读，没有一条会改编辑器进程的状态。另外拒掉路径里带 `..` 段、反斜杠、`%2e`、`%2f`、`%5c`、`%00` 的写法（浏览器发出来的地址不会有）。

观察到、流水里实际出现过的只有前十类里的 `/`、`/src/`、`/server/`、`/node_modules/`、`/@fs/…/node_modules/`、`/@vite/`、`/@react-refresh`、`/@media/`、`/api/cards/scopes`、`/api/prerender/info` 和热更新的升级。`/catalog/**` 与 `/api/media/file` 这两条没在流水里出现，是读代码加的（`src/cards/native/lottie.tsx`、`particles.tsx` 用 `fetch` 取 `/catalog/…`；`src/editor/io/mediaUrls.ts` 给没有哈希的老素材拼 `/api/media/file?path=`）。

**舞台原来在调、现在被拒的东西：没有。** 两趟流水里除了探针用户卡故意发的那些，没有一个请求被拒。舞台不经这个端口的东西不受影响：生成快照与轨道流的字节舞台直接向预渲染进程的端口取，项目数据由父页经 `postMessage` 给，卡片声音在编辑器页里求值，声音在编辑器页里播。

### 入口核实

- **打包后的桌面版走的是同一套入口。** `desktop/src-tauri/src/lib.rs` 第 573 行起的就是 `node_modules/vite/bin/vite.js --port … --host 127.0.0.1`，读的是同一份 `vite.config.ts` 的 `desktopConfig`，插件表里有 `stagePortsPlugin()`。没有另一套生产服务器。真的桌面外壳没参与验证（探针起的是本工作区的开发服务器，数据目录、素材目录、改动层都指到项目根之外，和打包版的摆法一样）。
- **在线构建不受影响。** `vite build --mode online` 的插件表只有换行统一、React、Tailwind、动效素材目录和舞台入口，没有 `stagePortsPlugin`（它还带 `apply: "serve"`）；`server/stage-gate.mjs` 只被这个插件引用，不进任何页面脚本。在线的舞台是单独的站点，由 nginx 给，没有编辑器进程。
- **预渲染进程**（`vite.prerender.config.ts`）没有舞台端口，不经过这道闸。
- 编辑器端口直连的请求不带代理写的头，两处判断都直接放过，行为一个字不变（单测与探针都核了）。

### 验证

单测 `server/test/stage-gate.test.mjs`，命令 `npm test -- server/test/stage-gate.test.mjs`，退出码 0，7 条全过：

- 白名单里的 20 种请求与热更新升级放行；白名单每条都有说明、都只读、前缀不是整个根。
- 有代表性的 161 条本机接口（Agent 绑定与对话、数据镜像、项目写入、素材写入、帧与导出的写口、MCP 与 Skill、卡片写入与同步、渲染节点、采集、网页工具、文档服务、项目根下的文件、`/@fs/` 任意文件、白名单路径上的写方法）一律不放行。
- 大小写、重复斜杠、点段、编码过的点和斜杠绕不过去。
- 把服务端插件源码里写着的每一条 `/api/…` 路由扫出来（147 条）逐个按六种方法判：除三条只读的以外全部不放行。以后新加的接口缺省就是拒的，放进白名单这条测试会要求同时改名单。
- 真的起两个舞台端口的代理：白名单外的 16 种请求经舞台端口回 403，后面的「编辑器进程」一个字节没收到；白名单里的照转；文档服务的升级 403、热更新的升级接上；同一批请求直连编辑器端口照常到业务、请求体原样；带着代理那个头直连编辑器端口的被第二道拒。

探针 `scripts/probes/stage-gate-probe.mjs`（真的编辑器、真的舞台窗口、无头浏览器），命令 `node scripts/probes/stage-gate-probe.mjs --port 29000`：结果见文末「最终验证」。一张写进改动层的用户卡在可见舞台里用自己模块里的 `fetch`、`WebSocket` 逐个去调。会动到这台机器别处的几条（开资源管理器、改用户级 MCP 配置、开网页、下载、起对话、起导出）没有在真舞台里试，由单测核。

贴轨道流与按住标尺拖：在同一道闸下跑现成的 `scrub-stream-probe.mjs --port 29010`（带流水），退出码 0，`fails: []`（点 5 处、拖 10 处、起播与暂停、后台补跑互换，截图与导出页逐帧比），舞台端口 2044 个请求，被拒 0 个。

看过的图（`docs/reports/assets/v18-guard/`）：`1-seek-1s.png`、`4-after-attack.png` 两张都是左上角用户卡的品红色块、底下视频的测试图样、中间文字卡（第二张文字清楚，第一张是入场动画中途）；第一张左下角有一条「clip-pulse 的卡片声音尚未生成」的提示，是那一刻还没生成卡片声音，之后探针生成成功。`5-after-card-edit.png` 见最终验证。

### 发现的、不在这次范围里的（要主会话定）

1. **预渲染进程对舞台的源全开。** 编辑器进程拉起预渲染进程时把两个舞台的源写进 `PROMPTCUT_CORS_ORIGINS`（舞台要直接向它取快照与轨道流），而 `originOk` 对名单里的源不分接口一律放行。所以舞台里的卡仍能跨源调预渲染进程的全部 `/api/**`（它的插件表有导出、数据镜像、成本记录、帧、素材、卡片、看画面）。这不经过舞台端口，这次的闸管不到；要堵得在预渲染进程的卡口上按源分名单（舞台的源只放行取快照、取流那几条读口），那是渲染一带的文件，没碰。
2. **同源单舞台没有隔离。** 舞台端口起不来（被占）或低内存模式时，舞台 iframe 与编辑器页同源，卡片代码和编辑器页是同一个源，这道闸不存在。语义 `product/platforms.md` 对在线页面写了「没有隔离环境的摆法自动不执行」，桌面版没有对应的规定。
3. **`/@media/**` 放行意味着卡片能按哈希或文件名读本机内容库里的任何素材**（不限当前项目）。舞台要画素材，这一层分不出「当前项目的素材」；记一笔。
4. 开发服务器自带的 `/__open-in-editor`（让本机编辑器打开一个文件）没有任何卡口，任何网页发一个 GET 就能触发；舞台端口这边现在拒了，编辑器端口照旧。

## 第二件：一位成员登录过期，全项目读选区回「发起方不在线」

`server/docservice/modules/selection.mjs` 的 `querySelections` 并不去问页面，它拿每条在线页面连接建连时的身份去问账号权威「这位现在还有没有读权限」。原来只有 403 算「这一位不算」，别的错一律让整次查询回 `authority-unavailable`，上层（`page-bridge.mjs`「取不到按不在线办」）就报发起方不在线。

逐种失败怎么算（权威实际会回什么，核过 `server/account/authority.mjs` 与 `server/account/client.mjs`）：

| 失败 | 权威回什么 | 改之前 | 现在 |
|---|---|---|---|
| 没权限、被移出、被禁 | 403 `not-listed` / `banned` | 这一位不算 | 不变 |
| 答非所问（回的不是放行、回的是别人的账号） | `checked` 归成 403 | 这一位不算 | 不变 |
| **登录过期、被撤销、凭证对不上** | 401 `authorization-expired` / `credential-revoked` / `principal-mismatch` / `login-required` | **整次失败** | **这一位不算**，撤掉这条连接的在场记录 |
| 断线 | 记录随连接删掉；查询途中断的由记录核对挡住 | 这一位不算 | 不变 |
| 超时、账号服务连不上 | 503 `account-unavailable`（客户端把超时也归成它） | 整次失败 | 不变 |
| 权威没同步完、协议错 | 503 | 整次失败 | 不变 |
| 项目没了、正在搬迁、请求写错 | 404 / 409 / 400 | 整次失败 | 不变 |

判据只有一行：401 与 403 是「只跟这一位的凭证有关」，其余都不是哪一位成员的事（问谁都一样），宁可不答也不给一张缺人的表。401 时撤记录而不是留着：这条连接凭的那一次登录不会再变回有效，页面续了登录是换一条连接、重新发选区。

权限没有放松：不算的成员的选区不进结果；那条连接凭过期的登录再发选区照旧被拒；发起方自己过期时给的是文档服务自己存的「发消息时的选区，非实时」那一份。

单测加在 `server/test/project-selections.test.mjs`（第 3 条），`npm test -- server/test/project-selections.test.mjs` 退出码 0，3 条全过。把判据换回只认 403，新加的那条红：`Error: authority-unavailable`。

没改的：`set`、`clear`、`captureSnapshot` 里的同类调用（它们问的就是发消息的那一位自己，401 本来就该拒）。

## 第三件：`move-guard.test.mjs` 第 143 行那条偶发失败

### 原因

**端口相撞。** 这个文件里的托管组合（进程内的 `startHostedCombo`）用的端口是先挑好再去占的（`hostedPorts()` → `freePorts()`：随机挑一个、试着监听确认空着、关掉、把端口号交出去）。从「确认空着」到「真的占上」有一段空档，这期间同一台机器上别的测试进程挑到同一个端口，后占的那个 `EADDRINUSE`。

证据：

- 端口被占时 `startHostedCombo` 多快失败：直接量，文档端口被占 49 毫秒（冷）、素材端口被占 6 毫秒，错误码 `EADDRINUSE`。第 143 行那条测试的头一句就是起组合，和「15 毫秒左右就失败」对得上；测试里后面的步骤（健康检查、建房间、搬迁）都要几百毫秒以上。
- 复现：改之前把这个文件 16 份并发、压着 8～10 个烧处理器的进程跑，共 112 次，失败 1 次，是同一个文件第 99 行那条（账号夹具的素材子进程）：`Error: asset child exited: 1; {"event":"asset.config-error","code":"EADDRINUSE"}`。**第 143 行那条在这 112 次里没有复现**，它失败时的原文我没有拿到（全量测试的事件记录不留错误文字）；上面两条是间接证据，如实写。
- 量空档里的相撞：24 个进程各挑 25 轮、每轮 8 个端口、挑完挂 1.5 秒不占（模拟起子进程的夹具），共 4800 次挑选。旧的 `freePorts`：23 次挑到别的进程 1.5 秒内刚挑中的端口。
- 排除掉的：头两步（挑端口、起组合、健康检查）单独循环 1000 次（4 个进程）零失败，所以不是与负载无关的随机错；前面几条测试结束后空等 25 秒、挂上未处理异常的监听，没有迟到的异步错误；环境变量没有泄漏到这条测试；临时目录都是 `mkdtemp` 的，不相撞。

### 改了什么

- `server/test/free-ports.mjs`（全量里 48 个测试文件经它要端口）：挑中的端口在 `<系统临时目录>/promptcut-test-port-claims/<端口>` 独占创建一个小文件记一笔，别的进程看到有人记着且没过期（90 秒）就换一个挑。记不下来（目录不可写）就退回原来的做法。同样的 4800 次挑选，相撞从 23 次变成 0 次。
- `server/test/move-guard.test.mjs`：进程内的两处起组合改用 `startCombo()`：`EADDRINUSE` 时换一对端口、换一个数据目录重起（最多 5 次），别的错照抛。断言一条没动，没有跳过。

没改的：账号夹具（`fixtures/cloud-queue-user-path.mjs`）的素材子进程占不到端口时不会重起。它的端口写进了证书和组合的配置，重起要整套重来；有了上面的记一笔，两个测试进程不会再挑到同一个端口。

## 没做成的及原因

- 第一件：真的桌面外壳没参与验证（同上一块）。局域网设备打开编辑器、托管方渲染服务的工作进程这两种摆法没有单独跑，它们走的是同一个插件、同一张白名单。
- 第三件：第 143 行那条失败时的原文没有拿到，原因是按特征（多快失败、同文件另一条复现出的错）推出来的。

## 裁定〔裁〕（都是三级：用户看不出区别）

- 〔裁一〕闸放在舞台端口的代理里，而不是只放在 `/api/**` 的总卡口上。原因：WebSocket 升级和开发服务器的静态文件都不经过 `/api` 卡口。
- 〔裁二〕闸管全部路径，不只 `/api/**`；`/server/**` 整个前缀放行（里面只有随包发的代码）。
- 〔裁三〕选区查询里 401 撤掉在场记录（和 403 一样），不是只跳过。
- 〔裁四〕测试挑端口时在系统临时目录里记一笔，90 秒过期。

## 对任务书或语义的更正建议

- `docs/semantics/mechanism/platforms.md`「桌面」一节建议加一条（原文建议）：
  > - **舞台端口只转白名单里的请求**：两个舞台端口的代理缺省全拒，只把 `server/stage-gate.mjs` 白名单里的请求转给编辑器进程：舞台自己的页面与脚本、素材字节、动效素材目录、定制卡归属表与预渲染进程地址这两条只读接口，以及热更新的 WebSocket。别的一律回 403。
- 上一块报告（`AGENT-v18-cardsync.md`）建议在 `product/platforms.md`「桌面」记的待办「舞台窗口里的卡片代码能调到编辑器进程的本机接口」可以销掉，换成上面「发现的」第 1、2 条。
- 派活指令说 `querySelections`「向项目里每个在线成员的页面问选区」：实际不问页面，问的是账号权威，所以没有「单个成员超时」这一种（超时是权威连不上，整次失败）。

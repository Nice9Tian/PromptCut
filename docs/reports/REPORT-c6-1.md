## 2. 与计划不一致的地方

1. **队列的任务增量不走频道广播**（H.0）。队列按连接逐个发，它的可见性（项目、纯浏览器按用户、M5b 起的指纹）比频道更细。隔离效果不变，I1、I2 验证过。核心的频道 API 已经就绪，C6.3 的项目操作通知是第一批走 `project:<id>` 的消息。
2. **没有禁止 `pc` / `host` 的全量 `watch: 'all'`**，只新增了摘要订阅。现有的本机节点和探针都依赖全量订阅；要不要收紧，在 M5b 契约里定。
3. **摘要的 `topPriority`、`openByFingerprint`** 由队列模块在任务发布时记下（H.7 第 2 条），因为 `q.describe()` 不带这两项，而本阶段不改队列本体。以后改队列本体时，可以让它的 `describe()` 直接给。
4. **测试方的建议**：I3 的内存门槛以后改成 `heapUsed + arrayBuffers`，因为积压的字节主要在 socket 的 Buffer 里。真正防住无界积压的，是「1013 关闭」那条断言。

# C10a 手机在线快照恢复与素材地址竞态

工作区 `.worktrees/c10a-r2`，分支 `claude/c10a-r2`，起点 `5263329`。C10a 是在线浏览器模式演示。本次不提交、不推送。

## 根因与修法

R2 的现场没有保留请求级日志，无法把那次 900 秒失活唯一归因到一条请求；集成报告第 9.4 节只证实内容库新键下的清单和小位图齐全，手机层表键未换。代码里确定存在一条能造成同样结果的路径：`OnlineSnapshotSource.tick()` 在本轮 `content.get` 返回后才安排下一轮定时器。一次永久悬挂会让 `running` 一直占着，后续 `kick()` 只能标记 `again`，层表和清单都不再轮询。原连接实现有 10 秒超时，但来源自身没有兜底；连接替换、测试注入或非标准传输若不结算 Promise，就会触发这条路径。现在来源给每次内容库请求加 12 秒兜底超时，超时后释放轮询并立刻允许重取层表。小位图的票据、网络和读体过程也加 15 秒兜底超时与中断，释放四个并发槽，下一轮可重取。

本次最初一轮探针发现另一个上游失活：手机修改确实以修订 2 写进文档服务，但预渲染节点的诊断仅有修订 1 的计划；临时内容库在 15 分钟内没有新层表，所以那一轮无法用于检验手机是否换键。`prerenderPreload.ts` 的单飞请求原先也无超时，永久悬挂会把 `inFlight` 留为真，后续编辑和空闲事件不再发请求。现在 6 分钟兜底取消并重试，丢弃迟到结果。该轮没有抓到创建者页面的请求栈，无法断言它正是这条路径；后续探针用调试口观察。

第二轮真浏览器诊断还看到手机来源已缓存 64 张小位图、就绪层表已有 120 帧，但舞台仍无小尺寸节点。`snapshotFeed` 原来在 `setSnapshots` 回包前把新键写进投递基线；活着的 iframe 若丢了回包，后续按基线判“已贴好”，暂停态也没有新帧事件补投。现在 `setSnapshots` / `setTime` 的 RPC 有 8 秒界限；失败时基线作废并主动重投。在线页可见时每 5 秒核一次舞台，强制带 reset 重投，覆盖“回包虽到了、舞台随后被 setTime 覆盖”的顺序。低内存档不追暂停态活渲，所以迟到的 `settled` 事件也不再抑制该档的小尺寸选帧。

404 有两条路径：在线构建初始 `mediaTier` 策略在远程地址未就绪时可能给浏览器 `/@media/<哈希>`；此外 `chooseTier()` 的后台可播性探测绕开可见素材的等待分支，用原片相对地址发起一次隐形 `<video>` 请求。现在初始策略明确在线，远程地址未就绪时哈希素材不给 URL、后台探测也不启动；地址就绪后自动使用远程绝对地址。舞台也在父页 RPC 前设置在线策略。

## 失活路径审计

| 路径、触发条件 | 证据与结果 | 处理 |
|---|---|---|
| 内容库单次请求永久悬挂 | `snapshotSource.ts:506-529,532-540,586-614`：下一轮只在 `tick()` 的 `finally` 安排；挂住时 `running` 不清 | 请求兜底超时；OS8 复现并验证恢复 |
| `px` 请求、票据或响应体永久悬挂，四个并发槽被占 | `snapshotSource.ts:639-675`：`active` 只在任务结束后减；`inflight` 只在 Promise 结算后删 | 15 秒超时及 AbortController；OS9 验证可重取 |
| 普通 `content.get` 抛错或断线 | `snapshotSource.ts:513,535-537,607-610` 捕获；`link.ts:124-139,193-200` 对等待者拒绝并重连，最长退避 5 秒 | 已有下一轮；层表失败后现在立即解除 3 秒取表间隔；OS7 |
| 定时器清除或组件卸载 | `snapshotSource.ts:432-438,498-519`；`Preview.tsx:623-646` 卸载时 `stop()`，重挂新来源 | 正常生命周期；运行中每轮重排定时器 |
| 页面隐藏和恢复 | `Preview.tsx:230-237` 低内存档隐藏时暂停；浏览器可能节流 `setTimeout` | 可见时主动 `focus()` 触发一轮 |
| 文档连接断开并重连 | `link.ts:193-209` 拒绝等待者并重连；`syncManager.ts:859-878` 重订成员，在线快照来源自己轮询而非服务端订阅 | 轮询自动重读层表；无须重新订阅快照推送 |
| 层表先于清单，或新清单尚无小位图 | `snapshotSource.ts:557-558,569-614` 先发新键空区间，未满清单每 2 秒重取 | 原逻辑可恢复；OS4、OS5 已覆盖 |
| 键或区间比较缓存 | `snapshotSource.ts:542-558,471-481` 层表签名含 key/resultKey；就绪签名含 key/ranges | 换键会发布；OS4 |
| 旧项目的迟到层表回包覆盖新项目 | `snapshotSource.ts:380-390,532-547` 项目切换可与在途请求交错 | 回包按发起时项目 id 核验，旧回包丢弃 |
| 来源停了但页面仍显示 | `Preview.tsx:623-648` 在线 effect 只在卸载清理；`snapshotFeed.ts:129,163-171` 停订会清索引 | 在线来源保留到卸载，缺帧到货用 `setSnapshotArrive` 重投 |
| 首次 `service.watch` 失败或素材服务晚登记 | `assetTiers.ts:350-369` 原来失败后置空远程地址，不重试；`endpoints.mjs:158-169` 服务器后续发送全量通知 | 在线页重试发现，并处理 `service.endpoints`；重连后重新 watch |
| 创建者的后台 `preload` 永久悬挂 | `prerenderPreload.ts:54-78` 原来 `inFlight` 不释放；`frameClient.ts:38-64` 预渲染 URL、镜像对齐、fetch、读 JSON 都是异步 | 6 分钟兜底取消、4 秒后重试；单测覆盖迟到回包 |
| `setSnapshots` 回包丢失，或 `setTime` 盖掉已投递的快照 | `snapshotFeed.ts:545-575` 原来回包前记基线；`stageRpc.ts:350-410` 原来只检查窗口关闭；`Preview.tsx:565-600` 暂停时没有帧回调 | 8 秒 RPC 界限、失败重置与重投；在线可见页每 5 秒重核舞台 |
| 低内存档收到迟到的 `settled` | `snapshotFeed.ts:378` 原来暂停态跳过已经 settled 的重卡，即使低内存档从不追精确活渲 | 低内存档仍选小尺寸；回归单测 |
| 后台可播性探测提前请求原片相对地址 | `mediaTier.ts:150-160` 原来 `pick()` 已等待远程地址，`probePlayable()` 却直接拿 `/@media/<哈希>` | 地址未就绪时不启动探测；回归单测 |

不存在指数增长的在线快照轮询退避：层表间隔 3 秒、未满清单 2 秒，文档连接退避封顶 5 秒。`full` 清单不会再取，前提是该段每帧已有小位图；结果键代表不可变产物。

## 复现与单测

- OS8 注入首个层表请求永久不结算；修前 `tickNow()` 无法结束，修后超时并在下一轮读到新键。
- OS9 注入首张 `px` 请求永久不结算；修后释放槽位，再次请求成功。
- LMT8 模拟在线页远程地址未就绪；视频和图片哈希素材不返回 `/@media`，地址到位后返回远程地址。
- OS4、OS5 覆盖层表先于清单与新键换用。
- 预渲染调度单测注入一次永不结算的 `preload`；修前请求占位不释放，修后取消并重试。
- T5-shared-4 注入首次服务登记失败，再验证重试与晚到通知。
- RPC 单测注入活 iframe 的 `setSnapshots` 回包永久丢失，8 秒后拒绝，下一包仍可送达；低内存单测注入迟到 `settled`，仍选出小尺寸。
- 在线媒体单测注入“原片和小版都已上传、远程地址尚未就绪”，确认可见素材与后台可播性探测都不会请求 `/@media`。

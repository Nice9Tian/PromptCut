# AGENT 报告:Lottie 覆盖随机数种子(分支 `claude/lottie-seed`)

任务:试「覆盖随机数种子」能不能让 Lottie 直接跳到任意一帧时,和从头顺着推到这一帧的画面完全相同;可行就留下原型。
出处:`docs/plan/render-refactor-task.md`「癸:Lottie 改成 remotion 式」(渲染重构十项里的第十项)的「要留意的一处」;用户 2026-10-12:「我觉得可以覆盖随机数种子。」

日期 2026-10-12。机器:PC,Intel i7-14700KF,20 个逻辑核;Chrome 152.0.7977.75;lottie-web 5.13.0。

## 结论

**可行。** 覆盖种子以后,带随机表达式的 Lottie 顺着推、直接跳、新建一份再跳、页面里先有别的卡取随机数、先有别的 Lottie,画面都相同(逐像素相同,看得见的 SVG 文本逐字节相同)。原型留在 `src/cards/native/lottie.tsx`,开关缺省关。

但有三件事和派活时想的不一样,做「癸」之前要知道:

1. **自带的 5 个素材都没有随机表达式,种子对它们没有任何影响。** `navidad` 有 50 个表达式,全在图层样式(`sy`)里,播放库的 SVG 画法根本不建它们,一个都不执行。任务书说「带表达式的素材(自带的 `navidad` 就是)要专门验」,验下来它没有这个问题。会出问题的是用户自己拿来的、带 `random()` / `wiggle()` 表达式的 Lottie。
2. **真正要覆盖的是播放库内部那一串随机数,不是全页的 `Math.random`。** 表达式作用域里的 `Math` 是播放库自己的 `BMMath`,各属性的 `randSeed` 取自它。它只在页面里还没有任何表达式播过种时才等于全页的 `Math.random`。所以只在 `pinEntropy.ts` 里罩住 `Math.random` 不够——我第一版就是这么做的,被探针后加的两份素材抓出两处错(见「第一次没过的」)。现在的做法是直接给播放库内部那一串播种,`withSeededRandom` 是第二层。
3. **`happy2016` 那 0.003% 的差异和随机数无关,种子管不到。** 原因查清了:播放库更新属性值时「新值和旧值差不到 0.00001 就不更新」。原型里另加了一个开关(任务书没要求)把它去掉,开了以后 `happy2016` 顺推和直接跳逐像素相同。要不要用由主会话和用户定,见「正式做癸时怎么接」。

fixture 关着时具体怎么不同(第 21 帧看过图:顺推和新页新建里红色圆和黄色条的位置、角度明显不同):

- **顺推 对 同页新建:20 个 N 全不同**,2.3%～10.9% 的像素,所有带表达式的图层都不同——同页第二份实例的 `randSeed` 取到的是别的数。
- **别的卡在前、别的 Lottie 在前:取的 3 个 N 全不同**,2.3%～10.7%。
- **连建两次:不同。**
- 建一份并推帧,全页共用的那一串 `Math.random` 被吃掉 6 个(fixture)、21 个(fixtureip:6 个 `randSeed` 加上首帧里 wiggle 取的 15 个)。吃掉几个跟先画哪一帧有关。

**什么样的素材会出问题:** 有活的表达式(不在图层样式里)并且——
- 表达式里有 `random` 这个词:同一份实例里顺推、跳着推都一样;但新建一份、页面里别的卡或别的 Lottie 先动过,画面就变。「癸」之后一张卡什么时候挂、和谁一起挂不再固定,这类素材就会看到不同。
- 表达式里只有 `wiggle()`:连同一份实例顺推和跳着推都不一样。

### 对主会话几条推测的核实

- 「每个带表达式的属性在初始化时取一个 `randSeed`,求值时按它加时间播种」:对,`lottie.js` 第 14634、14680 行。补两点:(a) 不管表达式里用没用随机都取;(b) 只有表达式文本里出现 `random` 这个词才在求值前播种(第 14380 行 `_needsRandom = val.indexOf('random') !== -1`),只有 `wiggle()` 的不播种。
- 「`randSeed` 取自 `Math.random`」:**不准确**。那段代码在 `ExpressionManager` 的作用域里,第 14020 行 `var Math = BMMath`,取的是 `BMMath.random`——全页所有 Lottie 共用的一串。它在模块加载时抓的是全页的 `Math.random`(第 202 行),第一次 `BMMath.seedrandom(...)` 之后被换成播放库自带的 ARC4 发生器,再不回头。实测佐证:fixture 关着时全页那一串被吃掉 6 个(这时还没播过种);开着种子时是 0 个。
- 「图层是用到才建的,所以顺推和直接跳建图层的先后不同」:**不成立**。卡片用的是 `progressiveLoad: false`,播放库在装载完成那一下把所有图层连同嵌套合成里的一次建好。探针核对了建好后的图层数:8/8、59/59、387/387、15/15、46/46、240/240。建图层的顺序是固定的,变的是「建的时候那一串走到哪了」。
- 表达式里的 `seedRandom(seed, timeless)`:播放库不看第二个参数,实际播的是 `randSeed + seed`(第 14596 行),所以它同样依赖 `randSeed`。

## 原型怎么做的

### 开关一:覆盖随机数种子(任务要的)

文件:`src/cards/native/lottie.tsx` 的 `loadLottie`,`src/kernel/pinEntropy.ts` 的 `withSeededRandom`。

- **种子 = 素材内容的散列**(`lottieSeedOf`:解析后的数据 `JSON.stringify` 再做 FNV-1a,32 位)。同一份 JSON 无论地址、机器、换行符,种子相同。速度、循环、适配不进种子:它们只决定「t 对应第几帧」,不该改变某一帧的内容。
- **拿到播放库内部的随机源。** `BMMath` 没有导出。表达式的代码在它的作用域里求值,看得到它(名字是 `Math`)和 `globalData`,所以建一份只有一个空图层的一次性动画,让它的表达式执行 `globalData.__pcLottieMath = Math`,取出来就销毁。全页只做一次。
- **建图层之前**按「种子 + build」给它播种:各属性的 `randSeed` 按固定顺序从这里取完。装载是异步的(字体、外部数据没到齐)时,建图层在播放库自己的回调里,所以把这份实例的 `checkLoaded` 也包进去。
- **每画一帧之前**按「种子 + 帧号」播种:只有 `wiggle()` 的表达式拿到的数只跟帧号有关。
- **装载完成后重画一遍当前帧。** 装载完成那一下播放库自己画了一次当前帧,用的是建图层取剩的数;不重画的话,这一帧以后再跳回来画出来的就不一样。用的是播放库里「当前帧再画一次」的写法 `renderer.renderFrame(null)`。
- **以上每一段都再包在 `withSeededRandom(种子, …)` 里**:全页共用的那一串不被 Lottie 挪动;播放库里直接调 `Math.random()` 的地方(文字图层的随机顺序)也落在种子里。
- 关着时 `loadLottie` 就是原来那两句 `lottie.loadAnimation` 和 `goToAndStop(frame, true)`。`LottieView` 只是把这两处调用换成经 `loadLottie` 走。没改 `frameMode`,没改画法。

### 开关二:属性值不留旧数(任务书没要求,我加的,可以整段删)

- 查 `happy2016` 时找到的:播放库 `setVValue`(`lottie.js` 第 3036 行)里,新值和手里的旧值差不到 0.00001 就不更新。顺着推时值一点点变,最后几步每步都不到门槛,就停在离终点差一点的地方;直接跳拿到的是准确值。落到变换矩阵上是 `1.0000001192092896` 对 `1`,光栅化出来几十个边缘像素不同。
- 做法:播放库自己就是靠换掉 `PropertyFactory.getProp` 给属性加表达式的,这里用同一个口子(`lottie.__getFactory('propertyFactory')`)再包一层;本开关开着的实例在建属性时,把它的 `setVValue` 换成「不相等就更新」。别的实例不受影响。
- 不放进开关一,是因为它会让不带随机的素材顺推出来的画面变(变成现在直接跳的那个画面),和「种子不该动不带随机的素材」要分开看。

### 开关怎么开

缺省都关,不在用户界面上。两种开法,在建实例之前生效:

| | 页面地址参数 | 或设全局变量(压过地址) |
|---|---|---|
| 开关一 | `lottieSeed=1` | `window.__pcLottieSeed = true` |
| 开关二 | `lottieExact=1` | `window.__pcLottieExact = true` |

代码里直接调 `loadLottie(容器, 数据, 适配, { seed, exact })` 可以不看开关。正式做「癸」时把 `lottieSeedEnabled` / `lottieExactEnabled` 的缺省改掉即可。

### 全页随机状态恢复的两种办法,选了哪种

- **甲:恢复成没被动过。** Lottie 取了几次,外面一次都看不到。在 Lottie 之后才取随机数的别的卡,拿到的数会比现在靠前(现在页面里第一个 Lottie 会吃掉若干个)。
- **乙:恢复以后把被吃掉的那几步补回去。** 别的卡拿到的数和现在一样。(这个发生器的状态是累加的,补 n 步是一次加法,实现不难。)

**实现的是甲。** 理由:

1. 乙补不准。现在被吃掉几个跟**先画哪一帧**有关(fixture 6 个,fixtureip 21 个,多出来的 15 个是首帧里 wiggle 取的),而且只在页面里第一个播种之前才吃;「癸」之后直接跳帧,先画哪一帧本来就不固定。能补准的只有建图层那一部分。
2. 甲才是要的性质:别的卡的画面不该因为页面里有没有 Lottie、Lottie 什么时候挂而变。乙是把现在的耦合原样留下。
3. 受影响面小:内置卡里没有靠全页 `Math.random` 出画面的(粒子卡用自己的 seed;`src/cards`、`src/parts`、`src/render` 里搜过,只有 `dataMirror.ts` 取会话号)。会变的只有「同一页里既有带活表达式的 Lottie、又有在它之后取 `Math.random` 的自建卡」这种组合。

### 第一次没过的(照实记)

1. **第一次跑 fixture(只有开关一的第一版):开着的 20 个 N 全判不同,另有 3 条真卡片、1 条页面报错。** 像素差全是 0。是探针比法的问题,不是原型:比的是原文,把看不见的图层上留着的旧属性也算进去了;页面报错是 favicon 404。改成比「看得见的」加像素以后,同一份原型 20/20。

3. **有一次整轮作废:** 改探针的写入没成功,跑的是旧探针配新接口,「开」实际没开。结果没用,重写后重跑。
4. **加了 fixtureasync、fixtureip 以后,原型真的错了两处**(这时前面的全部通过、`tsc` 和 `npm test` 也都过了):
   - fixtureasync:真卡片直接挂在第 21、41 帧,和直接跳的那一份比有 5.0%、9.6% 的像素不同,所有带表达式的图层都不同。原因:卡片在装载完成前跳过帧,我把「建图层」和「画那一帧」用同一串(种子 + 那一帧)播种,而 `randSeed` 正是从这一串取的,于是它跟着帧号变。这也是我发现「`randSeed` 取自播放库内部那一串、不是全页 `Math.random`」的地方。改成建图层固定用「种子 + build」。
   - fixtureip:第 0 帧「顺推」和「回跳」有 2.2% 的像素不同(两个只有 wiggle 的图层)。原因:装载完成那一下播放库自己画的第 0 帧用的是建图层取剩的数。改成装载完成后按帧号重新播种重画。
   修完后三份 fixture 全过,再跑了一遍 `tsc`、单测、`npm test`。

## 没做成的、没验的

- **没在真的导出管线和舞台 iframe 里开着开关跑。** 开关要么在页面地址上、要么要往页面里注入变量,导出页和舞台页的地址是 `server/` 和别的文件拼的,不在我的文件清单里。现在验到的是卡片这一层(真 `LottieView`、和产品一样的随机数钉子)。预览和导出用的是同一份卡片代码、同一个种子(素材内容)、同一个帧号,按理一致,但这句话没有实测支撑。
- **文字图层的「随机顺序」动画器没测。** 它直接调全页的 `Math.random()`,落在 `withSeededRandom` 里;同一次调用里有多个这样的图层时仍可能和路径有关。造这种素材要带字形数据,没做。自带素材里没有。
- **带网络字体的异步装载没测。** 异步装载那条路是用「外部数据素材」测的(fixtureasync),走的是同一个 `checkLoaded`。
- **生产构建里没实际跑。** 只做了静态核对:用 vite 缺省的压缩把 lottie-web 单独打了一份,压缩后 `randSeed=Math.floor(Math.random()*1e6),globalData=elem.globalData`、`Math=BMMath` 这些名字原样在(有 `eval` 的作用域不改名),`__getFactory`、`getProp`、`setVValue`、`checkLoaded`、`currentRawFrame`、`renderFrame` 这些属性名也在。
- **画布画法没管**(卡片用的是 SVG)。
- **导出确定性、快照重放那几项渲染附加项没跑**:开关缺省关,关着时卡片和改之前逐字节相同(上面验了),画面没变。
- 浏览器面板的预览没用:它不认 worktree,改用探针在真 Chrome 里验。

## 正式做「癸」时怎么接

- **直接复用**:`loadLottie`(连同 `lottieSeedOf`、取内部随机源、`checkLoaded` 的包法、装载后重画)、`withSeededRandom`、探针和测试素材。把开关的缺省改成开,或者去掉开关。
- **开关一建议缺省打开。** 它不动任何不带随机表达式的素材(5 个自带素材全长逐帧相同),只改带活的随机表达式的素材的画面——这些素材现在的画面本来就随挂载时机变,没有哪一个算「对」的。不开的话,这类素材按任务书那条就「不能按 remotion 式办」。
- **开关二要用户定。** 打开后:`happy2016` 顺推全长有 76 帧的 SVG 文本变了,抽查的帧里最多 74 个像素(0.0036%)不同;`bodymovin` 1 帧文本变了、像素不变;另外 3 个不变。变成的是现在直接跳就能拿到的画面。不打开的话 `happy2016` 顺推和直接跳差 74 个像素,过不了「癸」的验收「跳着取的若干帧也相同」。它动了播放库内部的一个门槛,任务书没提,**记待用户项**。
- **「癸」的验收写法要跟着改**:「改之前先留底,改之后逐帧相同」——留底如果是顺推出来的,开关二打开后 `happy2016` 会差 74 个像素。要么留底时就开着开关二,要么这一项对 `happy2016` 改成和「改之前直接跳」的画面比。
- **导出的像素基线**:演示项目 `src/demo.ts` 里没有 Lottie,全量比对测不到它,两个开关开不开基线都不变。Lottie 以探针这份针对性的比对为准。
- **别的卡**:用的是「恢复成没被动过」,见上「选了哪种」。带活表达式的 Lottie 后面跟着取全页 `Math.random` 的自建卡时,那张卡的画面会变一次。
- **预览和导出**:理由上一致(见「没做成的」第一条),「癸」里要在真管线上验一遍:同一个项目,导出全长对比跳着取的若干帧,桌面和在线各一遍。
- **节点 id**:开着种子时页面里会先建一份一次性动画,播放库按全页计数器发的节点 id(`__lottie_element_N`)会往后挪几个。不影响画面;要是有代码拿这些 id 当身份用,会受影响。「癸」之后不再存 Lottie 的 HTML 快照,应该用不到。

## 风险

- **依赖播放库内部的东西**,换版本可能失效:表达式作用域里看得到 `Math` 和 `globalData`;`lottie.__getFactory('propertyFactory').getProp`;属性上的 `setVValue`;实例上的 `checkLoaded`、`currentRawFrame`;`renderer.renderFrame(null)`。每一处取不到都有退路并在控制台警告,探针把页面警告算失败,换版本后跑一遍探针就知道。`package.json` 里是 `^5.13.0`,升级前先跑探针。
- **取内部随机源失败时退化得很弱**:只剩 `withSeededRandom` 那一层,它只在页面里还没有表达式播过种时管用。
- **一帧里各表达式的求值顺序**假定只跟帧号有关(只有 wiggle 的表达式共用一串、按顺序取)。fixture 里有两个顶层、一个嵌套的 wiggle 图层,入点不同,都过了;更复杂的互相引用没试。
- **种子换了,带活随机表达式的素材画面一定会变一次**(开关一打开那一次)。
- **wiggle 的样子**:按「种子 + 帧号」播种,每帧一串新数,和现在一样是逐帧跳动的;没有借机改成连续的噪声。
- 种子是 32 位散列,两份不同的素材撞上只是用了同一串随机数,不影响各自的确定性。

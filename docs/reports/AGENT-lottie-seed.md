# AGENT 报告:Lottie 覆盖随机数种子(分支 `claude/lottie-seed`)

任务:试「覆盖随机数种子」能不能让 Lottie 直接跳到任意一帧时,和从头顺着推到这一帧的画面完全相同;可行就留下原型。
出处:`docs/plan/render-refactor-task.md`「癸:Lottie 改成 remotion 式」(渲染重构十项里的第十项)的「要留意的一处」。

用户 2026-10-12 先后说了三句,对应原型里的三样东西:

- 「我觉得可以覆盖随机数种子。」→ **开关一**:给播放库内部那一串随机数播种。
- 「能不能用替换方式直接覆盖,比如替换 random 为 random_in_card()」→ **开关三**:改写表达式,把随机函数换成卡片自己的。
- 「你帮我在外面也兜住,把播放库的随机数也固定。」→ **外面那一层**:播放库自己直接取随机数的地方,开关一和开关三共用。

另有 **开关二**(属性值不留旧数),和随机数无关,任务书没要求,是查 `happy2016` 时加的。

日期 2026-10-12。机器:PC,Intel i7-14700KF,20 个逻辑核;Chrome 152.0.7977.75;lottie-web 5.13.0。

## 结论

**两种办法都可行。** 开着开关一或开关三,带随机表达式的 Lottie 顺着推、回跳、同页新建一份再跳、新开页面再跳、页面里先有别的卡取随机数、先有别的 Lottie,画面都相同(逐像素相同,看得见的 SVG 文本逐字节相同)。带「随机顺序」文字的素材靠外面那一层,同样全部相同。原型在 `src/cards/native/lottie.tsx`,开关缺省都关。

**建议正式用开关三加外面那一层,不叠开关一。** 理由在「开关一和开关三」一节,最主要的两条:开关三不碰播放库内部的任何对象,升级播放库时不容易坏;它让每个表达式的值只跟(素材、这个表达式、时间)有关,连「同一帧里别的表达式先算后算」都无关。代价是画面的性格变了两处,要用户点头:`wiggle()` 从逐帧乱跳变成随时间连续晃动;`seedRandom(n)` 不带第二个参数时变成随时间变(播放库现在不看第二个参数,一律不变)。

做「癸」之前要知道的几件事:

1. **自带的 5 个素材都没有活的随机表达式,也没有随机顺序的文字,三个开关对它们的随机没有任何影响。** `navidad` 有 50 个表达式,全在图层样式(`sy`)里,播放库的 SVG 画法不建它们,一个都不执行。会出问题的是用户自己拿来的素材。
2. **播放库表达式用的是它自己内部的一串随机数,不是全页的 `Math.random`。** 只在 `pinEntropy.ts` 里罩住 `Math.random` 管不到表达式(我第一版开关一就错在这里)。
3. **主会话推测的「图层是用到才建的」不成立**:卡片用 `progressiveLoad: false`,装载完成时全部建好。变的是建的时候那一串走到哪了。
4. **`happy2016` 那 0.0036% 的差异和随机数无关**,是播放库「新旧值差不到 0.00001 就不更新」。开关二去掉它。
5. **文字的「随机顺序」只按帧号播种反而会错**:它每份文字内容只算一次,带关键帧的在第一次画到那份内容时才算。按帧号播种的话,顺着推和直接跳是在不同的帧算的,结果不同(实测 11 个 N 里只有 6 个相同)。所以外面那一层里给它单独按(素材、图层、文字内容)固定。

fixture 关着时怎么不同(第 21 帧看过图:顺推和新页新建里红色圆的位置、黄色条的角度明显不同):

- **顺推 对 同页新建:20 个 N 全不同**,2.3%～10.9%,所有带表达式的图层都不同——第二份实例的 `randSeed` 取到的是别的数。
- **别的卡在前、别的 Lottie 在前:取的 3 个 N 全不同**,2.3%～10.7%。连建两次不同。

textrandom 关着时(第 45 帧看过图:三行方块字,前两行被抬高的字明显不同):顺推和新页新建在第 40、41、45 帧不同(1.4%～2.0% 的像素),不同的是文字内容带关键帧的那两层。原因是顺着推时两层的新内容分别在第 30、40 帧算,直接跳到第 40 帧以后是在同一次调用里按相反的先后算。同页新建 11 个 N 里 9 个不同(0.26%～2.6%),别的卡在前、别的 Lottie 在前取的 3 个 N 里各 2 个不同。

**什么样的素材会出问题:**

- 表达式里有 `random` 这个词:同一份实例里怎么推都一样;但新建一份、别的卡或别的 Lottie 先动过,画面就变。
- 表达式里只有 `wiggle()`:连同一份实例顺推和跳着推都不一样。
- 文字图层用了「随机顺序」的动画器:新建一份、别的卡先取过随机数就变;文字内容带关键帧且不止一层时,顺推和直接跳也不一样。

### 对主会话几条推测的核实

- 「每个带表达式的属性在初始化时取一个 `randSeed`,求值时按它加时间播种」:对(`lottie.js` 第 14634、14680 行)。补两点:不管表达式里用没用随机都取;只有表达式文本里出现 `random` 这个词才在求值前播种(第 14380 行),只有 `wiggle()` 的不播种。
- 「`randSeed` 取自 `Math.random`」:**不准确**。那段代码在 `ExpressionManager` 的作用域里,第 14020 行 `var Math = BMMath`,取的是播放库内部那一串。它在模块加载时等于全页的 `Math.random`(第 202 行),第一次 `BMMath.seedrandom(...)` 之后换成播放库自带的发生器,再不回头。
- 「图层是用到才建的」:**不成立**,见结论第 3 条。探针核对了建好后的图层数:8/8、9/9、3/3、59/59、387/387、15/15、46/46、240/240。
- 表达式是 `eval('[function _expression_function(){' + val + ';scoped_bm_rt=$bm_rt}]')[0]` 编译的(第 14422 行),`random` 在第 14326 行、`wiggle` 在第 14425 行、`seedRandom` 在第 14596 行:核对无误。播放库没有 `gaussRandom`。

## 原型怎么做的

### 开关三:替换表达式里的随机函数

- **改写**(`rewriteLottieExpressions`、`wrapLottieExpression`):交给播放库之前,把素材里每个表达式的原文包成

  ```
  var $bm_rt = (function (random, gaussRandom, seedRandom, wiggle, Math) {
  var $bm_rt;
  <原文>
  ;return $bm_rt;
  }).apply(null, __pcLottieFn(<素材种子>, <表达式编号>, time, value, Math));
  ```

  用的是主会话建议的「包一层、把名字遮住」,没有逐处替换。两处和建议不同:(a) 五样东西由一次调用一起给,这一次求值里它们共用一串随机数;(b) 形参 `random` 在文本里写成 `random`(同一个标识符):播放库看表达式文本里有没有 `random` 这几个字母决定求值前要不要给它自己那一串播种,这样包完以后它的判断和包之前一样。原文后面先换行再接 `return`,原文最后一行是 `//` 注释也不会把它注释掉。
- **表达式编号** = 它在 JSON 里的路径的散列。嵌套合成被引用多次时,里面同一个表达式的各份编号相同、随机数相同(AE 也是这样)。
- **卡片自己的函数**(`lottieExprRuntime`,挂在全局名字 `__pcLottieFn` 上,每个页面——舞台、导出页——各装一次,不记任何状态):
  - `random`:四种调用形式照播放库的。每次求值开一串新的,种子 =(素材种子、表达式编号、时间);连着调取下一个。
  - `wiggle`:算法照播放库的(频率写死成 5,累加前 floor(时间×5) 组随机数,再加下一组乘小数部分),但随机数取自只跟(素材、表达式)有关、不带时间的一串,所以随时间连续。
  - `seedRandom(offset, timeless)`:照 AE 的语义,`timeless` 为真时种子里不带时间。
  - `gaussRandom`:播放库没有这个函数(表达式里用了会报错),按 AE 的说明补了一个(约九成落在上下限之间)。这是新增的能力,不想要可以删掉这一个形参。
  - `Math`:继承播放库的 `Math`,只把 `random` 和 `seedrandom` 换掉。
- **`this.pv` 和 `value`**:播放库的 wiggle 用 `this.pv`,卡片的函数拿到的是表达式变量 `value`。探针核对:带关键帧的属性两者是同一个对象;不带关键帧的多维属性 `pv` 是 `value` 取单精度的样子(最大差 0)。卡片的 wiggle 先取单精度再算。
- 开关三**不取**播放库内部的随机源,**不给**它播种,不用装载后重画。

### 外面那一层(开关一、开关三只要开了一个就有)

- 建实例、装载完成(含异步装载时播放库自己的回调,包的是这份实例的 `checkLoaded`)、每次跳帧,都包在 `withSeededRandom` 里。建图层用(素材种子)一串,画第 N 帧用(素材种子、N)一串。全页共用的那一串不被 Lottie 挪动。
- 文字的「随机顺序」(`hookTextOrder`):`TextProperty` 没有导出,所以建一份只有一个文字图层的一次性动画(图层入点在动画之外,只建不画),从它身上取到原型,包住 `completeTextData`:算哪一份,就用(素材种子、图层、文字内容)播种。全页只包一次;没开开关的 Lottie 不受影响;素材里没有随机顺序的文字时不做。

### 开关一:给播放库内部那一串播种

- 建一份只有一个空图层的一次性动画,让它的表达式执行 `globalData.__pcLottieMath = Math`,取到 `BMMath`。
- 建图层之前按「种子 + build」播种;每画一帧之前按「种子 + 帧号」播种;装载完成后按帧号重画一遍当前帧(`renderer.renderFrame(null)`),因为装载完成时播放库自己画的那一次用的是建图层取剩的数。

### 开关二:属性值不留旧数(任务书没要求,可以整段删)

- 用 `lottie.__getFactory('propertyFactory')` 在播放库建属性的口子上包一层(播放库自己就是这样给属性加表达式的),开着的实例把属性的 `setVValue` 换成「不相等就更新」。

### 公共的

- **种子 = 素材内容的散列**(`lottieSeedOf`:解析后的数据 `JSON.stringify` 再做 FNV-1a)。同一份 JSON 无论地址、机器、换行符,种子相同。速度、循环、适配不进种子。
- 三个开关都关着时 `loadLottie` 就是原来那两句 `lottie.loadAnimation` 和 `goToAndStop(frame, true)`。没改 `frameMode`,没改画法。

### 开关怎么开

缺省都关,互相独立,不在用户界面上。在建实例之前生效:

| | 页面地址参数 | 或设全局变量(压过地址) |
|---|---|---|
| 开关一 | `lottieSeed=1` | `window.__pcLottieSeed = true` |
| 开关二 | `lottieExact=1` | `window.__pcLottieExact = true` |
| 开关三 | `lottieExpr=1` | `window.__pcLottieExpr = true` |

代码里直接调 `loadLottie(容器, 数据, 适配, { seed, exact, expr })` 可以不看开关。`debug: "no-outer" | "no-text-key"` 只给探针对照用。

### 全页随机状态恢复的两种办法,选了哪种

- 甲:恢复成没被动过。在 Lottie 之后才取随机数的别的卡,拿到的数会比现在靠前。
- 乙:恢复以后把被吃掉的那几步补回去,别的卡不变。(这个发生器的状态是累加的,补 n 步是一次加法。)

**实现的是甲。** 乙补不准:现在被吃掉几个跟先画哪一帧有关(fixture 6 个,fixtureip 21 个,textrandom 40 个),「癸」之后先画哪一帧本来就不固定。甲才是要的性质:别的卡的画面不该因为页面里有没有 Lottie 而变。受影响面小:内置卡里没有靠全页 `Math.random` 出画面的(粒子卡用自己的 seed)。

## 开关一和开关三

| | 开关一(给内部那一串播种) | 开关三(改写表达式) |
|---|---|---|
| 依赖播放库的什么 | 内部对象:表达式作用域里看得到 `Math` 和 `globalData`(用来把 `BMMath` 取出来);`BMMath.seedrandom` 会换掉 `BMMath.random`;`randSeed` 在建图层时取、求值前按文本里有没有 `random` 决定播不播种;`renderer.renderFrame(null)`;`currentRawFrame` | 素材格式和表达式的写法:表达式是属性对象上的字符串 `x`;原文被原样拼进一个函数体;外层有 `time`、`value`、`Math` 这几个名字。这些是 Lottie 格式和 AE 表达式的公开约定。不碰任何内部对象 |
| 升级播放库时 | 容易坏:上面任何一处内部细节变了都会失效或悄悄不准。取不到 `BMMath` 时会警告;但像「播种时机变了」这种不会报错,只能靠探针发现 | 不容易坏:只要表达式还是 `eval` 原文、还认这几个名字就行。坏了的表现是表达式报错,看得见 |
| 管得到的 | 表达式里的随机,前提是「同一帧里各表达式的求值先后只跟帧号有关」(只有 wiggle 的表达式按先后共用每帧那一串) | 表达式里的随机,每个表达式各自独立:和别的表达式、求值先后都无关 |
| 管不到的 | 表达式以外的(文字随机顺序)——靠外面那一层 | 同左,靠外面那一层 |
| 画面和现在比 | 数换了,性格不变:wiggle 仍逐帧乱跳;`seedRandom(n)` 仍不随时间变 | 数换了,性格也变:wiggle 随时间连续;`seedRandom(n)` 不带第二个参数时随时间变;多了 `gaussRandom` |
| 装载后重画 | 要 | 不要 |

**建议:正式用开关三加外面那一层,不叠开关一。**

1. 开关一最脆的两处——靠一份一次性动画把 `BMMath` 偷出来、装载后重画——开关三都不需要。我做开关一时错过两次,都错在对播放库内部时机的理解上(见「第一次没过的」第 4 条),这类错不报错、只让画面悄悄不对。

## 风险

- **开关三改写的是用户的表达式文本。** 包一层以后原文的 `this`、严格模式、能看到的名字都没变;但写法古怪的表达式(顶层 `return`、括号不配对)本来就有问题,包了以后的表现可能不同。
- **开关三的 wiggle、random 是照着播放库现在的写法另写的一份。** 播放库以后改了算法,卡片这份不会跟着变(画面仍然确定,只是和「不开开关的播放库」不一样)。
- **外面那一层的文字部分依赖播放库内部**:`renderer.elements[0].textProperty` 的原型上有 `completeTextData`、`elem.data.ind`、`elem.comp.data.refId`。取不到会警告(探针把页面警告算失败)。只有素材里有随机顺序的文字时才用到。
- **开关一、开关二依赖的内部细节**:见「开关一和开关三」的表;开关二是 `lottie.__getFactory('propertyFactory').getProp` 和属性上的 `setVValue`。`package.json` 里是 `^5.13.0`,升级前先跑探针。
- **种子换了,带活随机的素材画面一定会变一次**(开关打开那一次)。
- 种子是 32 位散列,两份不同的素材撞上只是用了同一串随机数,不影响各自的确定性。

## 待用户项

1. **正式用开关三还是开关一。** 建议开关三。它让 `wiggle()` 从逐帧乱跳变成连续晃动、`seedRandom(n)` 不带第二个参数时随时间变、多一个 `gaussRandom`;开关一不改这些。
2. **开关二要不要用。** 用,`happy2016` 顺推的画面有 76 帧微变(最多 74 个像素);不用,它顺推和直接跳差 74 个像素。
3. 开关缺省打开时,用户自带的带随机表达式或随机顺序文字的 Lottie 画面会变一次,是否接受。

# M6c 1080p 流编码基准对照

## 结论

在同一时段交替运行原样的 `stream-produce-probe.mjs`，当前分支没有可检出的 1080p 整帧编码回归。十次有效对照中，main 的 p50 平均为 255.0 ms，`claude/m6c-integ` 为 252.6 ms；当前分支减 main 的配对均值为 −2.4 ms，95% 置信区间为 −10.4～+5.6 ms，双侧精确符号翻转检验 p = 0.5。两边所有 p50 都低于原有 300 ms 门槛。未修改编码代码、探针或门槛。

先前报告的 main 294/294 ms、当前分支 325/337 ms，在这组交替对照中未复现。随后系统出现新的并行工作进程，两边探针都明显变慢，main 甚至超过 300 ms（见后面的高负载复测）。这直接支持门槛受共享系统负载影响；本次没有证据把先前差异归因于分支代码，也没有足够证据锁定某个具体外部进程。

## 方法与原始读数

- 对照版本：main `b84fee5`，当前分支 `fde97cb`。main 用临时 detached worktree；两边均使用同一套上级 `node_modules`、同一 `ffmpeg` 和各自的独立预渲染 Vite 服务。服务端口分别为 5410、5420；探针原样运行，传入对应 `--origin` 和 `--json`。
- 2026-09-26 07:01～07:08（Asia/Tokyo）按“当前分支、main”连续交替五对。每次完整探针都通过；表中 `编码三次` 是探针排序后的三次耗时，p50 是中间值。编码器均为 `libx264`，矩形均为 1920×1080，p50 对应 fMP4 字节数均为 426118。
- 进程范围是每 2 秒采样的系统同名进程总数，包含本次探针、两台测试 Vite 服务和原有进程；`chrome` 同时计入 `chrome` 与 `chrome-headless-shell`。运行前已有 1 个其它 node、11 个 chrome、0 个 ffmpeg；因此表中的 node 至少有 3 个是本次测试启动的（两台服务及正在运行的探针）。进程数只能描述竞争环境，不能直接等同于 CPU 利用率。

### 高负载复测

完成 1800 帧 × 2 遍的导出确定性验证后，新出现的并行进程使系统 node 总数从先前的约 3 个增至约 14～16 个，Chrome 从约 11 个增至约 47 个。此时当前分支单跑无 `--group` 探针，1080p 编码三次为 363 / 366 / 630 ms，p50 = 366 ms，因该门槛失败。马上交替跑 main 和当前分支得到：

|---:|---|---|---|---:|---|---|---|---|
| 13 | main | 17:19–18:08 | 336 / 348 / 378 | 348 | 16–18 | 47–59 | 0–2 | 编码门槛失败 |
| 14 | 当前 | 18:08–18:56 | 290 / 293 / 313 | 293 | 16–18 | 48–59 | 0–2 | 通过 |

两边的编码器仍是 `libx264`，段字节数仍是 426118。这个额外对照没有合并进前面的安静时段统计，因为系统负载状态已经改变。新增进程不是本次测试启动的；未结束它们。门槛本身以“无别的编码器争 CPU”为前提，在高负载共享机器上不能保证每次通过。

## 原因排查与改动

`git diff main -- scripts/probes/stream-produce-probe.mjs server/bakery/ffmpeg.mjs` 为空。两边探针报告的编码器、矩形和压缩段字节数一致；安静时段的进程数范围也没有当前分支独有的常驻 node、chrome 或 ffmpeg。两边都出现单次编码尖峰（main 344/340 ms，当前分支 343 ms），但三次取中值后都达标。高负载下 main 同样超标。当前证据支持原先的超标是时段性测量波动，未发现可修复的分支编码路径回归。按“差异不显著则不改代码”的要求，未修改代码，也未改变产物。

- `npx tsc -b --force`：退出码 0，零错误。
- `npm test`：2653 项，pass 2652、fail 0、skipped 1。首次沙箱运行因 Node worker `spawn EPERM` 未能执行，提权重跑得到上述结果。
- `node scripts/verify-determinism.mjs --url http://127.0.0.1:5420/?export=1`：两遍各 1800 帧，逐像素相同 1800、不同 0，退出码 0。没有改动渲染代码，因此未另做 main 与当前分支的跨分支导出像素比对。
- `node scripts/probes/stream-produce-probe.mjs --origin http://127.0.0.1:5420`：安静时段五次全部通过（p50 259、254、249、245、256 ms）；高负载后单跑一次 p50 366 ms 失败，紧接着的当前分支复测 p50 293 ms 通过。两次高负载运行均没有其它断言失败。
- `node scripts/probes/stream-produce-probe.mjs --group --origin http://127.0.0.1:5420`：通过，fail 0。

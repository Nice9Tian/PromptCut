# 0.7.18 块二：改密退出的确认链

分支 `claude/v18-logout`，从 `main` `316f3f7c` 分出，2026-10-13。只在这个工作区里干活；没连节点；`docs/local.md` 只查了那两个环境变量；VisuHive 仓库只读没改（本机验证用它现在的 `main` `1b3b002` 当账号后端）；ChatGPT 的分支和工作区没动。

几个词：

- **退出确认**：用户在网站改密或重设后选「退出别的设备」，账号服务发一条「旧登录作废」事件。网页一直显示「正在退出」，直到账号服务把这次退出记成办完。
- **四样确认**：账号服务（VisuHive）要收齐文档、素材、Agent、渲染四个服务的确认，外加文档服务签的一份「结束见证」（这次退出到哪个顺序号为止），才把退出记成办完。这是它现有代码的规矩（`account/events.mjs` 的 `REQUIRED_SERVICES`、`account/password-order.mjs` 的 `logoutComplete`）。
- **访问事件**：文档服务把账号的「旧登录作废」转成自己账本里的一条事件，素材、Agent 各自据它关掉旧登录的东西再回确认。
- **读取**：有人经 Agent 服务读对话（列表、历史、事件流）时，文档服务账本里记的一条「谁开着什么」。
- **一条任务一个进程**、**root**、**结清**、**保留的任务**：见上一块的报告 `AGENT-v18-worker.md` 开头。
- **续办器**：本块新加的 `server/account/logout-confirmer.mjs`，文档服务里定时把没办完的退出往下办的那一段。

## 开工时的实际状况（和摸底报告说的不一样）

摸底报告说「全部服务确认没接」。读代码以后具体是这样：

- 账号服务那一半**已经做完**：收确认、验结束见证、给网页回状态、网页只在 `logout.state === 'complete'` 时显示已退出，都在 VisuHive 的 `main` 上。
- 素材服务读事件、关流、回确认，已经做完，自带持久的位置记录和重发。
- 文档服务这一半**没接**：往账号服务回确认的函数（`flushAccountAcknowledgements`）生产代码里没有任何地方调；它要的「文档服务自己这一项的证据」没有人提供；结束见证没有人去登记；渲染那一项没有任何人确认；Agent 那一项遇到任何任务就永远不过。

所以在这之前，选了「退出」以后网页会**永远**停在「正在退出」。权限是当场撤的（旧会话、旧编辑器登录立刻不能用），只是「办完」永远不出现。

## 做了什么

### 1. 续办器：四样齐了才向账号服务报办完（`server/account/logout-confirmer.mjs`，新）

挂在文档服务的组合入口 `server/hosted/combo.mjs` 里，两个端口都在听了才启动。每秒看一遍账本里没办完的退出（也可以被叫醒：关完连接时会叫一下）：

1. 让 Agent 那一项按账本判一次（见第 2 节）。
2. 这一版里不代任何登录持有连接或流的服务，由文档服务写明原因代为登记（见〔裁 1〕）。
3. 四样里另外三样齐了，才形成文档服务自己这一项的证据，把带着各项回执的确认送给账号服务。
4. 账号服务收下以后，向它登记结束见证；它验过（四样确认都在、旧登录没有悬着的操作）才把退出记成办完。文档服务把见证的顺序号记进账本，这次退出在它这边也算办完。

哪一步没齐，只是下一秒再看，不报完成、不放弃。每一步都是先落盘再发：证据、回执、见证请求号都在账本里，回应丢了或进程重启以后重发的是同一份，账号服务认得出重复。办完的退出不再发任何东西。

### 2. Agent 这一项（`server/account/agent-read-control.mjs`、`server/hosted/doc-agent-assembly.mjs`）

照上一块留的口子接的，没有新增 Agent 一侧的调用：

- 新函数 `accessEventRunClosure(state, 事件号, { scoped })`，只读账本，判请求号为 `access:<事件号>` 的任务控制记录是否都收口。
  - 开了「一条任务一个进程」：要中止的每一条任务（私有对话里的、还没被读到的）都凭 root 的关闭记录结清了才算；还没绑到进程上就被撤掉的没有进程可关，不等；**保留下来继续跑的共有已读任务不在等的范围里**（契约原文：「共有任务按例外继续不等于设备仍登录，也不要求等该任务做完才能确认设备已退出」）。
  - 没开：这一档没有办法证明任务占着的进程资源已经关掉，所以和原来一样，只有任务清单是空的才算（往安全的方向卡）。
- `completeReadAccessEvents()` 用它判；办完时把被中止的任务填进回执的 `stoppedRuns`（原来固定是空数组），关闭记录的摘要一并记进账本里那份不可改的收口记录。
- 新口子 `completeAccessEvents()`：开了「一条任务一个进程」时先读一次 root 的关闭记录再判。这样主身份还没来问的时候（比如文档服务刚重启）也能结清。

**顺带修了一处会让这一项永远不过的毛病**（〔裁 2〕）：清点读取时，凡是没订阅过读取控制的 Agent 实例都被当成「来历不明、可能还开着读取」而一直等。每一代任务进程都会登记成一个实例，又从不订阅读取控制，于是开了「一条任务一个进程」以后，只要跑过一条任务，之后任何一次退出、踢人、切私有的读取清点都收不了口。现在：任务进程的实例在实例权威里明确不许用读对话的那组接口，读取清点也就不把它算进去；它占着的进程由任务的关闭记录管。改回去以后新加的集成测试会红在 `read-close-pending`（做过一次验证，见「验证结果」）。

### 3. 文档服务自己这一项的证据（`server/docservice/account-hosted.mjs`、`server/hosted/doc-assembly.mjs`、`server/docservice/modules/operation-history.mjs`）

证据由三样拼成，形成后记进账本，以后给出去的都是同一份：

- **连接**：这个进程亲手关掉旧登录的连接并记进账本的那一份（现在多记了每条连接是哪个登录的）；或者「这个进程开始接连接的时候，这条作废事件已经在账本里」——每个入口都先查作废名单，所以它从没放进过那些登录的连接。后一种是重启以后用的。
- **操作**：旧登录没有还没定序的操作。有悬着的先办结（定了序的落地，没定序的作废），还有就等下一秒。
- **位置**：旧登录在各项目里最后一条被接受的操作的顺序号。这一版只记不用，留给 0.7.20 的撤回。

### 4. 账号权威的两处小改（`server/account/authority.mjs`）

- 查一次退出还差谁（`revocationStatus`）：原来固定回「文档没确认、没办完」，现在照账本里的实际情况回。
- 新增 `completeLogoutBarrier`：记下账号服务签回来的结束见证。只记一次，重复记同一份不报错，换一份报错。

### 5. 没动的

- VisuHive 一个字没改。
- 素材服务的代码没改（它那一半本来就是全的）。
- 语义文档没改。界面上的字没定。

## 没做成的及原因

1. **Agent 服务带着旧登录的读取被结束或重启，这个登录之后的退出会一直停在「正在退出」。**
   文档服务账本里记着「这个实例开着这条读取」。实例没了以后，新起的实例拿不出「旧实例确实关干净了」的证明，现有设计（ChatGPT 定的，文件里写着「来历不明的旧实例不能凭一张空清单算关了」）就一直等。权限是撤了的，只是网页永远不显示办完。只要部署 Agent 服务时有人开着云端对话页，就会留下这样的读取。这一条和任务书「重启后续办、不卡死」对不上。
   同一个进程里读取控制的连接断了再连上（比如文档服务重启）不受影响，能续办，测过。
   解法见下表，都要动 Agent 服务和文档服务之间的约定，这一块没做：

   | 层 | 解法 | 问题 |
   |---|---|---|
   | 三级 | Agent 主服务正常停的时候先把名下的读取都关掉并回确认 | 只管正常停，崩溃不管 |
   | 三级 | Linux 上由 root 给出「旧的主进程确实没了」的记录，文档服务据它把旧实例名下的读取记为已关（实例权威里已有 `confirmClosed` 的口子，没接验证方） | 要先有上一块没做完的 Linux root 入口 |
   | 三级 | 同一张证书、同一份本机收口记录文件的新实例，声明前一个实例已死 | 现有设计明确不认这种自述；信任程度其实和它现在自己回的「读取已关」相同，但这是推翻 ChatGPT 的一条裁定 |
   | 二级 | 读取超过一段时间没有心跳就算关了 | 用时限代替证明，任务书不许「以超时报告完成」 |

2. **「一条任务一个进程」接在文档服务组合里的那几行没有被测试直接跑到。** 判断函数在集成测试二里用真子进程验过；但 `doc-agent-assembly.mjs` 里 `completeAccessEvents` 走「先读 root 关闭记录」的那个分支，只在 Linux 上才进得去。原因同上一块的第 3 条。
3. **素材服务被硬结束以后的续办没验。** 它没正常收口就被结束的话，下次启动要 root 给的关闭证明才肯起，Windows 上给不出。测的是「正常停、停着的时候来了退出、再起来」。
4. **浏览器探针没跑。** `scripts/probes/account-password-user-path-probe.mjs` 里有一条检查写的是「网页一定停在正在退出」，确认链接上以后它会失败，所以把那一条改成了「先看到的不能是已退出而接口还没办完；最后两边都是办完」并多截一张图。但这支探针要先 `npm run build`，端口写死在 6680～6689（不在分给我的段里），所以**改完没有跑过**，请主会话跑一次。
5. **网页分不出还差哪个服务。** 文档服务是四样齐了才一起送给账号服务的，所以办完之前账号服务那边四样都显示待确认。具体差谁只在文档服务的日志里有（`logout.diagnostic`，每条退出每种原因报一次）。要让网页显示得更细，得改成有一样送一样。
6. **用户自己点「退出登录」产生的作废事件没单独测。** 它和改密退出走同一条链，照理一样办完。
7. **踢人、删项目、关 Agent 的服务确认没有往下接。** 这三种不经账号服务，文档服务对外仍然回「服务确认中」，没有人把它改成办完。不在这一块的范围里，记一笔。

## 真实附件链

「附件」指云端 Agent 对话里传的附件。账号这条路上它**还不存在**：对话权威记消息时附件一栏固定写空（`server/account/conversation-authority.mjs` 第 230 行），账号模式的对话服务没有传附件的实现（归档 `three-versions-password-user-path-2026-10-09.md` 第 18 行记的是「附件的权威还没接通，接口回 503」；回什么码这次没有重验）。所以退出时没有附件的读取可关，这条链现在是「没有东西可接」。

等附件做出来，要接三处才算进了退出确认：

1. 读附件要像读对话一样在文档服务账本里登记成一条读取（`readControl.open`），这样退出时才清点得到、关得掉。
2. 附件的字节如果走素材服务，就落在素材服务已有的作废事件处理里，不用另接；如果放在 Agent 服务自己的工作目录里，Agent 服务要在回确认之前把正在传的流关掉。
3. 切私有、被踢时「附件清除」那一条走的是同一个读取清点。

## 要用户定的事

1. **网页上的字。**
   背景：改密或重设成功以后，网页分三步说话：密码改好了并问要不要退出别的设备；正在退出；已经退出。
   现状：网页上现在是 ChatGPT 写的三句长话（见「要 VisuHive 改的」那张表）。任务书里用户确认过的原文只有「密码已修改」「正在退出已登录设备」「设备已退出」三个短语。
   要定的：(1) 是不是照这三个短语原样显示；(2) 问要不要退出的那一句和两个按钮上的字，任务书里没有原文；(3) 现在的长话里有一句「本网站会保持登录」，是在告诉用户发起改密的这个网页不会被退出，要不要留。
   建议：三个短语照原文；问句用「要退出已登录的其它设备吗？」，按钮「退出」「不退出」；「本网站保持登录」留一句，免得用户以为自己也要重新登录。这只是草稿。
2. **退出一直办不完的时候网页说什么。**
   背景：如果某个服务一直不确认（比如素材服务停了），网页会一直显示「正在退出」。权限其实已经撤了，旧设备早就用不了，只是「办完」出不来。
   现状：只有「正在退出」这一句，没有期限，也不说差谁。
   选项与后果：甲，保持——最简单，但用户可能一直等；乙，过一阵加一句「旧设备已经不能再使用，剩下的确认还在进行」——更安心，要定字；丙，再细到显示差哪个服务——要改文档服务（有一样送一样），而且对普通用户意义不大。
   建议：乙。
3. **Agent 服务重启时有人开着云端对话页，这些人之后退出显示不了办完**（「没做成的」第 1 条）。
   背景与现状：见那一条。
   选项与后果：甲，这一版先这样，部署 Agent 服务时注意——不用再改代码，但这些人会看到一直「正在退出」；乙，这一版就解决——要等上一块没做完的 Linux root 入口，或者推翻 ChatGPT 的一条裁定。
   建议：甲，记进待办，和 root 入口一起做。

# AGENT-v18-move：账号办法的「本地项目搬到云端」（桌面版）

分支 `claude/v18-move`，从 main 162a72be 建，交活前合过一次 main（f952e969）。端口段 28950～28999。

名词：**账号云端** = 只认网站账号的那个云端节点（`https://visuhive.com`）；**账号项目** = 属于某个网站账号的云端项目；**本机协作房间** = 旧办法在本机开的多用户协作（项目名加密码进入，没有账号）；**占位** = 新建云端项目时带的一份空白项目；**请求号** = 新建接口用来认「是不是同一次请求」的编号，同一个请求号重放不会建出第二个项目；**账号桥** = 桌面外壳里替页面保管登录恢复凭证、代发账号请求的那一段（`desktop/src-tauri/src/account_vault.rs`）。

## 怎么做的

流程本身在 `src/editor/sync/accountMove.ts`（不认识界面和账号客户端，要用的东西都由调用方给，所以每一步都能单测）；接到编辑器上在 `accountMoveFlow.ts`；界面在 `CollabSection.tsx`。

**先云端、后本机**（旧流程是先封锁本机房间再传，失败就把房间变成打不开的）：

1. **核对**。登录了没有；协作房间要以创建者身份进入，并当场核对一次创建者密码（只读，不改东西）；等本机的修改都落定，取一份项目内容；内容超过一次根替换装得下的量就在这里停。
2. **建项目**。`POST /hosted/shared/account/create`，请求体只带占位（探针里 389 字节）。真内容不走这个接口，三个原因：它的上限是 1 MiB；账号桥一次请求也只让过 1 MiB，而且请求体要经一次 PowerShell 的 JSON 转换；同一个请求号重放时内容必须一字不差，而失败到重试之间用户可能又改了项目。请求号、项目名、占位内容先记在本机页面存储里（`localStorage` 的 `pc.account.move`，按「账号 + 本机项目号」存），再发请求。
3. **传内容**。另开一条文档连接（不是编辑器正在用的那条），拿到云端现在的内容，和本机这一份不一样就做一次根替换；超过单次提交上限（256 KiB）的由现成的 `DocSync` 拆成分片上传。传输断了在会话里接续，会话断了重建后补发，访问令牌到期按断线重建。
4. **核对**。再开一条连接把云端的内容读回来（这份是文档服务发回来的，不是本端自己算的），和本机那一份逐字段比。这期间本机又有新修改的，再传、再核对，最多三轮。
   —— 到这里为止，本机的项目文件、房间记录、协作状态一个字都没动；任何一步失败，本机原样可用。——
5. **协作房间才有**：搬的人不在主机那台电脑上时，先把项目引用的素材两档拉到这台电脑（关掉房间之后就取不到了）；然后关掉本机协作，走的是「取消多用户协作」同一条路（`collab.ts` 的 `disableCollab`：删房间、注销云端托管服务上的登记、本机回到普通本地项目）。关的那一下别人刚改过的，补传一次并核对。
6. **进项目**。本机这一份有草稿的存一次（存成协作已关的本地项目）；编辑器接到云端项目上（`enterAccountProject`，现成的）；项目引用到的素材交给现成的上传队列（`queueExistingMedia`）。之后的保存不再写回本机那份草稿。

**失败之后**：云端已经建好的那个项目留着（内容是占位，或上一次传上去的），本机记着它的项目号；再点一次接着用它，不再发新建。新建的回包丢了（请求其实到了云端）时本机只知道「结果不确定」，再点一次用原样的请求问清楚：建成了就接着用，确实没建成才用新名字另起。结果不确定的记录留一小时。

**「云端」指哪儿**：桌面版有账号桥、并且目标地址是账号云端（没填、与账号云端同一个主机、或内置的缺省托管地址及它的 sslip.io 写法）时走账号办法；用户自己填了别的节点，照旧办法（上一块的预检还在）。没有账号桥的环境（开发服务器直接开页面）一律旧办法，所以上一块的测试与探针不受影响。

**在线构建**里这一整段剪掉了（在线页面没有本机项目可搬），守门 `c10a-online-build.test.mjs` 的 `/api` 清单没有变。

## 谁能搬（用户第 2 条：「账号有权操作，不依托设备。」）

**做到的**

- 本地项目：登录了账号就能搬，哪台电脑都一样。真服务测试第 9 步：同一个账号从两台设备各搬一个本地项目，互不相干；另一台设备上的同一个账号直接是创建者。
- 本机协作房间：不再核对「是不是当初开房间的那台设备」（旧流程在本机恢复接口里核对主机绑定，账号办法不经那个接口）。以创建者身份进入房间的人，在哪台设备上都能搬，项目归他当时登录的那个账号。
- 搬的人不在主机那台电脑上时，素材先拉到这台电脑再关房间。**这一条只有单测，没有做两台电脑的端到端**。

**做不到的，和我的处理**

1. **房间里不是创建者的成员不能搬**。本机协作房间没有账号的概念，它唯一认得的「主人」是创建者口令；让成员搬，就等于成员能把别人的房间关掉。处理：成员点「搬到云端」得到一句「只有以创建者身份进入的人能把协作房间搬到云端。」。
2. **旧成员对应不到账号**。房间成员的身份是「用户名 + 设备」，没有办法知道他是哪个网站账号。处理：成员一个都不带，搬完提示把新的项目链接发给他们，各自登录自己的账号重新加入。
3. **创建者自己没有账号就搬不了**；项目归谁，只能是操作的人当时登录的那个账号，不能指定给别人。
4. **关本机协作仍要创建者密码**（这是房间自己的规矩）。这台电脑上存着的不用输；没存的（创建者在第二台设备上）点了之后出现输入框。

## 不随项目上云的东西

| 东西 | 去向 |
|---|---|
| 旧房间的成员、在线连接 | 房间删除时断开。旧成员用新链接、登录自己的账号重新加入 |
| 项目密码、创建者用户名与口令 | 作废。云端按账号认人 |
| 限定进入的名单（用户名加密码） | 不带。云端项目照新建接口的缺省是「知道链接并登录了就能加入」（见「要用户定的事」第 2 条） |
| 邀请码、邀请链接、二维码 | 随房间删除作废 |
| 禁入表（被踢的设备） | 不带。云端的禁入按账号，旧的按设备，对不上 |
| 云端托管服务上的登记与中继、本机保存的房间身份与主机绑定 | 注销（「取消多用户协作」现成的行为） |
| 本机文档服务里这个房间的数据 | 随房间删除（同上） |
| 版本号与操作历史 | 云端是一个新项目：占位是第 1 版，正文是第 2 版 |
| 撤销栈 | 换连接时清空（进任何共享项目都这样） |
| 本机 Agent 的对话、剧本、AI 栏的工具调用记录 | 不在项目正文里，不上云。页面里还在，本机草稿文件里照常保存 |
| 云端 Agent 对话 | 本机项目和本机房间本来就没有 |
| 预渲染的产物（轨道流、快照） | 不搬，云端和各端重新生成 |
| 素材库里这个项目没引用的文件 | 不搬（旧办法是三个素材库整个搬走） |
| 本机找不到文件的素材、补不上哈希的老素材 | 传不上去，用现成的那句气泡列出名字 |
| 渲染任务队列、锁、在场、选区 | 都是连接上的瞬时状态，不搬 |
| 本机那份文件 | 留着，是普通的本地项目（协作已关），不记云端关联。搬完之后的保存不再写回它 |

## 发现的现状问题

1. **（已修）本机协作房间里项目正文一过约 780 KB，保存、取消多用户协作都失败。** 房间里每次保存都要把「离线修改记录」（整份项目内容）写进本机保护存储；Windows 上保护存储是起一个 PowerShell 调 DPAPI，Node 取它输出的上限是缺省的 1 MiB，超了回 `ENOBUFS`，接口回 503「无法可靠读取或保存协作恢复信息」。实验：正文 70 万字符写得进，160 万字符失败。把上限放开之后还有第二处：核对输出是不是 base64 的那条正则带分组重复，输出到几 MB 时把调用栈撑爆。两处都在 `server/recovery/vault.mjs`，一共 8 行；测试 `server/test/recovery-vault-large.test.mjs`（换回旧文件是红的：`ENOBUFS`）。这个文件不在我的任务描述里，但不修的话「本机协作房间带大于 1 MiB 的正文」这一条过不了，所以改了，请主会话审。
2. **（没修）同一处的开销**：房间里项目每变一次就起一次 PowerShell 写一遍整份项目。160 万汉字的项目写加读一次 2.7 秒。大项目在本机协作房间里会明显拖慢。
3. **（没修）账号项目的设置里仍显示旧办法的按钮**：「作废并重新生成邀请码」「改项目密码」「改创建者密码」「已禁入的设备」「删除项目」，以及「这台设备上没有邀请链接」。它们对账号项目不起作用。从开始页新建的账号项目也一样，不是这一块带来的；但紧跟在「旧邀请码已作废」后面出现，容易让人糊涂（见 `local-5-done.png`）。
4. **（没修）新建的账号项目「云端 Agent」缺省是关的**（账本里新建时写的是 `agent: false`），语义 `workflow/project.md` 写的是缺省勾上。搬上去的项目同样是关的。
5. **（没跑，按报错推断）`scripts/probes/account-card-sync-probe.mjs` 现在可能过不了**：它建的那张用户卡没有引用 remotion 式框架，现在的建卡接口会拒（我的探针最初照抄它的卡片源码，被拒了，加一行 `import "../../kernel/remotionStyle";` 才过）。

## 没做成的与原因

- **搬的人不在主机那台电脑上**（创建者在第二台设备上搬）：代码有（先拉素材、再关房间），只有单测，没有做两台电脑的端到端。
- **真的桌面外壳没参与验证**。账号桥是替身；新建请求体经 PowerShell 转一遍 JSON 这一步没验（请求体就是 `createEmptyProject` 的结果加本机项目号，与开始页「新建云端项目」发的同一种形状）。
- **失败后云端留下的那个项目不自动删**。它在网站「我创建的」列表里看得到，内容是占位或上一次传上去的；用户不再点的话就一直留着（一次搬迁最多留一个）。没做自动清理：失败多半是因为连不上云端，那时也删不了。
- **内容超过约 838 万字符的项目搬不了**（一次根替换最多 64 片、每片 128 Ki 字符）。更大的要按路径拆开写，这次没做。
- **上传队列仍是逐个素材传**（每个素材先小后大，一个传完再传下一个），不是所有素材的小尺寸都先传。照现成的队列规矩，没改。
- 提交没有严格做到「每完成一块一个提交」：流程、接线、界面在同一个提交里。

## 裁定〔裁〕

二级（用户看得出区别）：

- 〔裁一〕本机协作房间只有以创建者身份进入的人能搬。理由见「谁能搬」。
- 〔裁二〕设置里选「云端」、目标是账号云端时，表单换成说明加登录状态，不再出现创建者用户名、密码、进入方式；地址填了别的节点才是旧表单。
- 〔裁三〕没登录时就在项目设置里给登录表单，登录成功接着搬，不让用户回开始页。
- 〔裁四〕协作房间搬之前弹一次确认框（会关掉本机协作、断开别人）。本地项目不弹。
- 〔裁五〕搬完时本机那份草稿自动存一次（存成协作已关的本地项目），之后的保存不再写回它。没存过草稿的项目不替用户新建草稿。
- 〔裁六〕失败后云端已经建好的项目留着、不删，再点一次接着用。
- 〔裁七〕限定进入的房间搬上去后，是「知道链接并登录了就能加入」；禁入表不带。
- 〔裁八〕账号办法搬上去的是一个新项目，版本从头计（与语义「切换前后版本号连续，不归零」不同，见下）。
- 〔裁九〕素材上传中用一条不自己消失的气泡提示，传完换成一句「已全部传到云端」。

三级（用户看不出区别）：

- 〔裁十〕新建一律只带占位，正文一律经文档连接写（任务书写的是「超过 1 MiB 时才这样」）。理由见「怎么做的」第 2 步。
- 〔裁十一〕请求号记在页面的 `localStorage`，不进项目文件；结果不确定的记录留一小时。
- 〔裁十二〕核对用另一条连接读回来比，不用上传那条连接自己算出来的结果。
- 〔裁十三〕保护存储的输出上限定为 256 MiB（恢复接口请求体的上限是 64 MiB）。

## 对任务书或语义的更正建议

- `docs/semantics/workflow/project.md`「多用户协作」：「项目设置里另有『搬到云端』『搬回本机』」建议改成：搬到云端是在云端新建一个属于登录账号的项目、内容与本机一致，搬完本机协作关闭、旧邀请码作废，旧成员用新链接登录自己的账号加入；「搬回本机」这一版收起。「等待完成后显示邀请链接与二维码…」那一句只对放本机成立。
- `docs/semantics/product/document-service.md`「部署组合」：「两种之间可以随时搬」「切换前后版本号连续，不归零」在账号办法下不成立（搬上去的是新项目）。
- 同一篇「共享项目与权限」：「云端新建、迁入和加入都核对网站账号」里的「迁入」现在就是「凭账号新建并写入内容」，没有单独的迁入接口。
- 任务书「超过新建接口 1 MiB 上限时先建项目再经文档连接分批写」：实际做法是一律先建再写（〔裁十〕）。
- `docs/reports/AGENT-v18-move-guard.md` 第 9.4 节「素材单件大小限制我没查」：这次也没查，上传走的是现成的分片上传队列。

## 要用户定的事（白话）

1. **界面文字**。上面那张表全是草稿。
2. **限定进入的房间搬上去之后谁能进**。旧房间可以设成「只有名单里的人能进」。云端项目现在只有两种：知道链接并登录了就能进（缺省），或只有账号名单里的人能进；而桌面版还没有「往名单里加账号」的界面。现在的做法是一律按缺省，等于原来限定进入的房间搬上去后，拿到新链接的人登录了都能进。选项：就这样；或者搬限定进入的房间时先拦住、等名单界面做出来。建议先就这样（链接只有创建者手里有）。
3. **被踢过的人**。旧房间按设备禁入，云端按账号禁入，对不上，所以禁入表不带；被踢过的人拿到新链接可以进。建议知会即可，创建者进了云端项目可以再踢。
4. **失败后留在云端的那个项目要不要自动删**。现在不删，再点一次接着用；用户放弃的话它一直留在「我创建的」里。选项：不管；或者在设置里加一个「放弃这次搬迁」按钮把它删掉。建议加按钮，放到下一版。
5. **搬完自动存一次本机草稿**（〔裁五〕）是否合适。不存的话，协作房间搬完后本机那份文件里还记着已经删掉的房间。
6. **账号项目的设置里那些旧办法的按钮**（「发现的现状问题」第 3 条）要不要收起来。

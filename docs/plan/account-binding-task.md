# 账号与云端项目任务书

2026-10-07 用户定。让云端项目一律走网站账号：加入云端项目时由服务器核对账号和密码，账号页的「我的项目」「我加入的项目」有内容；出一个版本、部署、清掉旧的云端项目，然后停下汇报。规则以 `docs/semantics/guide_files/` 为准，本文只写这件事的范围、用户的决定和验收。

用户的先后安排（原话）：「优先把那个部分做出来，发一个版本。之后的延后一个版本。」

## 背景

- 网站账号已经上线：`https://visuhive.com` 能注册、登录、改密码、绑定邮箱、凭邮箱重设密码。代码在另一个仓库 VisuHive（本机 `C:\Users\admin\Documents\VisuHive`，远端 `github.com/Nice9Tian/VisuHive`，私有）。规则与各项数字见那边的 `user_readme.md`，接口与实现见 `docs/accounts.md`。账号服务是新节点上的一个独立进程，只听本机。
- 账号页上两张项目列表的页面和接口已经有了，现在总是空的。本任务把它们接上。
- 现在进共享项目不认账号：自由进入（项目名加项目密码，用户名自报）或限定进入（创建者维护的用户名加密码名单），另有邀请码。见 `docs/semantics/workflow/project.md`「多用户协作」、`product/document-service.md`「共享项目与权限」。
- 托管端在新节点 149.88.94.84，连接办法见本机 `docs/local.md`。新节点上现有 4 个云端项目，其中一个是用户桌面上的 PromptCut 正连着的。
- 四段连做任务暂停着，成果在集成分支 `claude/four-stage`，没进 main；交接在那条分支的 `docs/reports/HANDOFF-four-stage.md`，第 11 节记了账号这件事对它的影响。

## 用户定的（语义照此改写，不用再问）

**A. 云端项目一律走账号。** 加入云端项目时由服务器核对账号和密码。用户原话：「以后加入项目（云端）的时候会从服务器验证账号和密码。」

**B. 旧的云端项目清掉，不兼容。** 用户原话：「云端项目全变。本次清除之前所有的云端项目，不再兼容。」清是删数据：动手前先备份，并当场再向用户确认一次。

**C. 本地项目不用账号。** 放在创建者电脑上的项目继续走自报 ID，或创建者定义的白名单，现有规则一条不改。云端托管服务照旧给本地项目做登记、牵线和中继。用户原话：「只有项目（PC）允许自己声明ID或者定义用户白名单。」「云端服务继续担任本地项目的转发。」

**D. 账号绑定两张列表**：「我的项目」（我创建的云端项目）、「我加入的项目」（我加入的云端项目）。本地项目不进这两张列表。

**E. 踢人对账号生效。** 被踢的账号从任何设备都进不来。

**F. 旧文件自动回到本机。** 用户原话：「加一个用户双击旧版本云端项目设置的Proc文件自动回退本地主机。」

**G. 账号本身的规则**（已上线，不在本任务里改）：账号名全站唯一、注册后不能改；注册只要账号名和密码；邮箱是推荐、非必须的绑定项；没绑邮箱的账号忘了密码找不回。

## 等用户定的（不答就按缺省办）

1. **这个版本的底。** 缺省：以集成分支 `claude/four-stage` 现在的成果为底，加上本任务，出 0.7.18；第四段没做完的云端 Agent 工具延到下一个版本，发版说明里逐项写明哪些工具还没有。理由：加入项目的鉴权在那条分支上改过很多，在旧的 main 上做，以后合并时这一块要重做。
2. **这一版怎么登录。** 缺省：加入云端项目的表单里直接填账号名和密码，托管端去问账号服务核对；桌面版和在线版一样。在网站上登录过，进编辑器时仍要再填一次；同一台设备之后重开这个项目不用再填。把编辑器搬到 visuhive.com 的子域名、网站与编辑器共用登录状态、桌面版跳浏览器登录，都延到下一个版本。
3. **F 的意思。** 缺省按这样理解：新版本打开一个旧的云端项目文件，云端已经没有这个项目了，就自动按「搬回本机」办——用文件里存着的那份内容，由本机做主机，多用户协作保持勾上，并明确提示一次「这个项目原来放在云端，云端的那份已经不在了，现在放在这台电脑上」。要再放回云端，登录账号后在项目设置里「搬到云端」。
   - 后果：每台拿着旧文件的设备各自得到一份独立的本机项目，互相不再同步；文件里那份内容可能比云端被清之前的旧。清之前创建者最好先在桌面版里把项目「搬回本机」，那样拿到的是最新的。
4. **和在线浏览器任务书的关系**（2026-10-07 已处理，不用再定）。`online-browser-task.md` 第一步原来写浏览器里新建云端项目「缺省自由进入、现在一律放行」，与 A 冲突；那份任务书已改成「新建之前要先登录账号、项目归账号」，并写明账号怎么核对由本任务做、它不重做。那份任务书还没有会话开工，`claude/online-browser` 这条分支现在不存在。
5. **什么时候开工。** 周额度规则（到 90% 不再派子 Agent）到 2026-10-12 重置前有效，写本文时是 89%。本任务要好几路子 Agent。用户放开就现在开工，不放开就等重置。

## 分几步做

每一步做完就提交、做这一步的轻量验收、在对话里贴证据，然后接着做下一步。

1. **设计与契约，语义对照。** 定清下面「设计时要定清的」各条；把「语义改动」一节的每一行写成确切的修改前、修改后文字。语义在这一步就写进分支。
2. **账号服务加两个口**（VisuHive 仓库）：给托管端用的核对口（账号名加密码 → 账号编号；只有同一台机器上的托管端调得到，页面调不到）；记录与查询「谁创建了哪个云端项目、谁加入了哪个云端项目」的口。账号数据加每天一次的自动备份。
3. **托管端**：云端项目的加入改成核对账号；把项目放到云端（新建、搬到云端）要先登录，项目归这个账号；创建者特权凭账号行使；踢人按账号；云端 Agent 对话的归属按账号。本地项目的登记、牵线、中继不变。
4. **编辑器（桌面版与在线版）**：云端项目的加入表单改成账号名加密码；放云端之前要求登录；相关提示与出错文案。本地项目的界面不变。
5. **旧文件回到本机**（F）：桌面版打开旧的云端项目文件时的处理与提示。
6. **网站**：两张列表显示内容，每一项能点进编辑器里的那个项目。
7. **完整验收、发版、部署、清旧项目**：见下文「做完的标准」与「规矩」。

## 设计时要定清的（写进契约；拿不准的列给用户）

- 托管端与账号服务之间凭什么互相信任。可以沿用第三段的托管方服务身份那一套，也可以用只在本机回环上可达加一份共享密钥；选一种，写明为什么。
- 账号服务暂时不在（重启、出错）时，云端项目的加入怎么表现；已经在项目里的人不受影响。
- 设备上存什么。不存账号密码；存的恢复凭证在账号改密码、被踢之后怎么失效。
- 账号名在项目里怎么显示。项目里认人认账号编号，不认名字。
- 邀请码在云端项目上还剩什么作用（缺省：只代替「知道是哪个项目」，账号和密码照填）。
- 限定进入的名单在云端项目上改成什么（缺省：名单里放账号名，不再另设一套用户名加密码）。
- 旧版本客户端（0.7.17 及更早）连到新的托管端时看到什么。

## 做完的标准

1. 设计与契约先写好再动手；语义照上表改完，凡是原来写「自由进入」「限定进入」「创建者用户名和创建者密码」的地方都分清了本地项目与云端项目。
2. 云端项目的加入：账号名和密码都对才进得去；任何一项不对都进不去，并且「账号不存在」和「密码不对」回同一句话。桌面版和在线版都验。
3. 借加入项目猜密码，和在网站上猜密码算在同一组限次数里，超了被挡。
4. 没登录不能把项目放到云端（新建、搬到云端都验）；放上去之后项目归这个账号。
5. 同一个账号在两台设备上进同一个云端项目，被认成同一个人；第二台设备不用别的凭证。
6. 创建者凭账号改设置、删项目、踢人；不是创建者的账号做不了。
7. 踢人：被踢的账号从原设备和新设备都进不来，正在连着的连接被断开；别的成员不受影响。
8. 账号页两张列表：创建和加入之后各自出现对应的项目；被踢、项目被删之后消失；别人的列表里看不到我的项目。每一项能点进那个项目。
9. 账号改密码之后，别的设备要重新填密码才能再进云端项目。
10. 账号服务停掉时：云端项目的新加入明确报「账号服务暂时不可用」，已经在项目里的人照常编辑；本地项目完全不受影响。恢复后不用重启别的服务。
11. 本地项目一条不退步：自由进入、限定进入、邀请码、创建者特权、局域网直连、经云端牵线与中继，照现有探针全过；全程不需要账号。
12. 旧文件（F）：用旧版本存下的云端项目文件，在云端已无此项目时，新版本打开后自动成为本机做主机的项目，内容是文件里那份，提示出现一次，之后保存、重开都是本地项目，不再去连云端；文件里没有可用内容时明确报错并保留原文件。桌面版双击文件与在软件里打开都验。
13. 旧版本客户端连新的托管端：云端项目明确提示要升级，不是莫名其妙的失败；旧版本做主机的本地项目经云端牵线与中继照常能用。
14. 云端 Agent 的对话按账号归属：换设备登录同一个账号看得到自己的对话，别的账号看不到。
15. 核对口只有托管端调得到：从公网、从在线页面、从同机别的用户进程都调不到或被拒。
16. 密码、会话、验证码不出现在任何日志、提交、报告里；设备上不存账号密码（查落盘的文件）。
17. 账号数据每天自动备份一次，能用备份恢复出账号（在测试副本上验）。
18. 基线全绿（按 `guide_files/verification.md`）；VisuHive 仓库的 `npm test` 全过。四段成果的完整验收在最终提交上重跑，已过的项不退步。
19. 发版：按 `git_and_release.md` 出 0.7.18 与补丁；`release` 判过后推进。发版说明写明：云端项目要账号、旧云端项目已清、旧文件会回到本机、云端 Agent 还缺哪些工具。
20. 部署到新节点并实测：用测试账号把第 2～10 条在真实部署上走一遍，验完删掉测试账号与测试项目。
21. 清旧项目：先把 4 个旧项目整体备份到节点上另一个目录并记下位置，列给用户看，用户当场确认后再清；清完用一份真的旧文件验第 12 条。备份保留到用户说可以删。
22. 文档收尾：`TODO.md`、VisuHive 的 `docs/accounts.md` 与 `user_readme.md`、本机 `docs/local.md`。

## 没过怎么办

- 小问题在分支上修掉、补测试、继续。按 `guide_files/solution_table.md` 试过仍不过的非核心项，记未达成，不挡合入。
- 核心项不过就不发版、不部署、不清旧项目，停下告诉用户：第 2、3、6、7、15、16 条任何一条不过；第 11 条本地项目退步；第 12 条旧文件打不开或丢内容。
- 部署后出问题：托管端与在线页面退回上一版；旧项目的备份还在，可以放回去。
- 改动若碰到本文没列的用户可见行为，当场列一条给用户，不攒到报告。

## 规矩

- **清旧项目、重启新节点的托管服务之前，先确认没有正在写入的客户端**：用户桌面上开着的 PromptCut（端口 5210）正连着其中一个旧项目。只许对 `http://127.0.0.1:5210/api/agent/status` 与 `/api/media/upload-queue` 做只读查询，等对话不再提交、上传队列空闲、项目版本连续 5 分钟不变再动；等满 3 小时仍在写，就停下告诉用户。
- 不碰用户在跑的东西：端口 5190～5192、5210～5212、用户装的 PromptCut 及其数据目录、不是自己启动的进程。测试进程静默运行，起子进程带 `windowsHide: true`。
- 新节点是在用的生产环境：验证只用测试账号与测试项目，验完删掉；改动前先备份。阿里云不碰。防火墙与系统安全设置不改。
- 令牌、密钥、密码的值不打印、不进提交、日志或消息。发信配置在节点的 `/etc/visuhive/smtp.env`，只读不抄。
- 子 Agent：日常用 `sonnet-dev-high`，核心难点用 `opus-dev`。托管端核对账号、设备上的凭证、核对口的隔离这三块用 `opus-dev`。
- 写 main、发版、部署、清旧项目各自要用户授权；用 `/goal` 设了目标的，以目标里写明的为准。

## 用户要知道的

- 这一版在网站上登录和在编辑器里进项目是两次输入，下一版才打通。
- 清掉之后，旧的云端项目只剩各人手里的文件和节点上的备份。清之前先在桌面版里把自己要留的项目「搬回本机」，拿到的才是最新内容。
- 云端项目从此依赖账号服务：它停了，新的人进不来。所以这次给它加了每天的备份；它的监控和自动重启只有 systemd 那一层。
- 账号没有「注销」功能，也没有管理页；要删某个账号得登录服务器手动删。
- 发信用的是 163 邮箱的个人 SMTP，有每日上限，发件人显示为那个邮箱地址。

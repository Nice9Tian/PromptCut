## 已拍板

- **账号与项目记录分工**：账号服务负责账号、密码、账号会话；**云端文档服务**记录云端项目是否存在、创建者、成员、禁入及项目状态。托管服务负责入口、牵线和中继，不成为第二套项目账本。网站两张项目列表向云端文档服务查询，服务不可用显示“暂时无法获取项目”，不得用空列表代替故障。
- **云端项目一律验网站账号**：新建、搬到云端、加入都需要账号；账号编号是身份依据，名称用于显示。桌面和在线浏览器均做。账号密码不落盘；每台设备之后重开可用可撤销的恢复凭证。
- **登录几次（2026-10-08 用户定）**：桌面版在编辑器里输一次账号密码，之后本机保存可撤销的恢复凭证，同一台电脑不用再输。在线浏览器不用另外登录，和官网共用登录（同一个域名下的 cookie）；下次打开还在不在，看登录时有没有勾「记住登录状态」。原写的「网站与编辑器分别输入账号、共享登录延后」作废；桌面版跳到浏览器里登录仍延后。
- **在线浏览器的地址**：`https://visuhive.com/editor/`（2026-10-08 用户定，当天已在节点上接通：官网的 nginx 站点里加了 `/editor`、`/hosted`、`/media`、`/catalog/`，与原地址 `149-88-94-84.sslip.io` 是同一份文件、同一组服务，原地址照常可用；舞台仍在 `s1`、`s2.149-88-94-84.sslip.io`）。共用登录本身还没做：文档服务怎么认官网的登录、cookie 的范围，在契约里落清。
- **进入权限**：云端项目“任何知道链接的人都可加入”默认勾选，仍须登录；取消后只允许账号名单中的人；被名单挡住的人可以点「发送申请」，创建者在名单界面的申请列表里点「通过」把他加进名单（2026-10-08 用户新增，0.7.20 做）。被踢账号从任何设备均被拒，当前连接及其旧用户授权失效；已读共有 Agent 当前任务按下述例外保留，不恢复该账号的访问权限。
- **云端 Agent 对话权限（本轮新拍板）**：支持共有/私有，新建默认共有，用户可主动设为私有。共有允许同项目所有已登录且有项目权限的成员查看完整历史、回复并发送；私有只允许所属账号。每条消息记录实际发送者；每轮只核对实际发起者是不是这个项目的有效成员，Agent 能做的事对所有成员都一样，不分创建者与参与者，只读成员不能操作 Agent（2026-10-08 用户定）；对话归属不能等同全部消息作者。不是仅私有对话，也不对匿名或项目外账号开放。
- **Agent 已读消息撤回例外（本轮新增并扩大到被踢）**：因改密选择退出或被踢时，已经发送并被 Agent 读到的消息不撤回，保留原文和实际发送者。私有 Agent 任务直接中止；已读消息触发的共有 Agent 当前任务及其修改保留、不撤回并继续执行。只已发送但 Agent 未读不自动满足例外；旧用户凭证或被踢账号仍不能发新消息、发起下一轮，被踢账号不能查看对话。任务例外不扩大到项目删除或关闭 Agent。
- **本地项目不用账号**：原有自报身份、白名单、邀请、创建者权限、局域网、牵线与中继保持。新增的保存和暂时离线处理按本轮确认的行为做，不改变本地身份规则。
- **过期云端项目转本地**：只在可信云端文档服务确认准确原项目不存在或已清理时触发。使用文件里保存的内容，不补造保存后只留在云端的修改；转后默认关闭“多用户协作”，用户需要时手动打开。
- **暂时离线项目**：超时、故障或连错节点都不证明项目过期。保留原云端关联和离线改动，下次打开/重连检查是否落后，询问是否发送离线改动；可能覆盖云端期间改动时提供可视化冲突处理。
- **缺失素材**：窗口提示具体缺失项；对应视觉内容用文字卡“找不到素材xxx”占位；缺失音频用提前做好、随软件分发的人声“找不到素材”占位，不存进项目（2026-10-08 用户更正；文件已做好，见契约「缺失素材占位」）。原素材信息保留以便找回，不能悄悄丢掉原引用。
- **保存状态**：非本机内容保存某一确定状态，记录哈希、时间及可定位的版本；本机暂时禁用前台编辑，等待本机写入完成后保存。不以整个云端长时间无人修改作为普通保存的前提。
- **改密界面**：先播放密码修改动画，成功显示“密码已修改”；再询问是否退出已登录设备。选否保留现有设备云端登录和写入权限；选是显示“正在退出已登录设备”，相关服务确认完成后才显示设备已退出。它取代旧的改密强制全部退出决定。
- **邮箱重设密码**：邮箱重设密码（忘记密码）和改密码内部是同一套逻辑，只是界面上的说法不同：重设之后同样问是否退出已登录设备，用户有权不退出；选了退出，后面的处理与改密码一样（2026-10-08 用户定；原写「邮箱重设一律撤销全部旧登录、不套用可选流程」作废）。
- **改密延迟处理区间**：选是时，撤回“改密码绝对时间至旧凭证账号下线”这段时间的旧凭证修改。账号服务通知携带权威改密时间；文档服务须识别操作归属，保护其他账号和本账号重新登录后的合法修改。撤回按修改项逐条核对（2026-10-08 用户定，规则全文见 `docs/semantics/product/document-service.md`「冲突」）：某一项之后被别人又改过算冲突。因改密码或重设密码选了退出而触发的撤回，不冲突的撤、冲突的不撤，不弹窗口；用户按撤销按钮，不冲突的直接撤、冲突的弹出窗口由用户决定。区间已定，跨服务时钟、完成点和补偿机制尚待设计，不盲目回滚整个项目。
- **范围与路线（2026-10-08 用户改定）**：分三个版本逐步完成，各版本做什么见下一节；每个版本各自按它的最终提交验收、交付。第四阶段未完成的云端 Agent 工具并入 0.7.18。仍用 Tauri，Electron 迁移已取消。原写的「在线浏览器先做，账号随后接通，最后按同一最终提交验收」「第四阶段未完成的云端 Agent 工具不混入本期」作废。
- **费用**：本任务不采用周额度 90% 的临时限制；既有资源按已授权范围使用，新增费用遵守仓库规则，不自动购买、升级或无限付费重试。
- **旧项目清理意向**：沿用此前已确认的旧测试项目清理范围及“不另加一次当场确认”的决定。它不构成本轮删除授权；实施授权、备份恢复验证、准确删除清单仍须写入定稿。

## 行为、数据与契约

1. 云端文档服务维护项目创建者、成员、禁入和存在状态。账号服务不复制一套可独立修改的项目关系；网站缓存不能授权或证明项目已删。
2. 跨服务创建、撤销、查询和补偿须有幂等操作编号、持久结果与重启续办；创建失败不得留下可访问的半成品。撤销确认后旧用户凭证与票据不能继续使用；私有任务中止，改密选择退出或被踢时的共有已读当前任务按上述例外继续，保留仅该任务所需的授权，不复活旧用户登录或被踢账号的项目权限。
3. 账号服务故障：新的云端登录/创建明确报不可用，已有连接原先继续编辑的意向保留；选择退出的改密事件迟到如何撤回修改，须按最终撤回契约处理。本地账号无关路径不受影响。
4. 文件保存哈希与时间只是状态标识。须同时保留基准内容或可回取的历史版本、未提交改动及素材引用；不依靠时间戳猜哪份更新，不直接用旧根覆盖当前云端项目。
5. 保存时“冻结”指固定非本机内容的一份确定快照，不是要求所有云端客户端永久停写。快照之后云端的修改留在后续版本中，下次打开提供落后提示及合并/冲突窗口。
6. 缺失素材与暂时读取失败分开：无法确认素材缺失的超时/未授权先报原因，不据此破坏原引用。缺失占位本身必须能保存、重开、播放并随项目发布。
7. 过期转换不得借用旧云端身份开新的共享房间；转后默认本地独立且协作关闭。新保存更新位置状态；原输入文件在成功另存/保存前保留。
8. 文件损坏条目标注：**需要复核各种不同细节情形**。具体细节至少包括截断、旧格式、未知版本、坏关联、部分可读、缺卡/缺素材、落盘中断及本机存储不可用。

## 两仓库交付、部署与回退

- VisuHive 推 main 后，定时器约每 5 分钟自动同步整个 `site/`，含删除；账号后端、nginx 与部署脚本仍须手动安装。**先提交向后兼容后端且不发布依赖新口的网页，手动安装并核对后端，再接 PromptCut 服务/客户端，最后放出依赖新口的 site。** 不能先推网页再等手装后端。
- 数据库变更需版本标识、备份和旧后端兼容/恢复路径；不可用未验证的旧程序直接打开新结构。部署记录同时列两仓库 SHA、数据库状态和在线构建来源。
- 产品交互验收在合入/发版前；真实网络环境验收在部署后；实际旧文件验收在旧项目清理后，三关各自有结果。
- 完整安装包与补丁都需要，来源与证据分开。应用目标依次是 0.7.18、0.7.19、0.7.20；三个版本每个都出完整安装包与补丁（2026-10-08 用户定）。Tauri 壳是否需要升级由兼容证据决定，不引入 Electron。
- 回退保留旧账号后端、托管组合、网页/在线构建及数据快照。网站自动同步必须配套处理：受控恢复旧 site 或兼容修复提交，防止下一轮自动更新再次覆盖；具体线上操作须获授权。
- 后端/网页/数据库回退按兼容组合执行。凭证撤销记录不能因回退复活，离线改动和新增账号数据不能被静默丢弃。清理后需恢复旧项目时，用已验证备份恢复准确项目，重新核对身份/入口和文件读取。

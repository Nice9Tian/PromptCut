## 做法与验收节奏（2026-10-06 用户改定；与下文冲突时以本节为准）

本文三段加 `cloud-agent-task.md`，共四段，**作为一个目标连着做完**，顺序：声音 → 在线执行用户卡与图卡 → 云节点渲染服务 → 云端 Agent。

**过程中只做轻量验收。**

- 每段一个分支与 worktree，做完按顺序 `--no-ff` 合进同一个集成分支 `claude/four-stage`（从最新 origin/main 出发）。
- 每段只验改动影响到的部分：类型检查与全量测试（都很快，照跑）；与这一段改动直接相关的单测与探针；需要托管端的用本机隔离的托管组合，不用生产节点。
- 下文各段里写的这些动作**全部挪到最后**，过程中不做：合入 main、改版本号、打补丁、换新节点的在线页面、部署到新节点、在新节点上的实测、完整的渲染附加项、笔记本的耗时复核。
- 每段做完：提交、写这一段的小结（做了什么、轻量验收的结果、留到最后验的清单）、播报一次，不停，接着做下一段。
- 某一段的核心项不过（见「没过怎么办」）：这一段不合进集成分支，写明原因；后面不依赖它的段照做。

**最后做一次完整验收。** 四段都处理完之后，在集成分支的最终提交上：

1. 整套基线：类型检查、全量测试、构建；完整的渲染附加项（导出确定性、快照重放、与 main 的像素比对 0 差异、预渲染探针）；仓库里现有的全部探针（主计划第 8 节）。
2. 本文与 `cloud-agent-task.md` 里列的**每一条验收**逐条过一遍，包括过程中留到最后的那些。 `cloud-agent-task.md`「用户体验验收」那一节（创建者发出 Agent 任务后关掉软件，一切照常运转）是整件事做成的标准，要在新节点上用真实部署走通。
3. 带耗时门槛的项在笔记本上复核（`guide_files/verification.md`「性能基准机」）；笔记本不在线就记「待笔记本复核」，不挡。

5. 再动新节点，顺序是：换在线页面 → 部署渲染服务 → 部署 Agent 服务（都从 main 的那个提交出，改动前备份，重启托管服务前按「规矩」等写入停止）。每部署一样，就做任务书里要求在新节点上做的那几条实测。模型 Key 这时由用户录入，录入前用模拟模型提供方验。
6. 新节点上哪一样实测不过，就停掉那一样的进程或把在线页面退回上一版，其余保留，写明原因。
7. 写一份总报告（四段的结果、〔裁〕清单、没过或没做的项、补丁信息、样本路径、待用户项），播报后停下。

## 用户定的四处改动（语义照此改写，不用再问）

**A. 导出时自动生成声音（第一段）。** `product/rendering.md`「有声动效卡」改为：导出开始时，先把所有未生成、缺失或过期的声音生成好，再开始出画面；生成进度算进导出进度，取消导出同时取消生成；只有某段声音确实生成不出来时才失败，并说明是哪个片段。预览时未生成的声音仍然提示。桌面导出与在线浏览器导出都照此办。

**B. 在线浏览器可以合成声音（第一段）。** `product/platforms.md`「卡片声音的平台边界」改为：在线浏览器可以自己合成声音，和画面一样按轻重区分——判轻的在浏览器里合成，判重的用已有产物、没有就交给渲染节点；测量合成耗时的时候静音，不出声。第一段只做内置的提示音、键盘声、内置有声卡；用户卡与图卡的声音随 C 在第二段放开。轻重判定、测量与记录沿用画面那一套机制，数字写进 `mechanism/`，标〔裁〕。

**C. 在线浏览器执行用户卡与图卡（第二段）。** `product/platforms.md` 改三处：

- 「这台设备跑不了用户卡、图卡的代码」一类的表述改为：在线浏览器可以执行经文档服务同步来的用户卡与图卡，画面和声音都算，和内置卡一样按轻重区分——判轻的在浏览器里跑，判重的用预渲染结果、没有就交给渲染节点。图卡要的素材原尺寸经素材服务凭票据取。
- 它们只在隔离环境里执行，拿不到项目凭证与票据（图卡取素材用的那张票据由宿主代取，不交给卡片代码）。转译失败、引用了在线页面里没有的模块、或这台设备的图形能力不够时，退回现在的做法（贴预渲染结果、发补渲、显示「需要本地 PC 渲染辅助」）。
- 「渲染节点」表里纯浏览器一行去掉「一期只限内置卡片」：用户卡、图卡的任务也可以认领；「只认领当前登录用户自己产生的」「不需要本机转码」两条不变。

保持原样：低内存档不预渲染、不当渲染节点。

**D. 托管方的渲染身份（第三段）。** `product/hosting.md` 与 `product/platforms.md`「渲染节点」补：云节点上的渲染服务是托管方自带的渲染节点，自动为放在这台节点上的所有项目服务，不用逐个配置项目凭证。它只有渲染身份：能读项目和素材、能写预渲染产物，不能改项目内容、不在成员名单里；成员列表里显示为托管方的渲染节点。项目创建者可以在项目设置里关掉它（一级：`workflow/project.md` 加这一项开关，缺省开）。放本机的项目不受它影响。认证办法、并发上限、资源上限写进 `mechanism/hosting.md`，标〔裁〕。

    - 手机仿真的低内存档打开一个含重卡的项目，补渲任务被云节点的渲染服务认领、产物贴上；
    - 在线普通档把判重的层交给渲染节点，云节点接了、结果贴回；
    - 含用户卡、图卡的任务它能渲（第二段之后的规则）；托管方渲染服务执行项目带来的卡片代码时按项目隔离，隔离同样用「越权探测卡」验收：读不到别的项目的内容与素材、读不到节点上的凭证与令牌、访问不了工作进程自己的本机接口、读不到工作目录以外的文件。**这一项是「关掉软件照常运转」的一部分，不因为缺验收夹具而退成不接用户卡任务**（2026-10-06 用户定）；
    - 新建一个项目，不做任何配置它就开始接活；创建者关掉开关后它不再接这个项目的活；删项目后它断开；
    - 它不能改项目内容：用它的身份提交一次编辑，被拒；
    - 渲染服务进程被杀后自动拉起并恢复接活；节点重启后自动起来；
    - 满载渲染时，同机文档服务的响应时间与素材下载速度的前后对比，写明数字；
    - 资源上限生效：超过并发或内存上限时的表现。
24. 语义按 D 改好；`hosting-migration.md` 补上渲染服务的迁移与重建步骤；`docs/local.md` 记新节点上多出的进程与目录；`draft_cloud-node-and-agent.md`「步骤 1」「步骤 2」标为已完成并写明出处，「步骤 3」不动。
25. 客户端有改动（D 的开关）就合入 main、出 0.7.20 与补丁、在线页面换成同一版；只有服务端改动就不出客户端版本，写明新节点上跑的是哪个提交。release 判过并推进。写第三段的报告；播报后停下。

## 越权探测卡

隔离验收用的测试夹具，只在测试环境里用，不进卡片库、不随发版。它是给我们自己的隔离做验收的防御性测试，不是攻击代码：

- 它是一张普通的用户卡（或图卡），在自己的代码里逐项**尝试**读取本不该读到的东西，并把每一项「读到了 / 被拒了 / 报了什么错」记进一个结果对象，由探针取回来断言。
- 尝试的项目是固定清单：页面上的全局对象里有没有凭证、票据；`localStorage`、`sessionStorage`、`indexedDB`、`cookie`；父页面与同源的别的窗口；向本机回环地址与工作进程自己的接口发请求；向一个测试专用的外部地址发请求；在 Node 一侧处理时读工作目录以外的文件。
- 探针事先在这些位置放好**只属于测试的假凭证**（一眼能认出的占位字符串），断言探测卡一个都没带回来。不使用任何真实凭证、真实项目、真实外部地址。
- 它不做任何破坏：不删、不改、不占资源、不绕过浏览器或系统的安全机制，只读、只报告。

写不出这张卡不算「做不稳」：它是验收夹具，缺了就补，不因此把被验收的功能退掉。

## 没过怎么办

- 小问题在分支上修掉、补测试、继续。按 `guide_files/solution_table.md` 试过仍不过的非核心项，记未达成，不挡合入。
- **第一段的核心项**不过就不合入、停下告诉用户：桌面预览听不到声音；桌面导出的成片没有声音；导出时自动生成不工作；默认参数的打字动画画面与 main 不一致；不含声音的项目导出画面与 main 不一致；tsc、npm test、构建任一不过。B 若做不稳，可以只交付已稳定的部分，其余记未达成。
- **第二段的核心项**不过就不合入第二段、停下告诉用户，0.7.18 保持现状：安全验收任何一条读得到凭证或票据；隔离做不到；桌面导出像素有差异。功能上做不全的（比如某类引用不支持、图卡的某种输入在线跑不了），记清楚范围，可以先交付能跑的那部分。
- **第三段的核心项**不过就不部署到新节点、停下告诉用户，前两版保持现状：渲染身份能改项目内容或能读到不该读的东西；本机演练不过；会拖垮同机的文档服务或素材服务。部署后出问题就先停掉渲染服务进程，托管服务恢复到部署前的提交，再查。
- 第二段没做成的话，第三段照做，只是「含用户卡、图卡的任务」那一项按当时的规则验。
- 改动若碰到本文没列的用户可见行为，或要动低内存档的现有规则，先停下问用户。

## 规矩

- **重启新节点的托管服务之前，先确认没有正在写入的客户端**：用户桌面上开着的 PromptCut（端口 5210）可能正在编辑放在新节点上的项目。只读查询 `http://127.0.0.1:5210/api/agent/status` 与 `/api/media/upload-queue`（不发任何写请求、不动这个软件），等 Agent 对话不再提交、上传队列空闲、项目版本连续 5 分钟不变再重启。等满 3 小时仍在写，就停下告诉用户。等的时候先做别的。
- 不碰用户在跑的东西：端口 5190～5192、5210～5212、用户装的 PromptCut 及其数据目录、不是自己启动的进程。对 5210 只许上面那两个只读查询。测试进程静默运行，测试期间不向扬声器出声。
- 新节点是在用的生产环境：验证只用测试房间与测试凭证，验完删掉；第一、二段除了换在线页面的静态文件不动它；第三段按第 22 条的顺序动，改动前先备份。阿里云不碰。
- 令牌、密钥、密码的值不打印、不进提交、日志或消息。
- 子 Agent：日常用 `sonnet-dev-high`，核心难点用 `opus-dev`（主计划 0.2 节）。安全隔离、转译接入、图卡的在线执行、托管方渲染身份这四块用 `opus-dev`。
- 每一条验收的证据直接贴在对话里。收尾汇报列出：三段的结果、没过或没做的项与原因、各补丁的信息、样本路径、要用户做的事。

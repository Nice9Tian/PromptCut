## 2. 普通档的两个舞台（D1）

- **语义**：「舞台有两个」（`mechanism/rendering.md`）；在线普通档「暂停后照常追到精确活渲」、后台舞台在闲时兼做渲染节点（`product/platforms.md`）。C10a 为 demo 只开了一个同源舞台（c10a-contract.md 第 8.1 节），普通档在这里补齐。
- **舞台源**〔裁〕：两个舞台 A、B 各用一个源，与编辑器页**同站跨源**，编辑器页与两个舞台页的响应都带 `Origin-Agent-Cluster: ?1`。这与桌面版「同主机不同端口 + OAC」（`docs/archive/restructure_planning/g0-a-webview2-probe.md`）同理：同站跨源本身不进独立进程，加 OAC 才进。
  - 部署（阿里云）：用子域 `s1.<主机>`、`s2.<主机>`（现为 `s1.8-219-80-16.sslip.io`、`s2.8-219-80-16.sslip.io`），走 443，不开新端口、不动防火墙；证书用 certbot 扩展，免费。nginx 在这两个子域上提供 `/editor` 的舞台页与 `/media` 反代（舞台读素材对自己同源，不需要 CORS）。
  - 本机开发与探针：同主机不同端口加 OAC，与桌面版一致。
  - 页面取舞台源：部署时写进在线构建的运行配置（`deploy-hosted` 新增 `--stage-origins`，写进 `/editor/` 的配置），页面读不到或舞台握手失败时退回 C10a 的同源单舞台，不许开不出画面（沿用 `dualStage()` 的兜底原则）。
  - 探针 P1 已证（第 15 节）：子域与换端口表现相同；三方都带 OAC 时主文档与可见舞台长任务都是 0、主文档 rAF p95 保持基线，两个舞台各成独立的 iframe 目标；不加 OAC（含同源）每 6 秒 22～44 个长任务、rAF p95 150～345 ms。判断是否隔离看 iframe 是否成了独立目标，**不看** `window.originAgentCluster`（Chrome 152 不带头也报 true）。
- **低内存档**：仍是单舞台，不开后台舞台（C10a）。
- **IndexedDB 分区**：舞台跨源，各自的 IndexedDB 与编辑器页分开（探针 P3 已证）。页面内快照库（第 4 节）只由编辑器页读写；舞台的产出（快照、测量结果）经舞台 RPC 交编辑器页。**大块产出**（例如一帧 HTML 快照）由舞台压缩成可转移的 `ArrayBuffer` 交出，不直接传大字符串（探针里直接传 2 MB 字符串让父页掉了一帧 66 ms）。
- **舞台读素材**：舞台一律用相对地址读自己源上反代的 `/media`（探针 P4 已证：这样 Range、Bearer、媒体元素与 canvas 在去掉全部 CORS 头时照常，Bearer 请求不需要预检）。不从舞台跨源直读素材服务：要靠 CORS，且 `src/` 里媒体元素都没设 `crossOrigin`，跨源载入的媒体画进 canvas 会污染它、`toDataURL()` 抛 SecurityError。
- **票据**：舞台读素材用的只读票据由编辑器页经 RPC 下发（沿用 C10a 的票据来源与 `?t=` 读法）。
- **后台舞台的摆放与节拍**〔裁：探针 P2〕：
  - 后台舞台留在视口里原位叠放、`opacity: 0`（与桌面一致）；不移出屏幕、不用 `visibility: hidden`（那两种被节流到每秒约 0.4 次 rAF，移出屏幕时定时器也只剩每秒约 3.6 次）。
  - 后台活（测量、暂停后的追活渲，以及 M7 的认领）由编辑器页判空闲（父页不透明，它自己的 `requestIdleCallback` 正常），经 RPC 发开始、停止；舞台里逐帧用 `setTimeout(0)` 推进、帧与帧之间查停止标志。**舞台里不用 `requestIdleCallback` 定节拍**（`opacity: 0` 的舞台里多半等到超时才回调，每秒只推进 1～4.7 帧）。
  - 页面隐藏时由页面自己停（浏览器不会替你停：探针里无头切标签仍每秒 1.2～2 帧、有头最小化仍 24～27 帧）；另加一道兜底：编辑器页的 rAF 间隔持续超过约 500 ms 时暂停后台活。
- **宿主能力表**：在线普通档开了后台舞台，`hostCapabilities` 照实报（能测量、能追活渲）；`prerender`（有没有预渲染进程）仍为假。页面按能力分支，编译期 `ONLINE` 只用于构建与 `/api` 守卫（`mechanism/platforms.md`「只按宿主能力分支」；S6）。

## 3. 测量与成本记录（K1 在线，D11）

- **普通档**：打开项目时在加载遮罩下，把 L2 里没有成本记录的卡在后台舞台测完才进入编辑；之后新加的卡在后台舞台里测（`product/rendering.md`「测量」）。`ProbeGate` 在线恢复。
- **成本记录**：`mode=build`（在线构建），按卡片身份与本机环境指纹为键写进 L2 的 `costs` 表；关掉再开，已有记录的卡不再测（与桌面「页面见到已有记录就不再测」一致）。
- **轻重分派**：页面按自己的成本记录判轻重（K2）。层表（渲染节点写的 `layers:<项目 id>`）只回答「这一层有没有别人的预渲染结果可取」。页面判重、层表里没有的层：播放时按兜底顺序占位，暂停追到精确活渲；页面不自己预渲染（第 8 节）。〔裁：D5。页面与节点的轻重可能不一致；以页面自己的判定决定怎么显示，以层表决定能取到什么，两者不互相改写。〕
- **低内存档**〔2026-09-27 用户定，取代原来的「不测、按卡片自己的声明」〕：共享成本记录加界限搜索（`product/platforms.md`「面向的平台」；做法在 `mechanism/rendering.md` 的「低内存档」）。本期落实三件：文档服务的成本记录模块（非低内存档的页面测完卡写入，`mechanism/document-service.md` 的「成本记录」）；页面的界限搜索；队列优先级（补渲标 `backfill`，排在本机判重的 `normal` 之后）。C10a 的过渡做法（全部按重卡）随之退出。分支 `claude/c10-cost`（第 20 节）。

## 4. 页面内快照库 L2（D6）

- **位置**：编辑器页的 IndexedDB，一个库，三张表（语义：浏览器本地只放能重新拉回的缓存，`product/platforms.md`「在线浏览器模式」；三张表的内容都能从文档服务与素材服务重新拉回，或重新测出）：
  - `costs`：成本记录（第 3 节）；
  - `snapshots`：从素材服务取来的预渲染块（`snap/<hash>`、`px/<hash>`，按内容哈希为键，值为字节与类型）；
  - `ranges`：按层与区间记就绪（哪一层哪一段的块都已在库里）。
- **写入即就绪**：`ranges` 一写入就通知可见舞台的快照来源（现有 `subscribeReady` 一路）。
- **配额与淘汰**〔裁：查资料 Q1、探针 P3；三级数字，C10 合入时写进 `mechanism/platforms.md`〕：
  - 软上限：普通档 256 MiB，低内存档 64 MiB，由页面自己的 LRU 守住；`navigator.storage.estimate()` 拿得到时取「上限」与「剩余额度的 10%」的较小者（探针里 Chrome 的 `quota` 恒为「已用 + 10 GiB」，实际起作用的是软上限）；
  - 按块的字节数做 LRU，`costs` 不参与淘汰；
  - 写入遇到 `QuotaExceededError`：在**一个事务里**回收 16～64 MiB 再试一次（探针 P3：删除立即释放用量，重试成功）；仍失败就这一块只放内存，不再写库；事务的 `error` 与 `abort` 两个事件都要接；
  - 一帧一个事务即可，不必攒批（探针 P3：20～200 KB 的块写入 136～143 MiB/s、事务 p95 0.8～0.9 ms，随机读 338～360 MiB/s、p95 0.4～0.5 ms，全程无长任务）；
  - 不依赖 `persist()`（探针里一律回 false，无痕模式也是）；L2 只当可重建的缓存，被浏览器清空（例如 Safari 七天没交互）不影响正确性，只是要重新取。
- **低内存档**：C10a 的内存 LRU（64 MiB）换成 L2，只存小尺寸（`cloud-task.md` L6 第 6 条）。

## 5. 普通档从素材服务取预渲染原尺寸（L3，D3、D4）

- **看哪一档**〔按语义；推翻 C10a 第 8.1 节的临时做法〕：普通档（电脑浏览器）取**预渲染原尺寸**（HTML 快照 `snap/<hash>`、PNG `px/<hash>`），低内存档仍取小尺寸（`product/rendering.md`「两档」；S4）。
- **键从哪来**〔裁：分布式队列设计 Q1「页面不移植键的计算」〕：页面不算键。层表（节点写）补上共享档的内容键与产出环境的指纹，页面按层表找清单、按清单取块。部署的 `/editor` 与渲染节点代码版本不一致时，层表对不上的层按「没有预渲染结果」处理（占位、暂停活渲），不报错。
- **不同环境不混用**：一层只取层表记录的那一种环境产的帧（`product/rendering.md`「不同环境的结果不混用」）。
- **流程**：可见范围的重层 → 按层表取清单 → 缺的块凭只读票据从素材服务拉 → 写 L2 → `ranges` 就绪 → 可见舞台下一拍换上。预取范围：播放头前后各 2 秒（与 C10a 一致）。
- **清单里没有的帧**：没有节点产过，按兜底顺序占位；不交页面自产（第 8 节）。

## 6. 播放与暂停（L4、K5）

- **播放**：没有流。重层每拍换一次 HTML 快照〔裁：D8，在线的按拍换帧不受 `SNAPSHOT_THROTTLE_MS` 的 33 ms 节流；节流只留给非播放时的投递〕。换帧成本 `swapMs` 计入每拍预算，`deadMs` 由拍长减去已占用算出；装不下的层显示占位（`product/rendering.md`「兜底顺序」）。`SWAP_MS` 缺省 3 ms，按卡种实测后写进 `mechanism/rendering.md`。
- **暂停、点击或拖动松开、播放到头**：重层在后台舞台渲到精确活渲，渲好后两个舞台互换（K5 第二路，与桌面双舞台同一套）；兜底画面撤下，直到下一次跳转或播放（`product/rendering.md`「停下就撤兜底」）。
- **低内存档**：播放时只贴小尺寸，不活渲；停下追当前一帧，时限 5 秒，超时维持占位（语义 `product/platforms.md`；C10a 第 17 节）。

## 7. 在线页面发布 `plan` 任务

- 在线页面没有编辑器进程。页面自己经文档服务连接发布一个 `plan` 任务，与桌面页面经编辑器进程发布的是同一种任务（`distributed-prerender-queue.md` 第 2 节）：测量落定后发，防抖，项目每次改动后重发（沿用 C6.6 的时机修复）。
- `source.userId` 由文档服务按页面连接的凭证填，发布方自报的不作数（现状）。
- 有能切分的节点（桌面版、独立渲染主机）在线时由它认领、切分、产出，页面按第 5 节取；没有时 `plan` 等着，重层播放占位、暂停活渲。页面不因没人认领而报错。
- 页面订阅 `task.done`，并入层表与就绪（现有路径）。

## 8. 后台舞台认领任务：并入 M7〔裁〕

- **裁定**：`cloud-task.md` L1（后台舞台按 `prerenderSet` 自驱预渲染、页面自己算键）不在 C10 做，并入 M7「纯浏览器节点」。
- **理由**：
  - 语义写的是后台舞台「从文档服务的任务队列认领自己做得了的快照任务」（`product/platforms.md`「在线浏览器模式」「渲染节点」），不是自驱；
  - 分布式队列设计 Q1 已定页面不移植键的计算，L1 的自驱要页面算键，两者冲突；
  - `cloud-task.md` L1 成文早于任务队列（M 系列），先做自驱再在 M7 换成认领，自驱那套会整个作废。
- **随之移到 M7 的**：L 节验收里「没命中的卡后台 iframe 30 秒内预渲染完 10 秒时间轴的锚帧，IndexedDB 有条目」「拖动 3 秒内后台不新增条目」两条，以及认领时的让路（一批 = 一帧，与 `product/platforms.md`「手里在做的那一批做完为止」一致；界面不加后台提示）。「30 秒」只在页面可见且空闲时判（查资料 Q4、探针 P2）。主执行计划第 7 节 M7 的验收同步加上这两条，改写为按队列认领的说法。后台舞台的摆放与节拍规则本期就定（第 2 节），M7 照用。
- **C10 为 M7 备好的**：后台舞台（第 2 节）、成本记录（第 3 节）、L2（第 4 节）、页面发布 `plan`（第 7 节）。

## 9. 用户卡与图卡（D10）

- **预览**：照语义，常驻显示「电脑 + 离线」图标和「需要本地 PC 渲染辅助」，不透明、不走兜底顺序、不显示沙漏（已有：`src/render/placeholderHost.ts` 的 `unsupportedHere`）。**不贴别人预渲染好的快照**〔裁：按 `product/rendering.md`「兜底顺序」末条，不改语义〕。
- **时间轴**：含用户卡或图卡的片段上显示提示「该模式暂不支持自定义卡」（片段内一个小徽标，悬停出全文）。片段照常可选中、移动、删除、改参数：改动经文档服务提交，桌面端的成员照常看得到、渲得了。

## 15. 可行性探针（`claude/c10-probe`，先于实现）

主会话 2026-09-27 派出（`opus-dev`），探针 `scripts/probes/c10-stage-probe.mjs`（子命令 `p1`～`p4`、`p3q`、`calibrate`；用真实的 `createSnapshot`），报告 `docs/reports/AGENT-c10-probe.md`。环境：puppeteer 的 Chrome 152.0.7977.75，有头、无头各一遍；这台机器 GPU 路径只有每秒约 11 次 rAF，全部用 `--disable-gpu`（有头 180 Hz、无头 60 Hz）；每轮开始时 CPU 占用 0%～88%，只比较同一时段的结果。

| 编号 | 问题 | 结果 |
|---|---|---|
| P1 | 同源、同站跨源、同站跨源 + OAC 下，后台舞台跑重活时主文档的长任务与 rAF 间隔（90 例、3 轮、布置交替） | 跨源（换端口或子域）+ 三方都带 OAC：主文档与可见舞台长任务 0，每轮、有头无头都是；主文档 rAF p95 保持基线（有头 6.2～6.6 ms、无头 17.5～20 ms）；两个舞台各成独立 iframe 目标，渲染进程 5 → 7。其余布置每 6 s 22～44 个长任务，rAF p95 150～345 ms |
| P2 | `opacity: 0`、移出视口、`visibility: hidden`、页面隐藏时的 rAF / 定时器 / `requestIdleCallback` | 留在视口里 `opacity: 0` 正常；移出视口或 `visibility: hidden` 被节流到每秒约 0.4 次 rAF。舞台里用 `requestIdleCallback`（1000 ms 超时）只推进每秒 1～4.7 帧，`setTimeout(0)` 不受影响；可见且空闲时每秒帧数约为 1000 ÷ 一帧快照的代价（轻场景 15～30 ms → 30～55 帧；重场景 130～260 ms → 4～8 帧）。隐藏时不会自己停（无头切标签 1.2～2 帧/秒、有头最小化 24～27 帧/秒）；puppeteer 的有头 Chrome 里 `visibilityState` 不变成 hidden，用户自己的 Chrome 里 `visibilitychange` 未证实 |
| P3 | IndexedDB 吞吐、`estimate()`、`persist()`、配额错误后回收重试、跨源分区 | 写 136～143 MiB/s、读 338～360 MiB/s，无长任务；`quota` 恒为「已用 + 10 GiB」，写到 32 GiB 也没有 `QuotaExceededError`，CDP 压低配额无效，没能造出真的配额错误；删 16 或 64 MiB 用量立即下降，重试成功；`persist()` 一律 false；跨源舞台看不到父页的库、有自己的配额 |
| P4 | 跨源舞台读 `/media` | 直读另一个源要靠 CORS（服务现在回 `Access-Control-Allow-Origin: *`，去掉就失败，401 跨源可读）；不带 `crossorigin` 的媒体画进 canvas 会污染它；舞台自己源上反代 `/media` 时，去掉全部 CORS 头 Range、Bearer、媒体元素、canvas 都照常，Bearer 不需要预检 |

没测到：Safari、Firefox、Edge、手机；隐藏 5 分钟后 Chrome 每分钟一次的唤醒；真实的 `QuotaExceededError`；「可见舞台与页面同源、只有后台舞台跨源」的布置；仓库里真实的重卡（用的是合成的 stateful 场景 + 真实 `createSnapshot`）；真实票据、HTTPS 与 nginx（P4 用本机托管组合与 Node 代理）。

顺带发现（本契约外）：`createSnapshot` 在元素带 id 时是平方复杂度，1400 个带 id 的元素要 6.5 s（`serializeScene` 每个 id 跑一遍正则改名）。记为 M7 之前的维护项（第 14 节）。

# 存储占用计划

主计划「M8 之后、团队测试之前」的二级功能项（2026-09-29 用户加，`TODO.md`「未开始的计划」）：桌面版帧库设上限、按项目最近使用淘汰、给「清理缓存」入口；导出产物有列表、大小与删除。本文件是计划与语义改动的 dry run，写于 2026-09-29，PC 主会话。

## 1. 现状（2026-09-29 在 PC 上只读量得）

| 位置 | 大小 | 构成 |
|---|---|---|
| `Videos\PromptCut\frame-library\` | 约 282 GB | 513 个整场景目录 243.6 GB：`mov\frames\*.png` 138.3 GB、`mov\playback-*.mov` 30.7 GB（282 个，**从不删**）、中止后留下的 `mov\full-<pid>.tmp.mov` 30.1 GB（64 个）、`mov\full.mov` 18.1 GB、`frames\` 13.8 GB、`html-blocks\` 7.9 GB、死进程留下的 `html-cache\live-*` 2.9 GB（392 个）、`preview-frames\` 1.9 GB；另 `tracks\` 19.2 GB（含 5 个遗留 `preview-*.tmp.mp4`）、`controls\` 18.9 GB、`controls-local\` 93 MB |
| `Videos\PromptCut\export-*`（27 份） | 约 203 GB | 成片 `preview.mp4` 每份只有 20～59 MB；其余是 `overlay.mov`（5～18.6 GB）、逐帧 `frames\`（5～13 GB）、`parts\`（多分片时 `overlay.mov` 的重复，最多 18 GB，拼接后不删；取消或失败的也留下） |
| `Videos\PromptCut\export-vision-*`（11 份遗留） | 1.5 GB | 视觉工具的临时导出，删除是「发出不等」，有漏删 |

要点：

- 帧库里的键大多是内容哈希；整场景目录的键 `entryKey` 按整个场景算、**不含项目 id**，每改一次画面就是一个新目录。库里没有「键属于哪个项目、最近什么时候用过」的记录，只有文件修改时间。
- 这台桌面没有在推送（没有 `push-queue.json`），帧库是这些结果的唯一一份：淘汰掉就要重新预渲染。
- 编辑器进程、预渲染进程、无头实例共用同一个帧库；Windows 上正被打开的文件删不掉。
- 语义里没有任何关于帧库上限、清理的说法；只有编辑器页的 IndexedDB 快照库有「软上限 + LRU」（`mechanism/platforms.md`）。
- 界面：没有任何查看或清理帧库的入口；标题栏菜单有「打开导出文件夹」「打开数据目录」；导出对话框「已停止」一栏写着「重新导出会覆盖它们」，实际每次导出都是新目录，这句不对。

## 2. 分两部分

- **A. 泄漏修复**（三级，缺陷，不改语义）：从不删的临时文件与中间文件。先做，单独就能腾出约 67 GB 帧库与大部分导出目录的空间。
- **B. 上限、淘汰与入口**（二级功能，加一级入口）：下面第 3 节的语义改动。

### 3.2 二级：`product/platforms.md`「桌面应用」

修改前：该节没有帧库与导出产物的条目。修改后（在「关闭编辑界面后转入后台运行」之前加）：

> - **预渲染缓存**：桌面应用把预渲染结果缓存在本机（帧库）。缓存有容量上限，用户可以改；超出时按项目最近使用的先后，先清掉最久没用的项目的预渲染结果，正在打开的项目不清。清掉的结果需要时重新预渲染；共享项目的结果仍在素材服务里，可以取回。
> - 用户可以随时「清理缓存」：清掉正在打开的项目以外的全部预渲染结果。
> - **导出产物**：每次导出一份，留成片与只含卡片的透明层，逐帧图片等中间文件导出完成后自动删除〔裁〕；取消或失败的导出留下的文件同样列出。用户可以查看历次导出的所属项目、时间与大小，删除整份，或只删中间文件。

### 3.3 三级：`mechanism/platforms.md` 新加「帧库」一节

> ## 帧库
>
> - 位置：导出目录下的 `frame-library`（桌面版缺省 `Videos\PromptCut\frame-library`）。
> - **缺省上限** 50 GB；所在磁盘总容量小于 500 GB 时取总容量的 10%；用户可在 5 GB 到磁盘总容量之间改〔裁：数字〕。
> - **使用记录**：帧库根下一份使用索引，按键目录记最近使用时刻与字节数。预加载打开一个项目的某个版本时，这个版本用到的键（整场景目录、本地档、共享档快照、独立卡、轨道流、轨道前缀）一起记为使用；项目开着时每 5 分钟再记一次。索引丢了按目录重扫，最近使用时刻取目录里最新文件的修改时刻。
> - **淘汰**：总量超过上限时，按最近使用时刻从旧到新删键目录，删到上限的 90%；30 分钟内用过的不删（正在打开的项目在这个窗口里）。删不掉的（被别的进程打开）跳过，下一轮再试。只删帧库根下认得的键目录，遇到符号链接或 junction 跳过。
> - **清理缓存**：删 10 分钟内没用过的全部键目录。
> - **遗留文件**：启动时与每次淘汰时一并清掉：死进程留下的 `html-cache\live-<pid>-*`、`mov\full-<pid>.tmp.mov`、`tracks\*\preview-*.tmp.mp4`；`mov\playback-*.mov` 用完即删。
> - **导出产物**：导出目录下每次导出一个 `export-<时刻>` 目录；导出成功后删 `frames`、`parts`、`glass`、`audio`、`media`、滤镜脚本等中间文件，留 `preview.mp4`（成片）、`overlay.mov`（透明层）与 `project.json`（列表显示所属项目用）。`export-vision-*` 是视觉工具的临时目录，不进列表，启动时清掉遗留的。

## 4. 接口约定（B 部分的服务端与界面照此并行做）

编辑器进程（`/api` 同源守卫之后；在线构建剪掉）：

| 接口 | 请求 | 回包 |
|---|---|---|
| `GET /api/storage` | — | `{ ok, frameLibrary: { bytes, capBytes, capSource: 'default' \| 'user', diskBytes, pinnedBytes, scannedAt, lastEvict: { at, freedBytes, removed, skipped } \| null }, exports: { bytes, count, intermediateBytes }, leftovers: { bytes } }` |
| `POST /api/storage/cap` | `{ bytes }`（5 GB ～ 磁盘总容量） | `{ ok, capBytes }`；设了立即判一次要不要淘汰 |
| `POST /api/storage/clear-cache` | — | `{ ok, freedBytes, removed, skipped }` |
| `GET /api/exports` | — | `{ ok, items: [{ id, projectName, projectId, at, finished, bytes, deliverables: [{ name, bytes }], intermediateBytes }] }`，新的在前；不含 `export-vision-*` |
| `POST /api/exports/<id>/delete` | — | `{ ok }`；`id` 只认 `export-YYYYMMDD-HHMMSS`（可带同秒重名后缀），必须是导出目录下的真目录 |
| `POST /api/exports/<id>/prune` | — | `{ ok, freedBytes }`：只删中间文件 |
| `POST /api/exports/<id>/reveal` | — | `{ ok }`：在文件管理器里打开 |

帧库的扫描与淘汰在预渲染进程里做（它是帧库的主要写入方），编辑器进程转发；上限存数据目录的 `storage.json`。

## 6. 验收

- 基线：`npx tsc -b --force` 0 错误；`npm test` 0 失败；动到预渲染与导出的跑 G0-R（导出确定性 1800/1800、像素基线 0 不同、快照重放 PASS、三个预渲染探针）。
- A：造各种遗留形态（死进程的 spill 目录、中止的 tmp.mov、播放用的 mov）后启动，核清掉的正是这些、别的不动；实导一次，核产物目录只剩成片、透明层与 `project.json`，成片与透明层逐字节同改前。
- B：探针在临时帧库里造 N 个项目的键（最近使用时刻各不同）、上限设小，核删的顺序、删到 90%、30 分钟内用过的不删、被打开的文件跳过；「清理缓存」只留 10 分钟内用过的；改上限立刻生效；接口的路径校验（`..`、链接、别的目录）一律拒。
- 界面：开始页「存储」显示两项占用与上限、清理缓存后数字变小、导出列表能删整份与只删中间文件；标题栏「存储…」能到；在线构建里没有这一块、没有 `/api/storage` 与 `/api/exports` 调用。
- 真机：用户在自己的 PC 上看开始页「存储」、清一次缓存（待用户项）。

# 开工指令交给不是 Claude Code 的执行方时怎么读

2026-10-15 写。`render-018-kickoff.md`（开工指令）是照 Claude Code 写的，里面有几处只有 Claude Code 才有的东西：`/goal` 判定、Agent 工具和几种子 Agent、`/subagent-gpt` 和 `/subagent-agy` 两个技能、`task-announce` 技能、Claude 账号的周额度。用户 2026-10-15 把这件事交给 Antigravity 里的 Gemini 接着做，本文写这几处换成什么。开工指令的其余内容（范围、授权、要先问的、不许做的、做到什么算完、什么时候停）照旧有效。

## 1. 授权

开工指令第 5 行写「用户用 `/goal` 指到本文开工时，本文里的授权才生效」。这次用户直接在第一条消息里把开工指令和本文交给你，**效力等同于用 `/goal` 指到它**，开工指令里列的授权（合进 `main`、发版、部署节点、按决定文件删节点数据等）都给你。

## 2. 没有 `/goal`

- 完成标准不变，就是开工指令「做到什么算完」和用户给你的第一条消息里那五项证据。没有判定模型替你核对，你自己在对话里逐项贴证据（命令、退出码、条数、看过的图）。
- 「用 `/goal` 跑的时候」那一节不适用，但「每条证据都贴在对话里」这一条照做。
- 到了「什么时候停」的某一条、又确实没有别的可做时：写清在等什么，停下等用户回复。

## 3. 没有子 Agent：一个人按顺序做

- 开工指令「分工与档位」那张表（Opus、Sonnet、GPT、Gemini 各用在哪）和「派活」的说法不适用。**实现、测试、合并都由你自己按顺序做，不另起子 Agent**，也不调 `/subagent-gpt`、`/subagent-agy`。
  - 你所在的工具如果自带多 Agent，而那些 Agent 用的是别的模型：只许让它们只读地查资料、搜代码，不许让它们改代码或写文档。
- **仍然一个任务一个工作区、一条分支**：会让基线变红的改动（代码、测试、构建配置、依赖）在 `.worktrees/<名>` 里做，分支名用 `gemini/<名>`；主工作区只做合并和纯文档改动（`guide_files/suggested_agent_behavior.md`「执行」）。
- `guide_files/multi_agent.md` 里的报告规矩照用在你自己身上：每一块做完写 `docs/reports/AGENT-<分支名>.md`（做了什么、怎么验的、〔裁〕、没做成的）。
- **合入前的闸门**照交接文档 `handoff-render-018.md` 第 9 节逐项跑；闸门脚本在 `out/main-session-tools/`，说明在 `docs/local.md`「主会话合入前的闸门脚本」。脚本是 bash 写的，用 `C:\Program Files\Git\bin\bash.exe` 跑。
- 交接文档第 9 节「大块合入前另派一位不带作者结论的独立审查」：没有子 Agent 时，改成合入前单独过一遍差异，对着契约、决定文件和语义逐条查，查出的问题和「没查到的地方」写进那一块的报告。
- 同时只开一个开发服务器、一组探针；端口照交接文档和 `docs/local.md` 的约定避开用户常驻的 5190～5192、5210～5212。

## 4. 额度

开工指令「什么时候停」第 5 条说的是 Claude 账号的周额度到 90%。换成：**你这边的账号额度或用量限制快用完时**（或者用户叫停），照第 5 条的收尾办：各分支提交并推送，更新交接文档（写成 `handoff-render-018.md` 的新一节，或新开一份交接文档并在 `docs/plan/TODO.md` 里指过去），停下等用户。

## 5. 播报

开工指令里的「用 `task-announce` 播报」，在这台 PC 上是一个本地脚本，不是 Claude 会话也能用。用法在 `docs/local.md`「任务播报脚本（不是 Claude 的会话也能用）」：先把内容写成 UTF-8 的 JSON 文件，再用那条 `Start-Process` 命令后台启动。什么时候播照开工指令「播报与汇报」。

## 6. 只记在 Claude 记忆里、没进仓库的用户习惯

下面几条是用户在和 Claude 的对话里定的，原来存在 Claude 的本机记忆里，你读不到，这里抄过来：

- **要用户拍板时在聊天里直接问**：正文里编号列出问题，每条写清这是什么、现在怎么样、有哪些选项、各自的后果、你的建议；不要弹选择题。
- **说白话、带背景**：术语第一次出现当场解释；代号（阶段号、裁定编号、分支名）第一次出现时用一句白话说明它指什么；不要把进度文件里的简写原样转给用户。用户看不懂会逐条追问，宁可每条讲透。
- **提到文档写文件名**，不写编号简称（这条仓库规则里也有）。
- **文档改动可以直接提交并推 `main`**，不用逐次问；代码照开工指令过闸门后合入。

## 7. 你会在文档里看到、但不用管的 Claude 专用东西

`CLAUDE.md` 里的 `@` 引用（你直接读 `AGENTS.md` 指的那三份文件）；`preview_start`、`mcp__…` 这类工具名；`opus-dev`、`sonnet-dev-high` 等子 Agent 名；`~/.claude/` 下的记忆和技能（播报脚本除外，见第 5 节）；提交说明末尾的 `Co-Authored-By: Claude …`（你的提交不用加这一行）。

## 8. 开工顺序

1. 读 `AGENTS.md`，再读它指的 `docs/semantics/developer_guide.md`、`guide_files/suggested_agent_behavior.md`、`guide_files/constraints.md`。
2. 读开工指令 `render-018-kickoff.md` 和本文。
3. 读交接文档 `handoff-render-018.md`，再读两份决定文件 `user-decisions-2026-10-13.md`、`user-decisions-2026-10-14.md`（冲突时以 10-14 为准）。
4. 读 `docs/local.md`（不入库的本机说明：节点、测试要设的环境变量、闸门脚本、安卓模拟器）。
5. 照交接文档第 5 节的顺序接着做；第一件事是把交接文档第 2、3 节和两份决定文件补进 `render-refactor-progress.md`、`three-versions-progress.md`。

## 2. 在线构建与入口

- **在线构建**〔裁〕：
  - `vite build --mode online` 产出 `dist-online/`，`base: '/editor/'`，编译期常量 `import.meta.env.VITE_PC_ONLINE === '1'`；
  - 桌面构建与开发服务照旧，不受影响；
  - 理由：在线页面从不该请求编辑器进程的 `/api/*`；用编译期标志，打包时能剪掉桌面专用路径，也免去运行期探测的延迟与误判。
- **判定模块**：新文件 `src/online/mode.ts`，内容固定为：

  ```ts
  /** 在线浏览器模式：由在线构建打开（c10a-contract.md 第 2 节）。桌面运行环境（桌面版、本机 dev server）恒为 false。 */
  export const ONLINE: boolean = import.meta.env.VITE_PC_ONLINE === "1";
  ```

  `c10a-web` 与 `c10a-lowmem` 两个分支都按这个内容逐字节建它，集成时不会冲突。
- **在线页面不请求 `/api/*`**：
  - 代码里约有 100 处 `fetch("/api/…")`，分布在 34 个文件里。在线模式下，这些入口要么隐藏或置灰，要么走在线替代，不许发出请求。
  - 开发期加一个守卫：`ONLINE` 下 `fetch` 的地址以 `/api/` 开头时抛错，让漏网的调用在测试里暴露。
  - 在线模式的替代：
    - 文档服务 = 同源的 `wss://<host>/hosted/`；
    - 素材服务 = 文档服务 `service.endpoints` 下发的公网地址（阿里云上是 `https://8-219-80-16.sslip.io/media/api/asset`）；
    - 素材票据由页面在自己的连接上 `auth.ticket` 取（auth 契约第 8 节，`server/auth/ticket-source.mjs` 可在浏览器用）。
- **纯浏览器的设备身份**：
  - 在线模式不经 `GET /api/docservice/device`（现在拿不到就不起同步，`device=null`、进入回 `not-ready`）；
  - 设备 id 用 128 位随机数，存在页面本地；
  - 设备名按主执行计划 12.2 节「浏览器名 + 系统名 + 随机 4 位」，同样存在页面本地；
  - 桌面运行环境照旧。
- **首屏**：在线页面打开是开始页，C10a 只提供「加入别人的项目」（新建与草稿见第 1 节）。
- **nginx**〔裁，照查资料 Q5 改成真实拓扑〕：
  - 在线构建放在 `/opt/promptcut-hosted/editor/`；
  - `location = /editor` 与 `location = /editor/index.html` 回 `index.html`，带 `Cache-Control: no-store`；
  - `location ^~ /editor/assets/` 找不到就回 404，带 `Cache-Control: public, max-age=31536000, immutable`；
  - `location /editor/` 按 `try_files $uri /editor/index.html` 回落；
  - `/editor` 系列都加 `Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`；
  - `/editor` 直接回 200，不做首跳重定向（重定向可能丢掉 `#` 片段）；
  - `/hosted`、`/media` 保持现状（`proxy_bind`、升级头、`proxy_read_timeout 3600s`、`client_max_body_size 2g`），媒体不压缩；
  - 改动由主会话在服务器上手工加：先备份，再 `nginx -t`，然后 reload。

## 4. 开始页「加入别人的项目」

桌面版与在线浏览器模式用同一套组件（`src/StartPage.tsx` 的主区里）。

- **三条路径**：
  - 手填，自由进入：项目名、项目密码、自己的用户名；
  - 手填，限定进入：项目名、名单里的用户名和密码；
  - 凭邀请链接：页面读到邀请码后先解析（第 5 节 `resolve`），显示项目名，然后
    - 自由进入：只填自己的用户名；
    - 限定进入：填名单里的用户名和密码。
- **「我是创建者」**：沿用 C6.5 旧对话框的次要入口。点了之后用户名框预填创建者名并置灰，只填创建者密码，以 `as: 'creator'` 进入（主执行计划 12.2 节）。
- **粘贴邀请链接**：开始页另有一个输入框，粘贴完整的邀请链接。从链接里取出服务器地址和邀请码，之后走上面第三条路径。在线页面与桌面版都有这个框，用于扫码后 `#` 片段没保留的情况（查资料 Q3）。
- **读邀请码**：
  - 页面启动时读 `location.hash` 里的 `invite=`，核对字符集（base64url）和长度（43）后放进内存；
  - 随即用 `history.replaceState` 把 `#` 片段清掉，再向同源服务提交；
  - 邀请码不进查询串，不写 localStorage，不进日志。
- **服务器地址**：
  - 在线页面就是本页的源；
  - 桌面版手填时用内置的托管地址（C6.5 的缺省值，可改）；
  - 粘贴链接时取链接的源。
- **校验与文案**：见第 14 节表 A。沿用 C6.5 已有的口径：
  - 「用户名或密码不对。忘了的话找创建者问一下。」：密码错与不在名单里一个口径，不透露名单；
  - 「你被创建者踢出了这个项目。想回来，找创建者撤销。」
- **用户名规则**：沿用服务端现有的校验，界面只做同样的前置检查，不另定规则。

## 5. 邀请码

- **生成**：`crypto.randomBytes(32)`，编码成不带填充的 base64url，共 43 个字符。
- **存储**（项目记录里；`fs` 实现落盘与凭证同处）：
  - `invite: { id, digest, createdAt, expiresAt, maxUses, used, redeemed: [userId…], revokedAt }`；
  - `digest = base64url(HMAC-SHA256(serverSecret, code))`；
  - 不存原文。
- **只有一个有效邀请码**〔裁〕：签发新的同时作废旧的。理由：语义是「作废并重新生成」，界面只显示一个链接。
- **缺省**〔裁〕：有效期 7 天（查资料 Q3 的产品经验值），次数不限（`maxUses: null`）。创建者签发时可以改。
- **链接**：`<托管端公网源>/editor#invite=<邀请码>`，公网源取 `--doc-public-url` 的源。
- **创建者操作**（auth 契约第 7 节的 `shared.admin`，证明同第 7 节，不对一律 `forbidden` 并计入限速）：

  | `op` | 字段 | 效果 |
  |---|---|---|
  | `invite-create` | `expiresInSec?`（缺省 604800）、`maxUses?`（缺省 null） | 作废旧的、签发新的，回 `shared.admin.ok { op, code, expiresAt, maxUses }`；原文只在这一次回包里出现 |
  | `invite-revoke` | — | 作废当前的；之后新加入凭它一律失败 |
  | `invite-status` | — | 回 `{ active, expiresAt, maxUses, used, revokedAt }`，不含原文 |

- **HTTP 端点**（auth 契约第 4 节的同一组，`shared/…`，JSON，`no-store`）：

  | 端点 | 请求 | 成功 | 失败 |
  |---|---|---|---|
  | `POST shared/invite/resolve` | `{ code }` | 200 `{ ok, projectId, name, mode }`，不扣次数 | 404 `invite-invalid`；429 `rate-limited` |
  | `POST shared/invite/redeem` | `{ code, username, deviceId }` | 自由进入：200 `{ ok, projectId, name, mode, kdf, project: { salt, key } }`；限定进入：200 `{ ok, projectId, name, mode }` | 404 `invite-invalid`；401 `banned`；429 `rate-limited` |

  - `invite-invalid` 一个口径〔裁〕：未知、已作废、已过期、次数用完都回它，不让人试探邀请码处在什么状态。界面文案见第 14 节表 A。
  - **自由进入回 `K`**〔裁〕：语义是「凭邀请码加入等价于填对了项目名和项目密码」。`K` 在本协议里等同于项目密码（主执行计划 12.2 节），客户端拿到 `K` 后照常按 auth 契约第 5 节握手，并像手填密码那样把 `K` 缓存在本机。
    - 作废邀请码不影响已经进来的人；
    - 改项目密码会让 `K` 失效，已缓存的也就失效。
    - 两条都与语义「作废不影响项目密码」「改项目密码也不影响已有的邀请码」一致。
  - **扣次数**：同一次处理里先核对「未作废、未过期、次数未满」，再给 `used` 加一。文档服务是单进程、同步处理，这一步本身就是原子的。同一 `userId`（用户名 + 设备 id）再兑换不重复扣。限定进入在兑换时就扣，理由：邀请码在那里只代替项目名，按设备计数足够。
  - **禁入表**：兑换时 `(username, deviceId)` 在禁入表里就回 401 `banned`。握手时照样再核对一次（auth 契约第 7 节）。
  - **限速**：`resolve`、`redeem` 失败都计入 auth 契约第 9 节的限速。
  - **不进日志**：两个端点不记录请求体。邀请码只出现在 HTTPS 请求体里。
- **放本机的项目**：挂载模式（局域网主机）实现同一组端点与 `op`，局域网内可用；邀请码的校验副本同步给云端托管服务属于直连计划。
- **改项目密码、改名单**：不动邀请码。
- **删项目**：邀请码一并删除。

## 6. 项目设置「多用户协作」

- **位置**：`src/editor/ProjectSettingsDialog.tsx` 加一段「多用户协作」。放在项目元数据之外，由共享状态管理，不写进项目文档。
- **勾上时的缺省**（语义）：放本机、自由进入、创建者用户名取设备名、密码自动生成并存在本机。
  - 〔裁〕「密码」指项目密码与创建者密码两样，都自动生成（各 16 个字符）并存在本机；设置里可以改（改法沿用创建者特权）。理由：两样都是新建时必须有的，语义没说只生成哪一个。
- **放云端**：
  1. 向托管端 `POST shared/create`（地址缺省是内置托管地址，可改，沿用 C6.5）；
  2. 以创建者身份进入，把当前项目以根替换写进去（C6.5 的路径）；
  3. `invite-create`；
  4. 显示邀请链接与二维码（第 7 节）。
  - 离线时不能开：回提示，见第 14 节表 B。
  - 首次开启的等待文案写「正在设置多用户协作…」，不写「搬到云端」；「搬到云端」只指把已在本机托管的项目迁过去（Gemini 第 17 点）。
- **放本机**〔裁〕：沿用 C6.5 的本机托管（本机起文档服务与素材服务、局域网广播），不向云端托管服务登记（直连计划），也不出邀请链接（C10，PC 窗口项）。界面照语义提示「你的电脑关机后其他人打不开，可在设置里搬到云端」，另加一行「当前版本放本机只支持局域网内的成员加入；要让局域网外的人加入，请选放云端。」理由：计划已把登记与牵线划出 M5～M8；照实提示，不让用户以为链接能从外网用。
- **设置里显示**（开启后）：
  - 项目名与项目密码（自由进入，带复制按钮）；
  - 邀请链接与二维码（放云端，带复制按钮）；
  - 邀请码状态：有效期、已用次数；
  - 创建者操作：「作废并重新生成邀请码」，每次当场输入创建者密码（语义「每次都要出示」）；以及 C6.5 已有的改项目密码、改名单、踢人、删项目。
  - 〔裁〕邀请链接只有创建者看得到：原文只在签发时回给创建者、存在他本机；服务端不存原文，别的成员取不到。自由进入的成员本来就知道项目密码，可以用手填表单的路带人进来。
- **取消勾选**（放云端的项目）：
  1. 确认；
  2. 把项目真身与被引用的素材原尺寸全部拉回本机（预渲染产物可以再生，不拉）；
  3. 以创建者身份 `delete` 云端项目；
  4. 本机项目回到 `local` 空间。
  - 中途失败就恢复勾选状态并提示重试（Gemini 第 15 点）。
  - 放本机的项目取消：停本机托管，回到 `local` 空间。
- **旧入口**：`src/editor/TopBar.tsx` 项目菜单里的「新建共享项目」「打开共享项目」两项删掉，对应的 `SharedDialogs` 里仍有用的部件（创建者操作、成员列表）保留并挪到设置里。语义：项目只有一种新建入口。

## 8. 低内存档

- **判定**〔裁：查资料 Q1 的规则；阈值是策略值，真机校准〕：
  - `lowMemory = override ?? (deviceMemory <= 4 || (coarsePointer && maxTouchPoints >= 2 && max(screen.width, screen.height) <= 1600))`；
  - `coarsePointer` 取 `matchMedia('(pointer: coarse)')` 或 `matchMedia('(any-pointer: coarse)')`；不看 UA（iPad 常报桌面 UA）；
  - `override` 是设备设置「显示档：自动 / 低内存 / 普通」，存在页面本地；从低内存切到普通要提示，下次载入时生效；
  - 运行中出现 `webglcontextlost` 或连续 3 次视频解码失败，本次会话改按低内存档运行，并提示一次；
  - 结果写进现有的 `hostCapabilities.lowMemory`（`src/render/stageRpc.ts`），它现在的判据「`deviceMemory <= 4` 或 Safari」换成上面这条；
  - 只在在线模式里判；桌面运行环境恒为普通档。
- **能力闸**（L6 第 1～4、6 条，逐条落到代码）：
  - **不开后台舞台**：在线页面只有一个同源舞台（第 8.1 节），不跑 `stageJobs`、`probeRunner`、`ProbeGate`，不认领任何任务；
  - **停下追当前一帧**〔2026-09-27 用户定，取代原来的「不追活渲」〕：见第 17 节；
  - **素材只拉小尺寸**：`mediaTier.ts` 的 `playbackUrl` 在低内存档恒给素材小尺寸；没有小尺寸的素材，这一层显示「等待上传方」角标与占位，不拉原尺寸（导出除外）；
  - **预渲染只拉小尺寸**：见第 9 节；缺小尺寸的重层按 `rendering.md`「兜底顺序」显示占位，不透明，也不拉原尺寸；
  - **缓存**〔裁〕：C10a 不做 IndexedDB 持久库（L2 随 C10），只在内存里按 LRU 缓存小尺寸，上限 64 MiB。
- **提示**：进入项目时提示一次当前是低内存档、哪些能力受限，文案见第 14 节表 C。

### 8.1 在线页面的单舞台 live 预览

- **现状**：没有舞台端口（静态构建就是这样）时，`dualStage()` 为假，退回同源单舞台。那个单舞台只渲占位内容，可见画面靠 `UnifiedPreview` 从预渲染进程取整帧。在线页面没有预渲染进程，所以什么都看不到。
- **C10a 的做法**〔裁〕：
  - `ONLINE` 时，同源单舞台 A 按 live 变体渲：素材层画进舞台、六个平面生效，相当于现在双舞台里 `&preview=stage` 的那一份；
  - A 就是可见舞台，没有 B；
  - 轻卡在舞台里活渲；
  - 重层显示预渲染小尺寸位图（第 9 节）。
  - 理由：低内存档本来就不许开后台舞台、不追活渲，单舞台正合适；普通档（电脑浏览器）的后台舞台兼做渲染节点属于 C10 其余。
- **普通档在 C10a**〔裁〕：电脑浏览器打开 `/editor` 时同样走单舞台。素材按 C6.6 的换档先小后大，重层在 C10a 里也用预渲染小尺寸位图（这是 C10a 里唯一从素材服务来的预渲染产物）。普通档其余行为（每拍换 HTML 快照、后台舞台）随 C10 补齐。

## 9. 预渲染小尺寸

- **尺寸**〔裁：查资料 Q7，与素材小尺寸一致〕：等比缩进 800×600 以内，不放大，保持项目画幅。例如 16:9 为 800×450，9:16 为 337×600。
- **生成**：由渲染节点（桌面版的队列节点、独立渲染主机；不是在线页面）在产出预渲染原尺寸时一并生成：
  - **HTML 快照**：在渲染节点的受控舞台里，把同一帧截成一张小位图，格式为 WebP，带 alpha，质量 80〔裁：比 PNG 小得多，Safari 14 起支持〕。原 HTML 快照不变。
  - **PNG 快照**：从原图等比缩一次，得到 WebP（带 alpha）。
  - **流**：不生成小尺寸（第 1 节）。
- **入库与清单**：
  - 小位图照 A3b 推到素材服务，键是内容哈希（`px/<hash>`）；
  - 清单（`snapshot-manifest` / `render-manifest`）每个区间在原尺寸之外带小尺寸那一份的哈希表；
  - 两档的就绪分开记：小尺寸就绪不能当作原尺寸就绪，导出只认原尺寸（c66-design.md 第 4 节）；
  - 任务完成的条件：两档都推送成功。
- **已有产物补小尺寸**〔裁〕：C10a 只给新产出的区间生成小尺寸。已就绪、缺小尺寸的区间，在线页面显示占位；由渲染节点补做属于 C10 其余。理由：demo 用新建的项目。
- **在线页面拉取**：
  - 按清单取当前可见的重层、当前播放头附近帧的小位图（`px/<hash>`，凭只读票据）；
  - 页面的快照来源（`src/render/snapshotSource.ts`）加一个在线实现，从素材服务读；
  - 预取范围：播放头前后各 2 秒。

### 11.1 低内存档逐帧导出（`c10a-lowmem`）

- **能力探测**：
  - HTTPS、`VideoEncoder`，以及按项目原尺寸与帧率的 `VideoEncoder.isConfigSupported`，编码用 H.264（`avc1.640028`，不支持再试 `avc1.4D0028`、`avc1.42E028`）；
  - 都不支持就停下，提示见第 14 节表 C〔裁：不提供 PNG 序列替代，查资料 Q6，那不是成片〕。
- **音频**〔裁〕：`AudioEncoder` 支持 AAC（`mp4a.40.2`）就编一条 AAC 轨；不支持就导出没有音轨的视频，并在开始前提示一次（第 14 节表 C）。混音沿用 `src/audio/renderMix.ts`。
- **导出前**：
  - 核对被引用的素材原尺寸在素材服务上都 `complete`，缺就照 C6.6 提示「等待上传方」并列出缺的素材；
  - 核对重层的预渲染原尺寸都已就绪，缺就提示有几个重卡片段还没有预渲染原尺寸，等渲染节点做完再导出〔裁：语义说重卡用已有的原尺寸、不重渲〕；
  - 两种情况都不设超时，用户可以取消。
- **逐帧**：
  - 按帧号定时间戳（`src/kernel/exportClock.ts`），每次只合成一帧到复用的原尺寸画布，然后 `encode()`，随即 `frame.close()`；
  - `encodeQueueSize` 不超过 3；
  - 素材原尺寸按 Range 只读当前需要的窗口，不整片读进内存；
  - 导出期间暂停预览，并释放小尺寸缓存。
- **写出**：
  - 有 `showSaveFilePicker` 的浏览器流式写文件（`src/editor/io/proc.ts` 已有辅助）；
  - 没有的（iOS）攒成 Blob 后下载，内存随片长增长；
  - 报告里记下 iOS 上实测能导出的时长与体积〔裁：写明是已知上限，不说恒定内存〕。
- **提示**：开始时提示「导出期间请保持页面在前台、不要锁屏」；过程中显示进度，可以取消。
- **不做**：低内存档不导出「只含卡片的透明层」（H.264 不带 alpha），菜单项置灰〔裁〕。

## 13. 查资料的结论（codex，`gpt-6-sol` / `high`；原文 `docs/plan/c10a-research.md`）

| 题 | 结论 | 怎么用 |
|---|---|---|
| Q1 内存与判定 | 移动浏览器没有公开统一的内存、解码器、WebGL 上限；`deviceMemory` 在 iOS 上没有；iPad 常报桌面 UA | 采纳：第 8 节判定规则、单舞台、手动覆盖 |
| Q2 后台节流 | 后台计时器、rAF、WebSocket 都不保证继续；discard 可能不发事件 | 采纳：回到前台（`visibilitychange`、`pageshow`）时幂等检查连接、按会话接续；低内存档切到后台时停预览 |
| Q3 邀请码 | 256 位随机、服务端只存摘要、事务扣次、作废立即生效；`#` 片段不进请求与 Referer，但进历史；扫码是否保留 `#` 无官方保证 | 采纳：第 5 节；读完即清 `#` 片段；粘贴链接作退路；真手机扫码记为待用户项 |
| Q4 二维码库 | Nayuki 的 MIT 零依赖实现可用 | 改用仓库已有的 `server/qr.mjs`（第 7 节） |
| Q5 `/editor` 与 nginx | `base: '/editor/'` 加 SPA 回落；HTML 不缓存、带哈希的资源长缓存；媒体 Range 透传、不压缩 | 采纳：第 2、3 节 |
| Q6 逐帧导出 | Safari 16.4 起有视频 WebCodecs，但 H.264 原尺寸编码与持续写文件没有统一保证；`mp4-muxer` 停维护，Mediabunny 是 MPL-2.0 | 采纳能力探测与限队列；自写封装器；不给 PNG 序列替代；iOS 时长上限写进报告 |
| Q7 预渲染小尺寸 | 与素材小尺寸统一在 800×600 以内；HTML 重层要独立小位图；手机不消费流 | 采纳：第 9 节；格式定为 WebP |

## 16. 开工后的裁定（2026-09-27，PC 主会话）

`claude/c10a-tests` 按本契约写测试时提出的空白处，主会话裁定如下〔裁〕，已同时告知 `c10a-web`、`c10a-lowmem` 两个分支。三个分支都从 C6.6 集成分支 `claude/c66-integ` 的 `851ffe9` 拉出，与 C6.6 的 T9 重叠进行〔裁：排期，不跳过任何验收〕；C6.6 合入 main 后三个分支合并 main。

1. **图片、音频在低内存档**：C6.6 只给视频生成素材小尺寸。低内存档对图片、音频用它们唯一的一档照常显示、出声；第 8 节「素材只拉小尺寸、没有就占位」只对视频生效。理由：语义「只看素材小尺寸」的本意是不拉重的素材原尺寸，单档素材本来只有这一档；否则图片永远是占位、声音永远没有。
2. **限速**：HTTP 端点被限速回 429，带 `Retry-After` 头（秒）和回包字段 `{ error: 'rate-limited', retryAfter }`；表 A 的秒数取它。
3. **邀请码的形状**：`expiresAt` 是毫秒时间戳；`invite-status` 在 `shared.admin.ok` 里平铺 `{ op, active, expiresAt, maxUses, used, revokedAt }`。
4. **限定进入的扣次**（改第 5 节「限定进入在兑换时就扣」）：`redeem` 只在用户名在名单里时才扣次数，回包不论在不在名单一律相同，不泄露名单。理由：兑换时不核对口令，拿到链接的人换设备名就能耗光次数。
5. **格式不对的邀请码**：长度不是 43 或字符集不是 base64url，一律回 404 `invite-invalid`，并进「一个口径」，也计入限速。
6. **`/api` 守卫**（改第 2 节「开发期加一个守卫」）：只要 `ONLINE` 为真就装，在线的开发构建与生产构建都装，不另设开关；桌面运行环境不装。
7. **分层**：`src/online/` 属于 render 这一层，只引 kernel、render 与同目录，不引 editor、mcp、ai；`src/layering.test.mjs` 的禁引表加 `online` 一行。
8. **单舞台**：`ONLINE` 时 `dualStage()` 恒为假（页面上有舞台端口表也一样），可见舞台 A 带 `preview=stage` 走 live 变体（第 8.1 节）。

## 17. 低内存档的过渡做法（2026-09-27 用户定）

语义 `product/platforms.md`「面向的平台」的低内存档一条已按用户定的规则改写：目标规则是共享成本记录加界限搜索，由 C10 其余落实（`c10-contract.md` 第 3 节）。C10a 里先做过渡：

- **全部按重卡**：低内存档不测，所有卡按重卡处理。播放时一律贴预渲染小尺寸，不活渲；没有产物的层显示占位符。第 8.1 节「轻卡在舞台里活渲」只对普通档保留，低内存档不再活渲轻卡。
- **停下追当前一帧**：暂停、点击或拖动松开、播放到头时，在单舞台里把当前这一帧的所有卡活渲一次。画出来之前照兜底顺序显示，画好的层替换上去；时限 5 秒（`mechanism/rendering.md` 的「低内存档」），到时限还没画好的层维持占位符，直到下一次停下。用户卡、图卡不追：有这一帧的预渲染小尺寸就照贴，没有才显示「需要本地 PC 渲染辅助」（2026-09-29 用户改语义，`c10-contract.md` 第 9 节）。取代第 8 节原来的「不追活渲」。
- **补渲**：判重、素材服务里又没有产物的层（按清单判），页面向队列发布补渲任务。它是带片段清单的计划任务，标 `priority: 'backfill'`；节点切出的细任务同样标 `backfill`。认领时 `normal` 先于 `backfill`；同一个结果键已有任务就不另起，已有的是 `backfill` 而又有人按 `normal` 发布就升级（`mechanism/document-service.md` 的「渲染任务队列」）。页面只发布，不认领。
- **验收**（并入第 12 节）：
  - 单测：低内存档所有卡判重；停下追一帧的时限与超时维持占位；补渲任务带 `backfill`、认领顺序、同键升级；
  - `c10a-demo-probe`（本机 `--local` 与阿里云各一轮）：手机仿真里播放只贴小尺寸、不活渲；暂停后当前这一帧在时限内画出，或超时维持占位（记下耗时）；缺产物的层会发出补渲任务，节点在本机判重的任务之后做完，小尺寸回到手机。
- **分支**：C10a 还没合入 main，在集成分支 `claude/c10a-integ` 里做，随收 `claude/c10a-aliyun`、G0 与 G0-R、重新部署、外网演示一起验收。
- **实现备注**（`claude/c10a-lowmem2`，主会话接受〔裁〕）：
  - 到时限还没画好的层维持兜底画面：已有预渲染小尺寸的留在小尺寸，不换成沙漏（`mechanism/rendering.md` 的「低内存档」）；
  - 无状态（direct）卡在预渲染管线里不产快照，补渲切不出任务：过渡期在低内存档播放时一直占位，停下时照常画。随 C10 其余的界限搜索解决（便宜的卡判轻、直接活渲）；
  - 补渲计划任务用共享项目 id 与文档服务确认过的版本（节点只能按这条路取当前版本），层表照常对得上；
  - 被补渲的卡进了层表，低内存档导出要等它们的预渲染原尺寸；
  - `priority` 同一字段兼容整数（normal 档内的名次，旧形状）与 `'normal'` / `'backfill'`，队列契约 A.4、B.3、H.3 随之改。

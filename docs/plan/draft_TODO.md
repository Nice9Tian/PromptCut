## 要做成什么

用户新买了一台 Ubuntu 云节点，要它承担四样：文档服务、素材服务、渲染服务、Agent 服务。手机用户和轻量浏览器用户右侧用不了 Agent 时，在线页面把请求转给云节点，由云节点上的 Agent 以这个用户的身份工作。

## 云端 Agent 的缺口

1. 没有独立的 Agent 服务进程与对外接口：`/api/ai/chat`、`/api/mcp/*`、`/api/agent/*` 都是编辑器进程的同源中间件（`server/vite-plugin-ai.ts`）。
2. 单项目、单用户：`agentBinding` 只有一份，后绑的顶掉先绑的；审查环路锁、额度熔断、登录状态、`ai.json`、对话记录都是进程级全局。
3. 在线页面一侧是剪掉的：右侧是占位（`src/editor/dock/DockPages.tsx`），工具通道在在线构建里整个删了；「在线页面不请求 `/api/*`」有守卫和棘轮清单（`c10a-contract.md`）。
4. 身份与票据依赖页面：文档服务已认 `agent` 角色，但连接票据靠同机页面经 SSE 签，有效期 2 分钟；托管部署下素材票据没接（`TODO.md`）。
5. Agent 的「看」：云端要一个只做即时渲染的进程和按需拉素材的本地库，`cloud-task.md` I2、I3 未做。
6. 读页面状态的工具（选区、播放头、播放暂停）要经公网问用户的浏览器，或在云端降级。
7. 模型凭证与计量：服务器上走不了命令行订阅的浏览器登录，现实做法是 API 直连（`server/harness/`）；按用户的上限、并发、计费没有任何设计。

## 等用户定的事

- 模型的钱谁出、每人上限与并发上限怎么定。
- 新节点与阿里云的关系：整体搬过去，还是两台并存。
- 新节点的规格（现阿里云内存 1.6 GB，只够文档与素材；四样都跑建议至少 4 核 8 GB）、地址、SSH 私钥在本机的路径。
- 语义：云端 Agent 从「愿景」变承诺是二级；AI 栏多一种「云端」接入方式、手机上出现 AI 栏是一级。都要先 dry run 给用户确认。

## 建议的顺序

1. 新节点装文档、素材、在线页面。不依赖别的工作，现在就能做。
2. 渲染服务常驻。做完后手机与轻量浏览器用户的重卡有节点渲。
3. 云端 Agent，先做最小一条线：只支持 API 直连，一个用户一个项目一个对话，只开改项目的工具；「看」和页面状态工具后补。

## 与「前后端解耦与渲染调度演进计划」的关系（2026-10-05 评估）

那份计划在 Antigravity 的工作区里（作者不详）、**未入库**：`~/.gemini/antigravity/worktrees/PromptCut/check_frontend_backend_separation/docs/plan/render-dispatch-and-separation-plan.md`（M1 概念统一已合入 main；M2 共享目录、M3 后端独立、M4 渲染调度、M5 舞台规整未做）。

结论：**不要等整个分离做完再做云端 Agent；只把其中一小块提前，并在那份计划里补一条。**

- 那份计划的 M3 列的是素材服务独立入口、文档服务独立进程、桌面壳脱离 Vite；Agent 只在目标目录里出现了一个名字（`backend/services/`），没有「Agent 服务独立」这一步。照它做完，Agent 不会自己分出来。
- Agent 服务端离不开 Vite，不是因为挂在中间件上，而是它要载入页面那套工具实现、store、卡片与部件注册表（`server/agent/ssr-host.mjs`，卡片是 TSX）。M2 计划搬进 `shared/` 的是鉴权客户端、节点会话、工具清单、消息类型，不含这些。
- 云端 Agent 最重的几条（多用户隔离、票据、在线页面的通道、计量）与目录怎么分无关，分离做完也还在。
- 云节点上可以直接跑 Vite：独立渲染主机就是这么起的。所以 Agent 服务现在就能以同样的方式常驻，不必等桌面壳脱离 Vite。
- 值得提前的只有一块：**Agent 服务的独立入口**（不带编辑页、带鉴权、按「用户 × 项目 × 对话」分实例）。做的时候按那份计划的目标位置放，以后分离时不返工。
- M2（建 `shared/`、补守门测试）不让缓存失效、风险低，可以与第 1、2 步并行做；M3 的桌面壳脱离 Vite 与 Electron 迁移（`electron-mac-plan.md`）撞在同一处，应合并考虑；M5 会让预渲染缓存整体换键，放最后。

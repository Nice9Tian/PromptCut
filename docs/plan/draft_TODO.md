## 三期之间怎么衔接

- **一期的 Agent 独立入口按二期的目标位置做。** 分离计划的目标布局里 Agent 宿主在 `backend/services/`，但它的步骤里没有「Agent 服务独立」这一项。一期把这一项做掉，二期只搬目录、不返工。约束：独立入口对前端代码的依赖只经一处载入缝（现在是 `server/agent/ssr-host.mjs`），不新增别的直接引用。
- **一期的云节点上照旧跑 Vite。** Agent 服务端要载入页面那套工具实现、store、卡片与部件注册表（卡片是 TSX），现在只有 Vite 能载。独立渲染主机也是这么起的。脱离 Vite 留给二期。
- **二期的「桌面壳脱离 Vite」只在 Node 这一层做**：把「起 Vite 开发服务器」换成「静态页面 + 独立 Node 服务」，外壳只是换一条启动命令，不碰 Rust。这样三期换 Electron 时主进程直接起这个服务，工作量更小。二期这一步最难的是服务端怎么不经 Vite 载入卡片与工具实现（预先打包成服务端产物是候选做法，待定）。
- **两次「大换血」要错开告知用户**：二期最后一步（舞台目录规整、收窄代码版本哈希）会让预渲染缓存整体换键一次；三期若采用 paint 取帧，导出像素基线要按后端各立一份。两件事都要事先经用户确认，发版通知里写明。
- **三期的第 0 步（证明 Electron 离屏 paint 取帧可行）不依赖一期、二期**，不改仓库现有文件，可以在任何空档先做。用户已定：先证明 paint 可行再换壳。

## 一期：云节点与 Agent 服务拆出

### 1.1 新节点装文档、素材、在线页面（不依赖别的工作）

- 用 `scripts/remote/docservice.mjs` 的 `install`、`deploy-hosted --write-token --save`；`server/hosted/main.mjs` 一个进程两个端口。
- nginx 配置不在仓库里：从旧机器抄 `/etc/nginx/sites-enabled/promptcut`、`promptcut-stages`，改域名与 `proxy_bind` 的内网地址；两个舞台子域要 DNS 与证书；`gzip_types`、`gzip_static`（`hosting-migration.md`）。
- 完成的标志：`/healthz` 通；在线页面能加入一个测试项目、读到素材；真机路径探针对新地址通过。
- 待定：整体从阿里云搬过去（步骤见 `hosting-migration.md`，约一小时停写），还是两台并存。

### 1.2 渲染服务常驻

- 现状：`scripts/render-host.mjs`（独立渲染主机）有代码，只在测试容器里以探针方式跑过。
- 要补：常驻配置与部署脚本；root 下 Chrome 自动加 `--no-sandbox`（`cloud-task.md` I0 写了、代码没做）；中文字体与启动自检；ffmpeg 在 PATH。
- 机制缺口：它要每个项目一份项目凭证写进配置才能取活（`render-host-contract.md`）。要自动为节点上所有项目服务，得新定「托管方自己的渲染身份」，二级决定。
- 完成的标志：手机低内存档打开一个含重卡的项目，补渲任务被云节点认领、产物贴上；节点重启后自动恢复取活。

### 1.3 Agent 服务独立入口与云端 Agent（一期的主体）

缺口（2026-10-05 查代码）：

1. 没有独立进程与对外接口：`/api/ai/chat`、`/api/mcp/*`、`/api/agent/*` 都是编辑器进程的同源中间件（`server/vite-plugin-ai.ts`）。
2. 单项目、单用户：`agentBinding` 只有一份，后绑的顶掉先绑的；审查环路锁、额度熔断、登录状态、`ai.json`、对话记录都是进程级全局。
3. 在线页面一侧是剪掉的：右侧是占位（`src/editor/dock/DockPages.tsx`），工具通道在在线构建里整个删了；「在线页面不请求 `/api/*`」有守卫和棘轮清单（`c10a-contract.md`）。
4. 身份与票据依赖页面：文档服务已认 `agent` 角色，但连接票据靠同机页面经 SSE 签，有效期 2 分钟；托管部署下素材票据没接。
5. Agent 的「看」：云端要一个只做即时渲染的进程和按需拉素材的本地库（`cloud-task.md` I2、I3 未做）。
6. 读页面状态的工具（选区、播放头、播放暂停）要经公网问用户的浏览器，或在云端降级。
7. 模型凭证与计量：服务器上走不了命令行订阅的浏览器登录，现实做法是 API 直连（`server/harness/`）；按用户的上限、并发、计费没有任何设计。

拆成三步：

- **1.3a 独立入口**：Agent 服务不带编辑页也能起，带鉴权，按「用户 × 项目 × 对话」分实例，进程级全局状态改成按实例。桌面版改为用同一个入口（行为不变）。完成的标志：桌面版全部 Agent 相关测试与探针不变红；同一进程里两个项目各一个对话互不干扰。
- **1.3b 在线页面接上云端 Agent**：右侧占位换成可用的 AI 栏，对话与工具经云节点转发；票据改为在线页面经公网替云端 Agent 签，或 Agent 服务持项目凭证（待定）；素材票据接上。先只支持 API 直连，只开改项目的工具。完成的标志：手机上发一句话，项目被改，别的成员看到改动且署名正确。
- **1.3c 补齐**：云端的「看」（即时渲染进程、按需拉素材）；读页面状态的工具；每人上限、并发上限与计量。

语义（都要先 dry run 给用户确认）：云端 Agent 从「愿景」变承诺、托管方的渲染身份，二级；AI 栏多一种「云端」接入方式、手机上出现 AI 栏，一级。

## 二期：前后端分离

依据 `render-dispatch-and-separation-plan.md`，M1（概念统一）已合入 main。本期做 M2～M5，并作三处调整：

| 步 | 原计划 | 调整 |
|---|---|---|
| M2 共享目录 | 建 `shared/`，迁前后端互相引用的模块（服务端引前端约 26 处、前端引服务端 9 个文件），补 `layering.test.mjs` | 不让缓存失效、风险低；若人手有余可提前到一期并行做 |
| M3 后端独立 | 素材服务独立入口、文档服务独立进程、桌面壳脱离 Vite | **补一项**：Agent 服务独立（一期已做入口，这里只搬到 `backend/services/` 并解决不经 Vite 载入工具实现与卡片）；「桌面壳脱离 Vite」只动 Node 层，不碰 Rust |
| M4 渲染调度 | 项目级调度规则、即时渲染派发、桌面端协助浏览器端即时渲染 | 云节点的渲染服务（一期 1.2）作为规则里的「渲染服务器」目标接入；设计稿另有一份 `render_dispatch_design.md`（仍在 Antigravity 工作区，含本机绝对路径，未拷入），其中等用户定的问题在开工前过一遍 |
| M5 舞台规整 | 整理 `stage/` 目录，代码版本哈希收窄到舞台与共享计算 | 预渲染缓存整体换键一次，放本期最后，事先经用户确认 |

完成的标志：守门测试拦得住前后端直接互引；桌面正式版不再起 Vite 开发服务器；G0、G0-R 全过，导出像素基线不变（M5 换的是缓存键，不是像素）。

语义：调度规则、成员互助即时渲染的开关是二级，设备上的「允许协助」开关是一级；开工前 dry run。

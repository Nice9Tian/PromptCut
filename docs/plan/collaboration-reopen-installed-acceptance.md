# 协作重开：真实安装版的系统双击验收

日期：2026-10-05。

对应 `collaboration-reopen-recovery-plan.md` 第 11 节「.proc / .procp / 草稿 / 系统双击 / 刷新」一行里还没通过的「系统双击」，以及 `REPORT-collaboration-reopen-recovery.md` 卡点 10 解法表第 13 行。结果记在那份报告里，本文只写做法。

## 为什么换成这条路

上一轮在 PC 上临时改写 `.proc` 的打开命令，想让资源管理器把双击交给隔离测试壳，19 轮都没有拿到测试壳的回执。用户 2026-10-05 改定：不再改写关联；在笔记本上真实安装候选包，关联由安装器按产品流程登记，再在资源管理器里真双击。

这只改验证方式，不改语义，也不降门槛：主机、成员两个角色的冷启动双击、已开窗口转发、原房间原身份恢复、双向编辑、带票据素材读取仍须全部有证据。

用户同日说明：上一轮的电脑操作是另一个工具做的，可能有缺陷，它的操作经验和限制不当作事实沿用；本轮各会话按自己的工具操作，以实测为准。

## 谁做什么

| 谁 | 做什么 |
|---|---|
| PC 主会话 | 指挥两个辅助节点；起任务自有的临时公开入口；成员角色时在 PC 上起隔离主机；收证据、写报告。不改写关联，不启动 PC 上已装的正式版 |
| 笔记本会话 | 从分支构建完整安装包、安装前备份、真实安装、用电脑操作在资源管理器里双击、跑带耗时门槛的项、验收后还原。不提交、不推送 |
| 云端会话 | 只能出网，只当 Node 层的外网成员：主机重开恢复后，从外网认证进同一个房间，读带票据素材、做一次编辑 |
| 用户 | 处理会话不该碰的东西（安全提示之类）；决定合入 |

## 硬性边界

- 不改系统设置：文件关联、防火墙、安全提示都不由会话动。关联只由安装器登记。遇到安全提示就截图、记为待用户项。
- 真实安装会覆盖笔记本已装的那一份，并使用笔记本真实的数据目录和 WebView2 配置。所以先备份、后还原；还原只改名和复制，不删文件。
- 密码、派生密钥、邀请码、会话秘密不打印，不进提交、消息和信箱。跨机器交接口令用 `scripts/probes/reopen-sealed.mjs`：收件方给公钥，发件方只回密文。
- 测试进程静默运行，不弹命令窗口（`verification.md`）。笔记本的测试端口只用 5580～5599；已装的应用固定用 5210～5212，是产品端口。
- 公开入口是任务自有的临时入口，随进程结束失效；不部署生产，不碰生产房间。

## 步骤

1. **构建**（笔记本）：在独立的 git 仓库里检出分支提交，跑 `desktop/` 下 `npm run release -- --from-head` 的等价流程，产出 `PromptCut-0.7.14-setup.exe` 和 `manifest-0.7.14.json`。记下安装包的 SHA-256 和 `runtime/VERSIONS.json` 的 `appSrcHash`。诊断提交地址用回环占位值，这是验收用的候选包，不是发版包。
2. **备份**（笔记本）：`scripts/probes/reopen-installed-state.mjs backup` 备份四个目录——安装目录、应用数据目录、WebView2 配置目录、导出目录——随后 `compare` 应为 `identical:true`。另把相关注册表键只读导出一份。
3. **安装与核对**（笔记本）：运行安装器。装前、装后各跑一次 `scripts/probes/reopen-installed.mjs --preflight-only`：装前应拒绝，装后应确认 `.proc` 的有效打开程序就是已装的候选版、运行副本逐文件对上清单。
4. **主机角色**（笔记本为主机）：`reopen-installed.mjs --manifest … --app-src-hash … --service <临时公开入口> --external-member`。探针启动已装的应用、建房间、让本机替身成员加入，正常退出应用；然后在 `control/handoff.json` 里写明该双击哪份文件。笔记本会话在资源管理器里双击，探针核对回执与恢复；云端成员此时从外网加入；最后在应用开着时再双击一次，核对转发。
5. **成员角色**（笔记本为成员，主机在 PC）：PC 上跑 `reopen-remote-host.mjs`，用隔离数据目录和隔离端口起主机并建房间；笔记本跑 `reopen-installed.mjs --member --remote-host-key <PC 给的公钥>`。成员首次用真实界面认证，退出后冷启动双击应先等待主机，PC 的主机回来后自动加入；再做编辑、读素材和第二次双击。
6. **带耗时门槛的项**（笔记本）：在最终提交上跑 G0-R 里计时的那几项。
7. **还原**（笔记本）：`reopen-installed-state.mjs restore`，把现状改名挪到旁边、把备份复制回原处，再 `compare` 确认。挪开的目录留给用户处理。

## 一次双击怎样才算数

探针不依赖测试壳，证据取自进程本身，四条同时成立才认：

- 进程的可执行文件就是已装的 `promptcut.exe`；
- 命令行里带着那份 `.proc`；
- 父进程是 `explorer.exe`，且父进程比它早创建；
- 创建时刻晚于探针写下「就绪」的时刻。

冷启动的那一次，启动地址还须带着 `?open=<那份文件>`。应用开着时的那一次，已开的窗口须收到 `pc-open-file` 事件并换成新的连接，原进程不退出。演练模式（`--rehearse-fixture`，用隔离测试壳、由探针带文件参数启动）只用来在 PC 上验证探针本身，不算双击证据。

## 判定

两个角色各退出 0，且各自的证据里有：装的就是被测构建；两次双击的回执；原房间、原身份；成员等待后自动加入；4 次双向编辑；三个命名空间各 50 000 字节的带票据素材读取；恢复过程建房 0 次；原文件不变。主机角色另有外网成员的结果。对端不在线时用本机替身先做，记「待跨机复核」。

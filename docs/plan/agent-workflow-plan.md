## 1. 现在的调用链路

- AI 栏两条路都进 `server/vite-plugin-ai.ts` 的 `callToolInternal`（约 407～452 行）：API 直连经闭包，CLI 经 `mcp-server.mjs` 的 `POST /api/mcp/call`。入口已有两道闸：审查环路的只读锁 `loopToolLock`、SKILL 闸 `checkGate`。
- 页面调过 `/api/agent/bind` 后，调用交给 `server/agent/agent-side.mjs` 的 `callTool`：`side: "agent"` 的工具在服务端的项目副本上跑、以「agent + 对话号」的身份提交给文档服务（`agent-exec.mjs` 的 `runRoute`）；`side: "page"` 的工具经 SSE 交页面执行。
- 每个页签的 `conversationId` 就是 Agent 对话 ID；服务端 `conversationOf` 给每个对话开一条文档服务连接，写入身份 `{ role: 'agent', conversation: n, session }`（`n` 是进程内计数，重启会变）。

## 3. 每段的验收（G0 与各段专属）

- 每段：`npx tsc -b --force` 0 错误；`npm test` 0 失败、跳过 ≤ 2；改到渲染或预渲染的跑 G0-R；两个代码指纹（`snapshotCode`、`captureCode`）不变，除非事先说明。
- A1：单测覆盖三档 × 工具对照表（低档调 `create_card` 被拒、中档能改代码不能新建、高档全放行）；`set_project_meta` 带未声明字段被拒；对话覆盖与项目默认的优先级；界面探针：项目设置里选等级、AI 栏对话改等级后生效。
- A2：单测覆盖编辑状态的汇总与节流、工具结果里的 `userEditing` 与 `overwrote`；探针：页面选中并拖动一张卡时 Agent 读它，结果带提示。
- A3：`spawn_agent` 的身份隔离（并行写入不再互相被拒）、公告板在服务端可见全部写入、递归上限；分工模式归档后原有入口不残留。
- A4：桌面 APP（至少 Claude 桌面版）经 MCP 直连改同一个项目，AI 栏按身份分组显示；无头实例相关代码归档后基线全绿。Codex 桌面版能否挂 MCP 先实测，不能就沿用命令行工具那条路并写明。
- A5：PC 上出完整安装包后实机：关窗不退出、托盘与悬浮窗唤回、右键关闭才退出；隐藏时 `side: "page"` 的工具照常（WebView2 被 `hide()` 后会停渲染，沿用挪到屏幕外的做法或把绑定移到服务端）。
- A6：沙箱限时限内存、只在高档开放、超时与异常回清楚的错误。

## 4. 要定的细节（〔裁〕，发给用户但不等）

1. 「正在编辑」的口径（A2，三级）：拖动中、文字编辑中、以及选中后 30 秒内动过的实体算「正在编辑」；只选中不动不算。
2. 递归拉起的上限（A3，三级）：主 Agent 拉起的子 Agent 不能再拉起（深度 1），同时在跑的子 Agent 至多 4 个。
3. 创造力等级存在项目文档里（A1）：随项目走、共享项目里所有成员看到同一个默认；对话覆盖只存在本机页签里。

## 5. 风险

- A1 的等级若存在项目里而 `set_project_meta` 不堵，Agent 能自己升档——所以堵口子与 A1 同批。
- A4 写进用户级 MCP 配置会影响用户的其它项目：配置项按项目或按端口发现做隔离，写之前备份。
- A5 只能在 PC 上出安装包；PC 不在线时 A5 的代码可以先做完合入，出包记为待办。
- A6 在用户机器上执行模型写的代码：只在预渲染 Chrome 的隔离页面里跑，不给 Node 能力。

## 发版前基线（在最终的 `main` 上）

1. `npx tsc -b --force` 零错误。
2. 全量 `npm test` 通过（有汇总行、日志大小正常；个别负载假失败要单跑复核并记原因）。
3. `npm run build` 退出码 0。
4. 渲染附加项：全长导出与起点提交逐字节比对、导出确定性、导出与快照重放一致。导出像素基线要变必须事先说清为什么（R01 返工本身就是一次有意的回退，基线对照取 `b362e254`）。
5. 版本号：根 `package.json` → `0.7.21`；`desktop/src-tauri/tauri.conf.json` 保持 `0.2.8`。若最终有分支动了 `desktop/`，按 `git_and_release.md` 的表重判并在报告里写明。
6. 先提交，再构建。

## 出包与上线

1. `desktop/` 下 `npm run release -- --from-head`：完整安装包 + 兼容补丁。记 SHA-256、字节数、各步耗时。
2. `git checkout release && git merge --ff-only main`；推 origin（`main`、`release`）。
3. 上传安装包到官网，下载链接换到 0.7.21（核 `Content-Length`）。
4. 部署节点（两棵树换文件、重启五服务），核 `version` 与 `codeVersion` 都是 `0.7.21`、`render.code-version match: true`。
5. 生产只读验收：`https://visuhive.com` 手机仿真 + 桌面仿真，页面错误 0、失败请求 0、无横向溢出；线上入口脚本与本机构建一致。验证缓存头要用没开过的地址连开两次（Chrome 按导航发起方分缓存条目）。
6. 新版本提示（B）与素材长期缓存（C）上线后在真实线上各验一次：换版本后老页面是否挂出提示条；舞台素材第二次打开是否命中长期缓存。

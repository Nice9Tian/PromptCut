## 用户定的（语义照此改写，不用再问）

**E. 云端 Agent 从愿景变成承诺。** `product/agent.md`、`architecture.md`：托管方提供云端 Agent 服务，跑在云节点上；在线浏览器的用户在 AI 栏里选它，对话与工具调用由它执行，改动经文档服务落地。桌面版仍默认用本机 Agent，行为不变。

**F. 模型。** 用托管方（用户）的 Key，服务端 API 直连（`server/harness/`），不用命令行订阅。Key 用仓库现有的加密分发办法送到节点（2026-10-07 用户定）：节点报出自己的机器识别码 → 用户在自己的电脑上用 `make-api-share.bat` 把 Key 加密成只有那台节点能解的密文（明文只经用户自己的手）→ 会话把密文送到节点导入，节点本机解开并按现有的落盘加密保存。会话全程只接触密文，不向用户要明文；Key 不进仓库、日志、消息。本机演练需要真实模型时，用这台 PC 上已经配好的 API 直连配置，不读出它的值。

**G. 上限。** 现在不设，优先跑通，但接口要在。每个项目有「云端 Agent」开关（缺省开，创建者可关）和一个额度字段（缺省不限）；所有对话与模型调用都经过同一处额度与并发检查，这处检查现在永远放行；用量按项目、按成员记下来，可查。以后用户按项目发上限时只改配置、不改代码。

**H. 身份。** Agent 服务自己持凭证连文档服务，不靠在线页面签票。它用托管方的服务身份接入；每个对话必须带发起成员的身份证明，由文档服务核验；它在这个对话里能做的不超过该成员本人的权限；改动署名为「〈成员名〉的云端 Agent」，成员列表里看得到。不复用任何成员的项目凭证，不把集群令牌带进数据面。创建者关掉开关、项目删除后，对应的对话立刻失效；成员被移出后该成员失去对话访问与发言权，任务按下述 2026-10-08 共有/私有例外处理，其他有效共有成员不受连带限制。

**2026-10-08 账号任务新增共有/私有权限。** 云端 Agent 对话默认共有，可主动设为私有；共有允许同项目所有已登录且有项目权限的成员查看完整历史、回复并发送，每条消息记录实际发送者；私有仅所属账号可访问和发送（例外：项目创建者能看、不能发）。H 的“发起成员”在共有对话中按每轮实际发起者核对，只核对他此刻是不是这个项目的有效成员；云端 Agent 能做的事对所有成员都一样，项目创建者发起的和参与者发起的没有区别，创建者特权 Agent 一律做不了（2026-10-08 用户定；原写「不能让其他成员借对话创建者的权限执行」读起来像成员之间权限有高低，作废）；单个成员旧授权失效不等于全部共有成员都失效。具体任务/接口/验收见 `account-binding-task.md`、`account-binding-contract.md`。这里只同步新决定，未实施功能。第四阶段没做完的约 25 个云端 Agent 工具并入 0.7.18（2026-10-08 用户定），见 `account-binding-task.md`「三个版本」。

**改密退出与被踢的例外。** 已发送且被 Agent 读到的消息保留；私有任务直接中止，共有已读消息触发的当前任务及其修改不撤回、继续执行。旧用户登录仍失效，被踢账号全部设备仍不能访问项目，均不能发新消息或启动下一轮；项目删除、关闭 Agent 的终止规则不被豁免。具体读状态、任务关联与授权机制在账号契约落清。

**2026-10-08 用户定的两件（原先在交接文档里列为「要用户定做法的」）。** 一、云端开子 Agent（`spawn_agent`）先关闭，三个版本都不做，记为 0.7.20 之后的待办；云端 Agent 调到它时回明确的「云端暂不支持开子 Agent」。二、云端素材采集缺省不带登录态，按未登录能拿到的清晰度下载；需要登录态时，让发起人的电脑代下（登录信息不出他的电脑，要他在线），这条做不成或他不在线，就退回不带登录态。把登录信息上传到节点这条路记为以后再做。

**I. 界面范围。** 在线浏览器宽屏下右侧 AI 栏可用，接入方式多一项「云端」。手机竖屏不做，AI 栏保持现在的占位（竖屏界面另有计划，见 `TODO.md`）。项目放云端时，桌面版的 AI 栏也能选「云端」（为了下面的用户体验验收；本机 Agent 仍是桌面版的缺省）。

**J. 工具范围（2026-10-07 更正：原先写的「第一版不开放建卡改卡、导入素材、素材采集、配音」是会话的建议，被误记成用户的决定，作废）。** 用户定的是把 Agent 服务搬到云端，所以云端 Agent 的工具与本机 Agent 一致。唯一可以缺省的是**要操作发起人自己界面的工具**（选区、播放头、播放与暂停、网页接管这类）：发起方不在线时回明确的「发起方不在线」，Agent 据此继续，不卡住。其余都要能用，包括建卡改卡、导入素材、素材采集、配音、感知类工具、看画面（即时渲染）。确因节点条件做不了的（例如某个感知工具要的扩展包或模型节点上没有），逐项写明原因与差什么，记未达成，不事先排除。配套要求：

- 建卡改卡写出的源码会在别的成员的浏览器和渲染节点上执行，靠第二、三段的隔离保护，与本机 Agent 在协作项目里建卡是同一种风险，不另设限制。
- 工具在节点上读写的一切都按项目隔离：素材经素材服务、项目经文档服务；一个对话读写不到别的项目的文件，也读写不到节点上的系统文件、凭证与别的服务的数据目录。
- 能发网络请求的工具（素材采集、下载）不能访问节点的回环地址、内网地址与同机别的服务的接口。
- 配音等要花钱的外部调用用托管方的配置，用量一并记进 G 的用量记录。
- 以上几条并进第 4 条隔离验收，用探针断言。

## 用户体验验收（2026-10-06 用户定，整件事做成的标准）

**项目创建者把项目托管在云端，发出一个 Agent 任务，然后关掉软件，一切照常运转。** 拆开来是：

- 创建者在桌面版里（另用在线浏览器再验一遍）对一个放云端的项目，让云端 Agent 做一个要跑一段时间、会改多处并触发重卡重渲的任务；确认任务已被云端接下后，完全退出软件（桌面版连托盘一起退出；浏览器关掉标签页），电脑不再连着。
- 之后云端自己把事做完：Agent 的对话继续跑到结束，改动逐次落进文档服务；被改动的重卡由云节点的渲染服务渲出来、产物入库。全程不需要任何成员的设备在线。
- 这期间另一位成员从在线浏览器进项目：看得到改动一条条出现、署名是「〈创建者〉的云端 Agent」，画面是渲好的，不是占位。
- 创建者重新打开软件：回到同一个项目，看得到这段对话的完整过程与结果，项目是最新版本，预渲染结果已经在；撤销能撤掉 Agent 的改动。
- 创建者中途想停：重新打开后能停掉还在跑的对话；也可以在另一台设备上打开同一个对话接着看、接着说。
- 出了错不悄悄丢：模型调用失败、额度用尽、渲染失败、创建者中途被移出或关了开关，对话记录里留下明确的原因，项目停在一个完好的版本上。

为此设计里要定清：对话与任务的状态存在云端、不依赖发起方的连接；发起方离线后身份证明怎么持续有效、多久失效（H 条的核验不能要求成员一直在线，但成员被移出、开关被关时必须立刻失效）；读页面状态的工具在发起方离线时怎么降级；重新打开后怎么找回对话。

这一节用一个端到端探针固定下来（真实地结束发起方的进程，不是假装断线），作为以后改动 Agent、渲染服务、托管端时的回归项。

**K. 诊断报告（2026-10-07 用户定）。** 云端对话与本机对话都能出诊断报告，两种去向都要有：下载到本地；一键「报告」提交到收集端存起来。提交复用仓库现有的诊断报告收集端（`tools/report-worker/`，桌面版「诊断」窗口的「提交」用的就是它；取回用 `report-inbox.bat`）。在线页面里报告在页面内生成，下载与提交都不经编辑器进程的 `/api/*`。报告内容是这段对话的过程、出错原因、客户端与版本信息；不含凭证、票据、模型 Key，用单测断言。本机 Agent 的对话原来若只能出整机诊断、不能按对话报告，这次一并补上。

## 完成条件

每一条的证据直接贴在对话里。

1. 设计与契约（`docs/plan/` 下）先写好再动手，定清：Agent 服务独立入口的形态与对外接口、鉴权；按「用户 × 项目 × 对话」分实例，原来进程级的全局状态（绑定的项目、审查环路锁、额度熔断、登录状态、配置、对话记录）各自怎么改；H 的认证流程与文档服务侧的核验；G 的检查点与用量记录的格式；在线页面到 Agent 服务走哪条通道、凭什么不违反「在线页面不请求编辑器进程的 `/api/*`」这条契约的本意、守卫与棘轮清单怎么改；对话记录存在哪、谁能读；节点上的资源上限。
2. 与后续工作的约定：独立入口对前端代码的依赖只经一处载入缝（现在是 `server/agent/ssr-host.mjs`），不新增别的直接引用；云节点上照旧跑 Vite 来载入工具实现；不动桌面壳。

## 没过怎么办

- 小问题在分支上修掉、补测试、继续。按 `guide_files/solution_table.md` 试过仍不过的非核心项，记未达成，不挡合入。
- 核心项不过就不部署到新节点、停下告诉用户：第 4 条隔离验收任何一条不过；桌面版的 Agent 行为退步；Agent 服务会拖垮同机的文档服务或素材服务。部署后出问题就先停掉 Agent 服务进程、在线页面退回上一版，再查。
- 改动若碰到本文没列的用户可见行为，先停下问用户。

## 规矩

- **重启新节点的托管服务之前，先确认没有正在写入的客户端**：用户桌面上开着的 PromptCut（端口 5210）可能正在编辑放在新节点上的项目。只读查询 `http://127.0.0.1:5210/api/agent/status` 与 `/api/media/upload-queue`（不发任何写请求、不动这个软件），等 Agent 对话不再提交、上传队列空闲、项目版本连续 5 分钟不变再重启。等满 3 小时仍在写，就停下告诉用户。等的时候先做别的。
- 不碰用户在跑的东西：端口 5190～5192、5210～5212、用户装的 PromptCut 及其数据目录、不是自己启动的进程。测试进程静默运行。
- 新节点是在用的生产环境：验证只用测试房间与测试凭证，验完删掉；改动前先备份。阿里云不碰。防火墙与系统安全设置不改，需要用户做什么把命令写给用户。
- 令牌、密钥、密码、模型 Key 的值不打印、不进提交、日志或消息。
- 子 Agent：日常用 `sonnet-dev-high`，核心难点用 `opus-dev`（主计划 0.2 节）。独立入口的多实例改造、身份与隔离这两块用 `opus-dev`。

## 用户要知道的

- 云端 Agent 的工具与本机一致（见 J）。它会用托管方的 Key 调模型，配音等也用托管方的配置，都是用户的费用。
- 现在不设上限意味着：任何能进云端项目的成员都能用托管方的 Key 跑模型，直到按项目发上限为止。对外开放之前先把上限发下去。

2026-10-06 用户定。在新云节点上做出云端 Agent 服务，让在线浏览器（宽屏）用户的右侧 AI 栏经它工作，出一版并实测，然后停下汇报。规则以 `docs/semantics/guide_files/` 为准，本文只写这件事的范围、用户的决定和验收。

## 做法与验收节奏（2026-10-06 用户改定；与下文冲突时以本节为准）

本任务是四段中的第四段，与 `sound-online-render-task.md` 的三段**作为一个目标连着做**。做法与验收节奏以那份任务书开头的「做法与验收节奏」一节为准：过程中只做轻量验收，不合入 main、不出版本、不动新节点；合入、出 0.7.18、部署 Agent 服务到新节点、在新节点上的实测、模型 Key 的录入，都在最后那一次完整验收里做。下文「前置」里说的三段，指的是集成分支上已经做完的前三段，不要求它们已经发版或已经部署。

## 用户定的（语义照此改写，不用再问）

**E. 云端 Agent 从愿景变成承诺。** `product/agent.md`、`architecture.md`：托管方提供云端 Agent 服务，跑在云节点上；在线浏览器的用户在 AI 栏里选它，对话与工具调用由它执行，改动经文档服务落地。桌面版仍默认用本机 Agent，行为不变。

**F. 模型。** 用托管方（用户）的 Key，服务端 API 直连（`server/harness/`），不用命令行订阅。Key 只放在节点上，按现有的加密封装保存，不进仓库、日志、消息；由用户自己在节点上录入，会话准备好录入的办法并告诉用户怎么做，不要让用户把 Key 发给会话。

**G. 上限。** 现在不设，优先跑通，但接口要在。每个项目有「云端 Agent」开关（缺省开，创建者可关）和一个额度字段（缺省不限）；所有对话与模型调用都经过同一处额度与并发检查，这处检查现在永远放行；用量按项目、按成员记下来，可查。以后用户按项目发上限时只改配置、不改代码。

**H. 身份。** Agent 服务自己持凭证连文档服务，不靠在线页面签票。它用托管方的服务身份接入；每个对话必须带发起成员的身份证明，由文档服务核验；它在这个对话里能做的不超过该成员本人的权限；改动署名为「〈成员名〉的云端 Agent」，成员列表里看得到。不复用任何成员的项目凭证，不把集群令牌带进数据面。创建者关掉开关、成员被移出、项目删除后，对应的对话立刻失效。

**I. 界面范围。** 在线浏览器宽屏下右侧 AI 栏可用，接入方式多一项「云端」。手机竖屏不做，AI 栏保持现在的占位（竖屏界面另有计划，见 `TODO.md`）。桌面版的 AI 栏这次不加「云端」选项。

**J. 第一版开放的工具。** 读项目与改项目的工具（时间轴、片段、卡片参数、效果、素材引用这些经文档服务落地的）。暂不开放、明确回「云端暂不支持」的：要读写节点本地文件的、网页采集与网页接管、语音识别与配音、建卡改卡（会写出要被执行的源码）、SKILL 相关。Agent 看画面（即时渲染）与读页面状态（选区、播放头）是这一版的可选项：做得稳就带上，做不稳就记未达成，不挡发版。

## 完成条件

每一条的证据直接贴在对话里。

1. 设计与契约（`docs/plan/` 下）先写好再动手，定清：Agent 服务独立入口的形态与对外接口、鉴权；按「用户 × 项目 × 对话」分实例，原来进程级的全局状态（绑定的项目、审查环路锁、额度熔断、登录状态、配置、对话记录）各自怎么改；H 的认证流程与文档服务侧的核验；G 的检查点与用量记录的格式；在线页面到 Agent 服务走哪条通道、凭什么不违反「在线页面不请求编辑器进程的 `/api/*`」这条契约的本意、守卫与棘轮清单怎么改；对话记录存在哪、谁能读；节点上的资源上限。
2. 与后续工作的约定：独立入口对前端代码的依赖只经一处载入缝（现在是 `server/agent/ssr-host.mjs`），不新增别的直接引用；云节点上照旧跑 Vite 来载入工具实现；不动桌面壳。
3. 独立入口：Agent 服务不带编辑页也能起，带鉴权，多个用户、多个项目、多个对话同时跑互不干扰。桌面版改用同一个入口，用户看到的行为不变：桌面版与 Agent 相关的全部测试与探针不变红。
4. 隔离验收用探针断言：成员甲的对话读不到、改不了成员乙没有权限的项目；一个项目的对话拿不到另一个项目的内容、素材与对话记录；伪造或过期的成员身份证明被拒；只读成员发起的对话改不了项目；创建者关掉开关后正在进行的对话被停掉。
5. 在线页面：宽屏下右侧占位换成可用的 AI 栏，接入方式有「云端」；发消息、流式回复、停止、工具调用的过程显示、对话记录的重开，都可用。手机仿真下仍是占位。守卫与棘轮清单按设计更新，在线构建不带出桌面专用的调用。
6. 端到端实测：桌面版建协作项目放云端；在线浏览器成员在 AI 栏里让云端 Agent 改项目（改文案、挪片段、调卡片参数各一次）；桌面版与另一个在线成员都看到改动，署名正确；撤销语义与本机 Agent 一致；两个成员同时各开一个对话互不串；Agent 服务进程被杀后自动拉起，进行中的对话明确报中断、可以重开。
7. G 的接口验收：把某个测试项目的额度临时设成一个很小的数，超出后请求被明确拒绝并告诉用户原因；设回不限后恢复；用量记录里查得到这几次调用的项目、成员、模型与用量。
8. Key 的录入办法写给用户并由用户执行；在用户录入之前，用仓库里现有的模拟模型提供方把第 3～7 条先跑通；用户录入之后再用真实模型把第 6 条跑一遍。
9. 节点资源：Agent 服务有并发与内存上限；满载时同机文档服务的响应时间与素材下载速度的前后对比，写明数字。
10. 语义按 E～J 改好；`c10-contract.md`、`c10a-contract.md` 等受影响的契约同步；`draft_cloud-node-and-agent.md`「步骤 3」里做完的部分标明出处，没做的（看画面、页面状态工具、未开放的工具、手机界面、按项目发上限的界面）留在那里写清差什么。
11. tsc、npm test、`npm run build` 全过；按 `verification.md`「按改动范围验证」只跑这次改动覆盖的探针，这次不改画面，不跑渲染附加项。
12. 合入 main，出下一个版本号的补丁；新节点上部署 Agent 服务（独立进程，改动前备份，按「规矩」等写入停止后才重启托管服务），在线页面换成同一版并核验；release 判过并推进；`server/hosted/deploy/` 的模板与 `hosting-migration.md` 补上 Agent 服务这一块；`docs/local.md` 记节点上多出的进程与目录。
13. 写报告，含〔裁〕清单；播报后停下，列出：每项结果、没过或没做的项与原因、补丁信息、要用户做的事。

## 没过怎么办

- 小问题在分支上修掉、补测试、继续。按 `guide_files/solution_table.md` 试过仍不过的非核心项，记未达成，不挡合入。
- 核心项不过就不部署到新节点、停下告诉用户：第 4 条隔离验收任何一条不过；桌面版的 Agent 行为退步；Agent 服务会拖垮同机的文档服务或素材服务。部署后出问题就先停掉 Agent 服务进程、在线页面退回上一版，再查。
- 改动若碰到本文没列的用户可见行为，先停下问用户。

## 规矩

- **重启新节点的托管服务之前，先确认没有正在写入的客户端**：用户桌面上开着的 PromptCut（端口 5210）可能正在编辑放在新节点上的项目。只读查询 `http://127.0.0.1:5210/api/agent/status` 与 `/api/media/upload-queue`（不发任何写请求、不动这个软件），等 Agent 对话不再提交、上传队列空闲、项目版本连续 5 分钟不变再重启。等满 3 小时仍在写，就停下告诉用户。等的时候先做别的。
- 不碰用户在跑的东西：端口 5190～5192、5210～5212、用户装的 PromptCut 及其数据目录、不是自己启动的进程。测试进程静默运行。
- 新节点是在用的生产环境：验证只用测试房间与测试凭证，验完删掉；改动前先备份。阿里云不碰。防火墙与系统安全设置不改，需要用户做什么把命令写给用户。
- 令牌、密钥、密码、模型 Key 的值不打印、不进提交、日志或消息。
- 子 Agent：日常用 `sonnet-dev-high`，核心难点用 `opus-dev`（主计划 0.2 节）。独立入口的多实例改造、身份与隔离这两块用 `opus-dev`。

## 用户要知道的

- 第一版里云端 Agent 不能建卡、改卡：它写出的源码会在别人的浏览器和渲染节点上执行，这条口子先关着。
- 现在不设上限意味着：任何能进云端项目的成员都能用托管方的 Key 跑模型，直到按项目发上限为止。对外开放之前先把上限发下去。

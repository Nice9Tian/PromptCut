## 实现后的更正（R2、R4 前半已落地，2026-09-22；和正文冲突时以这里和代码为准）

- **非 legacy 的开关是 `?preview=stage`**（`src/editor/previewMode.ts`）；不带参数、`?preview=legacy`、别的值都是 legacy。R7 才把默认翻过来。舞台端口 = 编辑器端口 +1 / +2（`server/stage-ports.mjs`、`server/vite-plugin-stage-ports.ts`）；端口被占就不起那一个代理、页面退回同源单舞台。**起 dev server 要给 +1 / +2 留空**（`npm run preview` 因此从 5191 挪到了 5195）。
- **`setRole` 的 `job`**：RPC 上是 J4 的三个值 `'probe' | 'catchup' | 'bake'`；父页的单飞队列（`src/editor/stageJobs.ts`）分三档「补跑 > 页面侧测量 > 探针」，测量这一档在 RPC 上映射成 `'catchup'`。

## 总规则：舞台像直播一样异步，永远不等

编辑器里的预览舞台是**消费者**。播放头由可见舞台按帧推进（K4），每一帧对每一层只问「此刻手里有什么」：有就显示，没有就这一层透明（或按 C4 回溯），来了就替换。死素材缺了不能让播放头等；只有轻卡自己的一拍可以让下一拍等（不跳帧）。**编辑界面不是不能渲染，而是一切渲染都异步：用户交互不允许有任何卡顿，舞台渲染和用户交互操作之间异步（pinned 渲染 1；落法：舞台在自己的进程里，交互永远不等舞台），唯一允许的退化是播放器画面来不及渲染（某层透明或沿用旧快照）；加载阶段的测量遮罩是 pinned 渲染 1 明写的例外。**

- **舞台 iframe 里是完整场景**：舞台页渲 `FrameScene` 的活播放变体（E7）。主文档只留音频。
- **可见舞台按 K 的分派分两条管线处理。** 轻管线：活渲——direct 卡按 `t` 求值，轻的 stateful 卡推帧；跳转时轻卡当场按片段重推（一拍内、帧间只让微任务、中间态不画出来），重卡贴死素材，可见舞台里永远看不到推帧过程（K3）。重管线：组件挂着、子树被藏，播放时贴流平面（G，E7 第 5 条：每个重控件一条上下拼合 alpha 的 H.264 流、裁到实体框），拖动时贴快照平面（E7 第 4 条：每个重控件一份 HTML 快照、只含该控件子树），暂停下来后追到精确活渲（K5）——这就是 pinned 渲染 10 的两种形态；死素材由预渲染管线按预渲染集合整段产，热舞台只在该位置判重时才贴它；`unknown` 卡（审阅表没覆盖到的卡——用户定制卡、带部件的组合卡片段在真实项目里都是它）**一律按 `belowDependent` 处理**：照 K1 实测、照 K2 分派，判轻就活渲，判重用本地档快照，不上云、不进流。**图卡（H，接替 Python 卡）是普通 `CardDef`，同样按实测分派；第 2b 步之后不再有「Python 卡」这一类。**
- **可见舞台是热的播放器舞台，播放由它按帧节拍。** 轻卡在它里面活跑，重卡播放和拖动中贴死素材、暂停下来后由后台舞台整场景补跑、互换成精确活渲（K5）。每一拍渲完才推进 1/fps，封顶项目 fps，慢帧就等、不跳帧、不往前冲（K4）；store 的 `t` 跟舞台报的帧，音频和 `<video>` 按墙钟播、偏差超过 1.5 帧就重对齐——这就是允许的「小卡」。**历史推进只在预渲染者做**（预渲染进程；将来后台 iframe 的 `bake` 角色）；推帧的卡在可见舞台里用自己子树的虚拟时间在快照平面后面追（K5 第一路），全局时钟不动；探针判定推不动的卡（Motion 的 JS 驱动动画）才由后台舞台整场景补跑后互换（K5 第二路）。
- **预渲染者是角色，不是进程；预渲染是辅助，不是主路。** 预渲染者的工作单位是「(片段, 本地帧) → HTML 快照」。播放时全力给播放头前方铺路（C4 的 `wanted` 优先）；空闲时不闲置——把有状态卡（React 不能按任意 `t` 重算的 DOM 产出：Motion、Lottie、`context` 毛玻璃）逐帧打包成 HTML 快照，直到全项目就绪，之后按 `localRev` 变化增量补。本地模式的宿主是预渲染进程（Node + Chrome；`user` / `full` 模式做 PNG 和轨道流，`agent` / `full` 模式做 Agent 看图）；在线浏览器模式的宿主是后台 iframe（只做 HTML 快照，没有轨道流，目标 L）。两种宿主都在本任务里，目标 J 保证它们驱动同一份预渲染页。
- **预渲染进程不可用时舞台照常**：轻卡、素材层、点选拖动在本地；重卡层没有死素材时透明。同源退回删除。
- **编辑器进程（Node 侧）不再有无头 Chrome 热池；预渲染进程给轨道流自建池**（D5）。页面侧的热渲染是可见舞台 iframe，两者不是一回事。
- **舞台就是 `StageView.tsx`**，露出来；推帧在 `front` 只为轻卡、在 `back` 只为探针，角色是运行时状态（K）。

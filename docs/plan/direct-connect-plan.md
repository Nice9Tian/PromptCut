## 目标

- **不依赖阿里云托管**：将来部署一台自有的 Ubuntu 服务器，只跑牵线模块。共享项目的主机可以是任何有公网可达性的成员机器，从而不依赖阿里云托管。
- **两种互联网模式将来并存**：阿里云托管和自有牵线，新建共享项目时多一个选项。
  - 选自有牵线时，三种直连都不通的，除了锁为局域网模式，也可以改选阿里云托管。〔搬出后注〕
- **不中继**：牵线服务不保存项目内容，不中继任何消息或字节；每种接入方式不通时，都能说清为什么不通。

## 设计要点

〔裁〕是当时主会话在 D10 授权范围内定的。

1. **牵线模块** `server/docservice/modules/rendezvous.mjs`，挂在远端文档服务上（主执行计划第 5.4 节的通用挂载）。
   - **每个共享项目只存一条登记**，字段是：
     - 项目名：全局唯一，不分大小写；
     - 主机密钥的哈希：主机密钥由创建时的主机生成，只存在主机本机；
     - 模式；
     - 每种方式的地址与测试结果；
     - 最近在线时间。
   - 不存密码，不存项目内容。〔裁〕
   - 主机用主机密钥证明自己，才能改登记（换地址、删项目）。项目名 30 天没有主机上线就释放。〔裁〕
   - **自有牵线服务器只挂这一个模块**；阿里云托管照旧挂队列、项目、内容等全部模块。部署脚本按参数选挂哪些模块。〔搬出后注，原文是「正式部署只挂这一个模块」〕
2. **三种方式与创建时的测试**：牵线服务对主机逐种测。
   - **端口映射**：
     - 先用 UPnP IGD 自动映射，用 `node:dgram` 发 SSDP、用 `node:http` 发 SOAP；
     - 不行就用用户在路由器上手工做的映射；
     - 牵线服务从公网回连映射出来的地址，要求对端答出一次性随机数，才算通。
   - **IPv6 直连**：主机报出自己的全球单播 IPv6 地址，牵线服务从 IPv6 回连。
     - 这一项要求牵线服务器有 IPv6；没有的话，这一项的原因写「牵线服务没有 IPv6」，而不是「主机不可达」。
   - **打洞**：
     - 主机从同一个本地端口连牵线服务的两个端口，比较对外映射的端口，判断 NAT 类型；
     - 端点无关映射判「可打洞」，对称 NAT 判「不可打洞」；
     - 真正的打洞在成员接入时做：`node:net` 带 `localPort` 的 TCP 同时打开，由牵线服务同时告诉双方对方的地址。〔裁〕
     - 先只做 TCP，这样上层的 WebSocket 不用改；TCP 实测成功率不够再评估 UDP，那要另加一层可靠传输，可能要引依赖，届时先问用户。
   - **三种都不通**：逐条列出原因码与人话说明，项目锁为局域网模式（或改选阿里云托管，见「目标」）。
3. **成员接入**：
   - 按「同网段发现 → 端口映射 → IPv6 → 打洞」的顺序逐种尝试，用第一个通的；
   - 每种方式限时 5 s，整个过程 ≤ 20 s〔裁〕；
   - 全部不通时，逐条返回每种方式的原因码与说明，不退回中继。
4. **局域网模式与局域网发现**。本条是局域网发现方案的唯一出处，主执行计划 SP 阶段引用本条，不另写。
   - 不经公网。主机在本网段用 UDP 组播广播「项目名 + 主机设备名 + 地址」，成员按项目名找到主机；
   - 同名项目并列显示主机设备名，由用户挑〔裁〕；
   - 组播地址、端口和广播间隔写在 SP 阶段的契约里（主执行计划第 7 节 SP）。
5. **主机侧绑定**：
   - 共享项目的主机，文档服务和素材服务要绑非回环地址；
   - 绑定时必须已加载 D9 的项目凭证，否则拒绝启动。这是 M5a「失败即关」的延伸。
   - 〔搬出后注〕原文还要求已设集群令牌；按 D9 第 8 条的修订，成员连接不再要求集群令牌。
6. **依赖**：只用 Node 内置能力（`node:net`、`node:dgram`、`node:http`、`node:os`）。要装依赖先问用户。

## 跨机验证

- 一台有公网可达性的机器作主机，建自有牵线模式的共享项目，回传创建时三种方式的测试结果；
- 另一台换到手机热点，回传每种方式的尝试结果。

## 验收

| 编号 | 场景 | 标准 |
|---|---|---|
| N1 | 创建时测试（本机模拟每种失败） | 契约里的每个原因码都至少有一条用例：制造对应的故障时恰好报出它；三种都失败时项目锁为局域网模式，原因逐条出现在结果里 |
| N2 | 牵线服务不存内容、不中继 | 守门测试：牵线模块 0 处引用队列、项目、内容、素材模块；登记记录的字段与白名单完全一致，不含任何密码字段。跨机验证期间牵线服务转发的项目消息 0 条，素材字节 0 |
| N3 | 成员按顺序尝试 | 本机模拟「只有第 k 种通」（k = 1～4）：每次都用第 k 种接上，前面各种都各有一条原因；全部不通时 4 条原因齐全，且不出现中继连接。接上的耗时 ≤ 20 s |
| N4 | 局域网模式 | 同网段成员 5 s 内发现并接入，全程不连牵线服务（牵线服务的连接数计数不变）；不同网段的成员发现不到 |
| N5 | 凭证 | 接上主机但不交项目凭证、交错凭证，都被拒；主机绑非回环地址而缺项目凭证时，进程退出码非 0 并打出原因（〔搬出后注〕原文另有「不带集群令牌被拒」一项，已按 D9 第 8 条的修订去掉） |
| N6 | 主机换地址 | 主机的公网地址变了（模拟），重新登记后，新成员 10 s 内按新地址接上 |
| N7 | 跨机，局域网模式 | 通过；与 N4 同标准 |
| N8 | 跨机，自有牵线模式 | 成员在手机热点下经牵线接入。**满足任一条即算通过**：<br>① 至少一种方式接上，且在上面完成一次项目快照读取和一次带票据的素材读取；<br>② 全部不通，但每条原因都与人工核对的实际网络状况相符（例如运营商级 NAT 判为对称 NAT）。<br>无论哪种，报告里都贴上三种方式各自的原始结果 |

- G0 通用门槛（主执行计划第 8 节）。本计划不动渲染路径，G0-R 不跑，报告写明。
- **浏览器**：浏览器没法用 Node 的 TCP 同时打开，打不了洞，只能用端口映射、IPv6 或局域网接入；验收要覆盖「只剩打洞能通时，浏览器得到明确提示」这一情形。

## 2. 渲染重构

### 2.1 撤快照与测试

- **撤快照直接撤**，不挪到发版之后。
- **真手机测试搁置**。原话：「我发现手机版UI还没做。手机实测先搁置，在本机测即可。」撤快照之前改用本机模拟手机测，过了就撤：
  - 在 `page-stream-probe` 的 `lowmem` 一场之外加一场「模拟手机」：浏览器设备模拟（约 390×844、触屏、安卓 Chrome 的标识）、页面加载前把 `navigator.deviceMemory` 报成 4、CPU 降速到 1/4～1/6、网速按 4G、给页面脚本内存设上限并记峰值。
  - 过关标准沿用 `docs/reports/AGENT-rr-lowmem-streams.md` 第 7 节：不报错、五张同屏时 4 张有画面、页面内存不超过 25 MB、每拍第 95 百分位小于一帧（30 帧的项目 33 毫秒）。
  - 测不了的：手机的视频解码器（用的是这台 PC 的显卡），写进报告。
  - 可选：安卓模拟器测功能（安卓 Chrome 认不认浏览器自带的编码器、能不能产流解流、触屏和手机档判定）。这台 PC 的 CPU 虚拟化已在主板里打开，但 Windows 的「虚拟机监控程序平台」没开，**要用户自己打开并重启**（改系统设置，会话不做）；模拟器和带 Chrome 的系统镜像约 6～10 GB，装在 D 盘，下载前问用户。模拟器限制成 2～4 个 CPU 核心（用户提的），内存按中端手机设，让速度更接近手机；但它跑的仍是这台 PC 的 CPU 和显卡，速度、发热、解码器上限只能当参考。iPhone、iPad 测不了。
- **整个画面的 HTML**：
  - 浏览器里为取像素临时生成 HTML 快照、画成位图就丢的那一步保留（网页不能给自己截图），不存、不当产物。
  - 导出确定性的基线脚本从比 HTML 文字改成比像素。
  - 预渲染小尺寸（从每张卡的 HTML 快照缩出来的）随撤快照删掉。
- **导出开头一秒多两次导出可能差一帧**（前 36 帧里带入场动画的卡）：这次查根因并修；查不出记未达成，不挡发版。修好以后导出比对恢复成只认一种结果。

### 2.2 舞台与在线导出

- 原话：「直接就把舞台改造成隔离的。抛弃隔离舞台。拿不准你自己做测试评估。」
- 读法：在线浏览器里所有舞台一律跨源隔离，不再分「隔离舞台」和普通舞台；「退回同源的单舞台」那条退路去掉（交接文档第 7 节第 5 条说那条路上没有闸，一并堵上）。别人同步来的用户卡、素材效果卡在任何舞台都能执行。
- **在线导出在隔离舞台里整帧渲**：所有卡连同素材一起画，像素交给导出页压视频，不再因为「导出页不执行同步来的卡」去等渲染节点。要先自己验三处：隔离舞台里能不能整帧取成像素、跨源的素材视频画进画布后能不能取像素、性能。拿不准自己做测试评估；做不到的部分才退回「独立卡浏览器借隔离舞台渲、其余找渲染节点」并报用户。「导出位图」那条渲染节点的路只作退路，评估后用不上就拿掉。
- 「快速导出 / 完整导出」照 10-13 的决定保留。

### 2.3 轨道流：谁产、关着时怎样

- **「生成轨道流」没打开时，托管方的渲染节点完全不为这个项目产流**（推翻 10-13 第 1 节第 3 条按「甲」的读法，以及进度文件待用户项 1.6）。
- 流存在云端素材服务里，谁产的都能用：桌面版、电脑浏览器以前产过的流，手机打开项目时直接贴。只有从来没有任何设备给这张卡产过流时，播放才是占位。
- **手机、平板也给本页产稀疏版**。「本页」指这台设备当前打开的项目、它要播放的重卡；不替别的项目、别的成员干活。语义和任务书里「身份为手机的页面不产流」要改。
  - 原话：「我认为H264一般手机平板都支持。可以默认支持。」页面开工前照旧问一次浏览器能不能编，答不能就不产。
  - 分工（用户认可）：手机、平板只产稀疏版；满密度版由电脑这一类设备补。
  - 先用 2.1 的本机模拟手机验；做不到的报用户。
- 两句提示（用户认可，一级原文）：
  - 设置里：「没有打开：托管方的渲染节点不为这个项目生成轨道流，播放时用成员们各自设备生成的轨道流。打开后托管方也会生成，重卡在在线浏览器里播放更流畅，会多用云端的渲染时间。」
  - `workflow/project.md`：「渲染节点下面另有一项『生成轨道流』，缺省关，创建者可以打开；没打开时托管方的渲染节点不为这个项目生成轨道流，播放时用成员设备生成的轨道流。」
- **权限分组（新功能，这一版做）**。原话：「根据项目创建者权限来匹配可不可以开。给每个账号加一个"权限分组"。不在分组的不能开。」要在 VisuHive 的账号后端加。默认：
  - **做一个网页后台**（用户选乙）：托管方（用户本人）登录网站就能给账号加进组、移出组。只有托管方的账号能进这个后台。
  - 新账号默认不在组里；用户本人的账号放进去（默认）。
  - 创建者不在组里时这一项灰掉，提示（草稿）「你的账号没有开启这一项的权限，请联系托管方。」
  - 已经打开、创建者后来被移出组的项目按关着处理；已经产出的流照旧能用。
  - 这次只管「生成轨道流」这一项。

### 2.4 预渲染的切分

- **motion 式的卡允许拆开并行做，一个任务至少 30 秒**（按项目时间，30 帧的项目是 900 帧）。原话：「15帧一段也太短了？我觉得至少30s（30fps就是900帧）我的回答是允许拆开。」比 30 秒短的卡整张由一台设备做。
- 这里说的是任务的切分长度（现在是 `STREAM_SEGMENTS: 8`，8 个分段 = 120 帧）；轨道流自己的分段（15 帧，关键帧间隔、稀疏版的取样间隔）不变。**remotion 式的卡仍是 8 个分段（30 帧的项目 4 秒）一个任务**（用户选甲）。
- **强的设备可以抢弱的设备领着的产流任务**。原话：「将来按照算力匹配。强算力做完了可以直接抢弱算力的设备的活。现在按照设备匹配。桌面版做完了可以直接抢电脑浏览器（优先做所有轨道流的稀疏，之后产完整轨道流）。」「不放手，但是允许被抢。」
  - 浏览器在用户播放时照旧不产、也不主动放手；桌面版做完自己的活以后，可以把电脑浏览器领着还没做完的产流任务接过去，浏览器已经推上去的分段留着用，不作废，被接走以后浏览器停下这一份。
  - 先后不变：所有流的稀疏版先做完，再做满密度版。
  - **优先级（用户定）：桌面版 > 托管方的渲染服务（「生成轨道流」打开时）> 浏览器；左边的可以抢右边的。** 读法：电脑浏览器和手机、平板同属「浏览器」一级，彼此不抢。
  - 按算力匹配记待办（第 4 节）。
- 「motion 式」「remotion 式」是现行名词（术语表），不要再说「有状态的卡」「靠动画库推进的卡」。

### 2.5 其它渲染决定

- **画布卡产流一律直接取像素**（推翻缺省的 `auto`：不再每段比快慢）。铺满画面的卡会慢 8% 左右，画面不变。
- **合并流先不做**（认可进度文件待用户项 1.5 的做法：先做「按像素量算预算、流层共用一个画图上下文」，已合入 `d92bcab8`）。
- **暂停时更好的结果原地换上**（认可 S1）：只管当场渲不出来或一时渲不完的情况（本页运行不了的卡、省内存模式和最低一档、很深位置的 motion 式卡推到当前帧之前）；换上的一律向左对齐，只取不晚于当前帧的画面（`streamPlayer.ts` 现在就是「只往回找」）。改语义时写清它是兜底规则，不影响「停下就精确」。
- **拖动时自己浏览器在产的流不被别的机器接走**（认可 S2）。
- **Agent 看画面早一帧**（`see_frames` 等拿到的第 f 帧等于整段导出的第 f+1 帧，交接文档第 7 节第 1 条）：修，修完过导出像素比对。
- **`bake_card` 和 3D 贴图**（推翻 10-13 第 1 节第 1 条「当场出图」的读法）。用户选「甲，这次就做」：
  - 播放时从这张卡的轨道流里取，稀疏版也行，向左对齐；没有流时先占位。
  - 暂停时当场渲当前帧（和 2D 预览「停下就精确」一致）。
  - 导出时每帧渲清楚的，不从流里取。
  - 开了 3D 模式以后轻卡也产流。
  - 贴图跟着播放动，不再定格在 `t`；`bake_card` 的工具说明跟着改。
  - 用户知道从流里取的图因压缩会略糊。
- **叫法**：统一说「HTML 快照」（抄下来的网页元素）和「PNG 快照」（`bake_card` 出的图片）。术语表两条都加；代码注释、报错、工具说明里的「卡片快照」跟着改（「它是一张快照，不是活的」随上一条一起改）。代码标识符不受限。
- **在线浏览器导入素材：这一版做**（页面上传，浏览器里转视频小尺寸；评估在 `docs/reports/AGENT-rr-small-first.md` 第 3 节）。

### 3.1 云端 Agent

- **采集代下：打开**（选乙）。桌面版代下时显示一行提示，原文：「云端 Agent 正在用这台电脑上的登录下载：〈网址〉」。开之前照报告先补「撤回已经在传的文件」的接口。随之「把网页交给本人」也和代下一起上线（`AGENT-v18-tools-w2.md` 的建议甲）。
- **后台作业**：这一版照现在等作业做完才收尾，最多一小时，同一对话的下一条消息排着（选甲）。把作业交给单独一直在跑的服务（用户叫它「背景任务」）记待办。两句字（默认，草稿）：

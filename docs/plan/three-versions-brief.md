## 1. 要做什么

把「账号与云端项目」整体计划分三个版本做完，每个版本各自验收、合入、出完整安装包和补丁、部署。范围以 `docs/plan/account-binding-task.md` 的「三个版本」一节为准，这里只给一眼能看完的版本：

| 版本 | 一句话 | 主要内容 |
|---|---|---|
| 0.7.18 | 账号打底，浏览器能开项目，云端 Agent 补齐 | 云端项目一律走网站账号（桌面版、在线浏览器的新建、加入、搬到云端）；网站两张项目列表；踢人对账号生效；在线浏览器新建云端项目、和官网共用登录；旧云端项目清掉，旧文件打开转成本地项目；缺失素材占位；带上四段任务已做完的部分，并做完剩下约 25 个云端 Agent 工具；Agent 对话共有/私有、逐条记发送者、已读记录；被踢或改密退出时的任务处理；改密码或重设密码后选是否退出其它设备 |
| 0.7.19 | 在线浏览器不再分档，断网不丢改动 | 撤销低内存档，舞台、素材、即时渲染三道闸门，档位气泡；保存时固定非本机快照；断网改动保留，重连后用面板逐项选合入或丢弃 |
| 0.7.20 | 退出后的撤回，申请加入 | 改密或重设密码选了退出时，撤回这段时间旧登录做的修改（按修改项逐条核对）；被账号名单挡住的人发送申请，创建者在名单界面通过 |

## 11. 工作方式（2026-10-08 用户定，只管这次三个版本连做）

这一节是用户给本任务的专门安排。和 `guide_files/` 里的一般规则不一样的地方，以这一节为准；这一节没说的，照一般规则办。

### 小阶段做完就进 main

- **日常工作在分支上做。** 主负责人有自己的工作分支，要并行就多开几条；子智能体各在自己的工作区里。分支和工作区的用处是互相不踩。
- **一个小阶段做完，就合进 `main` 并推送。**「做完」指说得清做成了什么，并且过了基线（类型检查零错误、`npm test` 零失败；涉及渲染的看图或跑探针）。这一步用户已经授权，不用逐次问。
- 不要把做到一半的东西放进 `main`；也不要攒到一整个版本做完才合。小阶段的大小由主负责人把握，大致是一两个功能点、几十到几百行这个量级。
- 合并用 `--no-ff`，合并说明写清这个小阶段做成了什么。
- **工作分支也及时推送到远端**，免得只在这台电脑上有一份。
- 第一个小阶段：从集成分支 `claude/four-stage` 接着做。先把 `main` 合进它，冲突的 9 个文档照第 4 节的原则解，过基线，再把它合进 `main` 并推送。集成分支上标〔裁〕的地方原本要用户在合入前审；现在改为先合入，把〔裁〕清单整理进进度文件的「待用户项」，用户事后审，推翻的返工。
- VisuHive 仓库同样办。注意它的 `site/` 推到 `main` 后 5 分钟内自动上线，依赖新接口的网页要等后端装好再合（第 3 节）。

### 进度文件

- `docs/plan/three-versions-progress.md`。**每次往 `main` 合一个小阶段就更新一次，随那次合并一起进仓库。**
- 里面固定有：现在在哪、已经做了什么、本次做了什么、接下来干什么、还差什么、待用户项、没做到的与原因。
- 目的是任何人不看对话也能知道做到哪了。会话中断后接手的人先读它。

### 子智能体在工作区

- 派给 Luna、Astra 的活，每个一个工作区、一个分支，建在 `.worktrees/` 下，照 `guide_files/multi_agent.md` 办。它们不推送、不合并。工作区是防止几方互相改到对方文件的保护。
- 收回后主负责人读差异、自己重跑基线，通过了并进自己的工作分支，再随小阶段进 `main`。
- **用完的、废弃的工作区和分支及时清理。** 清之前核对三件事：分支的提交已经在 `main` 或主负责人的工作分支里（废弃不要的，在进度文件里写一句为什么不要）；工作区里没有未提交或未跟踪的文件；里面没有 `node_modules` 的目录联接，有就先只删联接本身。
- 第 4 节「留着但多半用不上的」那几条不是本任务建的，不要清。

### 发版与 release

- 每个版本验收通过后：改版本号并提交到 `main`，从这个提交出完整安装包和兼容补丁，然后把 `release` 快进到这个版本并推送（照 `git_and_release.md`「release 分支」，推进前判那三条合入条件）。
- 两次发版之间 `release` 留在上一个可用版本不动。
- **快进不了时不要停、不要强推**，照 `docs/plan/release-fallback.md` 办（另建 `release_<版本号>` 分支，`main` 照常往下做）。那份文档只在快进失败时才需要读。
- 发版时把耗时和机器配置记进 `docs/reports/release-timings.md`。

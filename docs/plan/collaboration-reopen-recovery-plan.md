# 多人协作项目重新打开与身份恢复修复计划

日期：2026-10-03

状态：修复计划，已完成静态完备性 review；尚未实施或运行验收。执行会话收到用户明确的实施指令后，按本计划执行。本文中的接口和字段是设计约束，具体契约须依据现有代码确定。

## 1. 目标与范围

1. 原主机用户在原设备重新打开项目后，自动恢复原房间，向云端托管服务重新登记上线，继续担任主机。成员能够进入同一个房间并继续协作。
2. 成员在自己的设备重新打开此前保存的项目后，自动找到原房间，以原身份重新加入。主机未上线时保留身份并等待，主机上线后自动重试成功。

正常自动恢复的前提是本机恢复凭证存在且有效，房间未删除，设备未被禁止进入，服务可以恢复。失去凭证后要求重新认证属于明确的异常恢复，不得伪装为自动恢复成功。

覆盖本机托管与云端托管、自由进入与限定进入、.proc、.procp、本地草稿、系统双击打开及页面刷新。纯在线浏览器沿用其加入入口和恢复机制，不增加语义禁止的本地文件打开入口。

区分创建者权限、实际主机设备和普通成员。云端托管项目由云端服务担任实际主机，创建者重新打开后恢复创建者身份，不把项目自动搬回本机。创建者在另一台设备打开本机托管项目时只恢复创建者连接，不自动接管主机。

## 2. 已核实的问题与证据边界

- `src/editor/io/proc.ts` 的 `ProcFile` 与 `serializeProc` 未保存协作房间关联；.procp 和草稿复用该格式。
- `src/editor/sync/syncManager.ts` 的 `onLoad` 切到普通本机空间，清空共享连接信息。
- `src/editor/sync/CollabSection.tsx` 依据当前 `shared` 连接判断协作开关，连接丢失被显示为未开启。
- `src/editor/sync/collab.ts` 将创建者密码及项目密码等保存到 localStorage，按共享房间 ID 索引；项目文件没有提供恢复关联。
- `syncManager.ts` 的现有恢复记录仅在 sessionStorage 中，不能承担关闭应用或重启电脑后的恢复。
- `server/auth/store.mjs` 已将账户校验记录单独落盘，不能将问题描述成所有服务端密码记录均未保存。
- `docs/plan/direct-connect-plan.md` 标为未开始；协作代码注明本机托管尚不向云端登记。此证据来自静态检查，执行前必须核验当前部署和最新代码。

本计划不能把云端登记、中继或主机持久化能力当成已经可用。若探针证实缺失，纳入本次目标的必要实施项；只完成文件保存不能算目标达成。

## 4. 持久化模型

### 4.1 项目文件中的非秘密协作描述

在 .proc 顶层新增带版本的可选协作描述，草稿与 .procp 复用。包含稳定房间 ID、托管服务标识、托管位置和必要的非秘密定位信息。项目内容 ID 与房间 ID 分开，不因另存文件或内容复制而混淆。

项目名仅用于显示和辅助查找，不能作为自动认证或自动绑定依据。旧地址只作提示，每次恢复应重新发现当前地址。描述中的角色和用户名不能授予权限。

读取器校验类型、版本、长度和 URL；未知版本保留可读项目并明确恢复不支持，不静默丢弃协作关联后再保存。外部文件提供的服务地址不能直接接收本机秘密凭证：先核对本机记录中已信任的服务身份或走明确认证流程。重定向、服务变化及房间 ID 不一致时不得泄露恢复凭证。

### 4.2 本机身份存储

按托管服务身份、房间 ID、本机用户配置和身份记录保存用户名、member/creator 身份及恢复凭证；主机额外保存主机登记密钥、原主机设备绑定与服务状态定位信息。

恢复凭证可以沿用有效派生密钥或经契约确定的专用凭证，但不得保存过期票据作为长期认证手段。现有派生 K 等同密码能力，必须按秘密保护。每次重入重新挑战认证、取得会话与素材票据。

桌面端优先采用实际可用的系统保护存储及稳定应用数据目录；先探针验证，不能凭假设选型。UI 来源端口改变、软件升级或页面存储清理，不应在桌面稳定凭证仍在时造成身份丢失。

保存应原子化、可重试；写失败明确提示下次需认证，不吞错。保留自动生成密码的查看能力，安全迁移现有记录。成员首次成功加入即保存身份，含通过邀请码加入的成员；邀请码失效不应自动撤销独立有效的成员认证能力。

多身份不可只按房间 ID 覆盖。明确匹配时恢复，存在歧义时选择一次并保存绑定。自由进入允许同名，不把用户名误当成唯一人的标识；保持现有凭证与设备身份语义，不暗中新增第三方账户体系。

### 4.3 主机与云端状态

主机稳定目录持久保存最新项目及版本、账户校验、邀请码、禁入状态、主机登记密钥及恢复元数据。定义备份、原子写入、损坏检测和升级迁移；不因运行副本更新丢失数据。

云端仅按现有产品语义保存登记、校验派生值、邀请码校验副本、禁入信息和主机在线租约，不存本机项目字节或可直接通过主机认证的秘密。

登记更新需验证原主机权限，同一房间更新而非重复创建。在线租约和主机占用冲突必须能阻止第二台设备自动抢占。具体超时、重试和租约参数写入三级契约并由探针验证。

## 5. 统一恢复协调器

所有受支持的打开入口使用统一流程，替代文件打开后无条件 switchToLocal 的路径。

流程：解析文件 → 校验协作描述 → 查本机身份及主机绑定 → 恢复服务或发现房间 → 重新认证 → 获取最新状态 → 接入同步及素材服务。

状态至少包括：未开启协作、恢复中、本机已恢复但云端登记待重试、等待主机、已连接、暂时离线、需认证、身份被拒、房间已删除、主机冲突、恢复数据损坏。

持久协作开关与瞬时连接状态分开；断网不显示为取消协作。真正恢复成功以服务可用、认证和同步握手成功为准，不能仅凭 WebSocket 打开或登记请求成功。

使用恢复任务标识防止过时异步结果：恢复中打开另一项目、回首页、取消协作或关闭页面后，旧回调不得修改新项目、重新登记或恢复旧身份。重复打开复用同一服务实例；重试幂等且遵守 rate-limit 的 Retry-After。

自动恢复不调用“新建共享项目”；创建初始化、正常重入、灾难恢复是不同入口。

## 6. 主机恢复与重新上线

1. 确认原主机设备绑定和凭证，加载原房间服务状态。
2. 恢复文档服务和素材服务，确认凭证已加载后才对远端放行。
3. 在本机以创建者身份恢复页面连接，保留房间 ID、版本、账户及邀请码状态。
4. 向云端更新同一房间登记和当前地址，同步产品语义要求的校验副本及禁入状态。
5. 启动在线租约维护；云端确认且成员接入链路就绪后显示公网可加入。
6. 局域网发现、公网直连及中继按现有产品语义工作；本次至少交付实际网络所需的可达路径，并验证无公网直连时可经中继访问。
7. 恢复 Agent、渲染节点、事件订阅和素材目标，确保它们不残留在普通本机空间或旧房间。

离线时本机协作照常，云端登记退避重试；网络恢复后自动补。地址变化刷新登记与成员路由。主机正常退出尽力注销在线状态，异常退出依靠租约过期，不删除房间或成员身份。

另一台设备不得自动接管；明确的主机迁移不是本次新建用户流程。服务状态缺失/损坏时进入恢复提示，不能自动生成新密码或新房间。项目文件不含全部权限状态，必须明确哪些能恢复、哪些需原备份或重新认证；不能声称仅凭快照完整恢复。

## 7. 成员恢复

成员保存文件时写入房间关联，身份存在各自设备。重开后按房间 ID 发现主机，用原有效凭证认证，获取服务端最新状态和新素材票据。

主机未上线或暂时无法连接时保留关联和身份，显示等待并退避重试，主机上线后自动加入。不把网络故障当成密码错误，不清除可恢复记录。

凭证过期或被修改时要求重新认证，成功后原子更新本机记录。被踢、移出名单、禁入或房间删除时停止无意义重试，保留本地内容并明确原因，不通过改名绕过权限。

新设备没有秘密凭证时只自动定位，认证一次后可自动恢复。创建者第二设备按有效创建者凭证加入，不启动主机。在线浏览器在既有入口恢复，存储受限时明确告知限制。

## 8. 内容、版本与离线操作

服务状态存在时以服务端最新项目为准。文件快照不得作为重入时的根替换提交，尤其不得因恢复期间服务尚未加载而误判为空房间并初始化。

保存文件前等待最新操作确认，沿用语义。保存成功不得早于协作描述和所需本机身份记录可靠写入；保存失败保持可重试状态。

恢复中禁止把用户操作发到临时普通本机空间。若允许离线编辑，使用现有离线队列与版本冲突规则：保留期望版本，冲突先备份，让用户决定重放或丢弃，不静默覆盖。无法保证队列连续性时保留独立备份并明确状态。

版本连续不归零；服务数据缺失才走显式灾难恢复，认证资料不能从不可信文件直接导入。素材缺失单独提示，不把缺素材误判为整个协作身份失效；刷新服务地址与票据后验证原尺寸、小尺寸和必要产物读取。

## 9. 生命周期与兼容

- 旧文件正常读取；仅在可靠关联存在时迁移协作描述，否则提供一次认证关联。不能仅凭同名自动绑定。
- 迁移 localStorage、sessionStorage 中仍有效记录至新存储，保留原记录直到新记录成功；不把其它身份覆盖。
- 另存文件默认保留同一房间关联；已有“创建独立项目/副本”动作如有则清除关联及主机绑定。不得把复制文件变成复制权限。
- 取消协作是持久的显式操作：成功后文件/草稿描述、本机恢复记录、重试任务及云端登记一致更新；旧文件重开也不能自动复活已注销房间。
- 删除房间、密码与名单更新、踢人与解禁、邀请码变更，同步主机及云端状态并使相关恢复记录按权限正确失效。
- 搬云端/搬本机后保存新位置，保持可核验的房间身份连续性或显式映射，撤销旧主机登记，防止两处同时托管。迁移中断后能重试，不发布半完成位置。
- 未知格式、磁盘满、存储无权限、备份损坏均须保留现有文件和可恢复内容并报告，不覆盖成空项目。

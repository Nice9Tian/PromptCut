## 现状（代码摸底，main `738a44a8`）

- 入口 `index.html` → `src/main.tsx` → `src/Shell.tsx`：先是开始页 `src/StartPage.tsx`，再进编辑器 `src/Editor.tsx`。编辑器依次摆：顶栏 `src/editor/TopBar.tsx`、左栏（`src/editor/dock/DockPages.tsx`，含素材库 `left/LibrarySection.tsx`、动画与特效、字幕、编辑 `EditSection.tsx` / Inspector）、预览 `src/editor/Preview.tsx`、控制条 `preview/ControlBar.tsx`、右栏 AI（在线版是 `right/OnlineAgentPage.tsx` → `CloudAiPanel`）、时间轴 `src/editor/timeline/`、状态栏。
- **几乎没有响应式**：只有零星的 `@media`，没有触屏手势和捏合。手机上的 AI 栏在低内存时显示占位（`DockPages.tsx` 的 `OnlineAgentPlaceholder`）。

  - `src/online/device.ts` 声明了 `userAgentData.mobile` 的类型，但从来不读。

## 要做什么

1. **设备判别**。按 `mechanism/platforms.md`「身份」一条实现电脑 / 手机的判定，放在 `src/online/` 下的一个独立模块里，并配单元测试：
   - Chromium 系看 `navigator.userAgentData.mobile`，Safari 看标识里有没有 iPhone，其余算电脑；
   - 两样都读不到时，按下面「设计决定」1 办。
   - 舞台闸门、档位气泡不在本任务里，它们属于 `docs/plan/online-browser-task.md`。身份模块要能让那边以后接上 iPad 的判法。
2. **界面选择**。身份为手机的在线浏览器进手机版界面，其余进现有的桌面界面。
   - 判定在 `Shell` 这一层做一次，同一页面地址（`/editor`），不另开地址。
   - 留一个只给开发和验收用的地址参数（例如 `?layout=mobile` / `?layout=desktop`）强制选界面，不在界面上给用户开关。
   - 桌面界面一行都不改坏，桌面版（Tauri）不受影响。
3. **手机版界面**。照演示稿用 React 写进 `src/`（建议 `src/mobile/`），样式按演示稿「设计规则」用 CSS 变量。要有的部分：
   - 开始页（新建云端项目 / 加入别人的项目 / 项目列表）；
   - 顶栏（主页 / 返回、项目名、导出），冲突横条；
   - 预览（成员按钮在右上角），播放条；
   - 缩略时间轴：缩略卡、转场 ◇、当前帧标记、长按换序；
   - 完整时间轴：多轨、刻度、播放头、手柄、− / ＋ / 适应宽度、双指捏合、起点 / 终点对齐；
   - 子导航栏（含「引用」），底部导航栏（缩略预览 / 时间轴 / Agent，Agent 的强调与选中描边）；
   - 底部面板：素材库、卡片库、选剪辑、调整、冲突合并、成员、导出，三档拖动；
   - Agent 页：对话标签、创造力、引用标记、消息、操作卡片；
   - 返回层级与浏览器后退；深色细滚动条。
4. **接业务层**。每个按钮、手势都调真实的 store 动作和服务，不留假数据：
   - 选中与 seek 走 `playback`；换序、改时长、分割、复制、删除走 `clips`；
   - 剪辑走 `cuts`，素材走 `media` 和现有的导入；卡片、文字、转场走现有的卡片库与 `captions` / `effects`；
   - 撤销重做走 `coreActions`；Agent 页走 `CloudAiPanel` 背后的云端 Agent；
   - 成员走 `sync/MembersPanel` 的数据，冲突合并走语义里的待合并项，导出走现有的导出。
   - 业务层里本来没有的东西，按「设计决定」3 办。
5. **主要内容**：缩略时间轴放哪几段，按「设计决定」2 办，并在代码里留演示稿 `mainClips()` 那条待办（自动判断主要内容的算法）。
6. **写语义**：把下面「语义改动」照写进去。
7. **上线**：
   - 构建在线版，按部署清单部署到生产；
   - 在 `https://visuhive.com/editor/` 上用手机模拟和桌面各走一遍验收；
   - 合入 main 后按 `git_and_release.md` 判 `release`。

## 设计决定（用户确认提示词时一并认可；有改动以用户在对话里说的为准）

1. **身份读不到、iPad**：两样都读不到时算电脑。iPad 的 Safari 报桌面声明，舞台闸门实现之前按电脑算，用桌面界面。
2. **主要内容**：第一版取当前剪辑主轨（最底下那条视频轨）上的段，包括视频段、图片段、剪辑段，按时间顺序；主轨上没有段时，缩略时间轴显示空状态和「＋ 添加素材」。自动判断的算法留待办。
3. **业务层里没有的**：手机版不发明新的产品功能。演示稿里有、业务层也有的，照接；演示稿里有、业务层没有的（例如冲突合并界面若还没在 main 上），能用现有能力最小接上的就接，接不上的入口不显示，记进待用户项，不写假数据。
4. **授权**：用户说的是「上线」，所以本任务里写 main、部署生产、前进 `release` 都已授权，条件见下文「授权与边界」。

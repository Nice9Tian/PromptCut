6. **测试服务隔离**：按 `.claude/launch.json` 的 `dev-test` 使用 5203～5205，先检查三个端口。被用户进程占用时不得结束该进程，选择另一组三个空闲端口并记录原因。在测试进程设置 `PROMPTCUT_NO_PORT_FILE=1`，使用仓库 `no-user-dirs`/`user-dirs` 隔离机制；清理仅测试子进程继承的用户数据和导出目录变量，按实际目录解析路径设置任务专用数据目录。验证不会改公共 MCP 端口登记或真实用户数据。只清理自己启动的服务。

## 问题与目标

用户在 PromptCut 提交视频剪辑指令后，Codex CLI 返回 `401 Unauthorized`、`token_revoked` 和 `Failed to refresh token`，随后出现 `workspace routing discovery unauthorized (401)` 的连续重连。PromptCut 却仍显示“已登录”，且设置界面隐藏登录按钮。

目标：让已知的服务端认证失败及时反映到登录状态和操作入口；用户能够重新授权，并在恢复后重新发送原指令。

令牌被撤销的原因不能由现有日志确定。修复软件状态处理不能代替用户完成浏览器授权。

## 行为修改草案

本节是实施前的 dry run。涉及用户可见行为、事件字段或语义文档的修改，先由用户审阅确认；本计划不直接修改现有语义。

| 场景 | 修改前 | 修改后（拟定） |
|---|---|---|
| 运行明确报告 `token_revoked` | 输出原始错误并保持“已登录” | 显示“登录已失效，请重新登录”，同步更新服务商状态 |
| 失效后再次执行本地状态探测 | 可能重新标成“已登录” | 本地正向结果不能覆盖尚未恢复的失效状态 |
| 同一轮运行反复报认证失败 | 持续展示重连消息 | 明确不可恢复的凭据失效结束当前任务，一次性说明恢复办法 |
| 已登录时需要主动授权 | 登录按钮隐藏 | 显示“重新登录”，沿用现有授权流程 |
| 重新授权完成 | 仅依据本地探测更新状态 | 成功的新授权解除旧失效标记，再探测并刷新界面 |
| 临时网络故障或一般工具错误 | 重试或报告错误 | 保持原有处理，不误判为 Codex 登录失效 |

不得把任意 `401`、任意 MCP 服务的认证失败都当成 OpenAI 登录失效。明确撤销令牌和来源可确认的 OpenAI 认证失败优先识别；无法确认来源或可恢复性的错误保留为未知或普通错误。

## 实施步骤

### 1. 建立认证失效状态和识别逻辑

- 在认证模块集中保存运行时失效证据，避免前后端各自维护互相冲突的状态。
- 保留 `loggedIn: boolean | null` 的兼容含义；评估增加可选的状态或原因字段，以区分未登录、登录失效和无法确认。
- 明确区分 `token_revoked` 等不可用凭据证据与暂时性网络、服务器错误，避免无依据扩大错误匹配。
- 对 stderr 使用可处理分块的解析方式；不能假设错误关键字一定完整落在单个 data 事件内，也不能依赖已被截断的展示文本识别错误。
- 失效标记需要认证代次或等效机制：旧任务迟到的错误不能污染新登录，旧探测迟到的结果不能覆盖新失效。
- 默认要求失效证据跨后端重启保留：在 PromptCut 专属目录保存最小非敏感记录（原因、时间、认证代次及必要格式版本），不保存令牌、原始日志或账号内容。通过原子写入避免半文件；隔离不同 CLI home。文件损坏时安全降级为“待确认”并提供重登入口，不崩溃，也不直接宣称已登录。若环境不允许写入，内存中继续保留并明确报告不能跨重启保存的限制。
- 状态优先级：当前代次的明确服务端失效证据高于本地正向探测；未登录高于历史已登录；配置/探测错误为“待确认”。普通无失效证据的本地正向探测仍沿用现有已登录含义，不能宣称已经在线校验。

### 2. 连接运行错误、缓存和任务生命周期

- 在 Codex runner 收到可靠的认证失效证据时先更新后端认证状态，再使服务商列表缓存失效。
- 向前端传递可识别的认证错误原因，不能依赖界面解析原始英文日志。
- 对明确不可恢复的凭据失效停止本次 PromptCut 启动的 CLI；不停止其他会话或用户已有进程。
- 审查 `finish`、`abort` 的顺序及幂等性，避免错误被 abort 吞掉、重复终止事件、停止状态覆盖失效提示，或 done 提前完成后留下子进程。
- 验证文本协议、审核环路等上层封装能够透传认证错误，不把它误判成工具权限拒绝并启动另一轮重试。
- 前端收到认证错误后即时更新并刷新服务商状态；同一编辑器的其他聊天页签通过共享状态/现有通知同步，其他已打开的编辑器通过现有推送或有界刷新同步，不只保证下次打开设置时正确。具体同步机制先检查现有设施，以最小改动实现。
- 已知失效期间再次提交 Codex 指令，在服务端拒绝启动 CLI 并返回恢复提示；其他 provider 的状态及运行不受影响。不得仅靠某个前端页签禁止发送。

### 3. 打通重新登录恢复

- 已登录时也保留“重新登录”按钮；运行失效时提供通往现有登录流程的入口。
- 保留正在登录时的按钮禁用、任务复用、取消及设备码登录逻辑。
- 点击登录、打开网页、登录超时、取消或失败都不能清除失效证据。
- 新登录完成后的验证要能绕过“有效状态合成”而直接探测新授权结果，避免因旧失效标记一直返回 false 导致永远无法恢复。普通查询继续应用失效优先级；登录成功验证是单独的原始探测路径。
- 只有当前有效的新授权成功完成并通过原始探测，或能够证明当前认证已成功访问服务端，才解除对应失效标记。清除须与认证代次核对并同步持久记录；旧登录任务的成功回调也不能覆盖较新的状态。
- 重新登录成功后同时刷新认证缓存和服务商列表缓存。
- 不自动重放剪辑指令：失败前可能存在已执行的工具操作，由用户重新发送或继续，防止重复修改素材。

### 4. 核对并补充语义

实施前核对 `user-workflow.md` 和 `workflow/` 中 AI 设置与恢复流程，及 `product/agent.md`、`mechanism/agent.md` 的相关约定。

如现有语义缺少认证恢复承诺，先列出最小的“修改前 / 修改后”文案并请求确认；用户可见承诺写入产品或工作流程层，状态优先级、缓存和错误识别机制写入机制层。本计划不授权直接改动这些文件。

## 验收用例

| 用例 | 预期结果 |
|---|---|
| 本地探测返回已登录，运行返回 `token_revoked` | 当前聊天与 AI 设置更新为登录失效，出现重新登录入口 |
| 错误关键字跨多个 stderr 数据块 | 仍可靠识别，只有一次认证失败及终止结果 |
| 失效后重复刷新服务商列表 | 不因本地 `Logged in` 输出恢复为已登录 |
| 失效前发出的探测在失效后返回 | 旧结果不能覆盖失效状态 |
| 新登录完成后，旧运行迟到报错 | 新认证状态不被旧任务污染 |
| 登录成功、失败、取消和超时 | 仅成功授权解除相应失效标记；其他情况保留恢复入口 |
| 已登录状态主动重登、重复点击 | 入口可用，仍只启动一个登录任务 |
| 网络断开、超时、429、5xx、外部 MCP 401 | 不误标 Codex 登录失效，保留适用的重试行为 |
| 认证失败经过文本协议或审核环路 | 不重复启动同一失效凭据的执行，不吞掉认证错误 |
| 多页签及前后端缓存刷新 | 后端状态一致，界面不会被缓存反复切回已登录 |
| 已知失效期间从任意客户端再次提交 | 服务端拒绝启动 Codex CLI，其他 provider 仍可使用 |
| 失效后重启服务、不同 CLI home、损坏记录 | 重启仍提示失效；home 间不串状态；损坏时降级待确认并可重登 |
| 登录成功验证及持久状态清除 | 旧失效不会阻止新登录验证，重启后不复活旧标记 |
| 取消与认证失效同时发生、进程异常退出 | 终态一致，只结束本任务进程，Promise 收敛且无泄漏 |
| 真实用户重新授权后发送短指令 | 能实际运行；不能仅以界面显示已登录作为恢复证明 |

测试使用模拟 CLI 输出和注入的探测结果，不撤销真实令牌，不修改宿主机网络，不读取或输出凭据。真实浏览器授权由用户完成。

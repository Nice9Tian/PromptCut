# 账号、项目状态与保存契约（对齐草案）

2026-10-08。对应 `account-binding-task.md` 和先做的 `online-browser-task.md`。本文件记录已定行为及尚未选择的机制，**不是已实现接口或已通过验收**。VisuHive 的 `docs/accounts.md` 区分现有公开接口与本契约待实施部分。

## 权威记录与信任

| 信息 | 权威记录方 | 其他服务的边界 |
|---|---|---|
| 账号编号、名称、密码、账号会话、改密事件与退出选择 | VisuHive 账号服务 | 客户端不能自报有效身份；项目服务不能另存账号密码 |
| 云端项目是否存在、创建者、成员、禁入、项目状态、文档版本及操作 | 云端文档服务 | 账号页向它查询；托管目录或缓存不能成为另一套可独立修改的项目关系 |
| 素材与产物字节及入库状态 | 素材服务 | 文档服务记录引用/状态，小消息中不搬素材字节 |

网站列表查询失败回明确不可用，不把失败变成空数组。列表只是展示，不授予项目权限。创建、加入、被踢及删除后的记录由文档服务提交，重复请求不产生重复项目或成员。

账号核对必须复用网站试密码限制并传递可信来源信息；不能信任客户端自报来源地址。公网、在线页面和同机其他用户进程不能取得内部核对权限；只监听回环地址不够。隔离通道及进程身份方案尚待选定，不能先写一个共享密钥方案算已定。

## 跨服务操作

- 创建、加入记录、撤销、补偿分别使用幂等操作编号，持久保存已接受/已完成结果，重复与乱序消息不反复执行。
- 项目创建先获得可信账号身份，再由云端文档服务提交创建者和项目状态；中途失败要有可重试或补偿结果，不留下已对外开放但没有创建者的项目。
- 退出及踢人事件和各相关服务确认须持久化；通知丢失或重启后续办，不以一次请求超时报告完成。退出完成后用户的旧会话、恢复凭证和票据不能继续发言或写入；被踢账号全部设备失去该项目访问权限。私有 Agent 任务中止，改密选择退出或被踢时的已读共有 Agent 当前任务按下文例外继续，不把例外变成旧用户凭证或被踢账号仍可使用项目。
- 持久授权和密码变化分开：用户选“否”时，不能仅因密码时间变化就让全部现有云端登录失效。新登录仍须新密码。
- 退出登录、被踢、改密退出、项目删除是不同原因，不互相假冒；各自作用范围须在接口和验收中列清。

## 云端 Agent 共有与私有权限（2026-10-08 用户新拍板）

| 权限 | 可查看历史和回复 | 可发送 | 默认 |
|---|---|---|---|
| 共有 | 同一项目内所有已登录且有项目权限的成员 | 同一范围的所有成员 | 新建默认共有 |
| 私有 | 所属账号 | 所属账号 | 用户可主动设为私有 |

共有不指匿名或项目外账号。私有同账号换设备可继续访问；共有成员换设备仍按当前项目权限核对。读取、订阅及发送都由服务端判权限，不以列表是否显示作为防护。

对话归属按账号编号记录；每条消息另记实际发送者账号编号，界面显示谁发的，不能都记成对话所属账号。每轮 Agent 授权与项目修改关联实际发起者，只核对他此刻是不是这个项目的有效成员；Agent 能做的事对所有成员都一样，不分创建者与参与者，创建者操作一律拒绝；只读成员不能操作 Agent，发消息这一步就被拒（2026-10-08 用户定；现在没有只读成员这种身份）。发送者被踢或旧登录退出后，其旧用户授权不能继续发言或写入；被踢账号不能查看共有或私有对话。共有对话其他成员仍按自身有效权限访问和发言。改密选择退出或被踢时，已读共有任务的继续执行是单独任务例外，见下文，不授予旧登录或被踢账号发起下一轮的权利。

本期新增：共有/私有权限、发送者记录、界面展示、账号/权限接口及验收；第四阶段未完成的约 25 个云端 Agent 工具并入 0.7.18（2026-10-08 用户定，原写「仍延期」作废）。已有按主人隔离的数据不能仅改一个可见性字段就算共有支持，需核对存储、历史订阅和每轮委托。

待对齐：谁能切换共有/私有、谁能停止共有任务，切私有时对进行中任务和原参与成员的处理，已有对话迁移规则，以及多成员同时发言的排队和每轮执行顺序。默认共有与可查看/发送范围已经拍板，不重复询问。

## 过期云端项目转本地与暂时离线

“过期”不指文件年龄、账号会话到期或网络断开；指可信云端文档服务确认原云端项目已不存在或已清理。证明须对应准确服务及项目/房间标识，不能只凭项目名、错误节点上的 404、网站空列表或本机 `deleted` 状态名。

| 状态 | 行为 |
|---|---|
| 项目存在且有权限 | 连接原项目，采用云端当前版本；文件不是覆盖云端的依据 |
| 准确原项目确已不存在/清理 | 文件内容建立独立本地项目，默认关闭多用户协作；一次提示；保存写入本地位置状态 |
| 超时、服务故障、错误节点 | 暂时离线，保留云端关联、基准和离线改动，不能过期转换 |
| 未登录、密码错、凭证失效 | 要求认证；不能用离线提交绕过权限 |
| 被踢、名单外 | 明确拒绝，旧文件不能恢复禁入账号的权限 |
| 文件内容不可用 | 报错、保留原文件，不用空项目覆盖；需要复核各种不同细节情形 |

过期转换只承诺文件保存的内容，不补造之后云端独有的修改。`.proc` 不含素材字节；缺素材按下节处理。各设备转换后独立，不自动同步。本期不做独立副本共同标记或将来从标记点合入。

暂时离线的保存仍标为原云端项目。下次打开/重连取得云端版本后提示是否落后，询问是否发送离线改动；若会覆盖云端期间的修改，提供可视化窗口，显示基准、离线改动和云端改动并让用户处理冲突。用户取消时保留离线内容；解决完成前不盲目根替换或自动重放。云端在窗口期间又改变时重新核对，不覆盖新修改；重复提交幂等。

## 保存与修改状态检查

- **本机修改状态检查**：当前设备的前台编辑、待提交操作、本机 Agent、素材入库/上传、渲染和后台写入是否完成。
- **全局修改状态检查**：当前项目相关的全部设备与服务的上述状态，并区分本机与非本机。不是只检查 5210，也不等于所有人必须同时停工。
- 保存时禁用当前前台编辑，等待本机写入完成后保存；成功或失败后恢复可编辑状态，失败保留上次有效保存和未提交内容。
- 非本机内容“冻结当前状态”指取得并固定一份确定快照，记录内容哈希、权威时间、服务身份、项目标识和版本。后续远端写入不改这份快照，仍作为后续版本保留；下次打开按基准比较和处理冲突。
- 哈希说明内容是否相同，时间说明状态时点；它们不能重建内容、证明无并发写入或独自决定合并顺序。须保留基准内容或可可靠取得的历史版本、离线操作及相应素材引用。
- 无法取得远端已确认快照时只能报告暂时离线及已知基准，不能把本机时间伪装成云端确认时间。快照、版本、素材完成状态的共同确认方式及历史保留策略尚待设计。
- 普通保存不再以项目版本连续 5 分钟不变为充分条件。部署或数据删除的修改状态检查与普通文件保存是不同操作。

## 缺失素材占位

确认素材确实缺失后弹窗列出缺失项；视觉片段/卡片用默认文字卡“找不到素材xxx”，其中 xxx 是原素材显示名或可辨认标识。缺失音频用提前做好、随软件分发的一段人声占位，说“找不到素材”（2026-10-08 用户更正：原先写的“丢失素材”、创建成项目素材并经素材服务入库，作废）。它不是项目素材：不存进项目、不入素材服务，桌面安装包和在线页面的构建里各带一份。

这段人声已经做好：`src/audio/assets/missing-material.wav`，PCM 16 位、48 kHz、单声道、1.37 秒、131,564 字节，SHA-256 `5E615376504BDD9350A88E890E3FE320109719A5DAB42D760BC658B993CCF4E7`。做法（2026-10-08 用户定用系统语音合成）：Windows 自带的 System.Speech、语音 Microsoft Huihui Desktop、语速 0、音量 100，直接合成 48 kHz 单声道，再用 ffmpeg 剪掉首尾空白（取原始输出的 0.10～1.47 秒）并加 10 毫秒淡入、50 毫秒淡出。峰值 -2.5 dB，平均 -21.8 dB。代码还没有接它，放的位置接线时可以挪，挪了改这里和 `../semantics/workflow/materials.md`。

保留原素材标识、引用、片段位置、参数和可找回关系，不把占位当原素材成功恢复。时间轴不因占位偷偷挪位；占位音频如何适配原时长、同一视频画面与音轨均缺失时的组合方式待明确。暂时读取失败、未授权与不可解码需分开提示，不能一律声称文件不存在。

验收需覆盖缺一项、缺多项、缺全部、部分可读、素材找回、保存重开、发布后另一设备读取、人声播放及导出。占位人声不随 `.proc`、`.procp` 走；另一设备、在线浏览器、渲染节点各用自己那份软件里带的同一段，验收时核对各处放出来的是同一个文件。

## 改密、退出动画与延迟撤回

已定交互：修改密码动画 → 成功显示“密码已修改” → 问是否退出已登录设备。

- 选否：保留现有设备的云端登录和写入权限；新登录使用新密码，不执行此次旧登录退出及撤回。
- 邮箱重设密码（忘记密码）和改密码内部是同一套逻辑，只是界面上的说法不同：重设之后同样问是否退出已登录设备，用户有权不退出；选了退出，后面的处理与改密码一样（2026-10-08 用户定；原写「邮箱重设一律撤销全部旧登录、不套用可选流程」作废）。
- 选是：显示“正在退出已登录设备”；撤销旧用户凭证并中止私有 Agent 任务，已读共有任务按例外继续；完成确认后显示“设备已退出”。未确认或撤回仍未处理不能假装整个流程已结束，退出和修改处理进度分别表达。共有任务按例外继续不等于设备仍登录，也不要求等该任务做完才能确认设备已退出。
- 用户指定撤回区间：**改密码绝对时间至旧凭证账号下线之间**。需要识别本账号旧凭证在该区间产生的项目修改；不能把其他账号或本账号新登录的合法修改顺便回退。
- **Agent 已读消息例外（2026-10-08 用户新增并扩大到被踢）**：因改密选择退出或被踢的用户已经发送、且已被 Agent 读到的消息不撤回，保留原文、发送者和历史，避免移除 Agent 已消费的输入而阻断动作。仅“已发送”不等于“Agent 已读”；未读消息不因此取得继续执行授权，改密撤回仍按原区间处理。本次扩大不另行规定踢人要撤回该账号的全部历史修改。
- 已读状态需由 Agent 侧可核实的记录确认并持久保存，重启后仍能分辨；消息记录的已读与普通界面读回执分开，不能让客户端自报已读来绕过撤回。具体确认点待机制落清。
- **任务处理已拍板**：改密选择退出或被踢时，私有 Agent 任务直接中止，已读消息保留历史；共有 Agent 已读消息已经触发的当前任务保留并继续执行，该任务及其项目修改不因此次改密退出或踢人撤回。未满足共有已读例外的操作不获得任务授权豁免；改密撤回仍按原区间处理。
- 共有例外限定已确认的消息和当前任务，保留其本轮任务授权，不允许旧用户凭证或被踢账号继续发新消息或启动下一轮。被踢账号也不能查看对话，保留消息不恢复其访问权；其他有效成员仍可按自己的账号发言。项目删除、关闭云端 Agent 的终止条件不被此例外豁免。
- 保留消息、当前任务、委托和产物/项目操作之间的关联，补偿程序能精确排除该任务，不能只用时间范围误撤它的改动，也不能借例外保留同账号的其他不相关修改。共有/私有权限切换与退出/踢人的竞态、已读确认点、任务授权如何跨重启保留待设计。
- 改密事件至少需要可验证的事件编号、账号身份、权威改密时间、退出选择、受影响旧登录范围和完成结果。文档操作需要可追溯身份、会话/授权代数、权威接收次序和时间依据。时间值由服务确认，不采信客户端自行填写。
- 多个旧连接结束时间可能不同；区间的完成点怎样定义、账号服务和文档服务时钟不同如何映射到操作次序尚待设计。不能凭未经核对的时间比较选择破坏性撤回。
- 撤回用可审计的补偿操作处理相应改动，不盲目把整项目退回旧根。撤回按修改项逐条核对（2026-10-08 用户定，规则全文见 `docs/semantics/product/document-service.md`「冲突」）：某一项之后被别人又改过算冲突。因改密码或重设密码选了退出而触发的撤回，不冲突的撤、冲突的不撤，不弹窗口；用户按撤销按钮，不冲突的直接撤、冲突的弹出窗口由用户决定。
- 需要保留相应历史版本、操作内容及撤回所需信息；现有摘要/时间字段不等于具备完整选择性撤回能力。备份和回退不应复活已撤销的凭证。
- 停止后续读取/写入不能追回已下载文件或已发送的外部请求；本期撤回指项目修改及相关引用，不宣称能撤销外部世界的效果。

待定：当前网站会话是否保留、网站其他会话怎样随选择处理；退出与撤回失败的展示/重试、时钟与历史保留、怎样判定别人「在它基础上又改过」、撤销按钮冲突窗口里的选项。邮箱重设密码与改密码同一套逻辑已定。账号服务故障时已连接用户继续编辑的意向通过此延迟处理路径承接，不用“通知迟了”掩盖残留修改。

## 目标与范围

让 Agent 能为视频生成可调的短音效：先做「叮」等提示音、与文字出现同步的键盘敲击声；声音是项目内容，能反复预览、移动、裁切、重开与导出，不是编辑界面里临时响一下。

做完用户得到：

- 不找外部素材，也能生成提示音和键盘声；调音高、音色、时长、音量和敲击节奏。
- 打字动画和声音共用一份事件时间表，改文字或速度后可同步重生成。
- 声音能进独立的音频片段，与人声、背景音乐混合；桌面端和在线浏览器能听到，导出的 MP4 也有声音。

本期先交付少量可靠的合成预设。不做音乐编曲、完整音频工作站、真实键盘采样库或音频处理总重构；不引入 p5.sound / Tone.js 作为第二套播放引擎，也不新增 Java / Python 音频运行时。真实键盘录音可在后续作为可选素材混合使用，需用户提供或确认可分发的许可证，不是本期前置条件。

## 与后续各期及旧音频计划的约定

- **0.5 期先于一期。** 在现有桌面版、现有 Agent 入口与素材服务上完成，不等新云节点、不等 Agent 独立、不等前后端分离或 Electron。
- **合成是确定性的渲染工作。** Agent 负责选预设、参数和事件，JS 合成器负责产采样；结果不依赖 Agent 会话是否存活、真实时钟或音频设备。文档服务只保存配方与引用，素材服务只存取字节。
- **沿用浏览器端 JS 的方向。** `audio_structure_plan.md` 已记录音频处理使用浏览器端 JS 的决定；`audio_determine_plan.md` 已有分块、尾音与 PCM 误差的研究。本期复用相关契约与探针，不把其中尚未完成的全部重构、判重调度或新编码器当成前置条件，也不覆盖旧计划。
- **给一期留可迁移的边界。** 合成器和事件计算不直接依赖编辑器 UI、Agent 全局状态或本机绝对路径；以后运行在云端渲染宿主时仍执行同一份 JS，经素材服务取交产物。无头 Chrome 可离线计算，不以有声卡/扬声器为前提，但 Linux 实测通过后才能宣称支持。新节点常驻、鉴权与多用户调度仍由 `draft_cloud-node-and-agent.md` 处理。
- 二期只搬服务与共享代码的边界；三期换桌面壳时复用本期的测试样本。0.5 期不提前展开这两期。

## 已有能力与缺口（按 2026-10-05 的 main 核对）

| 已有 | 本期要补 |
|---|---|
| `CardDef.audio(sources, { start, count, sampleRate }, params)` 返回交错的 `Float32Array`；现有采样口径为 48 kHz | 面向用户的提示音、键盘声定义与参数，不能把测试探针当现成预设 |
| `inputs: {}` 可表达无素材输入的合成音频；`create_card` / `apply_card` 有音频入口 | 明确「选预设 → 调参 → 生成 → 入时间轴」的可复用流程 |
| `src/audio/cardAudio.ts` 可按块求值、拼成可定位 WAV 供桌面预览 | 现有内存/blob URL 不等于可共享素材；需持久化、版本和重生成处理 |
| 桌面导出已有 `buildAudioPlan`、`renderMix`、无头 Chrome 的 `OfflineAudioContext` 混音与 FFmpeg 合成路径 | 验证新音效进入真实成片，复用现有管线，不另造混音器 |
| 在线模式的 `cardAudio.ts` 跳过音频图卡求值；`browserExport.ts` 目前按普通素材生成音频计划 | 将生成结果作为持久化音频素材供在线预览和导出消费，不能直接假设在线能运行音频卡 |

## 步骤

### 0. 先跑最小闭环，锁定口径

- 用现有音频接口生成一个短提示音和一串固定种子的敲击声，验证无输入、48 kHz、声道数、返回长度、非零采样起点与片段本地时间的映射。
- 走一次「生成 WAV → 素材服务入库 → 普通音频片段 → 桌面预览/导出、在线预览/导出」，确认有声且没有双播。
- 复用 `scripts/probes/audio-determine-probe.mjs` 的比对经验；先测 Windows 桌面与 Linux 无头 Chrome，再核目标在线浏览器。区分「浏览器读取已有 WAV」和「运行合成代码」。
- 实测可接受的最长音效、事件数、同时合成数、内存峰值和取消响应，形成有数字的资源预算；超限明确报错或拆分，不偷偷截断。

完成的标志：留下测试项目、音频样本、最终 MP4 和测量报告；可行性、偏移、格式兼容性都过关后再定后续接口，不把未经验证的假设写成承诺。

### 1. 两类可复用的原生 TypeScript 音效

- **提示音**：振荡器/泛音叠加与音量包络，支持单音或短音列；暴露音高、波形/音色、起落包络、时长、音量。先给少量可试听预设，避免刺耳、爆音和过长尾音。
- **键盘声**：短瞬态、带限噪声与衰减共振组合；事件带时刻、力度和必要的键型，支持按固定种子做轻微变化。初版以合成敲击质感为目标，不承诺还原某款实体键盘。
- 复用 `CardDef.audio` 与现有参数控件，纯合成显式写 `inputs: {}`，不要误走默认素材输入。预设的来源、参数范围和推荐用途可被 Agent 查询。
- 每个采样只由版本、参数、种子、事件身份和采样位置决定；不得靠 `Math.random()` 调用顺序、播放次数或挂载时间推进。带滤波/尾音时，从事件起点计算或用足够预滚恢复，不能每个请求块都重置后直接拼接。

完成的标志：相同配方能重生成；改变请求块大小、顺序或起点不会改变事件节奏、噪声序列和尾音。

### 2. 声画共用事件，音频单独成段

- 从文本及其打字节奏生成一份确定的字符事件表；视觉卡和音频生成器共用它，不各自按字符数重算。
- 文字、延迟、速度、停顿与种子都进入配方。明确空格、标点、换行是否发声，以及中文/emoji 的字符划分；不把每个 UTF-16 单元当一个可见字符。
- 音效放独立音频片段；画面与声音使用同一个时间轴锚点。整体移动、裁切、分割或改变速度时，事件的本地时间与素材偏移须一致，切出来的后半段不能重新从第一个字响。
- 默认允许尾音自然衰减到声音片段内；超出片段或项目出点时按已定裁切/淡出规则处理，不隐式延长项目。密集敲击允许事件重叠，但须留混音余量。

完成的标志：包含中文、标点、emoji、停顿的打字示例，从中途播放或切分后仍声画对齐；新增音频段符合现有序列内片段不重叠的规则。

### 3. 生成结果持久化，并保留可修改配方

建议的首版交付路径：`音效配方 → JS 按块合成 → WAV → 素材服务 → 普通音频素材段`。这样在线模式消费现有支持的素材，不要求它执行音频图卡。

- 配方保留预设/合成器版本、完整参数、固定种子、事件表或其可重建来源、采样率、声道与时长；素材保存内容哈希。配方与产物的关联字段先列 dry run，再按确认后的项目契约实现。
- 复用键包含合成器/源码版本、参数、种子、事件表、采样率、声道数、生成范围/样本数，以及可选输入素材哈希；缓存键与 WAV 内容哈希分清。改任一声音相关项都不能误用旧产物。
- WAV 经素材服务正常接口入库，项目只存可持久化引用；临时文件、页面 blob URL 与本机绝对路径不进共享项目。项目重开、换设备、离线打包均能找回声音或明确指出缺失。
- 参数修改后生成新版本，成功入库后才切换引用；失败/取消不覆盖旧版本。已经过时的任务结果不得回写新配方，重试不能重复创建时间轴片段。
- 同一音效片段只走一个播放来源：首版成段使用 WAV 后，不再同时播放原图卡输出。任务进度、可取消、失败原因可见；生成失败不能假装成功或静默导出缺声成片。

完成的标志：生成者关闭页面或 Agent 会话后，另一设备仍能听到；改参数得到新产物，取消/失败不破坏可用的旧版本。

### 4. 接上当前 Agent 与预览/导出

- 通过现有 Agent 工具与参数编辑入口调用，不等待独立 Agent 服务。遵守 `server/card-authoring-guide.md`：先找可调的现成预设，只有现有参数达不到才考虑新建音频卡。
- 桌面与在线的时间轴试听、音量、静音、淡入淡出、暂停与恢复沿用当前语义；声音跟随画面，画面落后时的音频暂停/恢复规则不另起一套。
- 桌面导出复用现有音频计划/混音/封装路径；在线导出复用 WAV 素材输入路径。无 AAC 支持等情况沿用现有明确提示，不让缺声悄悄通过。
- 所需 Chrome、FFmpeg、WAV 编解码能力按实际运行路径自检；不增加收费服务或额外音频常驻服务。合成按块进行，避免超长整段缓冲拖垮编辑器。

完成的标志：用户能要求「给这段打字加键盘声，结尾加一个提示音」，得到可编辑的音效段，调参数后预览和成片都更新。

### 5. 验收与交接

以下阈值为本草稿的建议，须在第 0 步测量并在定稿时确认；未测试的平台不得标成通过。

| 验收 | 检查方法与完成的标志 |
|---|---|
| 分块/随机访问 | 同一运行环境中，一次生成与不同块长、乱序请求、非零起点结果比较，编码前 PCM 的 `maxRel ≤ 1e-6`；另查边界跳变、尾音完整，静音样本单独校验 |
| 重播与编辑 | 暂停/继续、反复 seek、重播、平移、裁切、分割、速度修改后无重复敲击/漏音/首事件重启；纯采样映射误差不超过 1 个采样 |
| 声画同步 | 同一事件表驱动打字和发声；扣除可测的设备/编码延迟后，事件与目标画面差不超过 1 个项目帧；检查 AAC 延迟及导出起点 |
| 混音质量 | 快速连击、多个音效与人声/BGM 叠加；检查峰值不超过满幅、无 NaN/Inf、无突兀截尾，并人工试听；不靠静默削波掩盖过载 |
| 缓存/持久化 | 改参数/种子/版本必失效；刷新、重开、换设备、打包回读正确；取消、失败、旧任务晚到均不覆盖新结果 |
| 成片有声 | 对最终 MP4 检查音轨、时长及事件窗口能量，再实际试听；仅 WAV 存在或容器里有音轨不算通过 |
| 跨平台与在线 | Windows 桌面、Linux 无头 Chrome、目标在线浏览器分别测试预览和成片；跨环境编码前 PCM 沿用旧音频计划的 `maxRel ≤ 8%` 门槛并记录 RMS/onset 差异，不承诺 Web Audio 跨平台逐字节相同；AAC 成片不用逐样本差作判据 |
| 回归/资源 | 音频卡、普通素材、静音与混音相关测试，加类型检查和现有全量基线；记录第 0 步资源预算是否满足。新增声音不改变既有画面像素基线 |

交接时附样本、探针命令、环境版本、通过/失败/未测清单和已知限制；`audio_structure_plan.md` 尚未完成的工作仍单独保留，不把本期做完表述为音频总重构完成。

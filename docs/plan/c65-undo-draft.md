# C6.5 用户感知到的撤销 / 重做行为与文案

本文档依据 `c65-design.md` 的技术框架与语义文档输出，描述撤销与重做的界面表现与用户文案。

## 0. 现状
目前 `src/Editor.tsx` 与 `src/editor/TopBar.tsx` 中的撤销 / 重做逻辑：
- **快捷键**：只认 `Ctrl/Cmd+Z` 与 `Ctrl/Cmd+Shift+Z`，没有 `Ctrl+Y`；当焦点在 `INPUT`、`TEXTAREA` 或可编辑元素内时，直接跳过处理交由输入框自身（`Editor.tsx` 159-170行）。
- **界面按钮**：顶栏有两个纯图标按钮（label 为“撤销”与“重做”），目前没有基于历史栈长度的禁用态；标题栏的“快捷键”弹窗文字写死，不含 `Ctrl+Y`（`TopBar.tsx` 491-496, 541-545行）。

## 1. 撤销 / 重做按钮与快捷键（相对现状的改动）
- **改动点**：增加 `Ctrl/Cmd+Y` 映射为重做；顶栏按钮增加基于各自历史栈空状态的禁用态；同步更新“快捷键”弹窗文字加上 `Ctrl+Y`；保持原有逻辑：输入框内按 `Ctrl+Z` 仍归输入框自身处理不触发项目撤销。
- **行为感知**：
  - **撤销**：用户按下 `Ctrl+Z` 或点按钮时，撤销自己在这个页面会话里做的上一步操作（拖动松手、或数字框回车 / 300ms 连续输入合并算作一步）。按下后无需弹出“已撤销：某某步骤”的提示，相关的画面、时间轴、属性面板会像普通操作一样直接跳变成撤销后的状态。没有东西可撤时按快捷键无任何反应。
  - **重做**：重做亦然，行为与撤销对称。
  - **历史上限**：最多能撤回 100 步历史。
- **禁用态与悬停提示 (Tooltip)**：
  - **撤销按钮**：当前页面的本地撤销栈为空时置灰不可点。悬停提示：“撤销 (Ctrl+Z) —— 只撤你自己在这个页面做的”。
  - **重做按钮**：当前页面的本地重做栈为空时置灰不可点。悬停提示：“重做 (Ctrl+Shift+Z / Ctrl+Y) —— 恢复刚撤销的操作（有新操作后即失效）”。
- **理由**：由于撤销栈按写入身份隔离，打破了传统“全局最后一步”的直觉，悬停提示必须一句话交代清楚边界。静默跳变符合现代编辑器交互预期，不打扰用户。

## 2. 撤销 / 重做的「部分冲突」反馈
撤销和重做本质都是一次提交。当发生冲突，部分实体因在这一步之后被其他身份改过而无法回退（或重做）时，弹出全局提示条（Snackbar）。
- **提示文案**（以撤销为例，重做同理）：
  "撤销了，但这几处被后续的新修改覆盖，未做退回："
  - 片段「开头空镜」 (由 Agent「写分镜」 修改)
  - 效果「全屏泛光」 (由 张三 修改)
- **折叠规则**：最多列 3 处。当恰好等于 3 处时，列出全部 3 处；多于 3 处时，列表只显示前 2 处，第 3 行显示 "等 X 处 (点击展开)"。展开后所有实体完整列出，带垂直滚动条。
- **身份显示**：冲突身份可能是：另一位成员（如“张三”）、Agent 对话（如“Agent「整理轨」”）、甚至用户自己在其他页面的操作（如“你在另一个页面”）。
- **实体显示**：按顶层实体计，前缀带类别（如“片段「名称」”、“序列「主序列」”、“项目设置”）。
- **点击交互**：点击列表里的实体名，页面时间轴和属性面板自动跳转并选中该实体，方便用户直接看现状。停留较长（如 8 秒）后自动消失，带关闭按钮。
- **理由**：依据“最后写的赢”原则，清晰交代哪些没生效及由于谁的操作导致，给出下一步操作（点击查看），缓解用户的失控感。

## 3. 全部都因冲突而无法生效
- **提示文案**："没撤成。这几处后来都被改过了，保留了现在的样子："
  *(下面复用第 2 节的列表和折叠规则，列出实体与修改者，例如：)*
  - 片段「结尾花絮」 (由 Agent「调色」 修改)
  - 等 [X] 处 (点击展开)
  *(重做文案：“没重做成。这几处后来都被改过了，保留了现在的样子：”并同样列出)*
- **后续引导**："你可以 [点击这里] 查看被修改处的现状，或直接手动调整。"
- **理由**：直白告诉用户操作未生效及原因，展示冲突明细让用户放心，并引导下一步动作，安抚用户情绪。

## 4. AI 栏里的「撤销这一步」
- **入口位置与显示条件**：在 AI 栏，只有修改了项目的进度条目（有写操作）底部才有「撤销这步」按钮；只读查询（如搜索、查布局）不显示该按钮。
- **操作方式**：不论是否是最新一步，都可以直接点击，不需要二次确认。不是最新一步点击时，等同于针对该步骤提交逆向操作，若冲突则按上述部分冲突逻辑处理。
- **成功反馈**：操作成功后，该按钮变为 "已撤销" 并置灰不可点。
- **对 Agent 的影响**（用户视角说明）："撤销后，不发专门通知，但在 Agent 下次准备改动时，会发现版本变了并自动知晓你改回去了什么内容。"
- **理由**：撤销是可逆安全操作，免确认降低成本。基于 C6.5 期望版本的 `stale` 和 `since` 机制，Agent 本来就能在被拒时感知到谁改了什么，自然实现通知闭环。

## 5. 多人同时在线时的相互影响
别人（含另一位成员、Agent、另一个页面的自己）执行撤销或重做操作，且影响了我正在看的内容：
- **画面感知**：不弹出“某某撤销了一步”的专门提示。画面或参数直接跳变成最新状态。
- **覆盖通知**：仅当用户满足 `c65-design.md` 规则（被覆盖的内容我刚好是最近写入者、在 10 分钟内、且覆盖方是不同身份）时，用户会收到标准通知：“你的近期修改已被 [身份] 覆盖。已将你修改的版本存入草稿备份。〔找回入口待裁定〕” 同时，页面会在底层将其备份至草稿目录 `backups/`。
- **理由**：撤销本质就是一次普通的写入操作，完全遵循 `product/document-service.md` 中的冲突与覆盖通知语义，不发明专门处理；补上下一步引导能缓解覆盖焦虑。

## 6. 离线后重连的冲突对话框
当断网期间本地有（如 5 步）未发操作，重连后第一条因别人改过被拒时，弹出对话框。
- **对话框内容**：
  **标题**：断网期间项目有新改动
  **说明**："你有 5 步断网期间的修改。但这段时间项目有以下改动，可能会和你的修改重叠："
  *(下面列出 since 回包中谁改了哪些实体的摘要列表)*
  "还要把你的修改加进去吗？"
- **选项按钮**：
  - 【重放】："加进去（可能会盖掉他们刚改的地方）"
  - 【丢弃】："不要了，用现在的最新版本"
- **关闭行为**：右上角可直接关闭弹窗。关掉代表暂不决定，同步暂停，用户可以先到处看看现状再做决定。（如弹窗关闭按钮带有悬停提示：“暂不决定，保留离线修改先查看项目”）
- **理由**：将内部被拒的 `since` 数据翻译为易懂的人话。列出未发步数和改动摘要，让用户充分知情后决定是否“硬盖”。

## 7. 待主会话裁定汇总
1. **撤销因全局冲突完全失败时，该步是否从本地撤销栈中移除？** （若不移除，用户再点撤销仍是冲突；若移除，则视为废弃该步，下一次撤销将撤上一跳。）
2. **AI 栏点“撤销这步”，这次写入算作用户的操作还是算 Agent 的操作？** （若算用户的，会进用户的 Ctrl+Z 栈，后续覆盖算用户覆盖；若算 Agent，则视作 Agent 发起的修正。）
3. **覆盖通知后的本地备份找回**：语义中要求存入草稿 `backups/`，但未提供恢复 UI 入口。是否只需让用户在操作系统的文件管理器中自行提取？
4. **协同修改短暂高亮**：画面或属性面板在他人改动时是否伴随短暂的高亮闪烁？若目前协同底层暂无此视觉支持，则仅做直接跳变。
5. **离线冲突弹窗的延后决定**：关闭弹窗保持离线暂停状态后，界面上应该在哪里提供入口再次唤出此弹窗做决定？（如顶栏的云朵图标变红并作为触发入口？）
6. **离线修改丢弃前是否备份**：用户在弹窗点击「丢弃」时，是否需要按照 `product/document-service.md` 保护机制，将这批被丢弃的本地草稿也存入 `backups/` 留个底？

## 目标

把现在挂在 Vite 开发服务器里的后端拆成能独立运行的服务，前后端代码只经共享目录和网络协议往来；在此之上做项目级的渲染调度。

做完用户得到：桌面版后端更稳；桌面端能帮浏览器端即时渲染；改编辑界面不再让预渲染缓存失效。

## 与前后两期的约定

- **接一期**：Agent 服务的独立入口一期已做，本期在 M3 里把它搬进新目录，并解决不经 Vite 载入工具实现与卡片。一期的云节点渲染服务在 M4 作为调度规则里的「渲染服务器」目标接入。
- **保留 Tauri 外壳**：「桌面壳脱离 Vite」只在 Node 这一层做，把「起 Vite 开发服务器」换成「静态页面 + 独立 Node 服务」，外壳只换一条启动命令，**不碰 Rust**。原三期 Electron 迁移已取消（2026-10-07）。
- **M5 会让预渲染缓存整体换键一次**：放本期最后，事先经用户确认，发版通知里写明；本期不因取消 Electron 迁移而改变像素基线。

## 现状（2026-10-05 实测）

- **协议已分开**：页面与服务端经 `/api/**` 与文档服务的 WebSocket 往来。
- **运行时没分开**：后端是 25 个 `vite-plugin-*` 中间件，挂在 Vite 开发服务器里；桌面正式版的外壳直接起 `node_modules/vite/bin/vite.js`（`desktop/src-tauri/src/lib.rs`）。原计划列了两处由此而来的隐患：静态中间件的文件穿透要靠 `fsDeny` 挡；文件监视器异常会拖垮服务。
- **代码互相引用**：服务端有 21 个文件直接引前端目录，前端有 7 个文件直接引服务端目录（都不含测试）。
- **代码版本哈希取整个 `src/`**（`server/frame-code.mjs`），所以改编辑界面也会让预渲染缓存失效。
- **M1（即时渲染 / 预渲染的术语统一）已合入 main**，本期从 M2 起。

## 目标布局与守门规则

四层：

| 层 | 放什么 |
|---|---|
| `frontend/editor` | 编辑界面：界面、store、交互、页面侧的 Agent 面板 |
| `frontend/stage` | 浏览器渲染舞台：渲染管线、卡片、部件、舞台控制协议 |
| `shared` | 前后端同构的纯模块，零 Node 内置依赖：项目数据模型、确定性计算、通信与消息契约 |
| `backend` | 原 `server/`：文档服务、素材服务、渲染（调度、截图驱动、预渲染进程）、Agent 宿主与感知类工具 |

规则（进 `src/layering.test.mjs`）：`shared` 不引用另外三层；`frontend/editor` 与 `backend` 之间不许直接 import，只经 `shared` 或网络协议；`frontend/stage` 只引 `shared`。

注意：`constraints.md` 现在的分层约束写的是「kernel ← render ← editor / mcp / ai」。新布局落地时这一条要跟着改，属于改规则，先给用户确认。

## 步骤

| 步 | 做什么 | 完成的标志 |
|---|---|---|
| M2 共享目录 | 建 `shared/`，把互相引用的模块迁进去（鉴权客户端、节点会话、工具清单、消息类型，以及服务端引用的前端纯计算）；补守门规则 | 守门测试拦得住前后端直接互引；类型检查与全量测试全过；缓存键不变 |
| M3 后端独立 | 素材服务独立入口；文档服务独立进程与启动配置；**Agent 服务搬进 `backend/services/`**（原计划没有这一项）；桌面正式版改成「静态页面 + 独立 Node 服务」 | 桌面正式版的进程树里没有 Vite 开发服务器；桌面全部探针不变红 |
| M4 渲染调度 | 项目级调度规则存进文档服务；即时渲染由调度器定向派发，预渲染仍由队列认领；桌面端协助浏览器端即时渲染，项目与设备双重同意；纯浏览器节点仍不替别人干活 | 在线页面遇到渲不了的用户卡、素材效果卡，停下时由桌面端或云节点即时渲出并贴上 |
| M5 舞台规整 | 整理 `stage/` 目录与 `__pc*` 协议；代码版本哈希收窄到舞台、共享计算与截图核心 | 改编辑界面不再换缓存键；导出像素基线不变 |

- **M3 最难的一处**：服务端不经 Vite 怎么载入卡片（TSX）与工具实现。预先打包成服务端产物是候选做法，未定；开工前先做探针。
- **M2 可以提前**：它不让缓存失效、风险低，人手有余时可以在一期并行做。
- 每步都跑 G0；M3、M5 加跑 G0-R（`guide_files/verification.md`）。

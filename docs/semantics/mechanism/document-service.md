# 文档服务：机制

本册写 `../product/document-service.md` 背后的具体机制（三级），从属于它，与它冲突时以它为准。

## 职责

- 路由层不绑定具体业务，渲染任务队列只是挂在它上面的模块之一。

## 会话与传输

- **选传输**：先试 WebSocket，握手失败就转 HTTP 长轮询；每次重连都从 WebSocket 重试。共享项目配置里没有选传输的字段，用户侧没有任何传输选项；强制走某一种只留给开发者排障用的环境变量或探针参数。降级的原因写进日志和连接诊断，`/healthz` 能看出每条会话走的是哪种传输。
- **凭证**：HTTP 长轮询建连的那一次请求交的凭证，与 WebSocket 握手交的是同一份，核对规则与一次性随机数的规则都不变。建连成功后得到会话号，会话号只放在请求头里，不进地址、不进日志。
- **会话内接续**：单次传输中断不结束会话。客户端带着会话号和已确认的序号重连，服务端补发对方还没确认的消息，客户端也补发自己还没被确认的消息。超过保留时限才算断线；保留时限与 WebSocket 靠心跳发现死连接在同一量级，数字只在契约里定。
- **断线之后**：行为与现在相同：订阅清空，租约按渲染任务队列的规则回收，重连要重新交凭证，节点用 `hello.resume` 报手里的租约。`hello.resume` 管租约，序号管消息，两者并存。
- **不做**：不做 SSE，不做二进制帧，两种传输都只收发文本 JSON。素材字节的中继是云端托管服务的职责，属于 `docs/plan/direct-connect-plan.md`，不走文档服务的任何传输。
- **内嵌模式**：挂在编辑器（vite）里的本地文档服务只接 WebSocket，不接 HTTP 长轮询。
- **账号云端项目的连接寿命与失效通知**（2026-10-14 用户定，推翻定时换会话机制）：已经建好的连接不再按时间失效，也不轮询；失效一律由账号服务主动通知。账号服务发生影响登录的改动（改密选退出、退出登录、被踢、移出项目、删账号等），发给文档服务，两边互相握手确认变更办完。若文档服务未回确认，账号服务超时重发（退避重试最多 15 次，超过 15 次记进错误日志）。文档服务关掉相关连接、做完收尾后回确认；文档服务收到通知后转告素材服务和云端 Agent 服务，沿用现成落盘重发办法。文档服务重启或和账号服务重新连上后，先把错过的通知按顺序号补齐。建新连接时用的票据和访问令牌仍是短时效的，但连接建好后不再跟着它到期。页面不再定时换会话；断网、睡眠醒来等真断线照旧按离线重连处理，重连时凭新票据，重连后的补发带期望历史序号。

## 连接发现

- **服务地址下发（已引入）**：素材服务 URL 的动态下发作为基础设施发现功能提前引入。素材服务所在的一方把它的地址上报给文档服务，文档服务再下发给需要它的渲染节点和客户端；上报方断开后，这个地址随之撤回。
- **设备间直连（预留）**：公网直连所需的地址交换归云端托管服务的牵线（见 `../product/hosting.md`），机制在 `docs/plan/direct-connect-plan.md`，现在只留接口，不实现。
- **局域网发现（已引入）**：本机项目的主机在本网段广播项目名和地址，成员据此走局域网直连，连上它的文档服务和素材服务。这一步不经云端，也不承担任何传输。

## 版本与身份

- 项目每次被修改，项目历史序号加一（2026-10-14 用户定）；卡片源码每次被修改，卡片版本号加一。
- 同一个提交号已经落地过的，再次提交直接回当初的历史序号；判断「是不是同一个请求」看账号、登录、登录代数、设备、页面会话和提交内容，不看访问凭证号（它跟着访问令牌约两分钟换一次）和期望历史序号；落地时的署名与审计记录仍是第一次被接受时的完整身份，含凭证号。〔裁：主会话 2026-10-14，`AGENT-v18-cardsync.md`；实现在 `server/docservice/operation-wiring.mjs`〕

## 保存基准与修改状态检查（2026-10-08 对齐要求，待实施）

- 本机修改状态检查覆盖当前设备前台编辑、待提交操作、保存、素材入库/上传、本机 Agent、渲染和后台写入。保存暂时禁用前台编辑，等待本机写完；失败不覆盖上次有效保存，并恢复编辑。
- 全局修改状态检查覆盖同项目各设备、云端 Agent、上传/分片、渲染及后台产物的修改状态；不能只用某台桌面状态或项目历史序号不变推断全部无修改。
- 非本机内容固定一份确定快照，记录哈希、权威时间、服务/项目标识和历史序号；保存快照之后的远端修改仍作为后续历史序号保留，不要求全局一直停写。快照内容与素材引用/入库状态怎样共同确认待契约落清。
- 哈希和时间不替代可比较的基准内容、离线操作和历史序号。断网期间的离线操作在桌面版落盘至本机恢复文件、在在线浏览器落盘至浏览器本地缓存（`IndexedDB` / `localStorage`）；连上文档服务后（以及在线点击撤销产生未决冲突时），按「项目 × 用户身份」存入文档服务独立于项目 JSON 的待合并表，清理对应本地暂存。用户在「冲突合并」窗口分批点「合并」时，重检当前云端历史序号并提交 `project.op`，已合并或点「删除选中」的二级修改项从该用户的待合并表中移除，重复提交幂等。

## 账号事件与延迟撤回（2026-10-08 对齐要求，待实施）

- 云端文档服务持久记录项目创建者、成员、禁入与存在状态。跨服务创建、撤销、补偿使用幂等操作编号，重启后继续，不另建第二套权威项目关系。
- 用户改密选否保留现有云端登录与写入权限；选是按事件撤销旧授权，处理改密码绝对时间至旧凭证账号下线期间的旧凭证修改。
- 改密选择退出与被踢均需保留 Agent 已读消息及其共有当前任务的操作：私有任务中止，共有已读当前任务保留继续且修改不撤回；消息、任务、委托和操作关联持久记录，改密补偿不只按时间扫描。例外不恢复旧用户登录或被踢账号的项目权限；删项目或关 Agent 仍中止对应任务。
- 操作历史需要区分账号、旧/新登录、授权代数、服务接收次序和可信时间依据，保留撤回所需内容。不能只凭客户端时间戳，或用已有有限摘要历史声称能完整选择性撤回。
- 退出确认的跨服务完成点已按下面这一条实现；补偿机制 0.7.20 已实现，见下面「改密退出后的逐项撤回」。撤回不能顺便删除其他账号或新登录的合法修改；因改密或重设密码触发的撤回里，别人在待撤回的修改项基础上又改过的，那一项不撤回、不弹窗口；用户按撤销按钮遇到冲突才弹窗口（2026-10-08 用户定，见 `../product/document-service.md`「冲突」）。详见 `../../plan/account-binding-contract.md`。
- **退出确认（已实现）**：账号服务收齐文档、素材、Agent、渲染四样确认，再收下文档服务签的结束见证，才把一次退出记成办完。文档服务里的续办器（`server/account/logout-confirmer.mjs`，缺省每秒看一遍，`account.logoutConfirmPollMs` 可改）把账本里没办完的退出往下办。每一步先落盘再发，进程重启后重发的是同一份，账号服务认得出重复。四样的来源如下。〔裁〕：见 AGENT-v18-logout.md
- **退出确认的时限**：一次退出等各服务确认最多 45 秒（`LOGOUT_CONFIRM_TIMEOUT_MS`，2026-10-14 用户定，原 120 秒改为 45 秒），从用户选「退出」那一刻起算。到时由账号服务按它自己的钟判，状态接口回 `logout.state: 'failed'` 并带一段不含令牌、票据、密钥和登录号的调试信息（事件号、原因 `confirmation-timeout`、等了多久、哪几样确认了哪几样没有）；库里的状态不改，仍是「在办」，每次读时现算。文档服务到时在自己的账本里记一次「这次退出超过时限」、写日志，并把它这边的情况（哪几样确认了、原因码、等了多久、实例号）按白名单报给账号服务。到时不动作废名单：旧登录在选「退出」那一刻就作废了。迟到的确认照常收，四样齐了状态照实变成「办完」，失败和调试信息不再出现。失败时提示「退出没有确认完成。旧设备已经不能再使用；需要帮助时，请把下面的信息发给我们。」八行调试信息默认收起，点开才看。选「不退出」之后提示「密码已修改。已登录的其它设备保持登录。」（2026-10-14 用户定）。
  - 素材：素材服务自己读访问事件、关掉旧登录的流，再向文档服务确认。
  - Agent：文档服务据账本判。开了「一条任务一个进程」时，要中止的每条任务都凭 root 的关闭记录结清才算；还没绑到进程上就被撤掉的任务不等；保留继续的共有已读任务不等。没开时只有任务清单为空才算。没配 Agent 的部署里 Agent 服务不存在，由文档服务写明原因代为登记。
  - 文档服务自己：由三样证据拼成并记进账本。连接是这个进程亲手关掉的旧登录连接，或进程起来时这条作废事件已在账本里；操作是旧登录没有还没定序的操作；位置是旧登录在各项目里最后一条被接受的操作的顺序号，0.7.20 起作为改密退出撤回的区间终点（见下面「改密退出后的逐项撤回」）。
  - 渲染：渲染服务以服务自己的身份工作，不代任何登录持有连接或流，由文档服务写明原因代为登记，回执标 `attestedBy: 'doc'`。
- **改密退出后的逐项撤回（0.7.20 已实现，`server/account/logout-rollback.mjs`）**。区间是改密事件的顺序号到上面那个「位置」之间，区间里旧登录的操作才是候选；凭「共有已读、当前任务」保留证明定序的，和这次退出保留下来继续跑的任务做的，都不是候选。**怎么判「在它基础上又改过」**：按操作历史记下的修改项（叶子属性、带 id 数组的元素增删、数组的顺序各算一项）逐条看——这一项最后一段连续的改动都是候选，而且那一段开始之后没有别人改过这一项、它的上级或下级，就退回那一段之前的值；否则算冲突、保留现状。上级的「顺序」项不算（别人往同一个数组里加了别的元素不碍事）。撤回作为一次补偿操作经同一条有序提交落地，写入身份是 `{ accountId, rollbackEventId }`、不带任何登录号，由账号服务凭文档服务签的撤回证明定序。补偿操作号的前缀 `logout-rollback:` 留给文档服务，页面与 Agent 提交用这个前缀一律拒；发给页面的操作号与写入身份里不带事件号（事件号是占号的凭据），存储里照旧是全的。
  - **这几个数都是三级**〔裁，主会话 2026-10-22〕：一批补偿操作最多 **1000** 个修改项或 **256 KiB**（后者与页面一次提交的上限取同一个数），批与批之间让出事件循环，气泡只在第一批发；一个项目一次退出最多撤 **50000** 个修改项，超出的不撤、单独记账（不并进「别人改过所以保留」）；账本里每个项目记下的撤回／保留路径最多 **50** 条、每条最长 **300** 字符，超了截断并标记；续办器一轮最多等某一次退出的撤回 **1 秒**，到点就去办别的退出，「没办完就不登记结束见证」不变。定这些数的理由：撤回不该比页面一次提交更重，而且任何一次退出都不能把文档服务的事件循环长时间占住——区间里改了多少由那个要被踢掉的会话自己决定，不设上限就是一条可被触发的拒绝服务路径（2026-10-22 对抗性安全专审 SEC-03、SEC-04、SEC-05）。

## 渲染任务队列

- **拉取式**：节点在闲时向文档服务认领任务。认领是「比对状态再加锁」一步完成：只有还没被认领的任务能认领成功，两个节点同时认领同一个任务时只有一个成功，另一个换下一个。
- **节点自己挑**：每个任务标明它有多重、要求什么能力（例如要不要本机转码、有没有用户卡或素材效果卡）和渲染环境；节点按自身能力和环境过滤，只认领自己做得了、环境相符的。
- **指纹前置过滤（特例）**：为防止指纹锁引发并发风暴，允许特定队列（如预渲染队列）基于节点环境指纹进行前置拦截过滤，作为不干涉节点原则的特例：环境指纹与任务要求不符、或这张卡已被别的环境锁定的任务，不发给该节点，也不让它认领。能力过滤仍由节点自己做。
- **谁发布**：需要预渲染结果的一方（编辑界面、Agent）只发布粗粒度的计划任务「给这一版项目做预渲染」。第一个认领它的渲染节点算出要预渲染哪些卡，把细粒度的任务切分后发布回队列。任务按预渲染结果的键标识，同一个结果只有一个任务，重复发布不产生第二份。
- **完成**：节点先把产物推送到素材服务，再向文档服务报完成；文档服务把完成通知发给关心这个项目的各方，它们从素材服务取字节。
- **断开与超时**：认领者的会话断线（见上文「会话与传输」；单次传输中断不算），或在约定时间内既没报进度也没报完成，它认领的任务回到未认领状态，别的节点可以重新认领。晚到的完成报告按最新的认领为准，旧认领者的报告不作数。
- **队列只在内存里**：队列是可以重建的记账，不持久化。文档服务重启后队列为空，各发布方重连后把自己仍需要的任务重新发布一遍；已经在素材服务里的结果不用重做。
- **优先级**：任务带 `priority`。`backfill` 原来表示为弱设备补做预渲染；2026-10-07 用户定在线浏览器发布的任务一律 `normal`，0.7.19 起页面不再发 `backfill`（`rendering.md` 的「界限搜索与成本记录」），队列与节点仍认这一档，只为部署切换期间还开着的老页面〔裁：三级，老页面发来的 `backfill` 照旧排在后面，不拒收〕；缺省、`normal` 和旧形状的整数都算 `normal`（本机判重而发布的），整数只在 `normal` 里排名次。节点认领时先认 `normal`，没有了才认 `backfill`；同一优先级按发布先后。同一个结果键已有任务时不另起任务；已有的是 `backfill` 而又有人按 `normal` 发布，就升为 `normal`。同一档里计划任务排在细任务前面：细任务要等计划切分了才有，切分只要一两秒；计划排在节点自己积压的细任务后面，新改的卡要等积压做完才有任务，不会切分的纯浏览器节点这段时间没活可接〔裁：2026-10-01 `claude/m7-race`，卡点 1 第 1 行，报告 `docs/reports/AGENT-m7-race.md`〕。
- **即时渲染不进队列**：Agent 的即时渲染和用户交互需要的即时画面仍在各自所在的位置直接做（见 `rendering.md` 的「即时渲染与预渲染进程」）；队列只管预渲染。

## 成本记录

- 文档服务按项目空间存成本记录，给在线浏览器做界限搜索用（`rendering.md` 的「界限搜索与成本记录」）。
- 键是「卡片身份（不含测量机器）+ 环境指纹」；值是活渲单帧耗时、采样帧数、测量时刻和构建模式（开发 / 构建）。
- 桌面版与在线浏览器的页面测完卡都写入，同一个键只留最新一条；在线页面打开项目时读本项目的全部记录（界限搜索用；两个舞台的页面有对得上的记录时也先用界限搜索）。（2026-10-07 用户定，0.7.19 落地；原先只有一部分页面写、一部分页面读）
- 和内容库一样按项目空间隔离；只放耗时，不放字节。
- 「最新」按测量时刻比：新来的一条不比已有的旧才替换，同一时刻后到的赢。这样桌面版接上共享项目时补传的旧记录不会盖掉别人刚测的新记录。
- 环境指纹与预渲染结果键同一套（操作系统、GPU 基础类别、Chrome 主版本，`rendering.md` 的「不同环境的结果不混用」）：页面只报原始值，由文档服务算，归一规则只有一处。
- 数字（可调）：一次最多写 500 条；一个项目最多存 20000 条（满了只许替换已有的键）；一次读最多回 5000 条，超了按测量时刻从新到旧留、并标明截断。
- 云端 Agent 代成员的连接只能读（`cost.list`），发布预渲染之前判轻重用，不能写（`agent.md`「补发预渲染任务」）。〔裁：主会话 2026-10-21 派的 `claude/agent-publish-heavy`（三级）〕
- 成员才能读写本项目的记录；每个项目一条追加日志，与内容库共用这个空间的存储，文档服务重启后照旧在（与只在内存里的渲染任务队列不同）。

## 项目文件

- 项目保存成文件（`.proc`）由页面完成，文档服务不写项目文件。页面只在拿到文档服务对最新操作的确认之后才写。

## 游客

产品承诺见 `../product/document-service.md`「游客」（2026-10-23 用户定）。这里只写怎么做到。

- **编号**：`gst_` + 24 位十六进制，和账号编号 `acc_` + 24 位同形状。在成员名单、禁入表、权限判断里当同一类主体用，只有「谁签发、谁核对」和限额不同。
- **令牌**：`gst1` + `base64url(JSON)` + 43 个字符的 `base64url(HMAC-SHA256)`，整串只有 `[A-Za-z0-9_-]`。不带点号是硬要求：它要当 `Authorization: Bearer` 送，那一层只认这个字符集，带点号会被当成没登录挡回来。签名段定长，从尾部切就分得开两段，不要分隔符。
- **认不认由签名说了算，不由前缀说了算**：验得过就一定是本服务发的；验不过就往下交给账号服务去认。过期的单独标出来（签名没问题但过了期），直接拒，不往账号服务那边漏——漏过去只会得到一个莫名其妙的错。允许 30 秒时钟偏差。
- **有效期 24 小时**，页面每次用之前自己续，**每次续来的都写回本机**；交回一张签名对得上的令牌就是续期、编号不变——**过期了也续**，只要过期不超过 3 天（`GUEST_LIMITS.renewGraceMs`，和游客项目的寿命一样长：超过 3 天没来，他建的项目也清掉了）、这个身份没被作废。不交、改过的、过期超过 3 天的、作废过的，随机一个新身份。编号只由服务端生成，请求体里写什么都不收。〔裁〕claude/guest-fix，审查 B：原先「交一张过期的就随机一个新身份」、页面续期又只在内存里，游客隔天回来就成了另一个人、进不了自己的项目，和产品承诺「下次进来还是同一个人」相反
- **登录账号之后作废**：页面登录账号、或者点「我有账号，去登录」时，把手里那张令牌交回同一条路由、带 `revoke: true`；服务端把这个编号记进撤销表（和账号退出登录同一张 `revokedLogins`），之后这个编号的令牌核不过、也续不了期。发不出去不拦着登录，本机那一份照样清掉。〔裁〕claude/guest-fix，审查 S9：原先只在页面那一侧清掉，服务端那张令牌照样能用、能一直续期
- **密钥**存在数据目录的 `secrets/guest-key`（0600），第一次跑时生成。密钥一换，在手的令牌全不认，游客会在那一刻丢掉身份，所以存坏了不自动改写；读不了写不了时游客这条路整条关掉（回 503 `guest-unavailable`），账号那条路不受影响。
- **领令牌的路由不要 Bearer**（他还没有身份），按**来访 IP** 限流：同一个 IP 任意连续 1 小时里最多发 20 个**新身份**，到数回 429 `guest-rate-limited`，响应带 `Retry-After`；续期（带着能续的旧令牌来）不数（〔裁〕claude/guest-fix，审查 E：原先续期也数，同一个网络里的几个人、或一个人刷新 20 次就被挡在外面）。这只挡得住随手刷的，挡不住换 IP 刷；真正挡得住的是验证码或账号，这一版不做。
- **这条路由不在桌面外壳的账号桥放行清单里**（桥上只有 create / join / session / admin / members 五条，加一条要发新外壳，见 `platforms.md`「更新补丁换不掉外壳」）。页面在桌面版上根本发不出这个请求：`src/account/client.ts` 先挡掉。守门测试 `JRC-7` 据此把它单列为「只在线」，并另有一条断言盯住那个判断还在。
- **限额**的数都在 `server/account/guest.mjs` 的 `GUEST_LIMITS`：项目 1 个、视频 3 条、每条源文件 100 MB、3 天清理、令牌 24 小时、过期 3 天内可续；领令牌每 IP 每小时 20 个新身份在 `guest-rate.mjs`。页面上那句说明由同一组数拼出来，有测试守着两边一致。
- **「3 条视频」怎么数**（2026-10-23 用户改定口径；原先数的是 3 个已入库的文件，但在线编辑器传一个视频会上传小档预览和原尺寸**两个**文件，于是第二个视频的原件就被拒了）：数一个项目里**不同的视频源**，一条视频源对应一个原尺寸、至多一个小档，所以按「原尺寸档几个、小档几个，取多的那个」数；图片和音频不计条数。尺寸那一条照旧对**每个**上传的文件都查。〔裁〕claude/guest-fix，审查 A1、A2：原先只数原尺寸档、按页面报的扩展名认视频，游客把每一片都标成小档、或者把视频报成 `jpg`，5 条 mp4 全收
  - **是不是视频，按文件头字节认**（`server/asset-store/media-sniff.mjs`），不信页面报的扩展名：mp4 / mov / m4v（`ftyp` 盒子，图片牌子 AVIF / HEIF、音频牌子 M4A 除外）、WebM / Matroska、AVI、MPEG-TS / PS、FLV、ASF、Ogg Theora 认作视频；PNG、JPEG、GIF、WebP、BMP、AVIF、SVG 认作图片，MP3、AAC、WAV、Ogg、FLAC、M4A 认作音频。**认不出的按视频算**（失败闭合），只有开头是一段文本的不算（能播放的视频容器开头一定是二进制）；页面报的扩展名本身是视频的，不管文件头怎么说都算。
  - 是哪一档，仍由页面在上传时声明；**声明缺失或不认识一律当原件**。档位是页面说的，但按「取多的」数，全报小档也照样数到；最多只能靠「3 个报原件、3 个报小档」多放进 3 个文件，最坏 6 个、每个不超过 100 MB。
  - 闸门：开**新的**暂存、报的扩展名是视频时先数一次（已入库的按文件头、正在收的按登记的扩展名和档位），超了当场拒，给老实的页面早点说「不行」；**收尾**是真正的闸门——收尾前按登记的数一次，超了不收尾、暂存留着；入库之后再按这一条自己的文件头连同已入库的重数一次，超了把刚入库的这一条删掉、回 403 `guest-video-limit`。整件上传（`/api/media/upload/<名>`）报的扩展名不是视频时，先从请求体里读出开头几十个字节按文件头认。游客不能用 `/api/media/adopt`（补算内容键，给素材收集用；它能把还没收尾的分片暂存挂进库）。整件上传核权出错（包括暂时性的 503）照错误回，不往下放。
  - 在线上传队列遇到这几种 403（视频满了、文件太大、只读）不再重试：这一项整项出队、记成被拒，后面的照常传；编辑台的素材库（手机版是编辑页）用提示条说「『某某』没有传上云端：游客最多上传 3 条视频……」。原先它无限退避重试、把后面的全堵住，界面上什么也不说。〔裁〕claude/guest-fix，审查 D（用户看得见，二级）
- **只读**拦在 `server/account/authority.mjs` 的 `permission` 一个口子上：名单里哪怕写着读写，游客在别人的项目里也按 `r` 算。通过申请、创建者改名单时也落账成 `r`，免得名单上显示的和实际能做的两样。
- **三天清理**走创建者点「删项目」那同一条路：标成已删除、落墓碑、记一条访问事件、按 delete 围栏停任务，下游不用为游客另认一种「项目没了」。素材服务收到这条删除事件就把整个项目的素材库删掉（`asset-service.md`「项目删掉，库也删掉」）；删掉的项目号只有原创建者能再建，别的游客、账号带这个号新建回 409 `project-id-taken`。文档服务起来先扫一趟（关着的时候到期的补上），之后每小时扫一次。项目记录上新加了 `createdAt`；没有这一项的老项目（这条规矩之前建的）一律不动，不猜生日、不误删。〔裁〕claude/guest-fix，审查 C：原先删除事件只断流、字节永远留在盘上，而且已删除的项目号谁都能重建，另一个游客带同一个号新建就成了创建者、和前一个人的字节在同一处库里
  - 还没做的：文档服务自己存的项目内容、云端 Agent 服务按项目存的对话目录，删项目之后是不是也清，这一轮没查（只修了素材字节）。

# Agent：机制

本册写 `../product/agent.md` 背后的具体机制（三级），从属于它，与它冲突时以它为准。

## 云端对话权限与发送者（2026-10-08 对齐要求；0.7.18 已在账号模式下实现，只读成员那一条除外）

本节的实现在账号权威的两本账里：对话账本 `server/account/conversation-authority.mjs`（记录版本 `v: 2`），运行授权账本 `server/account/run-authority.mjs`。〔裁：见 `docs/reports/AGENT-v18-worker.md`、`AGENT-v18-prod.md`；本节原标「待实施」〕

- 云端对话分别记录项目、所属账号和共有/私有权限；新建默认共有。共有允许本项目所有已登录且有项目权限的成员读取完整历史/回复和发送，私有仅所属账号，另外项目创建者可以读（只读）；共有切成私有后，别的成员的读接口与历史订阅立刻被拒；读接口、历史订阅和发送接口都在服务端核对，不能只隐藏界面。每个对话还记权限版本 `aclRevision` 与队列版本 `queueRevision`，事件流的轮询据它们发现权限或队列变了。
- 每条用户消息记录服务端确认的发送者账号编号（`senderAccountId`）；每轮运行记录实际发起者，并关联其消息、委托和项目修改。对话所属账号、消息发送者和 Agent 运行身份不能混成一个字段。
- 改密选退出或被踢时，已发送且 Agent 已读的消息保留原文和作者；私有任务直接中止，共有已读消息触发的当前任务及其修改保留继续。已读由 Agent 读完整条消息后向文档服务确认（`confirmRead`，带完整提示词的摘要）：文档服务核提示词与账本里的消息逐字一致，才写下已读收据（`readReceiptId`）并把这一轮的授权从 `preparing` 转成 `active`。仅发送/送达、界面已读、客户端自报都不产生收据。改密退出（围栏种类 `credential`）与被踢（`member`）下，授权同时满足「对话仍是共有、读的那一刻是共有、有已读收据、是这个对话的当前一轮」才转成 `retained` 继续，其余转成 `revoked`；这位账号还没轮到的排队消息作废。收据与授权都存在账本里，重启后仍在。
- 每轮只核对实际发起者此刻是不是本项目的有效成员（在项目里、没被踢、登录有效）。Agent 的能力不按发起者是创建者还是参与者区分，创建者操作对任何人发起的 Agent 都拒绝（2026-10-08 用户定；原写「按实际发起者项目权限核对，不借对话创建者的更高权限」作废）。只读成员在发消息这一步就被拒，不是「能发起但改不了项目」；现在没有只读成员这种身份，集成分支 `cloud-agent-contract.md` 4.4 预留的只读机制照此改。共有已读任务例外单独记录消息、任务、委托和项目操作关联，仅保留本轮所需能力，不让旧用户凭证发新消息或发起下一轮；被踢账号的全部设备不能读取、订阅或发送，共有其他成员独立核对。项目删除和关闭 Agent 仍终止对应任务，不属于此例外。
- 共有对话的排队：每个对话一条队列，按服务端收到的顺序一轮一轮跑，同时只有一轮在执行；切成私有时队列里别的成员的消息一并作废，正在跑的那一轮若是别的成员发起的就中止（2026-10-08 用户定，规则见 `../product/agent.md`）。已有对话不用迁移：云端 Agent 服务此前从没部署到节点上，生产环境里没有存量对话。队列在对话账本里：每条消息按到达序号 `arrivalSeq` 排队，状态 `queued`、`preparing`、`cancelled` 等，切成私有时别的成员排队中的消息记 `cancelled`（原因 `private`）。同一个对话上一条没结清下一条领不到，所以同时只跑一轮（见「账号模式的进程分工」）。〔裁：见 `docs/reports/AGENT-v18-worker.md`〕

## 工具

- **读**：项目、素材、卡片清单、布局等从项目副本读。
- 只读页面独有状态（当前选中、播放头交互、面板界面）的工具在编辑界面里执行。
- 工具的清单和参数由卡片定义等数据自动生成，加卡片不需要改工具。

## 汇报与对用户说话（2026-10-20 用户定，见 `../product/agent.md`「汇报」）

- Agent 对用户说话用工具 `send_message`，`to` 填 `"user"`、`text` 写一两句话。它和多 Agent 协调的 `send_message`（发给别的 Agent 的对话 ID 或 `all`）是同一个工具。API 直连（本机与云端）由 `server/harness/tools/index.mjs` 就地答，不经公告板；经 MCP 的 CLI 驱动由公告板 `server/agent/agent-board.mjs` 直接答「已显示」。托管档的开放清单里没有 `send_message` 时，harness 补一个只能发给用户的（`server/harness/tools/userMessage.mjs`）。
- harness 的执行规则在有 `send_message` 时让模型每组操作前后用它说一两句，和这一组的工具调用放在同一次回复里；收尾仍交 `final: true` 的 `report_progress`。说过话的一轮，最后一次空回复不算「没有返回」。
- 气泡里显示的话由页面从这一轮的事件里取（`src/ai/userMessages.ts`）：这一轮调过 `send_message`（发给 user、没失败）的，按先后列出它们的 `text`；一次都没调的，用文字回复（相邻的文字并成一句）。两种不混：调过的那一轮，文字回复只在「显示思考」里看得到。原先「没交收尾汇报就按文字回复代交一份汇报」（2026-10-19）撤掉，免得同一段话在气泡和汇报里各出现一次。
- 操作区（`src/editor/right/chat/ActivityPanel.tsx`）一次显示一轮：缺省跟着最新一轮，点气泡切到那一轮，也能前后翻；内容是这一轮的操作图标、操作详细预览（写了项目的那一步能「撤销这步」）和阶段 / 本轮小结。只取这个对话的消息，不取文档服务项目频道上的工具事件（原「Agent 操作记录」`src/editor/sync/AgentEventLog.tsx` 按项目频道列，会混进别的对话和别的成员的调用，已不挂在 AI 栏）。每一轮的回复各占一个气泡，紧跟在发起它的用户消息后面，不再把没交本轮小结的回复和后面几轮并成一个气泡。

## 桌面 APP 接入

- 桌面工具经 stdio MCP 服务 `server/mcp-server.mjs` 接入。找实例的优先级为 `--port`、`PROMPTCUT_PORT`、`--port-file` / `PROMPTCUT_PORT_FILE`、公共 `%TEMP%\promptcut\port.json`；每次调用重新找。找不到、进程已退出或端口无人监听时返回说明。
- Claude Code 按 MCP 进程区分会话，Codex 按 `tools/call` 的 `_meta.threadId`（兼容旧字段 `x-codex-turn-metadata.thread_id`）区分；多个 Codex 线程共用一个 MCP 进程时仍分别登记。厂商由 `initialize.clientInfo` 识别，登记类型为 `desktop`，创造力等级跟项目。
- SKILL 做法由 MCP 初始化的短 `instructions` 和桌面会话本地工具 `get_skill_guide` 提供，不写用户级 skill 文件。
- 登记项名为 `promptcut`，写 Claude Code 的 `~/.claude.json` 或 Codex 的 `~/.codex/config.toml`，只写命令与脚本，不写端口。整份配置先备份到 `<skillRoot>/mcp-register/`；撤销只还原该条目，用户改过条目或无法安全识别 TOML 写法时拒绝覆盖。
- 桌面调用在服务端按登记身份经过 SKILL 闸；AI 栏里的 Agent 与未报桌面身份的调用不经过这道闸。AI 栏按桌面会话分组：每个会话保留最近 20 次调用、30 份报告，界面显示最近 5 份报告；最多 16 个会话，2 小时无活动且没有调用在跑的不显示，推送节流 100 毫秒，只存内存。SKILL 下草稿的独占锁照常持有；悬浮窗的上一步画面由用户这份页面渲染，只记录时间轴操作。〔裁：2026-10-02 接手 A4 收口，`docs/reports/REPORT-post-M8.md` 第 15.8 节卡点 1 第 1 行；承接归档 `AGENT-skill-mcp.md` 第 5、8、10 节〕

## 创造力等级的判定

- 工具需要的等级集中在一张对照表（`server/agent/creativity-gate.mjs`），在所有工具调用的总入口、执行之前判：新建卡片、新建效果要「高」；改已有卡片的源码（含整篇重写已有的卡）、改效果的定义（表达式、步骤、参数声明）要「中」；其余（用已有的卡片、效果、部件拼装，改片段参数，只改效果的名字和说明，内置测量）「低」就能用。自定义测量代码（`measure_audio_js`）要「高」。
- 这个对话生效的等级：AI 栏的对话取它自己的覆盖值，没有覆盖就跟项目；桌面 APP 的会话（以及认不出来源的调用）跟项目。项目没写等级按出厂的「高」。越级的调用什么都不做，回当前等级、这个操作要的等级和怎么调，Agent 据此停下说明。
- 等级只由用户在项目设置或 AI 栏里改；`set_project_meta` 只收它声明过的字段，Agent 写不进等级，也不能借它改项目里别的内容。〔裁：2026-09-30 `claude/creativity`，出处 `docs/plan/agent-workflow-plan.md` A1〕

## 自定义测量

- Agent 写的测量代码只在一个专用的无头 Chrome 里跑：每次一个新的无痕上下文，代码在 Worker 里执行、到点终止；不给 Node 能力，不能联网（内容安全策略、请求拦截、指向无人监听端口的代理、Worker 里换掉联网接口，四道各自独立）。不用预渲染的 Chrome：内存上限是整个浏览器的启动参数，模型写的内存炸弹不能带走正在预渲染的页面。
- 测谁与内置的响度测量相同（片段用到的素材原声、整个素材、时间轴混音），服务端把那段声音解成 32 位浮点 PCM 交给代码，代码返回可 JSON 序列化的汇总。要单声道时各声道取平均；时间轴混音与导出一致是立体声。
- 数字：缺省 16 kHz（8～48 kHz）、最多 2 声道、所有声道合计最多 1200 万个样本；代码缺省 10 秒、最长 30 秒；结果最多 256 KB；V8 老生代 256 MB；空闲 60 秒关掉 Chrome。
- 代码自己的错（语法、抛错、超时、结果不能序列化或太大、内存超限）回给 Agent 改代码重试，不当成工具故障；沙箱崩溃或卡死（测量期间每秒问一次页面，连续 3 次没回话）就整个重开，只丢这一次。〔裁：2026-09-30 `claude/custom-measure`，出处 `docs/plan/agent-workflow-plan.md` A6〕

## 用户正在编辑与覆盖提示

- 编辑界面把正在编辑的片段（卡片、字幕条都算所在片段）报给本机服务：拖动中、文字编辑中、选中后 30 秒内动过的算；只选中不动不算，取消选中即作废，撤销、重做与 Agent 让页面做的修改不算动过。推送节流 250 毫秒，非空时每 5 秒续一次，拖动与文字编辑 15 秒没续期就清掉。
- Agent 读到或写到这些片段时（参数点名的、这次提交实际写到的、读整个项目的），工具结果带 `userEditing` 与一句「用户正在编辑……」的提示，只提示不拦。
- 文档服务回的 `overwrote`（10 分钟内覆盖了别人写的实体）进工具结果：写入方是页面的标「用户刚改过」，是别的 Agent 的标「Agent <对话>（<厂商>）刚改过」。
- 共享项目里别的成员的页面经文档服务的在场状态发布正在编辑的片段（15 秒过期，随心跳续期），本机服务记成另一个来源，Agent 读写到时提示「用户 <成员>正在编辑」；本机页面自己发布的那份按页面会话号认出、不重复算。〔裁：2026-09-30 `claude/user-editing` 与 `claude/multi-agent`，出处 `docs/plan/agent-workflow-plan.md` A2、A3〕
- 被覆盖的一方：文档服务发给它那条连接的覆盖通知按对话记下，在它下一次工具结果里带「你写的 … 被 用户 / Agent <对话>（<厂商>）覆盖了」。

## 多 Agent

- 主 Agent 用 `spawn_agent` 拉起子 Agent：新对话 ID 即新身份，登记厂商、驱动（沿用父对话）、预设角色、父对话；开一个带角色名的新页签，不抢焦点；任务作为第一条消息进它的信箱，页签空闲就发出；角色提示词每一轮拼进它的系统提示词。子 Agent 不能再拉起；同一个主 Agent 开着页签的子 Agent 至多 4 个，关掉页签才腾出名额；没有页签可开（桌面 APP 会话、编辑台没打开）时回错误。子 Agent 的创造力等级取父对话此刻生效的等级，之后也不高于父对话。
- 协调公告板在本机服务里、按项目一份：范围声明、改动记录、信箱。改动记录由文档服务的提交流喂，带写入身份（用户、各 Agent、共享项目里别的成员）；没接文档服务时由工具入口记。范围按「剪辑->序列」算。一个 Agent 30 分钟没动静就不算在跑，它的范围不再拿来比。
- 消息：收件页签空闲就作为一条用户消息发出，忙就带在它下一次工具结果里、跑完还没看到的再送；自动连锁至多 3 层，到顶的留到用户下次开口。
- 工具结果里带（提示在最前）：给它的消息、别人动了它声明的范围（每条一次）、它写的被覆盖了、它这次写进了别的在跑 Agent 声明的范围。
- 共享项目里，Agent 的范围与互发的消息经文档服务的在场状态转给其它成员（不进项目历史，范围 30 分钟过期）；文档服务不认识在场状态时停发，不报错。〔裁：2026-09-30 `claude/multi-agent`，出处 `docs/plan/agent-workflow-plan.md` A3〕

## 云端 Agent

本节全部〔裁：主会话 2026-10-06，待用户合入前审；出处契约 `../../plan/cloud-agent-contract.md` 第 N 节，实现记录见同文件第 20、21 节〕；对应产品承诺是 `../product/agent.md` 的「运行位置」。

**入口与实例**

- 一份服务实现两种挂法：桌面档是只有一个实例的特例，托管档（`server/agent-service/main.mjs`）是独立进程，不带编辑页，按「项目 × 成员」分实例，闲置 10 分钟回收（没有进行中的一轮才回收）。托管档对 `src/` 的依赖只经 `server/agent/ssr-host.mjs` 这一处载入缝。（第 2、3 节）账号模式下主服务不跑任务，进程这样分：见下一块「账号模式的进程分工」。
- 对外接口在 `/v1/` 下（经反向代理是 `/agent/v1/`）：消息、事件流、停止、对话列表与详情、改标题、删除、用量、`info`、`healthz`、传附件、交回反向通道的结果（`page-results`）；回包 JSON，请求体上限 256 KiB。页面不请求编辑器进程的 `/api/*`，在线产物里 `/agent/` 开头的地址字面量只有 `/agent/v1` 一种（守门 C10A-API-05、07、08）。（第 2.3、10 节）账号模式下 `DELETE` 对话是真的删（见「删除对话」一条）；`page-results` 在账号模式的主服务挂了反向通道的登记表：先核交的人此刻读得到这个对话，再在登记表里核发起人、页面号、一次性随机数和这一轮的授权，这一轮已经结束、内容对不上的回 409 或 410；没挂登记表的装配（`conversation-policy.mjs` 那一份）仍回 503 `run-unavailable`。〔裁：主会话 2026-10-14，`AGENT-v18-chats.md`、`AGENT-v18-wire.md`，取代 v18-semsync 的两处 503〕

**账号模式的进程分工**（一条任务一个进程；〔裁：v18-semsync 2026-10-13，待用户合入前审；出处 `docs/reports/AGENT-v18-worker.md`、`AGENT-v18-runner.md`、`AGENT-v18-prod.md`〕）

- **主服务只做控制。** 账号模式下 `server/agent-service/main.mjs` 只装配 `account-master-assembly.mjs`：对页面开 `/v1/` 接口、用只做控制的主身份连文档服务、事件库、附件存储、一个只绑回环的双向 TLS 内部口。这个进程不起 vite、不载工具、不跑任何任务。命令行入口要三样配置，缺哪样都拒绝启动：`PROMPTCUT_AGENT_INTERNAL_PORT`（内部口，不能和公开口相同）、`PROMPTCUT_AGENT_ROOT_FINGERPRINT256`（root 那张证书的 SHA-256 指纹）、`PROMPTCUT_AGENT_SHARED_DATA`（各代任务进程共用的数据目录，已存在、可写）。还带着在主进程里跑任务的旧变量（`PROMPTCUT_AGENT_CONTROL_PORT`、`PROMPTCUT_AGENT_ACCOUNT_LOOK=1`、`PROMPTCUT_AGENT_RUN_ASSET_*`）也拒绝启动。文档服务不认主身份、内部口占不上，同样拒绝启动。打出的 `config.error` 的 `reason` 分别是 `account-task-processes` 与 `account-master`。启动时文档服务连不上不退出，隔 2 秒再试登记。
- **内部口上的两类请求。** 任务进程交事件（`POST /internal/v2/worker/events/append`，凭任务证书加它内存里钥匙的签名，逐条回文档服务核对）。槽调度来问「哪些对话在排队、哪些任务要强制关」「这一条的强制终态」（`/internal/v2/master/scheduler/pending`、`…/scope-control`），这两条只认 root 的证书；主服务原样转问文档服务，回来的强制终态是文档服务签的，root 的发布器自己验签，主服务改不了。
- **任务槽与任务进程。** 每个槽是一个 systemd 单元，一次装一代任务进程（`account-task-worker-cli.mjs --control https`，用专门建的非 root 用户跑，不许用 `nobody`），一代只跑一条任务；槽的个数就是全节点同时跑的任务数。任务进程在本机 HTTPS 口上认四条指令：`POST /internal/v2/agent/run-scope/control/prepare`（领取）、`…/start`（开跑）、`…/close`（收尾）、`GET …/settlement`（长挂，结算结果出来才回）。这个口只认 root 那张证书，带反向代理转发头的一律 403，指令的请求头带槽号、第几代、实例号，只用来防串代。领到任务、root 绑定之后才起进程内的 vite，没领到任务的一代不付这份开销。
- **root 入口。** `account-root-main.mjs` 只在 Linux、以 root 跑，三种跑法：常驻、`--bootstrap`（初始化槽：开第一代随即退掉）、`--status`（只读）。它只做槽调度：有排队的对话又有空槽就开一代，叫任务进程去文档服务领任务，把文档服务签的分配交发布器绑定，再让它开跑；任务进程交来「文档服务签的终态加它自己签的意向」就关掉这一代并写关闭记录；文档服务出现强制终态（停止、切私有、踢人、改密退出、进程死了）就凭强制终态关。启动时自己核它执行的代码只有 root 改得了，不满足拒绝启动（`root-code-untrusted`，带上路径）；单元 `Restart=always`。
- **结清。** 关闭记录写好后，文档服务读它，把这条任务记为结束、让出对话的名额，同一对话的下一条才领得到。结果记「做完」还是「被中断」由文档服务按它自己的记录定：停止在结清之前生效的一律记「被中断」，哪怕任务已经报了做完。
- **停止最多等 15 秒。** 页面点停止，主服务凭同一个请求号在服务器上等到 root 关掉进程、文档服务结清再回成功，最多等 15 秒（`stopWaitMs`）；到时没办完回「还在办」，同一个请求号再问原样回成功，不关第二遍。
- **放弃结算。** 任务进程自己判断没法按正常路径结算时，分两种，只看文档服务在放弃之后的那一次回答。清单里已有这条任务的强制终态（它就是因为被停止、被撤销才放弃的）：照强制关。清单里没有（已读确认之后出了暂时性故障：事件交不上去、收尾没形成记录）：调度让这一代主进程停下、写失败观察，文档服务据此签「进程故障」的强制终态，结果记「失败」，槽让出来。没人来强制关的任务因此不会一直占着槽。
- **重启。** root 入口或主服务重启时正在跑的任务记「失败」；节点重启后每个槽要换新的 `authorityId`、空的登记目录，重新初始化，才能再用。
- **调度不在问时。** 15 秒没有调度来问就算不在：消息仍持久排队，`GET /v1/info` 的 `executorMounted` 回 `false`，`/healthz` 回 `taskProcesses: true, scheduler: false`。
- **数据目录两份。** 任务进程设置里的 `dataDir` 各代共用、长期保留：对话的模型历史、工作目录（含用户上传的附件，主服务也往里存）、用量流水、额度、模型配置；`stateDir` 只属于这一代：已读意向等本机状态，不自动清。所以下一条任务的新一代进程接得上上一条的历史。
- **素材工具凭任务授权。** 导入素材、配音与音效入库、按素材读取（量响度）这几个工具在账号模式下凭这条任务的授权读写所在项目的素材，不借成员的票据。传输登记在任务进程的运行资源登记器名下，关闭放在运行器收尾之前，关不干净这条任务只能由强制路径收口。配置在 root 入口配置的 `worker.runAssets`：素材服务的内部口与证书指纹、`maxResponseBytes`、`maxImportBytes`，可选 `timeoutMs`（一次请求里连接多久没动静就放弃，缺省 5 秒）；导入遇到素材服务或文档服务一时答不上，隔一会儿用同一个请求号接着传，最多三次。
- **看画面凭运行授权。** 云端 Agent 看画面时，项目号取自文档服务签的任务授权，工具参数改不了；向渲染服务登记请求之前、每趟去问之前都先问文档服务这条任务现在还能不能读，不能就撤回排着的请求，文档服务一时问不到就隔一会儿再问，问三次都不通也撤回，并告诉模型是「确认不了」。请求体带 `run`（任务授权号、任务号、对话号），渲染服务记在这条请求上。看画面的客户端由 root 入口配置的 `worker.look`（渲染服务的回环地址与签请求用的服务私钥目录）随任务进程的设置下发。现状：渲染服务一侧只核服务私钥的签名，不向文档服务核这条任务授权；各任务进程共用同一把私钥。〔以上两条：见 `docs/reports/AGENT-v18-runner.md`〕

**云端运动追踪**（`track_status`、`track_install`、`track_points`、`get_track`、`attach_clip_motion`；`server/agent/service/perception/track.mjs`、`hosted-motion.mjs`；已实现，已挂载（给模型看的系统提示词按建出了哪几族来写；节点没配追踪的运行环境时 `track_status`、`track_points` 如实说明）；〔裁：主会话 2026-10-14，`AGENT-v18-wire.md`，取代 v18-semsync 的「还没挂载」〕〔裁：v18-semsync 2026-10-13；出处 `docs/reports/AGENT-v18-tools-p3.md`〕）与本机的差别：

- 追踪结果按「项目 × 对话 × 素材 × 素材版本」保存在结果表（SQLite）里，同项目换一个对话读不到、要重追；素材换版后读到的结果带 `stale: true`。`track_points` 多一个可选参数 `force: true`（同一请求缺省返回同一个作业，要重追才带），它不在工具定义里，模型从返回的 `hint` 里知道。`get_track` 没追过时回 `{ ok: true, found: false, hint }`，不回 `null`。
- 素材只经项目素材落到这个对话的工作区，用完删；作业状态写工具作业表，每次推进都重核授权与栅栏版本，被收回时子进程由运行资源登记器杀掉。

**新对话的空对话**（账号模式；〔裁：v18-semsync 2026-10-13；出处 `docs/reports/AGENT-v18-newchat.md`〕）

- 事件流（`GET /v1/conversations/<id>/events`）对看不到的对话回 404，响应体 `{"ok":false,"code":"no-conversation"}`（`server/account/conversation-authority.mjs`）。读取通道在没有任何一次读取被文档服务受理时不放行 2xx，所以不能用 200 加结束事件表达。「页面刚建、还没发过消息」「被别人设为私有」「已删除」是同一种回应；路由不存在的 404 是另一个码 `not-found`，那是故障。
- 页面（`src/ai/cloud/session.ts` 的 `open(id, { fresh })`）靠自己知不知道这个对话存在过来分辨。只有页面自己刚建、还没发过消息（`fresh`），并且这次打开之后既没读到过它的事件、也没发消息被收下过（`known` 为假）时，收到 404 `no-conversation` 才当作正常的空对话：连接状态停在 `idle`，不报问题、不重试，发出第一条消息后照常接上事件流。这次打开之后读到过它的事件、重连后得到 404 `no-conversation` 或 `no-project`，是被设为私有、被删除或项目被删：清掉正文，显示「当前账号已无法读取这个对话，请重新选择有权限的对话。」，停止读，不重连。其余按断线重连并一直重试：不是新对话、这次打开后也没读到过事件的 404（历史里选的、记着的旧对话）、发完第一条消息后偶尔还读不到、502、连不上、没带错误码的 404、`not-found`。401、403 和身份类错误（`unauthorized`、`no-identity`、`forbidden`、`disabled`）停下并给原因；其中被踢、不在成员名单（`banned`、`not-listed`）显示同一句「已无法读取」，Agent 被关显示它自己的那一句。〔裁：见 `docs/reports/AGENT-v18-private-notice.md`〕
- 事件流开着的时候，Agent 服务每一轮轮询都向文档服务核读权限。文档服务明确拒绝（401、403、404）才向页面发 `access.revoked` 再关流；文档服务一时连不上、超时、读取通道被掐断只关流，页面照常重连，不会被说成没权限。〔裁：同上〕设为私有、被踢、退出登录、Agent 被关这类撤销，文档服务发围栏，Agent 服务掐掉那条流，被掐断的流写不出事件；页面不靠事件，靠「读到过的对话重连得到 404」识别撤销，暂时性故障（503 一类）不说成没权限。〔裁：主会话 2026-10-14，`AGENT-v18-private-notice.md`〕
- 「这是页面刚建的新对话」记在浏览器本地存储里（键 `pc.cloudFresh:<账号范围>:<项目>:<页签>`，只记当前那一个还没发过消息的新对话的编号，发出第一条消息后清空），刷新页面后靠它认出仍是新对话。

**补发预渲染任务**

- 改动落地后攒 3 秒发布预渲染任务、只发受影响的片段、每个计划最多 200 个；按「连续 10 分钟没有进度」判定放弃，另有绝对上限 12 小时；重启后重发；项目往前走了的旧计划与旧细任务按内容核对，内容没变照做、被取代的作废，不算失败。（第 16 节）
- **只发重卡**（`../product/agent.md`「发出任务后可以离开」：托管方只为被改动的重卡产流；渲染节点把清单里的片段一律当重卡产流）：写入挑出的片段只是候选，攒满上面那 3 秒再判轻重，判轻的不进清单。判法与在线页面同一套：片段的成本身份照页面的探针与分派表（剪辑段里的卡按摊平视图的虚拟片段），耗时取文档服务里本项目的共享成本记录（`document-service.md`「成本记录」；同一张卡几条记录取中位数，与界限搜索的代表耗时同一条），分派照 `planPipelines`（预算、成本倍率、按位置贪心都不另设）；没有记录的卡按页面测完之前的兜底（声明 `direct` 的判轻，其余判重），服务端认不出的卡（项目自带的用户卡还没登记进来、未知卡片）判重。攒那 3 秒是为了等在线成员的页面把改过的卡测完写进记录（改参数会换成本身份）；没人在线时等不到，按没有记录判。一轮收尾时攒着的马上判、马上报。判定模块载不了、成本记录读不到（旧文档服务不许 Agent 读）时照原来全发。〔裁：主会话 2026-10-21 派的 `claude/agent-publish-heavy`，出处 `docs/archive/agent-reports/AGENT-agent-publish-heavy.md`（三级）〕
  - **改过参数的卡按同一张卡估**：片段的成本身份没有记录时，先看**同一张卡**（同一个卡片 id、同一份源码版本；参数、片段长度、帧率不论）别的身份有没有记录，有就把那些记录当成这个身份的记录，照上面同一条取中位数，再照同一张分派表判；同一张卡一条记录都没有，才按上面的兜底。「同一张卡别的身份」取自此刻项目里同一张卡的其它片段，和这个对话（账号模式：这一条任务进程）里每次写入之前、之后的项目（写之前的那一版就是 Agent 改参数之前、多半已被页面测过的身份）。共享记录只有单帧耗时，估出来的数和直接查到的数走同一条分派（推帧卡按一拍内追得上算、长片段不另算），不另设数字。不跨任务进程记：上一轮改出来的身份没人测过、这一轮又改，就只剩此刻项目里同一张卡别的片段可借。〔裁：主会话 2026-10-21 派的 `claude/agent-heavy-followup`，出处 `docs/reports/AGENT-agent-heavy-followup.md`（三级）〕
  - **判定看得见**：每次判定记一条摘要（候选几张、判重几张、判轻几张、为什么、记录几条、估了几张、判轻的片段 id 截前 10 个），日志事件 `agent.render.judged`。账号模式下摘要随 `render_request` 事件交给主服务，由主服务记进它自己的日志（`promptcut-agent`）；一张重的都没有时任务进程也交一条片段为空、只带摘要的 `render_request`，主服务只记日志、不发布。旧主服务见片段为空直接不管，旧任务进程不带摘要、主服务照旧只发布。任务进程自己的日志（运行器、工具）一行一条 JSON 写到标准输出，由任务槽单元收进系统日志。〔裁：同上〕
- 账号模式：任务进程只在每次写入落地后报「这一轮写到了哪些要预渲染的片段」（`render_request` 事件，经主服务内部口交上去），不拿任何发布凭证；常驻的主服务以托管方的服务身份（Agent 服务的服务私钥、本机文档服务的控制连接）要只能发布的票据、发清单计划，跟到结果并补进对话（挂在写到它的那一轮名下，一轮先收尾、不等渲染）。项目号只取文档服务核过的事件绑定，事件正文改不了项目；文档服务只在渲染节点与「生成轨道流」都开着时给这种票据，连接上只许发本项目的带片段清单的计划。「生成轨道流」关着时不发，对话里记「没开生成轨道流，云端没有预渲染」；文档服务明确不给票据时记一次失败并说原因，不反复重试。〔裁：主会话 2026-10-21 授权，`docs/reports/AGENT-account-render-publish.md`〕

**Key 与模型**

- Key 用现有的加密封装保存，只放在节点上；模拟模型提供方按消息里的脚本走，供不连真模型的验收用。（第 8 节）
- **Key 的加密分发**（〔用户 2026-10-07 定〕；`server/agent-service/service-keys.mjs` 文件头与 `server/hosted/deploy/README.md` 有命令与步骤）：节点用 `machine-id.mjs` 报出机器识别码（Linux 取 `/etc/machine-id`，加盐取 SHA-256 前 100 位，不掺主机名、IP、用户名；重装系统后才变）→ 托管方在自己的电脑上用 `make-api-share.bat` 把 Key 加密成只有这台节点解得开的密文（信封与桌面版「API 分发」同一套：PBKDF2-SHA256 + AES-256-GCM，口令是识别码）→ 会话把密文经 ssh 标准输入送到节点、写进数据目录的临时文件 → `import-key.mjs` 在节点本机解开并按落盘加密保存（`ai.json` 与 `keys/custom.key`），临时文件导入完即删。会话全程只接触密文；输出只有厂商、模型清单与 Key 末四位。密文格式不对、被截断、过期、厂商不对、不是给这台机器的（与被改过在密码学上分不出来，报同一句）都明确报错、什么都不写。
- 按服务名导入：`--service model`（缺省）与 `--service voice`（配音，`keys/voice.key`，另一把封装）；以后加别的外部服务只在服务表里加一项。
- `set-key.mjs` 保留 `--mock` 与 `--clear`；交互式录入明文只作本机调试用、运行时先说明，不收命令行与环境变量里的 Key。
- 账号模式下，模型配置与额度放在各代任务进程共用的数据目录里（任务进程读的是那一份）：`set-key.mjs`、`import-key.mjs`、`admin.mjs quota` 的 `PROMPTCUT_AGENT_DATA` 要指到它，任务用户要读得到其中的 `config/`。〔裁：见 `docs/reports/AGENT-v18-prod.md`；依据 `server/hosted/deploy/README.md`〕
- **每条消息的运行选项**（〔用户 2026-10-18 定〕）：页面发消息时点的模型、思考强度、创造力记在文档服务的这条消息上（`runOptions`），进到交给任务进程的消息记录里；没点的消息记录与摘要和原来一样。文档服务与主服务只核形状，不认识的键或值回 400 `invalid-run-options`。任务进程按托管方的清单挑模型，点的不在清单里就用第一个；思考强度不带就随模型的默认，创造力不带就跟项目。档位清单只在 `server/account/run-options.mjs` 一处，`GET /v1/info` 的 `efforts` 报的就是它；账号模式的主服务读同一份 `config/ai.json` 报模型清单（不解 Key，Key 只看文件在不在），所以主服务用户也要读得到 `config/`。
- 思考强度在云端走 OpenAI 兼容口径的 `reasoning_effort`。2026-10-18 在节点上对两个模型逐档实测（openlux 网关）：`low` / `medium` / `high` 被网关换成 Claude 的思考模式（与直接写 `thinking.budget_tokens` 的请求同形）；`xhigh` / `max` 不报错，但请求与不带档位时同形，等于被忽略，所以清单里不放这两档。换网关或换模型后要重测。

**成员列表的计数**（〔用户 2026-10-07 定〕）

- 判定只看成员列表里每个成员行的连接项：连接项带 `service: 'agent'` 的是云端 Agent，其余（页面、本机 Agent、渲染进程）说明成员的设备在线。人数 = 至少有一条非云端 Agent 连接的成员行数（自己总算在线，至少 1）；Agent 个数 = 各行本机 Agent 连接数之和，加每位成员至多一个的云端 Agent（同一个实例的多条连接只算一个）。托管方服务行不进两个数。
- 成员的页面断开后，文档服务把会话保留 60 秒（`server/docservice/session.mjs` 的保持期），期间连接仍算在线；所以发起方关掉软件约 60 秒后，他那一行才会改标「离线，Agent 在跑」。云端 Agent 的实例在没有进行中的一轮后还会连着、直到闲置回收（10 分钟），所以一轮说完后，这个标记最多还会挂 10 分钟。

**诊断报告**（〔用户 2026-10-07 定〕）

- 在页面里由这段云端对话的事件重建出的消息、会话状态、`info` 与客户端信息拼成 JSON（`src/ai/cloud/report.ts`），不经任何 `/api/*`；字符串字段超过 4000 字截断并写明。

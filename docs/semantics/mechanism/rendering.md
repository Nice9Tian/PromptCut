# 渲染：机制

本册写 `../product/rendering.md` 背后的具体机制（三级），从属于它，与它冲突时以它为准。

## 总规则

- 切换帧率后，全部成本记录和预渲染结果作废，重新测量。

## 舞台

- 舞台有两个，角色可以互换：
  - **可见舞台**：用户看到的画面，负责播放。
  - **后台舞台**：负责测量卡片成本，以及为只能靠全局时钟推进的卡整场景补跑，补跑完与可见舞台互换。在线浏览器下，它还在闲时为认领到的单卡轨道流任务逐帧交出像素：当场生成这张卡的快照、画成位图送进编码器，快照用完就丢〔裁：M7 纯浏览器节点加的一句，出处 `docs/plan/m7-contract.md` 第 13 节 D18 的 dry run；2026-10-13 随每张卡的快照作废改写（三级）〕。逐帧生成时，每推一帧都把这一帧排下的界面更新提交完再往下，所以接着上一帧做和从挂载帧重新推，得到同一份快照〔裁：2026-10-13 `claude/rr-push-exact`，出处 `docs/reports/AGENT-rr-push-exact.md`（三级）〕。
- 在线浏览器两个跨源舞台首次握手：每一台从自己的页面加载完起 20 秒内要握上；可见舞台挂上 20 秒还没握上，先用同源单舞台出画面，两个跨源舞台在隐藏处接着加载，两台都握上后换回双舞台（只换一次，换回时新的可见舞台画好当前帧再露出来）；某一台加载完 20 秒没握上，或自挂上起 2 分钟两台还没都握上，就留在同源单舞台。后台舞台等可见舞台的页面加载完再挂〔裁：2026-09-30 `claude/stage-handshake`，慢网络下舞台页光下载就超过 20 秒，被误判握手失败〕。
- 握上之后某一台断开（每 5 秒问一次、15 秒没有回包算断开；页面隐藏时不判）、重载后 20 秒内握不回来，或 10 分钟里断到第 4 次，就退回同源单舞台，本页会话内不再回到双舞台，也不再重载；预览不因舞台断开而一直空白〔裁：2026-09-30 `claude/misc-maint`，出处 `docs/plan/c10-contract.md` 第 2 节「握手之后又断」〕。
- 舞台接管全部计时方式（`performance.now`、rAF、`Date.now`、定时器），时间只由舞台的时钟给。`Date.now` 固定为一个纪元，不取真实时间。推帧时每一帧的时刻按帧号直接算（帧号 ÷ 帧率），不逐帧累加；动画被拨到结尾时，它的结束回调由舞台当场交付，不等浏览器出帧〔裁：2026-10-13 `claude/rr-push-exact`，出处同上（三级）〕。

## 播放

- **音频跟随时刻。** 舞台的某一拍比应到时刻晚出超过 40 毫秒，就暂停音频；恢复时对齐到当前时刻。阈值固定 40 毫秒，不按帧率换算。

## 轻卡与重卡

轻重靠实测，不靠声明。轻卡在可见舞台里活渲，重卡贴预渲染结果。

### 测量

- 卡片和它依赖的对象的身份（参数、源码版本、帧率、审阅表、机器与渲染路线）都没变时，直接复用上次的测量记录。
- 每张卡测这几个数：
  - **活渲单帧耗时**：取多帧的稳健统计值，缺省为第 90 百分位、至少 16 帧；单次最大值另记，只作诊断。这是唯一进入判重的数。
  - **追帧总耗时**：推帧卡从第 0 帧推到最后一帧的活渲耗时之和。
  - **生成快照的三段耗时**：样式内联、画布栅格化、序列化，分开记录。只在浏览器里为拿像素而生成快照的地方（在线页面、浏览器节点）顺带记，用来安排产流的产能，不进判重。
- 测量分两趟：第一趟只计时；第二趟给判重的卡产一套稀疏的轨道流（每 15 帧一张，见「重管线：预渲染」）。在线页面由后台舞台紧接着这张卡的第一趟自己产；桌面由预渲染进程在全部卡测完以后产。「太慢」按单帧判，不按整趟的累计时间截断。遮罩下产稀疏版最多等 50 秒，到时就先进编辑，剩下的闲时接着产。这 50 秒是墙上时钟，从这一轮遮罩下第一次等稀疏版起算，只管产稀疏版，不截断测量本身：到时以后还没测的卡照常测完才撤遮罩。〔裁：主会话 2026-10-14 的读法，用户事后审〕在线页面为了在测量时就拿到这台浏览器的环境指纹，渲染连接在测量落定之前就开，认领队列里的任务仍等测量落定；测量时这一趟不问线上有没有能切分的节点。〔裁：主会话 2026-10-14〕
- 成本倍率、取第几百分位、最少采样帧数是可调系数，调它们不改预算公式，也不改代码。

### 分派

- **预算** B = 1000 / fps × 70%。
- 活渲单帧耗时超过 B 的卡，在所有位置都判重。
- **按位置分派**：所有卡片的入点和出点合起来作为分段边界，每一段各算一次。在每一段里用贪心搜索，按每拍的实际成本从小到大把卡纳入轻管线，直到再加一张就会超出预算，其余为重卡。
- **推帧卡按最差情况算**：需要不可见追帧的卡，按从第 0 帧追到最后一帧的总代价判，总代价在追帧预算内才能进轻管线，这样跳到片段最后一帧也追得上。
- **实际追多少帧按位置估**：播放头落在 t 时，长推帧卡实际要追的帧数按 (t − 入点) × fps 估。这只决定追多少帧，轻重仍按整段最差代价判。
- **人工钉死为重卡**：用户或探针可以把一张卡钉死为重卡（`pinnedHeavy`）。钉死的卡不参与轻重判定，直接进预渲染集合；它和降级一样是判重的输入之一。
- **预渲染集合**：所有段里重卡的并集。只在所有段都判轻的卡不产任何预渲染结果；任一段判重的卡，整段完整预渲染。可见舞台在每一段按该段的轻重结果处理。

### 界限搜索与成本记录（原「低内存档」）

〔2026-10-07 用户定：低内存档撤销，统一为在线浏览器，规则见 `../product/platforms.md` 的「在线浏览器」。本节各条尚未按新规则改写，代码也还是旧做法；改写前这样读：**共享成本记录、界限搜索**留用，适用于所有在线浏览器（有别的机器测好的记录就二分只测几张，没有就逐张实测），所有在线浏览器测完都写记录；**过渡（C10a）全部按重卡、停下追一帧的 5 秒时限、预渲染任务与 `backfill` 优先级、「播放时判轻的卡同样不活渲」**各处作废；**用户卡、素材效果卡不执行、不参加搜索、项目变化后不再测**同样作废：在线执行按隔离环境的能力判断，随项目变化更新相关测量；**只有一个舞台**只作为性能不足时的回退。**预渲染小尺寸**2026-10-13 起停产；本节说到它的地方（「停下追一帧」里的两处）按「没有」读。〕

- **共享成本记录**：非低内存档的机器（桌面版、电脑浏览器）测完一张卡，把「卡片身份、测量机器的环境指纹、活渲单帧耗时」作为一条成本记录写进文档服务（`document-service.md` 的「成本记录」）。这里的卡片身份去掉测量机器那一部分，只留卡片本身（参数、源码版本、帧率、审阅表），不同机器测的同一张卡才对得上；单帧耗时就是「测量」一节里进入判重的那个数。同一张卡可以有多条记录，来自不同环境。
- **界限搜索**：
  - 低内存档打开项目时取本项目的成本记录，每张卡取一个代表耗时（有多条时取中位数），按代表耗时从小到大排序；
  - 在自己的舞台里对排好的卡做二分查找：测中间那一张的活渲单帧耗时（照「测量」一节，只计时、不生成快照），不超过预算 B 就往更耗时的一半找，超过就往更省的一半找，直到找到第一张自己跑不动的卡；
  - 它和比它耗时的卡全判重，比它省的全判轻；界限两侧各再测 1 张作余量（可调），实测和排序矛盾时以实测为准，界限随之挪动；
  - 没有成本记录的卡按重卡处理，不测；
  - 测过的结果按「卡片身份 + 本机环境指纹」存在页面本地，下次打开复用；
  - 测量次数约为 log₂(卡数) + 2。
  - 数字（可调）：界限两侧各再测 1 张；余量测出矛盾、界限挪动之后，同一侧接着再测，这样多测的总数至多 2 张；测量次数的上界因此是 ⌈log₂(有记录的卡数 + 1)⌉ + 2 + 2。单帧耗时照「测量」一节取（第 90 百分位、至少 16 帧），判重式与分派相同（单帧耗时 × 成本倍率 > B）。测量失败的卡按跑不动算、不存。
  - 代表耗时有多条记录时取中位数，偶数条取中间两条的平均；代表耗时相同的按卡片身份定序。
  - 低内存档不执行用户卡、素材效果卡的代码，它们不参加搜索，按重卡。
  - 低内存档只有一个舞台：测量时把它临时当后台舞台用，一次只测一个片段，测完切回可见舞台、整份项目重灌；真要测的时候盖加载遮罩（本地复用全命中就不盖）。
  - 搜索之后项目又变了（加卡、改参数）：不再测，测过的按实测，有代表耗时的按它落在界限哪一侧判（不小于界限那张卡的代表耗时算重），没有记录的算重。
  - 轻重判定只决定预渲染任务发给谁、导出时谁由本机逐帧渲；播放时判轻的卡同样不活渲，没有产物就显示占位符，停下时画出（`product/platforms.md` 的「面向的平台」）。
- **过渡（C10a）**：不测，所有卡按重卡处理。C10 其余落实界限搜索后退出。
- **停下追一帧**：暂停、点击或拖动松开、播放到头时，在舞台里把当前这一帧的所有卡活渲一次，重卡也画。时限 5 秒（可调）：画出来之前各层照兜底顺序显示，画好的层替换上去；到时限还没画好的层维持兜底画面（有预渲染小尺寸就是它，没有才是占位符），直到下一次停下〔裁：「维持占位」按兜底顺序读，已有小尺寸的层不换成沙漏〕。推帧卡按从入点追到当前帧算，同样受时限。低内存档下用户卡、素材效果卡不追：有这一帧的预渲染结果（预渲染小尺寸）就照贴，没有才显示「需要本地 PC 渲染辅助」的提示。
- **补发预渲染任务**：低内存档发现判重的层在素材服务里没有产物（按清单判）时，向队列发布预渲染任务：一种带片段清单的计划任务，标 `priority: 'backfill'`。认领它的渲染节点把清单里的片段当作重卡算键、切出细任务，细任务同样标 `backfill`（`document-service.md` 的「渲染任务队列」）。同一个结果已有任务就不再发；低内存档只发布，不认领。

### 有声动效卡的画面成本
〔用户 2026-10-06 定:「直接自动即时补测试。不要默认判重。」〕画面是组件、另写了 `audio()` 的有声动效卡，它的画面就是一张普通的 DOM 卡：第一次要用时自动即时测量，测完按结果判轻重，不默认判重。做法：成本身份的节点取片段自己的卡节点（`pipelinePlan.mjs` 的 `clipCostNodes`），图里的节点不动，所以预渲染结果的键不变。

**仍然按重的情况**：
- 在线页面里本页运行不了的同步用户卡（退回原做法）；
- 画面由 `card()` 出的素材效果卡、只有 `audio()` 的音频素材效果卡：测量用的缩水项目不带素材与卡片图节点，它们没有成本身份、不测；声明了 `frameMode: "direct"` 的按声明判轻，没声明的按重；
- 没声明 `direct` 的卡在第一次测完之前的那几秒（按重，贴已有的层）；
- 测量这一轮没做成（下次项目变动、卡片更新或重开时再测）；
- 成本记录本身判重。

### 声音的轻重

规则见 `../product/platforms.md` 的「卡片声音的平台边界」、`../product/rendering.md` 的「有声动效卡」（2026-10-06 用户定），本节是做法。只在在线浏览器模式里判；桌面运行环境一律自己合成，不判。〔裁：2026-10-06 `claude/sound-ab`，用户定「轻重判定、测量与记录沿用画面那一套机制，数字写进 mechanism」；本节的数字与做法都是这次新设的，出处 `docs/reports/AGENT-sound-ab.md`「〔裁〕清单」〕

- **判的对象**：一段会出声、又由合成得到的声音——独立音效（提示音、键盘声，片段里存着配方）和卡片声音（内置有声卡、内置音频卡的 `audio()`）。这台设备跑不了它的代码的（同步来的卡在本页没有隔离的声音线程、载入不成、读素材采样、与内置卡串在一起，见 `platforms.md` 的「在线执行用户卡与素材效果卡」）不判，按重；同步来的用户卡与素材效果卡的 `audio()` 在隔离的声音线程里合成，测量走同一条路，也不出声。
- **测量**：合成按块做，一块 4096 个采样帧（48 kHz 下约 85.3 毫秒）。从这段声音的开头逐块合成，到尾绕回开头，采够 16 块为止；一次测量的合成耗时累计到 500 毫秒就停，按已有的块算。不足一块的声音按实际帧数合成，耗时按比例折算到一整块。块与块之间让出主线程，让出的时间不计。
- **进入判定的数**：每块合成耗时的稳健统计值，取法、可调系数与画面的活渲单帧耗时相同（缺省第 90 百分位、至少 16 块，不足时取最大值）；单次最大另记，只作诊断。
- **预算与判重**：预算 = 一块的时长 × 70%（与画面预算 B 的 70% 是同一个数，4096 帧时约 59.7 毫秒）。块耗时 × 成本倍率 > 预算，判重；否则判轻。
- **测量不出声**：测量只调纯合成函数，算出的采样当场丢掉，不建音频上下文、不建媒体元素、不生成可播放的地址。
- **记录与复用**：一条记录是「声音身份、设备串、块耗时、单次最大、块长、采样率、采到的块数、测量时刻」。声音身份：独立音效取配方的身份，卡片声音取卡片声音身份（参数、源码版本、输入）加采样帧数。设备串是「浏览器标识、CPU 核数、运行模式、取第几百分位、最少块数」。记录存在页面内快照库的成本表里，与画面的成本记录同表、键不相撞；身份与设备串都没变就复用，不重测；库打不开时只留在页面内存。声音的记录不写进文档服务的共享成本记录。
- **什么时候测**：第一次要用这段声音时（预览挂上它、点「生成声音」、导出开始），不盖加载遮罩；同一段声音同时被问到只测一次。
- **判轻**：在浏览器里合成。预览里没有有效产物的，合成一份只在本页有效的临时声音当播放源，不入库、不改项目；有了有效产物就改用产物。「生成声音」与导出开始时那一步照桌面的办法合成、入库、提交到项目。
- **判重**：不在浏览器里合成，用已有产物；预览里没有有效产物就照「未生成的声音」提示，导出开始时没有有效产物就失败并指出片段。交给渲染节点生成的那一步留了接口，还没有接收方（见 `docs/reports/AGENT-sound-ab.md`「没做成的」）。
- **产物的字节取不到**（项目里有记录、素材服务里没有文件）：在线预览按没有有效产物处理，判轻的由浏览器合成；导出开始时按缺失重新生成。
- 原按「低内存档」一律不测、不合成的限制已被 2026-10-07 用户决定覆盖；声音按本节的轻重测量和隔离能力处理，不按设备身份预先禁用。代码中的旧限制仍待 0.7.19 按新规则改掉。

## 轻管线：活渲

- 轻卡永远在可见舞台里活渲。
- 跳转时：可定位的卡直接钉到目标帧；短的推帧卡当场从起点逐帧推到目标，中间态不画出来；长的推帧卡不可见地追，追上再显示。能用自己子树的虚拟时间推进的卡在可见舞台里追；只认全局时钟的卡由后台舞台整场景补跑后与可见舞台互换。连续播放中逐帧走过挂载帧、自然进场的卡不是跳转，不互换；从卡中间开始播放（跳到卡中间再播、打开就停在卡中间再播、暂停后在卡中间继续播）的照跳转办〔裁：2026-09-30 `claude/swap-tuning`，出处 `docs/plan/c10-contract.md` 第 18 节〕。
- **降级**：播放中任一秒内，每拍超出 1/fps 的部分累计超过 1/fps，就把这一秒实测最贵的一张轻卡降为重卡。降级不立即生效：这张卡先进预渲染队列，排在正在跑的那一批之后，不打断它；预渲染结果就绪前照常活渲，就绪后才改贴预渲染结果。「就绪」按当前播放位置判：从当前位置起 1 秒（不足 1 秒到片段结束）都有预渲染结果覆盖。预渲染集合只增不减，播放中不把卡移出集合。

## 重管线：预渲染

- 每张卡单独保存，只保留实体部分，其余透明。
- 预渲染只在闲时进行，不服务用户的即时交互。打开项目、测量卡片时先给每张重卡产一套稀疏的轨道流；之后要补的只在暂停时产，播放时不产；稀疏版排在满密度版前面。
- **不同环境的结果不混用**：Canvas / WebGL 的字体微调和抗锯齿在不同硬件上有像素差，不同硬件渲的连续帧拼在一起会闪。所以预渲染结果的键里带着渲染它的**环境指纹**（操作系统、GPU 基础类别、Chrome 主版本）。**一张卡的轨道流只出自一种环境（卡片级指纹锁）**：最先为这张卡产出轨道流的环境锁定它，这张卡剩余的帧只能由指纹相同的节点接着做。别的环境要接手，只能用自己的指纹另起一套键、从头产这张卡；锁随之转给它，原环境的这张卡不再投递。锁定方是在线页面的节点时，它在播放、拖动期间不产，但每隔一段时间向队列报「还在」，这期间它锁着的卡不算闲置，别的环境不接手。〔裁：主会话 2026-10-14〕同一版项目里不同的卡可以出自不同的环境：页面按卡分层贴图，一层里的帧不混环境就不会闪。键相同的结果在哪台节点上产出都可以互相替用，前提还有节点渲染用的代码和卡片源码与发布方一致（见 `platforms.md` 的「渲染节点」）。
- 拿不到这一帧时照下面的兜底顺序处理，不因为别的节点还在做而等待。
- 预渲染结果只有一种形态：**轨道流**，播放、暂停、拖动都贴它。每张或每组重卡一条上下拼合 alpha 的 H.264 视频流，裁到实体框，从这条流自己的第一帧起每 15 帧一个分段；单卡流的第一帧就是片段的第一帧，组流、依赖下层的流的第一帧是这条流盖住的那一段的第一帧。清单记着这条流的第一帧，分段号按「这一帧减去第一帧」算。同时活跃的流超过硬件解码器预算时，把相邻的独立重卡合并成一条组流。不为任何卡存每帧的 HTML 快照。
- 每条流有两版，用同一个键：**稀疏版**每个分段只截一张（分段的第一帧），其余帧重复它；**满密度版**每帧都截。清单里每个分段记着自己是哪一版；满密度的分段产出来以后在分段边界换上。
- 怎么产，按卡分：remotion 式的卡不从挂载帧回放；画面全在画布里的卡从画布直接取像素送进编码器；独立卡单独产流；依赖下层的卡（含审阅表没覆盖到的卡）连同下层一起渲染来产流，流只含目标卡改动的那一块区域，这段时间里下层任一控件变了就作废重产；转场和套在视频上的素材效果卡，连同它用到的视频一起渲，产成一条流，贴的时候这条流顶替那段视频原来的画面，视频或卡的参数变了就作废重产；外框用了三维变形的卡，流里是变形之前的画面，贴的时候再做变形。
- 占位符的位置取流清单里的位置矩形：产稀疏版时每个分段量一个收紧的框。这张卡的流还没有产出来时，占位符照现在的办法定位。〔裁：主会话 2026-10-13 的读法，用户事后审〕
- 预渲染结果的复用：依赖卡的预渲染结果以依赖对象的身份为键，依赖没变就一直复用。在线页面测量时自己产的稀疏流，只给本页能单独产流的独立卡产；键里带的是这台浏览器的环境指纹。

### 兜底顺序

- 某一层这一拍拿不到精确画面时，按以下顺序取第一个可用且装得下预算的：1. 这一帧的满帧率轨道流；2. 稀疏轨道流（打开项目时先铺满全段的版本，每 15 帧一张；取不晚于这一帧的最近一张，只往回找）；3. 占位符。
- 轻卡在第 1 步之前还有活渲；降级的卡在就绪前照常活渲。
- 预算：轨道流占硬件解码器预算（同时活跃的解码器、解码帧字节）。超出解码器预算的层显示占位符。
- 满帧流这一拍画不出来（解码器不够、清单或分段未到、解码跟不上）时，这一层留着它上一张画面，最多留一个分段的时长；到时还没有新画面就落到占位符。起播和跳转后的第一拍，流的第一帧画出来之前不藏这张卡原来的画面；暂停着的时候把播放头下重卡的这一帧先解好。
- 来不及的状态持续满 120 毫秒才显示占位符；更短的空档不显示，避免闪烁。
- **旧输入的层不贴**〔裁：stale-layer，2026-09-29 PC 主会话；数字 15 秒新设〕：层表里每条流带生成它的输入签名。进签名的是成员片段在项目数据里的输入（参数、部件、强调、框的宽高、时长、采样相位、滤镜与素材、素材效果卡的上游，以及画幅、帧率、主题、样式）、片段在时间轴上的位置（采样窗口），组流和依赖下层的流另加成员的摆放和上下顺序；单卡流不带画面上的位置、缩放、旋转、不透明度、淡入淡出，它们不在流里。片段在时间轴上挪了，旧流每一帧都对不上时刻。在线页面按当前项目算同一个签名，对不上的流不贴。过期后 15 秒内当结果在路上（本页运行不了的用户卡、素材效果卡显示沙漏，时间轴不挂徽标），过了还没等到新流按没有结果处理（图标、徽标）；本页能运行的用户卡、素材效果卡与内置卡同样处理。卡片源码、字体、环境的变化靠渲染节点换键重写层表。
  - 层表里的流除了渲染节点自己要产的，还有切分时给浏览器出过键的单卡流，候选只列实际出键的指纹。〔裁：2026-10-12 渲染重构「甲一」，`../../plan/render-refactor-progress.md`〔裁〕清单第 5 条〕在线页面发的清单计划，切分方自己能产流时连自己的那一份单卡流一起出，和给浏览器的那一份成对，谁先认领谁得；成对的流在层表里候选的先后按实际是谁产的排。〔裁：2026-10-13 渲染重构「甲三」，同一清单第 14 条〕
- **在线浏览器的重层**：和桌面同一个兜底顺序：满帧流、稀疏流、占位符。分派时每张重卡每拍的固定成本，贴流以后取多少还没有量，实现时量了再写。

## canvas 卡的共享 WebGL 渲染器

- 同一个舞台的所有 canvas 卡共用一个 WebGL 上下文和一个 Worker。每张卡自带着色器、各自编译，素材纹理只上传一次。每拍只传时间和变了的参数；Worker 把所有卡画进一张图集，按卡裁成位图交回各自的画布，画完主线程才推进一拍。图层关系仍由舞台管。
- 两条路线都实现，项目选项可切换：
  - **路线 1**（桌面默认）：每个舞台各一个 Worker 和上下文。
  - **路线 2**（在线浏览器性能不足时的回退）：编辑界面只开一个 Worker 和上下文，两个舞台共用。
- 导出页自己开一个。
- 粒子卡不进 Worker，仍在主线程画；长的粒子片段靠轨道流。

## 即时渲染与预渲染进程

- 预渲染进程有三种模式：
  - **Agent 模式**（本机只有 Agent）：不预渲染，只按 Agent 的要求即时渲染精确的某一帧。
  - **User 模式**（本机只有用户在编辑）：只预渲染重卡。
  - **Full 模式**（两者都在本机）：优先 Agent 的即时渲染，其次预渲染。
- 用户机上缺省一个预渲染进程，以 Full 模式起（编辑器进程里总有本机 Agent）；模式在进程启动时定下。模式不接的请求当场回错、不排队：User 模式收到 Agent 的即时渲染请求回「没有 Agent lane」，Agent 模式收到预渲染请求回「不做预渲染」、预加载请求回「跳过」。Agent 模式不当渲染节点。〔裁：2026-09-30 `claude/query-render-2`〕
- 即时渲染不进文档服务的任务队列，队列只管预渲染。
- 预渲染进程做 User 模式或 Full 模式的预渲染时，同时是一个渲染节点：除了本机项目的预渲染，也可以在闲时认领队列里别的任务。
- **Agent 优先只是插队**：Agent 的请求只在一个专用渲染实例里走，不提高进程优先级。专用实例每做完一个任务，先从 Agent 队列里按先后取下一个；Agent 队列空时接普通预渲染任务。它不打断正在跑的任务，Agent 任务永远不排在排队中的预渲染任务后面，也永远不占用别的实例，所以用户总能等到预渲染。
- 本机渲染节点在 Agent 专用实例开着且空闲、专做队列任务的那个实例正做着一项时，多认领一项快照任务交给专用实例；不是同一张卡、不认领轨道流。专用实例没开时不多认领。〔裁：2026-09-30 `claude/query-render-2`〕〔2026-10-13 起没有快照任务，这一条没有东西可认领：删掉，还是改成让专用实例帮着产稀疏流，实现时定〕
- 专用实例做队列任务时按批（4 帧）推进，批与批之间有 Agent 任务就先做 Agent 任务（正在跑的那一批不打断），连着来的 Agent 任务等 1 秒一起做完再接着做队列任务；让路期间照常续租约。〔裁：2026-09-30 `claude/maint-3`〕
- 专用实例只在自己的 Chrome 开着时接普通预渲染，每次接一项：普通预渲染队列里的一项，或后台那一趟正在做的那张卡里还没开工的一批（4 帧）；做完一个 Agent 任务后空 1 秒才接，免得同一次工具调用里的下一个 Agent 任务白等。同一张卡的队列任务不在两个实例上同时跑，这张卡的收尾（编 MOV）只由后台做、等借走的批都落定之后〔裁：2026-09-30 `claude/query-render`，报告 `docs/archive/agent-reports/AGENT-query-render.md`〕。
- AI 栏的操作预览（用户点开看的改动前后动图）在专做队列任务的那个实例上插到所有待办之前，不经专用实例；3D 视图的空闲贴图预取排普通预渲染队尾，用户等着看的那一张同样插队〔裁：同上〕。
- 用户交互需要的查询（如选中卡片的实体框）在用户自己的后台舞台上算，不走预渲染进程。

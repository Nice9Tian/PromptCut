# 渲染：机制

本册写 `../product/rendering.md` 背后的具体机制（三级），从属于它，与它冲突时以它为准。

## 总规则

- 切换帧率后，全部成本记录和预渲染结果作废，重新测量。

## 舞台

- 舞台有两个，角色可以互换：
  - **可见舞台**：用户看到的画面，负责播放。
  - **后台舞台**：负责测量卡片成本，以及为只能靠全局时钟推进的卡整场景补跑，补跑完与可见舞台互换。
- 舞台接管全部计时方式（`performance.now`、rAF、`Date.now`、定时器），时间只由舞台的时钟给。`Date.now` 固定为一个纪元，不取真实时间。

## 播放

- **音频跟随时刻。** 舞台的某一拍比应到时刻晚出超过 40 毫秒，就暂停音频；恢复时对齐到当前时刻。阈值固定 40 毫秒，不按帧率换算。

## 轻卡与重卡

轻重靠实测，不靠声明。轻卡在可见舞台里活渲，重卡贴预渲染结果。

### 测量

- 卡片和它依赖的对象的身份（参数、源码版本、帧率、审阅表、机器与渲染路线）都没变时，直接复用上次的测量记录。
- 每张卡测这几个数：
  - **活渲单帧耗时**：取多帧的稳健统计值，缺省为第 90 百分位、至少 16 帧；单次最大值另记，只作诊断。这是唯一进入判重的数。
  - **追帧总耗时**：推帧卡从第 0 帧推到最后一帧的活渲耗时之和。
  - **生成快照的三段耗时**：样式内联、画布栅格化、序列化，分开记录，只用来安排测量和预渲染的产能，不进判重。
- 测量分两趟：第一趟只计时、不生成快照；第二趟才生成快照并存下。「太慢」按单帧判，不按整趟的累计时间截断。
- 成本倍率、取第几百分位、最少采样帧数是可调系数，调它们不改预算公式，也不改代码。

### 分派

- **预算** B = 1000 / fps × 70%。
- 活渲单帧耗时超过 B 的卡，在所有位置都判重。
- **按位置分派**：所有卡片的入点和出点合起来作为分段边界，每一段各算一次。在每一段里用贪心搜索，按每拍的实际成本从小到大把卡纳入轻管线，直到再加一张就会超出预算，其余为重卡。
- **推帧卡按最差情况算**：需要不可见追帧的卡，按从第 0 帧追到最后一帧的总代价判，总代价在追帧预算内才能进轻管线，这样跳到片段最后一帧也追得上。
- **实际追多少帧按位置估**：播放头落在 t 时，长推帧卡实际要追的帧数按 (t − 入点) × fps 估。这只决定追多少帧，轻重仍按整段最差代价判。
- **预渲染集合**：所有段里重卡的并集。只在所有段都判轻的卡不产任何预渲染结果；任一段判重的卡，整段完整预渲染。可见舞台在每一段按该段的轻重结果处理。

## 轻管线：活渲

- 轻卡永远在可见舞台里活渲。
- 跳转时：可定位的卡直接钉到目标帧；短的推帧卡当场从起点逐帧推到目标，中间态不画出来；长的推帧卡不可见地追，追上再显示。能用自己子树的虚拟时间推进的卡在可见舞台里追；只认全局时钟的卡由后台舞台整场景补跑后与可见舞台互换。
- **降级**：播放中任一秒内，每拍超出 1/fps 的部分累计超过 1/fps，就把这一秒实测最贵的一张轻卡降为重卡。降级不立即生效：这张卡先进预渲染队列，排在正在跑的那一批之后，不打断它；预渲染结果就绪前照常活渲，就绪后才改贴预渲染结果。「就绪」按当前播放位置判：从当前位置起 1 秒（不足 1 秒到片段结束）都有预渲染结果覆盖。预渲染集合只增不减，播放中不把卡移出集合。

## 重管线：预渲染

- 每张卡单独保存，只保留实体部分，其余透明。
- 预渲染只在闲时进行，不服务用户的即时交互。
- **不同环境的结果不混用**：Canvas / WebGL 的字体微调和抗锯齿在不同硬件上有像素差，不同硬件渲的连续帧拼在一起会闪。所以预渲染结果的键里带着渲染它的**环境指纹**（操作系统、GPU 基础类别、Chrome 主版本）。**一张卡的同一种预渲染结果只出自一种环境（卡片级指纹锁）**：快照、轨道流各算一种结果，最先为这张卡产出这种结果的环境锁定它，这张卡剩余的帧只能由指纹相同的节点接着做。别的环境要接手，只能用自己的指纹另起一套键、从头产这张卡；锁随之转给它，原环境的这张卡不再投递。同一版项目里不同的卡可以出自不同的环境：页面按卡分层贴图，一层里的帧不混环境就不会闪。键相同的结果在哪台节点上产出都可以互相替用，前提还有节点渲染用的代码和卡片源码与发布方一致（见 `platforms.md` 的「渲染节点」）。
- 拿不到这一帧时照下面的兜底顺序处理，不因为别的节点还在做而等待。
- 两种形态：
  - **快照**：用于暂停和拖动，也是播放中的兜底。每张重卡每帧一份 HTML 快照，只含该卡的子树，画布已栅格成带实体框的图片。
  - **轨道流**：用于播放。每张重卡一条上下拼合 alpha 的 H.264 视频流，裁到实体框。同时活跃的流超过硬件解码器预算时，把相邻重卡合并成一条组流。
- 超过体积上限的快照帧（DOM 卡 300 KB、画布位图 1 MB）不投递，那一层按缺料处理。
- 预渲染结果的复用：依赖卡的预渲染结果以依赖对象的身份为键，依赖没变就一直复用。测量时推过的帧，只有独立卡能直接当预渲染结果存下；存下时键里带的是测量所在浏览器的环境指纹，这张卡的快照随之锁定到这个环境，用上前端的算力。本机预渲染进程遇到被别的环境锁定的卡：已经齐了就直接投递，不再渲；还缺帧、而锁定方已经有一段时间没有再产出，就用自己的指纹接手整张卡。

### 兜底顺序

- 某一层这一拍拿不到精确画面时，按以下顺序取第一个可用且装得下预算的：1. 这一帧的满帧率轨道流；2. 稀疏轨道流（先铺满全段的低帧率版本，帧率为项目帧率的 1/3）；3. 同一区间内最近的一帧快照（向前回溯，不跨区间）；4. 占位符。
- 轻卡在第 1 步之前还有活渲；降级的卡在就绪前照常活渲。
- 预算：轨道流占硬件解码器预算（同时活跃的解码器、解码帧字节）；快照占换帧预算（每次投递的字节上限、换帧节流）。超出解码器预算的层直接从第 3 步开始。
- 满帧流这一拍画不出来（解码器不够、清单或分段未到、解码跟不上）时，这一层当拍落到下一步，不等下一次分派。
- 来不及的状态持续满 120 毫秒才显示占位符；更短的空档不显示，避免闪烁。

## canvas 卡的共享 WebGL 渲染器

- 同一个舞台的所有 canvas 卡共用一个 WebGL 上下文和一个 Worker。每张卡自带着色器、各自编译，素材纹理只上传一次。每拍只传时间和变了的参数；Worker 把所有卡画进一张图集，按卡裁成位图交回各自的画布，画完主线程才推进一拍。图层关系仍由舞台管。
- 两条路线都实现，项目选项可切换：
  - **路线 1**（桌面默认）：每个舞台各一个 Worker 和上下文。
  - **路线 2**（低内存档默认）：编辑界面只开一个 Worker 和上下文，两个舞台共用。
- 导出页自己开一个。
- 粒子卡不进 Worker，仍在主线程画；长的粒子片段靠轨道流。

## 查询渲染与预渲染进程

- 预渲染进程有三种模式：
  - **Agent 模式**（本机只有 Agent）：不预渲染，只按 Agent 的要求渲染精确的某一帧。
  - **User 模式**（本机只有用户在编辑）：只预渲染重卡。
  - **Full 模式**（两者都在本机）：优先 Agent 的查询，其次预渲染。
- 查询渲染不进文档服务的任务队列，队列只管预渲染。
- 预渲染进程做 User 模式或 Full 模式的预渲染时，同时是一个渲染节点：除了本机项目的预渲染，也可以在闲时认领队列里别的任务。
- **Agent 优先只是插队**：Agent 的请求只在一个专用渲染实例里走，不提高进程优先级。专用实例每做完一个任务，先从 Agent 队列里按先后取下一个；Agent 队列空时接普通预渲染任务。它不打断正在跑的任务，Agent 任务永远不排在排队中的预渲染任务后面，也永远不占用别的实例，所以用户总能等到预渲染。
- 用户交互需要的查询（如选中卡片的实体框）在用户自己的后台舞台上算，不走预渲染进程。

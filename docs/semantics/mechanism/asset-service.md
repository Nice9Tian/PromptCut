# 素材服务：机制

本册写 `../product/asset-service.md` 背后的具体机制（三级），从属于它，与它冲突时以它为准。

## 职责

- 为让局域网里的其它设备直接访问，素材服务允许跨源访问。
- 本机来源不需要票据，本机按请求真正的发起方判断。服务直接对外时，回环地址来的请求就是本机来的；部署在反向代理之后时，代理转进来的请求在服务看来也是回环地址，所以这时必须关掉回环信任，回环来的请求同样要票据（开关见 `docs/plan/shared-project-contract.md` 的 `PROMPTCUT_TRUST_LOOPBACK`）。
- 所有内容按内容哈希寻址，写入后不可变，天然去重。
- **同步状态只问素材服务**：某份内容的分片收了哪些、是否传完，一律向当前连接的素材服务查询，这是唯一事实来源。本机的临时缓存不作判决依据，项目文档里也不记同步状态。

## 上传

- **逐个素材上传**：同一份素材先传素材小尺寸、再传素材原尺寸，两档都传完才轮到下一份素材。

## 预渲染的产物

- 从文档服务的任务队列认领任务的渲染节点，先把产物推送到这里、确认收全，再向文档服务报完成（见 `document-service.md` 的「渲染任务队列」）。

## 本地内容库

- 每台设备有一份本地内容库，按哈希存字节，它是素材服务在该设备上的存储或缓存：连本地素材服务时它是本地素材服务的存储；连云端或别人本机的素材服务时，它是该设备上的缓存兼上传队列，作为缓存时不作「是否传完」的判据。其它角色都经素材服务的接口读写它，不直接读写。

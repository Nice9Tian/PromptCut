# 平台

展开 `../architecture.md` 的「默认位置」和扩展点，以及 `../product-purpose.md` 的范围。从属于 `architecture.md`，与它冲突时以它为准。本册写产品功能（二级）；怎么做到见 `../mechanism/platforms.md`。

## 面向的平台

| 平台 | 运行形态 | 一期 |
|---|---|---|
| 桌面应用 | 带预渲染进程，可在本机运行文档服务和素材服务 | 做 |
| 桌面浏览器 | 在线浏览器模式 | 做 |
| iPad 浏览器 | 在线浏览器模式 | 做 |
| iPad 应用 | 在线浏览器模式套壳，没有预渲染进程 | 不做 |
| 手机浏览器 | 在线浏览器模式 | 做 |
| 手机应用 | 在线浏览器模式套壳 | 不做 |

- **手机、iPad 的浏览器就是在线浏览器模式，不分档**（2026-10-07 用户改定；原先 2026-09-27 定的「低内存档」撤销）。它们与电脑浏览器是同一个页面、同一套规则，见下文「在线浏览器模式」：照常活渲、照常按轻重区分、照常执行用户卡与图卡、照常在闲时当纯浏览器节点、照常拉素材原尺寸。设备弱的时候靠所有设备通用的办法兜住（轻重判定把跑不动的卡判重、`rendering.md` 的「兜底顺序」），不另设规则。
  - 别处文档与代码里的「低内存档」「普通档」，以及只为低内存档设的做法（预渲染小尺寸只给它预览用、为弱设备补渲及其排队次序、成本记录与界限搜索、两个舞台共用一套 canvas 渲染路线的缺省、页面内快照库 64 MiB 的上限、只有一个舞台），都待按本条清理；清理前与本条冲突的以本条为准。哪些做法留下来改成通用的、哪些删掉，清理时列给用户定。
  - 已知风险（记录，不是规则）：轻重判定量的是耗时，量不出内存；手机浏览器内存超了会被系统整页杀掉重载。撤档后真机上出现这种情况，再按实际情况加通用的保护。
- Agent 端（Agent 服务与预渲染进程的 Agent 模式、Full 模式）面向 Windows、Linux、Ubuntu。

## 渲染节点

预渲染由认领任务的渲染节点完成（队列规则见 `document-service.md` 的「渲染任务队列」）。

| 节点 | 是什么 | 能认领什么 |
|---|---|---|
| 本机 PC | 桌面应用的预渲染进程 | 全部：快照、轨道流、用户卡、图卡 |
| 独立渲染主机 | 局域网或远程主机上的预渲染进程，不带编辑界面 | 全部；可以同时为多个项目、多个用户取活 |
| 纯浏览器 | 在线浏览器模式的后台舞台 | 只认领当前登录用户自己产生的、不需要本机转码的快照任务，且一期只限内置卡片 |

- 节点只在闲时认领：本机 PC 和纯浏览器在用户播放、拖动时不认领新任务，手里在做的那一批做完为止。
- 加入共享项目的桌面应用自动成为这个项目的渲染节点，可以认领本项目任何成员发布的任务。
- **只能出网的节点**：没有入站连接、出网只能经代理走 443 端口 HTTPS 的机器，例如云端容器。
  - 它永远是成员，不能当主机。加入放本机的项目只能走中继路径（见 `document-service.md` 的「部署组合」）。
  - 它可以新建放云端的多用户协作项目，这不使它成为主机。
  - 当渲染节点时和别的节点一样按能力认领，例如没有本机转码就不认领要转码的任务。
- 纯浏览器节点绝不替别的用户干活，同一共享项目的其他成员也不行：既不让别人的项目内容进用户的浏览器，也不让用户的设备算力被别人占用。这条边界由文档服务按登录凭证把关（见 `document-service.md` 的「渲染任务队列」）。

## 桌面应用

- 桌面应用自带运行所需的全部组件：Node、Chrome、ffmpeg、内置 Python。用户不需要自己安装它们。
- 桌面应用所在的是**桌面运行环境**：它可以连本地的服务，也可以连云端或别人本机的服务，两者可以混合，见 `document-service.md` 的「部署组合」。
- 桌面应用可以在本机运行本地文档服务和本地素材服务；它们也可以为同一局域网里没有渲染能力的设备服务。项目勾上「多用户协作」并放本机时，本机的本地文档服务和本地素材服务就是这个项目的主机，成员按「连接路径」连上来（见 `document-service.md` 的「部署组合」）。
- 内置 Python 只用于感知类工具（语音转写、镜头识别、运动追踪、主体检测、素材收集），不用于卡片。
- **预渲染缓存**〔裁：2026-09-29 PC 主会话按用户定的「帧库设上限、按项目最近使用淘汰、给清理缓存入口」写〕：桌面应用把预渲染结果缓存在本机（帧库）。缓存有容量上限，用户可以改；超出时按项目最近使用的先后，先清掉最久没用的项目的预渲染结果，正在打开的项目不清。清掉的结果需要时重新预渲染；共享项目的结果仍在素材服务里，可以取回。
- 用户可以随时「清理缓存」：清掉正在打开的项目以外的全部预渲染结果。
- **导出产物**：每次导出一份，留成片与只含卡片的透明层，逐帧图片等中间文件导出完成后自动删除〔裁：同上〕；取消或失败的导出留下的文件同样列出。用户可以查看历次导出的所属项目、时间与大小，删除整份，或只删中间文件。
- 关闭编辑界面后转入后台运行，见 `../user-workflow.md` 的「后台运行」。

## 在线浏览器模式

- 本节适用于所有浏览器：电脑、iPad、手机，不分档（2026-10-07 用户定）。
- 本机没有进程，文档服务和素材服务都在别处。
- **能新建放云端的项目，不存草稿**（用户 2026-10-07 改定；原先 2026-09-27 定的是「只加入，不新建」）：在线浏览器模式的开始页有「新建项目」和「加入别人的项目」。在浏览器里新建的项目一律是放云端的多用户协作项目，新建的人是创建者。项目内容、素材、预渲染结果都在文档服务与素材服务里，关掉浏览器再打开从云端重新拉，浏览器本地只放能重新拉回的缓存。本地草稿、打开 `.proc` 仍只在桌面版。谁可以新建、每人能建多少，现在不设限制：任何打开页面的人都能建；托管方将来可以加限制，新建入口要为此留好位置（用户 2026-10-07 定）。
- **入口**：服务器直接提供编辑器页面，地址是服务器地址加固定后缀（如 `/editor`），打开即是编辑器，不需要安装；页面连同一台服务器上的文档服务和素材服务。
- 页面打开后的第一页是开始页，加入项目在这里，表单与桌面版相同（见 `../workflow/project.md` 的「多用户协作」）。
- 请求不到预渲染进程。后台舞台在闲时兼做渲染节点，从文档服务的任务队列认领自己做得了的快照任务，产 HTML 快照，生成后推送到素材服务。
- 可以从素材服务取别人预渲染好的快照，直接用在可见舞台上。
- 没有本机转码能力，也没有轨道流：重卡在播放时每拍换一次快照；换帧成本装不下预算的重卡显示占位符（见 rendering.md「兜底顺序」）；暂停后照常追到精确活渲。
- **导出**：允许，逐帧渲染、逐帧写出，慢但能出。导出只用原尺寸：导出前拉素材原尺寸，没到齐时照常提示等待上传方；重卡用已有的预渲染原尺寸，不重渲。（这一条原先写在低内存档下，撤档后归到这里。）
- 用户卡、图卡与内置卡一样：有预渲染结果就照贴，没有就照常发布补渲任务，由桌面版等渲染节点渲，结果到了自动换上。这台设备跑不了用户卡、图卡的代码，所以只有这一帧没有预渲染结果、又轮到这台设备自己渲染时，该片段在预览里显示「电脑 + 离线」图标和「需要本地 PC 渲染辅助」（见 rendering.md「兜底顺序」），不透明、不显示沙漏；时间轴上的片段同样提示「需要本地 PC 渲染辅助」，出现条件与图标相同。

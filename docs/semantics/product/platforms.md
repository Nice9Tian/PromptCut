# 平台

展开 `../architecture.md` 的「默认位置」和扩展点，以及 `../product-purpose.md` 的范围。从属于 `architecture.md`，与它冲突时以它为准。本册写产品功能（二级）；怎么做到见 `../mechanism/platforms.md`。

## 面向的平台

| 平台 | 运行形态 | 一期 |
|---|---|---|
| 桌面应用 | 带预渲染进程，可在本机运行文档服务和素材服务 | 做 |
| 桌面浏览器 | 在线浏览器 | 做 |
| iPad 浏览器 | 在线浏览器 | 做 |
| iPad 应用 | 在线浏览器套壳，没有预渲染进程 | 不做 |
| 手机浏览器 | 在线浏览器 | 做 |
| 手机应用 | 在线浏览器套壳 | 不做 |

- 电脑、iPad、手机的浏览器都是「在线浏览器」，同一个页面、同一套规则，不分档（2026-10-07 用户定；原先 2026-09-27 定的「低内存档」撤销，「普通档」一词随之不用）。个别功能按身份或性能回退，规则见下文「在线浏览器」。
  - 代码里的低内存档、设备设置里的「显示档」、进入低内存档的提示、运行中自动降档，都待按「在线浏览器」一节改掉；机制文档里相应的做法尚未改写的，以「在线浏览器」一节为准。
- Agent 端（Agent 服务与预渲染进程的 Agent 模式、Full 模式）面向 Windows、Linux、Ubuntu。云端 Agent 服务跑在 Linux 云节点上，不带编辑界面。

## 渲染节点

预渲染由认领任务的渲染节点完成（队列规则见 `document-service.md` 的「渲染任务队列」）。

| 节点 | 是什么 | 能认领什么 |
|---|---|---|
| 本机 PC | 桌面应用的预渲染进程 | 全部：快照、轨道流、用户卡、图卡 |
| 独立渲染主机 | 局域网或远程主机上的预渲染进程，不带编辑界面 | 全部；可以同时为多个项目、多个用户取活 |
| 纯浏览器 | 身份为电脑的在线浏览器的后台舞台 | 只认领当前登录用户自己产生的、不需要本机转码的快照任务；内置卡片、用户卡都可以，前提是这张卡在本页能运行；图卡的任务不认领（整屏画面超过体积上限）〔裁:主会话 2026-10-06,待用户合入前审〕 |

- 身份为手机的在线浏览器不当渲染节点，不认领任务，只发布（2026-10-07 用户定；身份见下文「在线浏览器」）。
- 节点只在闲时认领：本机 PC 和纯浏览器在用户播放、拖动时不认领新任务，手里在做的那一批做完为止。
- 加入共享项目的桌面应用自动成为这个项目的渲染节点，可以认领本项目任何成员发布的任务。
- **只能出网的节点**：没有入站连接、出网只能经代理走 443 端口 HTTPS 的机器，例如云端容器。
  - 它永远是成员，不能当主机。加入放本机的项目只能走中继路径（见 `document-service.md` 的「部署组合」）。
  - 它可以新建放云端的多用户协作项目，这不使它成为主机。
  - 当渲染节点时和别的节点一样按能力认领，例如没有本机转码就不认领要转码的任务。
- 纯浏览器节点绝不替别的用户干活，同一共享项目的其他成员也不行：既不让别人的项目内容进用户的浏览器，也不让用户的设备算力被别人占用。这条边界由文档服务按登录凭证把关（见 `document-service.md` 的「渲染任务队列」）。

## 桌面应用

- 桌面应用自带运行所需的全部组件：Node、Chrome、ffmpeg、内置 Python。用户不需要自己安装它们。
- 桌面应用所在的是**桌面运行环境**：它可以连本地的服务，也可以连云端或别人本机的服务，两者可以混合，见 `document-service.md` 的「部署组合」。
- 桌面应用可以在本机运行本地文档服务和本地素材服务；它们也可以为同一局域网里没有渲染能力的设备服务。项目勾上「多用户协作」并放本机时，本机的本地文档服务和本地素材服务就是这个项目的主机，成员按「连接路径」连上来（见 `document-service.md` 的「部署组合」）。
- 内置 Python 只用于感知类工具（语音转写、镜头识别、运动追踪、主体检测、素材收集），不用于卡片。
- **预渲染缓存**〔裁：2026-09-29 PC 主会话按用户定的「帧库设上限、按项目最近使用淘汰、给清理缓存入口」写〕：桌面应用把预渲染结果缓存在本机（帧库）。缓存有容量上限，用户可以改；超出时按项目最近使用的先后，先清掉最久没用的项目的预渲染结果，正在打开的项目不清。清掉的结果需要时重新预渲染；共享项目的结果仍在素材服务里，可以取回。
- 用户可以随时「清理缓存」：清掉正在打开的项目以外的全部预渲染结果。
- **导出产物**：每次导出一份，留成片与只含卡片的透明层，逐帧图片等中间文件导出完成后自动删除〔裁：同上〕；取消或失败的导出留下的文件同样列出。用户可以查看历次导出的所属项目、时间与大小，删除整份，或只删中间文件。
- 项目放云端时，桌面应用的 AI 栏可以选「云端」，由托管方的云端 Agent 服务执行；缺省仍是本机 Agent。选「云端」的对话在云节点上运行，桌面应用退出（含后台运行一并退出）后继续，重新打开项目能找回。
- 关闭编辑界面后转入后台运行，见 `../user-workflow.md` 的「后台运行」。

## 在线浏览器

- **名词**（2026-10-07 用户定）：用浏览器打开页面来用本产品，统一叫「在线浏览器」。电脑、iPad、手机的浏览器都是它，同一个页面、同一套规则。不按设备种类预先分档，不给用户切换档位的设置。每台设备能做到哪一步，由下面三道**闸门**判出来。正式进入编辑界面后，用气泡告诉用户这台设备现在处在哪一档。四档的名字与气泡文字（2026-10-08 用户定）：顶配模式（两个舞台各一套渲染器）：「这台设备运行在顶配模式」；标准模式（两个舞台共用渲染器）：「这台设备运行在标准模式」；精简模式（只有一个舞台）：「这台设备运行在精简模式：复杂的效果交给云端渲染」；低配模式（最低一档）：「这台设备运行在低配模式：播放时只显示已渲染好的画面」。四档都提示。气泡出现在预览窗口上方，几秒后自动消失。
- **身份**：分「电脑」和「手机」。电脑与手机按浏览器的声明判；iPad 的声明分不出来，看舞台闸门：撑得住双舞台的算电脑，撑不住的算手机（2026-10-07 用户定，替换同日早些时候的「以第一代 iPad Pro 为界」）。身份只决定一件事：电脑当渲染节点，手机不当（见上文「渲染节点」）。
- **三道闸门**（2026-10-07 用户定；替换同日早些时候的「启动时跑一个小测试」与「查设备表」）。先舞台，再素材，再即时渲染；做法见 `../mechanism/platforms.md` 的「在线浏览器」。
  - **舞台闸门**。三级，从低到高：一个舞台；两个舞台共用一套 canvas 渲染器；两个舞台各用一套。每次刚打开页面时从低往高试，哪一级把页面撑崩了，重新载入后就停在它的下一级，这次使用期间不再往上试。只在刚打开页面时试。崩一次就算，不等第二次。崩过之后有一段**护栏**时间：护栏内重新打开直接停在上次到达的那一级，不往上试；过了护栏再从头试。护栏随崩的次数加长（数字见 `../mechanism/platforms.md`），所以偶然崩一次只受限一小会儿，老是崩的设备越试越少，不会每次打开都崩一回，也不会永远受限。8 GB 的门槛只管安卓上的 Chrome 系浏览器（那里舞台崩了整页跟着崩，又不会自动重新载入）：报到 8 GB 内存才往上试，不到的直接停在一个舞台，不试。电脑上的 Chrome 系直接试（舞台崩了页面还在）；Safari 直接试（崩了会自动重新载入）。（2026-10-07 用户定）
  - **素材闸门**。两个子闸门：
    - 解码：打开时测出这台设备解得动多大的素材；超过上限的素材只用小尺寸，没超过的照常。解码上限打开时测一次，这次使用期间不变；之后导入的素材拿它和这个上限比，不重新测（2026-10-08 用户确认：「不用重新测，因为已经测得了最大支持的极限素材大小」；同日别的会话写的「随项目素材变化更新相关测量」作废）。
    - 网速：不单独测，看素材实际下载的快慢，使用中随时调整。它只决定要不要先拉小尺寸：够快就只拉原尺寸；低于界线就先拉小尺寸显示，再拉原尺寸替换。
    - 载入原尺寸把页面撑崩了的，重新载入后记得，不再照原样载入。
  - **即时渲染闸门**。就是轻重判定（见下文）：开始时逐张卡实测，跑得动的即时渲染，跑不动的当重卡。它依赖舞台闸门的结果（只有一个舞台时借可见舞台来测），之后随项目变化更新相关测量，不是开始时测一次。测某张卡把页面撑崩了的，重新载入后这张卡直接当重卡（2026-10-08 用户明确测量时机）。
- **最低一档**（2026-10-07 用户定）：连最简单的一张基准卡都跑不动，或连一个舞台都撑不住的设备，**播放时**不做任何即时渲染：画面全部用预渲染结果，没有预渲染结果的层显示占位符并发布任务，由渲染节点渲。**停下以后**先显示占位（有预渲染结果的层照常显示它），再尽量把当前这一帧渲出来，渲好一层替换一层，不设时限。素材用小尺寸。
- 预渲染结果用原尺寸，性能不足时回退为用小尺寸；这一项归哪道闸门管，做的时候定。
- 页面本地的缓存上限按实测到的环境分配，不按身份或档位定固定数。
- 本机没有进程，文档服务和素材服务都在别处。请求不到预渲染进程，没有本机转码能力，也没有轨道流。
- **能新建放云端的项目**（用户 2026-10-07 改定；原先是“只加入，不新建”）：开始页有“新建项目”和“加入别人的项目”。新建前必须登录网站账号；一律是放云端的多用户协作项目，创建者为该账号，归属由云端文档服务记录。项目内容、素材、预渲染结果在相应云端服务。每人可建数量目前不限，新建入口留好限制位置。桌面 `.proc` 打开仍只在桌面版；浏览器不提供本地草稿列表，但暂时离线的未提交改动必须持久保留，不能当可丢弃缓存（2026-10-08 离线行为，见 `document-service.md` 和 `../workflow/project.md`）。
- **入口**：服务器直接提供编辑器页面，地址是服务器地址加固定后缀（如 `/editor`），打开即是编辑器，不需要安装；页面连同一台服务器上的文档服务和素材服务。
- 页面打开后的第一页是开始页，新建与加入都在这里，加入的表单与桌面版相同（见 `../workflow/project.md` 的「多用户协作」）。
- **播放**：轻卡实时渲染；重卡每拍换一张快照，换帧成本装不下预算的层显示占位符（见 rendering.md「兜底顺序」）。
- **停下**：暂停、点击或拖动时间轴后松开、播放到头，回到精确的实时渲染；最低一档按上文逐层尝试、不设时限，运行不了的用户卡、图卡按下文退回。
- **轻重判定**：按舞台闸门结果实测，只有一个舞台时借可见舞台；随项目变化更新相关测量。项目里已经有别的机器测好的耗时（成本记录）时，按它排序，用二分法只测几张来划线。测完把耗时写进文档服务，供别的设备用。判定结果决定播放时哪些卡实时渲染。
- **渲染任务**：自己渲得出来的自己渲，其余发布任务由渲染节点渲，结果到了自动换上。发布的任务一律是普通优先级。身份为电脑时，后台舞台在闲时兼做渲染节点，从文档服务的任务队列认领自己做得了的快照任务，产 HTML 快照，生成后推送到素材服务。
- 可以从素材服务取别人预渲染好的快照，直接用在可见舞台上。
- **用户卡、图卡**：在线浏览器执行它们，不分身份（2026-10-07 用户定）。**不设出口护栏**（2026-10-08 用户定）：在线浏览器里用户卡与图卡的画面在所有浏览器上都执行，不因浏览器不认 `Connection-Allowlist` 而退回；卡片引用的外链资源（图片、字体、样式、脚本）照常加载，和桌面版一样。拦卡片代码往外发数据的那层护栏（出口限制）这三个版本不做，记为以后的待办。舞台与编辑页面分在不同的源这一层结构不动（它不拦外链，拦的是卡片代码碰编辑页面和账号）；素材不能跨项目读照旧。集成分支上原定的两条〔裁〕（不认这个机制的浏览器不执行画面；外链资源加载不出来）作废。
- **导出**：允许，逐帧渲染、逐帧写出，慢但能出。导出只用原尺寸：导出前拉素材原尺寸，没到齐时照常提示等待上传方；重卡用已有的预渲染原尺寸，不重渲。
- **AI 栏**：接入方式是「云端」，由托管方的云端 Agent 服务执行，不分身份（2026-10-07 用户定）。云端 Agent 服务随四段连做任务上线；手机窄屏上 AI 栏怎么摆见 `docs/plan/TODO.md` 的竖屏界面一行。
- 在线浏览器执行经文档服务同步来的用户卡与图卡，不分身份（2026-10-07 用户定），画面和声音都算，和内置卡一样按轻重区分：判轻的在浏览器里跑，判重的用预渲染结果、没有就交给渲染节点。图卡要的素材原尺寸经素材服务凭票据取。（2026-10-06 用户定）
- 用户卡与图卡只在隔离环境里执行，拿不到项目凭证与票据；图卡取素材用的那张票据由宿主代取，不交给卡片代码。编辑页面本身不执行它们的代码。（2026-10-06 用户定）
- 转译失败、引用了在线页面里没有的模块、或这台设备的图形能力不够时，这张卡退回原来的做法：有预渲染结果就照贴，没有就照常发布普通优先级的渲染任务，由渲染节点渲，结果到了自动换上；只有这一帧没有预渲染结果、又轮到这台设备自己渲染时，该片段在预览里显示「电脑 + 离线」图标和「需要本地 PC 渲染辅助」（见 rendering.md「兜底顺序」），不透明、不显示沙漏；时间轴上的片段同样提示「需要本地 PC 渲染辅助」，出现条件与图标相同。参数面板说明这张卡为什么没在浏览器里运行。（2026-10-06 用户定）
- 在线页面里用户卡与图卡的范围（实现细节与数字见 `../mechanism/platforms.md` 的「在线执行用户卡与图卡」）：
  - **读素材采样的音频图卡**不在线合成：用已入库的声音，没有就交给渲染节点。〔裁:主会话 2026-10-06,待用户合入前审〕
  - **审阅结果不随源码同步**：同步来的用户卡在切分渲染任务时按「未知」当重卡，不出给纯浏览器节点；预览里的轻重判定不受影响。审阅结果随源码同步另立专项。〔裁:主会话 2026-10-06,待用户合入前审〕
  - **托管方可以整体关掉**在线执行（运行配置里的总开关，缺省开）：关掉后所有用户卡与图卡按上一条「退回」处理，参数面板说明站点没有开启；不用重新出版本。〔裁:主会话 2026-10-06,待用户合入前审〕
  - 没有隔离环境的摆法（同源单舞台、本机开发服务器、托管端的反向代理没有配好）自动不执行，表现同「退回」。

## 卡片声音的平台边界

- **在线浏览器可以自己合成声音**（2026-10-06 用户定）：和画面一样按轻重区分——判轻的在浏览器里合成，判重的用已有产物、没有就交给渲染节点。测量合成耗时的时候静音，不出声。轻重判定、测量与记录沿用画面那一套，做法与数字见 `../mechanism/rendering.md` 的「声音的轻重」。
- 内置的提示音、键盘声、内置有声卡如此；用户卡与图卡的声音同样可以在线合成，只在隔离的后台线程里执行（2026-10-06 用户定）。要读素材采样的音频图卡不在线合成，用已有产物或交给渲染节点。

# 文档服务

展开 `../architecture.md` 的「文档服务」角色。从属于 `architecture.md`，与它冲突时以它为准。本册写产品功能（二级）；怎么做到见 `../mechanism/document-service.md`。

## 是什么

即时的文本信息中转站：接收各方的小消息，排序、记版本、转发给该收到的人，并记录项目和任务的进度。它只记账，不算账：没有渲染能力，不测算力，不派任务。

## 不是什么

不是计算服务，不是存储服务。

## 职责

- 文档服务是项目文档的唯一修改入口。编辑界面和 Agent 都只向它提交操作，由它排序、记版本、通知各方、管理锁。各方手里的项目都是它的副本。
- 云端文档服务是云端项目存在状态、创建者、成员、禁入及项目状态的权威记录方。网站“我的项目”“我加入的项目”向它查询，服务不可用明确报不可用，不回假空列表。账号、密码及账号会话由 VisuHive 账号服务管理（2026-10-08 用户明确）。
- 它管理：项目信息、每一次操作的接收与分发、锁、覆盖通知、卡片源码、渲染任务队列。
- 它和每一方之间是一个会话（见下文「会话与传输」），传小消息、要求快速响应。素材字节和预渲染结果不走会话，走素材服务。
- 它是通用的轻量文本 / JSON 调度分发中心：渲染任务队列只是挂在它上面的模块之一；以后与渲染无关的文本消息模块也可以挂上来。无论挂什么模块，都只传小的文本消息，不传字节。

## 会话与传输

- 文档服务与每一方之间是一个**会话**。会话内的消息双向有序、带序号，接收方确认收到。
- **传输**是会话的搬运方式：WebSocket 与 HTTP 长轮询并存。挂在文档服务上的业务模块不感知消息走的是哪一种传输。
- 传输由系统自动选择，用户不感知，也没有选择传输的选项。

## 部署组合

- 文档服务有两种部署：**本地文档服务**跑在本机，**云端文档服务**跑在云端。素材服务同理：**本地素材服务**、**云端素材服务**，见 `asset-service.md`。
- 无论怎么部署，协议不变：操作和通知只走文档服务，素材字节和预渲染结果都经素材服务读写。
- **多用户协作项目放在哪**：只有两种，谁都能选。
  - **本机**：文档服务和素材服务都在创建者本机。创建者本机不在线时，其他成员打不开这个项目。勾上「多用户协作」时默认放本机。
  - **云端**：文档服务和素材服务都在云端，项目内容、任务队列、内容库、素材和预渲染产物都在那里，成员直接连过去。
  - 两种之间可以随时搬（见 `../workflow/project.md` 的「多用户协作」）。
- **连接路径**：成员连本机项目的主机时按顺序找路，用第一条通的：
  1. 局域网直连：在本网段发现主机，直接连上；
  2. 公网直连：按云端托管服务牵线给的地址直接连；
  3. 云端托管服务中继：往来全部经它转发（见 `hosting.md`）。

  三条都是常规路径，依次更慢，中继最慢、受限速。
- **公网可达性只用来告知**：勾上「多用户协作」时，云端托管服务验证创建者机器能否从公网直连。不可达时提示「局域网外的成员将经中继加入，会受限速」，仍可放本机，不锁任何选项。
- **本机项目不依赖云端**：本机项目的创建、局域网发现与接入都不依赖云端，断网照常工作。可达性验证尽力而为，离线时提示「当前离线，局域网外成员暂时无法加入」，项目照建。向云端托管服务的登记在有网时做，离线就跳过，恢复后自动补。
- 只能出网的机器永远是成员，不能当主机，见 `platforms.md` 的「只能出网的节点」。
- 切换所连接的服务是用户的显式操作，不自动发生；切换前后版本号连续，不归零。

## 连接发现

- 文档服务只下发地址，不承担素材传输流量；成员直连不到主机时的转发属于云端托管服务的中继，不属于文档服务。

## 版本与身份

- 每次写入都带写入者的身份：是哪个用户的哪个页面，或哪个 Agent 的哪个对话。
- 身份来自凭证，不由消息自报。共享项目里，用户由进入时的凭证确定；本机 Agent 沿用它所属用户的凭证，另记它是第几个对话。云端 Agent 的对话可以是共有的，一个对话里会有多人发言：每一轮按实际发起这一轮的成员核对身份、署他的名，不按对话归谁（2026-10-08 用户定，见 `agent.md`「接入」；原句没分本机与云端）。
- 协作身份可凭各设备可靠保存的有效恢复凭证跨应用重启恢复，每次重入重新认证、签发会话和素材票据。服务状态存在时以它为准，旧项目文件不得成为重入的根替换；版本与离线操作的期望版本保持连续。创建者权限与实际主机设备分开，第二设备不得自动接管。〔裁：用户授权 `collaboration-reopen-recovery-plan.md` 第 10 节〕

## 共享项目与权限

- 共享项目是权限的隔离单位：文档服务按共享项目隔离项目内容、任务和通知，成员看不到别的项目的任何东西。
- 本地项目进入方式二选一：自由进入，知道项目名和项目密码就能进，进入时自报用户名；限定进入，只有创建者名单里的用户名加密码能进。本地项目不依赖账号。
- 云端新建、迁入和加入都核对网站账号。项目“任何知道链接的人都可加入”默认勾选，仍需账号；取消后只允许账号名单。账号编号决定身份，创建者账号行使特权，被踢账号的全部设备及旧用户授权被拒；已读共有 Agent 当前任务按下述例外保留，不恢复被踢账号权限。邀请只定位云端项目，不代替账号认证。
- **邀请码**：项目的文档服务签发的令牌；本地自由进入等价于知道项目名和项目密码，限定进入只等价于知道项目名；云端只定位项目，账号与禁入仍须核对。可作废、可限时限量；本地作废不影响项目密码。邀请码由签发它的文档服务核对；本地托管服务保存校验副本，牵线时先验（见 `hosting.md`）。邀请码不进地址的查询串、不进日志。
- 创建者特权只有三项：改进入设置、名单或邀请码，删项目，踢人；本地每次出示创建者用户名和密码，云端核对创建者账号。其余操作所有成员一样。
- 本地项目凭证由文档服务核对；云端账号密码由账号服务核对，云端文档服务再判断项目权限并签发授权。素材服务凭文档服务签发的票据放行（见 `asset-service.md`）。
- **本机按真正的发起方判断**：本机上的编辑界面和进程连本机的文档服务，不用交凭证。「本机」按连接真正的发起方判断：经同一台机器上的反向代理转进来的连接和请求按远端对待，照常核对凭证。
- 本地项目的一期不做第三方登录和项目密码找回；云端网站账号已有邮箱重设密码，不另做第三方登录。

## 冲突

- 普通在线协作仍是**最后写的赢**，不做多人实时合并。暂时离线重入是例外：需要基准比较与可视化冲突处理，不能静默覆盖。延迟撤回按修改项逐条核对，规则见下文。
- **发生覆盖时，覆盖方和被覆盖方都要知道。** 被覆盖的一方在换成最新版本之前，先把自己那份存成本地备份。
- **撤回按修改项逐条核对**（2026-10-08 用户定）。项目内容是 JSON，一步操作改了哪几项是确定的；撤回只动这一步改过的项，不把整个项目退回去，也不动别人改的其它项。
  - **判冲突**：这一步改过的某一项，之后又被别人改过（另一位成员、Agent，或同一账号的新登录），这一项算冲突；之后没人再改过的，不冲突。同一步里可以有的项冲突、有的不冲突，各按各的办。
  - **改密码或重设密码选了退出而触发的撤回**（没有人在场处理）：不冲突的项撤回；冲突的项不撤，保留现状。不弹窗口。
  - **用户按撤销按钮**（含 AI 栏的「撤销这一步」）：不冲突的项直接撤回；有冲突的项时弹出窗口，列出冲突的地方，由用户决定。窗口里给哪些选项待定，属于界面，先给用户看。
  - 项目只有自己一个人在改时没有冲突可言，撤销、重做和现在一样。
- 某张卡最近的写入者在新版本落地时收到通知；Agent 和用户都可以对某张卡退出跟踪。
- Agent 的写操作带期望版本，和当前版本不符就拒绝，并告诉它期间落地了哪些改动，由它重读后再改。用户在页面上的操作不带期望版本，按到达顺序落地。
- 两个 Agent 在短时间内反复交替改同一张卡时，锁住先写的那一方对这张卡源码的写权限，并通知双方和用户；由用户解锁，或空闲一段时间后自动解锁。

## 离线

- 连不上文档服务时允许的编辑操作持久保存在本地，保留原服务/项目关联和基准哈希、时间、版本及可用于比较的内容；暂时离线不等于项目过期。
- 重开或重连先取当前云端版本，提示是否落后并询问是否发送离线改动；冲突提供可视化基准/离线/云端比较，用户处理后提交。取消不丢离线内容；提交时再次核对版本，避免覆盖窗口打开后新的修改。

## 保存与延迟退出的修改处理（2026-10-08 用户定，待实施）

- 保存等待本机修改状态检查完成，前台编辑暂时禁用；非本机内容固定确定快照并记录哈希、权威时间、版本，不要求整个云端长期停写。哈希与时间不能代替基准内容及历史操作。
- 改密后用户可选择是否退出已登录设备；选否保留现有云端登录和写入权限，选是撤销旧用户凭证、中止私有 Agent 任务，共有已读当前任务按下述例外继续。
- 邮箱重设密码（忘记密码）和改密码内部是同一套逻辑，只是界面上的说法不同：重设之后同样问是否退出已登录设备，用户有权不退出；选了退出，后面的处理与改密码一样（2026-10-08 用户定；原写「邮箱重设一律撤销全部旧登录、不套用可选流程」作废）。
- 云端延迟收到退出通知时，需处理“改密码绝对时间至旧凭证账号下线”区间的旧凭证修改。须保留可追溯操作与撤回依据，保护其他账号及重新登录的合法修改。撤回按修改项逐条核对（2026-10-08 用户定，规则全文见上文「冲突」）：某一项之后被别人又改过算冲突。因改密码或重设密码选了退出而触发的撤回，不冲突的撤、冲突的不撤，不弹窗口；用户按撤销按钮，不冲突的直接撤、冲突的弹出窗口由用户决定。
- 改密选择退出与被踢均有 Agent 已读消息例外：该用户已发送、且被 Agent 读到的消息不撤回，保留原文、实际发送者及可核实读状态。私有任务中止，共有已读消息触发的当前任务及其修改保留继续，不因此次改密退出或踢人撤回；消息/任务/操作关联须精确核对，不能误保留其他修改。旧用户凭证和被踢账号的项目权限不恢复；删项目与关闭 Agent 仍终止任务，见 `agent.md` 和账号契约。
- 这是对齐后的产品要求，确切跨服务时间映射、历史保留、撤回机制及失败补偿仍待设计，见 `../../plan/account-binding-contract.md`，不以现有摘要字段声称已实现。

## 渲染任务队列

预渲染不绑在某一台设备上：本机、局域网或远程的独立渲染主机、在线浏览器的页面都可以做**渲染节点**，从文档服务托管的任务队列里取活。

- **只记账，不分配**：文档服务只记每个任务的状态和认领者，不测算节点的算力，不主动把任务派给谁，也不替节点判断它做不做得了。唯一的例外是指纹前置过滤（见 `../mechanism/document-service.md` 的「渲染任务队列」）。
- **只把权限关**：文档服务不替节点判断能力，但要按凭证把权限关。节点只能看到、只能认领自己所在共享项目的任务。纯浏览器节点更窄：只能看到、只能认领当前登录用户自己产生的任务，同一共享项目里其他成员的任务也不行；这两条都由文档服务保证，不靠节点自己过滤。
- **任务不带字节**：任务只写要渲染什么（项目版本、片段、帧范围、预渲染结果的内容键），不带项目文件以外的字节。节点按项目版本从文档服务取项目，按哈希从素材服务取素材。
- 〔2026-10-07 用户定：本条撤销。在线浏览器发布的任务一律是普通优先级，不再有「为弱设备补渲」这一类，见 `platforms.md` 的「在线浏览器」；以下为原文〕**补渲排在后面**（2026-09-27 用户定）：为弱设备补渲的任务（低内存档判重、素材服务里又没有产物而发布的，见 `platforms.md` 的「面向的平台」）排在本机判重的任务之后：渲染节点先做创建者本机判重的任务，空下来再做补渲的。
- **离线**：连不上文档服务时，本机的预渲染进程照常为本机的项目做预渲染，不经过队列；恢复连接后照机制里「队列只在内存里」那一条重新发布（见 `../mechanism/document-service.md` 的「渲染任务队列」）。

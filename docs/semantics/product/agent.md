# Agent

展开 `../architecture.md` 的「Agent」角色。从属于 `architecture.md`，与它冲突时以它为准。用户怎么选接入方式、创造力等级、多 Agent 和保护规则，见 `../user-workflow.md`。本册写产品功能（二级）；怎么做到见 `../mechanism/agent.md`。

## 接入

- 所有 Agent 通过同一套工具接口操作项目，不论它是 AI 栏里经命令行或 API 接入的、桌面 APP 经 MCP 接入的，还是托管方的云端 Agent。
- 每个 Agent 会话有自己的身份。文档服务、通知、多 Agent 协调都按这个身份区分。

## 工具

- **写**：Agent 的写操作经文档服务落地，和编辑界面的操作一样排序、记版本、通知。
- **素材与产物**：Agent 进程像外部客户端一样，经素材服务的接口读写素材和预渲染的产物；哪怕和素材服务在同一台机器上，也绝不直接读素材服务的存储目录。
- **看**：实时看画面走即时渲染，结果从渲染所在的位置直接回传，见 `rendering.md` 的「即时渲染与预渲染进程」；审阅成片，或所在环境没有渲染能力时，经素材服务拉取预渲染的产物。云端 Agent 第一版没有渲染能力，也不经素材服务拉取产物来看。

## 看到的卡片

Agent 看的、改的卡片是卡片的约定封装，见 `cards.md`。

## 汇报

- Agent 的文字回复不直接展示给用户。它通过结构化的进度汇报交代做了什么、还有什么没做、遇到了什么问题。
- 桌面 APP 的 Agent 按 SKILL 提示词约定的结构化方法汇报。

## 运行位置

- Agent 默认在用户本机运行。桌面版的 AI 栏缺省用本机 Agent。
- **云端 Agent**：托管方提供的 Agent 服务，跑在云节点上，只为放在这台节点上的项目服务。在线浏览器模式的用户在 AI 栏里用它；项目放云端时桌面版的 AI 栏也可以选它。对话与工具调用由它执行，改动经文档服务落地，和本机 Agent 的改动一样排序、记版本、通知、可撤销。
- **发出任务后可以离开**：云端的对话在云节点上运行，不依赖发起它的设备。发起的成员关掉页面或退出软件后，对话继续跑到结束，改动照常落地；被改动的重卡由云节点上托管方的渲染节点渲出来并入库，全程不需要任何成员的设备在线。成员重新打开项目，或在另一台设备上以同一个用户名进入，能看到对话的完整过程、停掉还在跑的对话、接着说。
- **出错留痕**：模型调用失败、额度用尽、渲染失败、对话被停掉或失效时，对话记录里留下明确的原因，项目停在最后一次成功的改动之后。
- **模型**：云端 Agent 用托管方的模型凭证，服务端直连模型接口。凭证只在云节点上，不经任何会话明文传递：托管方在自己的电脑上把 Key 加密成只有这台节点解得开的密文，再交给节点导入（办法见 `../mechanism/agent.md`「Key 与模型」）。〔用户 2026-10-07 定〕
- **身份**：云端 Agent 服务用托管方的服务身份接入文档服务；每个对话另须出示发起成员的身份证明，由文档服务核验。这份证明在成员发消息时签发，成员离线后在这一轮之内仍然有效。它在这个对话里能做的不超过该成员本人的权限，改动署名为「〈成员名〉的云端 Agent」，成员列表里看得到。它不使用任何成员的项目凭证。
- **开关与失效**：每个项目有「云端 Agent」开关，缺省开，创建者可以关。创建者关掉开关、成员被移出、项目删除后，对应的对话立刻失效，进行中的对话被停掉。创建者关掉开关时，别的成员收到一条气泡；打开时不提示。〔用户 2026-10-07 定〕
- **上限**：所有对话与模型调用都经过同一处额度与并发检查；每个项目有一个额度，缺省不限，由托管方按项目发放。用量按项目、按成员记录，可查。
- **工具范围**：云端 Agent 的工具与本机 Agent 一致，包括建卡改卡、导入素材、网页采集、配音、感知类工具、看画面（即时渲染）。〔用户 2026-10-07 定〕（原先写的「第一版不开放这些」是会话的建议被误记成用户的决定，作废。）
  - 唯一可以缺省的是**要操作发起人自己界面的工具**（选区、播放头、播放与暂停、网页接管这类）：发起方不在线时回明确的「发起方不在线」，Agent 据此继续、不卡住；发起方在线时要能用。〔用户 2026-10-07 定〕
    - 「在线」指发起这一轮的那张页面（在线浏览器的页面，或选了「云端」的桌面版）还开着：读选区、跳播放头、播放、暂停作用在这一张页面上，在 AI 栏里与本机 Agent 的这几步显示得一样；同一位成员在别的设备上开着同一个对话只是看，不会被操作。
    - 网页接管、采集的扫码登录、开子 Agent 页签这三样在云端还做不了（发起方在线时回明确的原因，不在线时同样回「发起方不在线」），记未达成；差什么写在 `../../plan/cloud-agent-contract.md` 第 28.3 节。
  - 确因云节点条件做不了的工具（例如某个感知工具要的扩展包或模型节点上没有），调用时明确回「云端暂不支持」并说原因；逐项的清单与原因在 `../../plan/cloud-agent-contract.md` 第 9 节的工具表里，不在这里重复。
  - 建卡改卡写出的源码会在别的成员的浏览器和渲染节点上执行，靠用户卡与图卡的隔离保护，与本机 Agent 在协作项目里建卡是同一种风险，不另设限制。
  - **隔离**：工具在节点上读写的一切都按项目隔离：素材经素材服务、项目经文档服务；一个对话读写不到别的项目的文件，也读写不到节点上的系统文件、凭证与别的服务的数据目录。能发网络请求的工具（网页采集、下载）不能访问节点的回环地址、内网地址与同机别的服务的接口。
  - **花钱的外部调用**：配音等要花钱的调用用托管方的配置，用量并进「上限」一条里的用量记录（按项目、按成员，可查）。
  - 云端不提供深度自主与审查环路（「深度自主」置灰并写原因）；云端下**可以附文件**，与本机相同。〔用户 2026-10-07 定〕
  - 空对话里的示例句只有一条：「为我快速创建一个视频告诉我软件都可以做什么。」本机与云端相同；工具范围与本机一致，这支短片云端也照常做得出来。〔用户 2026-10-07 定〕
- **对话记录**存在云节点上，归发起它的成员，只有他能读；托管方的运维读得到（数据在它的节点上）。创建者与限定进入的成员换一台设备也能找回自己的云端对话；自由进入的成员（用户名是自报的）只能在原设备找回。〔裁：主会话 2026-10-06，待用户合入前审〕
- **诊断报告**：云端对话与本机对话都能按对话出诊断报告，两种去向都有：下载到本地；一键「报告」提交到诊断报告收集端存起来（用 `report-inbox.bat` 取回）。在线页面里报告在页面内生成，下载与提交都不经编辑器进程的 `/api/*`。内容是这段对话的过程、出错原因、客户端与版本信息，不含任何凭证（票据、委托、模型 Key）。没配收集端地址时「提交」置灰并说明原因，仍可复制或下载。〔用户 2026-10-07 定〕
- **成员列表怎么数**：成员列表按「成员：N 人 · Agent：M 个」分开计数。人数只算真人在线的；本机 Agent 与云端 Agent 都计入 Agent 个数。成员本人不在线、只有他的云端 Agent 还连着时，他那一行照常显示并标「离线，Agent 在跑」，不计入人数、计入 Agent 个数。〔用户 2026-10-07 定〕

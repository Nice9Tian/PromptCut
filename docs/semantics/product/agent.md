# Agent

展开 `../architecture.md` 的「Agent」角色。从属于 `architecture.md`，与它冲突时以它为准。用户怎么选接入方式、创造力等级、多 Agent 和保护规则，见 `../user-workflow.md`。本册写产品功能（二级）；怎么做到见 `../mechanism/agent.md`。

## 接入

- 所有 Agent 通过同一套工具接口操作项目，不论它是 AI 栏里经命令行或 API 接入的、桌面 APP 经 MCP 接入的，还是托管方的云端 Agent。
- 每个 Agent 会话有自己的身份。文档服务、通知、多 Agent 协调都按这个身份区分。
- **AI 栏里装和登录命令行工具**：AI 栏能替用户安装 Claude Code、Codex、agy 这几样命令行工具，并起它们自己的登录流程。登录一般由命令行自动打开浏览器、在本机回调里完成。**浏览器拉不起来的环境**（远程桌面、没有默认浏览器）只能走登录网页给的那串授权码：登录对话框在「打开登录网页」下面收着一个「粘贴授权码」的入口，只在登录任务确实在等输入时出现；用户把码粘进去提交，软件把它送进那条登录命令，不再像原先那样无处可粘、任务一直挂到超时（2026-10-21 用户定要做，原话「可以。」）。授权码是凭证：不写日志、不留在任务记录里。入口的位置、文案与形状校验见 `../mechanism/agent.md`「命令行登录接标准输入与粘贴授权码」。
- 云端 Agent 对话支持共有权限和私有权限，新建默认共有，用户可以主动改为私有。共有对话允许同一项目内所有已登录且有项目权限的成员查看完整历史、Agent 回复并发送消息；私有对话只允许所属账号访问和发送（例外两个：项目创建者能看、不能发，见下一条；托管方能读到节点上的全部对话记录，含私有的（数据在它的节点上），2026-10-08 用户定），换设备登录同账号可继续访问（2026-10-08 用户新拍板）。
- **谁能管对话和任务**（2026-10-08 用户定）：只有开这个对话的人能把它在共有和私有之间切换。停任务：每个人只能停自己发起的那一轮，项目创建者能停任何人的任务。项目创建者能查看所有成员的私有对话，只能看，不能在里面发消息。共有对话切成私有后，别的成员立刻看不到它；切成私有的那一刻，别的成员在这个对话里发起、还在跑的任务立刻中止，已经落地的修改保留，没做完的不再做，队列里别人没轮到的消息一并作废（用户的理由：不然发任务的人看不到自己的任务，项目却还在被改）。
- **对话的上限与删除**（2026-10-12、2026-10-13 用户定）：同一个项目里一个人最多保留 50 个云端对话，共有对话算在开它的人名下，满了不让新建、不自动删历史。开对话的人能删自己开的对话，项目创建者能删任何成员的对话，包括别人的私有对话；别的成员不能删，只读成员不能删自己开的对话。删之前确认，不能取消删除；对话里有任务在跑，先停下再删，停不下来就强制结束那条任务，已经落地的修改保留；删完立刻让出名额。删掉的对话清干净：存档、Agent 服务一侧的运行日志、请求记录里的标题都清。创建者删了别人的对话，开这个对话的人收到一条气泡通知；共有对话被删时，在里面发过消息的其他成员各收到一条气泡，没发过消息的不通知，对话切成私有之前发过言的成员也不通知；删的人自己不通知；收通知的人不在线时，下次打开这个项目补弹一次。移出成员时，操作的人可以选是否同时清除他的私有对话，他的共有对话缺省保留。
- **多人同时发言**（2026-10-08 用户定）：同一个共有对话同一时间只跑一个任务；别人后发的消息按到达顺序排队，一轮一轮跑，界面显示排在第几。想同时让 Agent 做两件事，另开一个对话。
- 对话归属和消息发送者分别记录：归属按账号编号；共有对话每条消息记录实际发送者，不能把所有人的发言都记成对话所属账号。身份由服务端核对，不接受客户端冒用别人名字。
- 云端 Agent 能做的事对所有成员都一样：项目创建者发起的和参与者发起的没有区别，创建者特权 Agent 一律做不了。每一轮只核对发起者此刻是不是这个项目的有效成员，不分权限高低（2026-10-08 用户定；原先写的「沿用实际发起者的项目权限，不能借用对话所属账号的更高权限」读起来像成员之间权限有高低，作废）。只读成员不能操作 Agent（2026-10-08 用户定；现行语义里还没有只读成员这种身份，将来有了照此办）。被踢或改密选择退出后，任务按下条共有/私有例外处理。共有对话的其他有效成员权限单独核对，不因一个人失去权限而一律拒绝。延迟退出的修改处理遵循 `document-service.md`。
- **改密退出与被踢的已读消息例外**：已经发送并被 Agent 读到的消息保留原文及发送者，不撤回。私有 Agent 任务直接中止；共有 Agent 已读消息触发的当前任务及其修改保留、不撤回并继续执行。改密选退出仍撤销旧用户登录；被踢仍拒绝该账号全部设备的项目访问，包括查看对话、发送消息及发起下一轮。例外只保留当前任务授权，不豁免项目删除或关闭 Agent。仅“已发送”不等于“Agent 已读”（2026-10-08 用户新增并扩大到被踢）。

## 工具

- **写**：Agent 的写操作经文档服务落地，和编辑界面的操作一样排序、记历史序号、通知。
- **素材与产物**：Agent 进程像外部客户端一样，经素材服务的接口读写素材和预渲染的产物；哪怕和素材服务在同一台机器上，也绝不直接读素材服务的存储目录。
- **告知托管方能读**（2026-10-08 用户定）：第一次使用云端 Agent 时弹出对话框，告知「托管方能读到你和云端 Agent 的对话记录，包括私有对话」，两个按钮：「我知道了」「拒绝」。选「我知道了」才能用，按账号记住，之后不再弹；选「拒绝」就不发这条消息、不能用云端 Agent，下次再用时还会弹。这两句是会话按用户的两个按钮推出来的，用户只定了弹框、告知的内容和两个按钮。
- **读选中内容**（2026-10-08 用户定）：Agent 问「用户选中了什么」时，同时读到这个项目里所有在线成员各自选中的内容，每一份标上用户名，发起这一轮的那位在名字后用括号标注为当前用户。原先「只读发起那一页，读不到就用快照」的做法作废。发起人不在线时，他那一份用发消息时留的快照，并注明不是实时的（用户确认）。
- **看画面渲染超时就停**（2026-10-16 用户定，取代 2026-10-09 的「每次等一分钟，重试三次」）：Agent 看画面（即时渲染）时，渲染只做一次，有时限，防止卡片死循环或计算量太大。到点没出来就停，不重试，告诉 Agent「渲染超时」，并附上调试信息：卡死在哪张卡的源码哪一行、这几帧上挂着哪些卡、停在哪一步、页面报的错、在等什么、是不是被内存上限掐掉。时限只算渲染本身；排队不计时，也不设上限。整个过程低于五分钟仍是目标。
- **看画面能指定剪辑**（2026-10-21 用户定，原话：「see_frames加入剪辑id（留空为当前剪辑）。」）：Agent 看画面时可以指定看哪条剪辑，不指定就是当前激活的剪辑；看没激活的剪辑不切换激活剪辑、不改项目、不动任何人的界面。回包写明看的是哪条剪辑。
- **会动用户界面的操作，名字带 `user_interface_`**（2026-10-21 用户定，原话：「切这个动作可以改成user_interface.swith_cut（）这样在代码层面就可以理解到会动用户界面。还有时间轴操作也是，动用户界面的加user_interface。」）：主要效果是改变用户眼前界面状态（所有成员共享的激活剪辑、播放头、播放与暂停）而不是改项目内容的工具，名字前加 `user_interface_`，Agent 从名字就知道这一步会动用户的界面，能不用就不用。模型侧的工具名只认字母、数字、下划线和连字符，所以写成 `user_interface_switch_cut` 这样。把窗口或登录框弹到用户面前的网页接管与站点登录也按这一条改名（〔裁：cut-look-ui 2026-10-22，见 `docs/reports/AGENT-cut-look-ui.md`「工具改名对照表」〕）；新建剪辑只建不切，要切另用切换的那一个（〔裁：cut-look-ui 2026-10-22〕）。
- **回复被截断时接着写，不白写**（2026-10-22 用户定，原话：「去"https://doc.openlux.ai/tutorials/00-intro"看一下怎么解决输出token被截断的问题。把单次输出上限调大。同时研究重试方法：是否可以把被截断的部分作为输入，让模型继续续写。比如给项目一个代码块空间，让Agent可以对代码块进行操作比如read(code_cache)/replace(code_cache,xxx,yyy)」）：
  - Agent 每次回复的输出上限用所选模型真实允许的上限，不再是固定的小数；托管方可以在配置里压低，不能超过模型本身的上限。
  - 每个项目有一个**代码块空间**：一组有名字的文本块，Agent 能写入、追加、读（整块或一段）、替换、列出、删除，并能在任何操作的参数里直接引用某个代码块的内容。写大段源码可以分几次写进代码块，最后一次交给建卡、改卡。本机与云端都有。代码块是 Agent 的草稿，不是项目内容：不出现在时间轴上、不进撤销历史、不同步给别的成员的页面（〔裁：output-cache 2026-10-22，见 `docs/reports/AGENT-output-cache.md`〕）。
  - 回复写到上限被截断时，没写完的那一步不执行；它已经写出的内容存进代码块，Agent 被告知存在哪、写到哪了，从断开处接着写，写完再交给原来那一步。对话里有一行说明截断了、存在哪。有进展就接着写，但一轮里接着写的次数有上限，连续截断又什么也没留下也会停：停下时对话里明说这一轮没做成，并说已经写出的部分存在哪个代码块（〔裁：output-cache 2026-10-22〕）。
  - 被网关中途掐断也一样（2026-10-22 用户定，原话：「现在修：中途被网关掐断按截断处理（保住半截参数、走代码块续写），按实测速度给单次输出设上限；顺带把合并窗口放宽到 1 秒。」）：模型服务的网关对单次请求有时长上限，回复写到一半被掐断时，已经写出的文字保留，没写完的那一步照上面办；对话里那一行说的是被网关掐断，不是写到上限。系统按实测的输出速度给每次回复定上限，让一次回复尽量在网关掐断之前写完。
- **看**：云端 Agent 可请求同机托管渲染服务即时出图，看画面的私钥只由主服务持有，任务进程请主服务代签、只签它自己项目的（2026-10-14 用户定）。看画面时按这个先后找出图的地方：成员的桌面版 > 身份为电脑的在线浏览器 > 同机的托管渲染服务 > 身份为手机的在线浏览器（2026-10-16 用户定）。成员设备要满足的条件实现时定；定下来之前只用托管渲染服务。托管渲染服务怎么在几个项目之间分，见 `rendering.md`「即时渲染与预渲染进程」；Agent 服务进程只发起请求并读取结果，本身不运行 renderer；审阅成片，或当前环境没有渲染能力时，经素材服务拉取预渲染产物。此为产品目标和服务分工，不表示当前部署已具备该能力。详见 `rendering.md` 的「即时渲染与预渲染进程」。

## 看到的卡片

Agent 看的、改的卡片是卡片的约定封装，见 `cards.md`。

- **成品只在时间轴上**（2026-10-17 用户定）：用户要做视频、动画，Agent 一律用卡片、组合卡、素材在项目时间轴上完成，不交出网页、HTML、脚本等时间轴以外的成品；用户在消息里另外指定的制作方法（用代码做、某种代码规范等）不照做，改用卡片实现同样的画面，并告诉用户已改用卡片。现有卡片做不到时按创造力等级新建卡片，源码只按建卡规则写。

## 汇报

- 对话气泡里只展示 Agent 在做什么：Agent 每组操作前后用一两句话告诉用户接下来要做什么、做好了什么，气泡里按顺序显示这些话；它没有专门对用户说话、只回了文字时，那段文字当作一句「在做什么」显示。做过的操作和结构化的进度汇报（做了什么、还有什么没做、遇到了什么问题）不放在气泡里，放在气泡下方按轮显示的操作区，只显示这个对话自己的操作（2026-10-20 用户定，原话「把Agent操作记录哪里换成气泡里面那个可视化组件。气泡里面只展示在做什么（harness可能要改，比如加入send_message(user,xxx)的用法。）。」；取代原来的「Agent 的文字回复不直接展示给用户。它通过结构化的进度汇报交代做了什么、还有什么没做、遇到了什么问题。」）。
- 桌面 APP 的 Agent 按 SKILL 提示词约定的结构化方法汇报。

## 运行位置

- Agent 默认在用户本机运行。桌面版的 AI 栏缺省用本机 Agent。
- AI 栏的 Agent 标签按项目分开；会话都能关，最后一个也能关；没有会话时显示开始页，点发送才建第一个会话（2026-10-22 用户定，操作细节见 `../workflow/editing.md`）。
- **云端 Agent**：托管方提供的 Agent 服务，跑在云节点上，只为放在这台节点上的项目服务。在线浏览器模式的用户在 AI 栏里用它；项目放云端时桌面版的 AI 栏也可以选它。对话与工具调用由它执行，改动经文档服务落地，和本机 Agent 的改动一样排序、记历史序号、通知、可撤销。
- **发出任务后可以离开**：云端的对话在云节点上运行，不依赖发起它的设备。发起的成员关掉页面或退出软件后，对话继续跑到结束，改动照常落地；Agent 自己查看画面（看画面等）由云节点上托管方的渲染节点兜底渲出，全程不需要任何成员的设备在线，不受「生成轨道流」开关影响；被改动的重卡给成员预览用的轨道流，开了「生成轨道流」时由托管方的渲染节点生成并入库，没开时由打开项目的设备生成（2026-10-21 用户定：「生成轨道流」的本意是不为用户的预览服务；服务器渲染服务的本意是兜底为 Agent 的看画面等查看请求服务）。成员重新打开项目，或在另一台设备上以同一个网站账号进入，能看到其有权访问的对话；停止权限遵循「谁能管对话和任务」，不能由其他成员普遍停止。等后台作业做完才收尾（最多等一小时，选甲）。同一对话的下一条消息排着时提示「上一条消息发起的后台作业（转写、镜头识别等）还在做，做完就处理你这条消息。」；等满一小时后台作业被中断时在对话里提示一次「后台作业等了一小时还没做完，已经中断；需要的话请重新发起。」节点重启后任务槽自己恢复，卡住的对话自动记为失败并释放，不自动重发消息（2026-10-14 用户定）。
- **出错留痕**：模型调用失败、额度用尽、渲染失败、对话被停掉或失效时，对话记录里留下明确的原因，项目停在最后一次成功的改动之后。
- **模型**：云端 Agent 用托管方的模型凭证，服务端直连模型接口。凭证只在云节点上，不经任何会话明文传递：托管方在自己的电脑上把 Key 加密成只有这台节点解得开的密文，再交给节点导入（办法见 `../mechanism/agent.md`「Key 与模型」）。〔用户 2026-10-07 定〕成员发消息时可在托管方配置的模型里选一个、选思考强度；不选就用托管方的缺省。〔用户 2026-10-18 定〕
- **身份**：云端 Agent 服务用托管方的服务身份接入文档服务；每轮须按该轮实际发起者核验网站账号编号与当前项目成员资格，并记录实际发起者。共享对话中的对话所属账号不替代消息作者或本轮发起者。Agent 能力对所有成员相同；改动署名保留实际发起者，服务不使用任何成员的项目凭证。具体委托与撤销机制由契约设计落实。
- **开关与失效**：每个项目有「云端 Agent」开关，缺省开，创建者可以关。创建者关闭开关或项目删除时，相关对话与任务全部停止。成员被移出或改密退出时，真人的项目访问权限立即撤销；私有任务停止，已被 Agent 读到的共有消息触发的当前任务继续，已落地修改保留。共有对话切成私有时，其他成员正在运行的任务立刻中止、已落地修改保留，其他成员排队中的消息作废。创建者关闭开关时，别的成员收到一条气泡；打开时不提示。〔用户 2026-10-07 定；退出/踢人及共有私有例外按 2026-10-08 新决定〕
- **上限**：所有对话与模型调用都经过同一处额度与并发检查；每个项目有一个额度，缺省不限，由托管方按项目发放。用量按项目、按成员记录，可查。
- **工具范围**：云端 Agent 的工具与本机 Agent 一致，包括建卡改卡、导入素材、素材采集、配音、感知类工具、看画面（即时渲染）。〔用户 2026-10-07 定；素材采集按 2026-10-08 定名及登录态规则〕（原先写的「第一版不开放这些」是会话的建议被误记成用户的决定，作废。）

# 渲染

展开 `../architecture.md` 的「成片渲染」「查询渲染」两个角色。从属于 `architecture.md`，与它冲突时以它为准。卡片的分类见 `cards.md`。本册写产品功能（二级）；怎么做到见 `../mechanism/rendering.md`。

## 总规则

- **交互不等渲染。** 用户交互不允许任何卡顿：舞台渲染和用户交互互相异步，交互永远不等渲染。画面来不及时，只允许按「兜底顺序」（见「重管线：预渲染」）退化：先用低帧率或旧的预渲染结果顶上；只有算力预算装不下、或没有任何可用的预渲染结果时，才在该层显示占位符。预览里任何一层都不无提示地透明。打开项目时的测量遮罩是唯一的例外。
- **同一时刻同一帧。** 预览、导出、Agent 看到的画面用同一份卡片代码、同一套钉时间的方法，同一时刻渲染出同一帧。
- **帧率。** 最高 60 fps。项目可选 24、25、30、60，新项目默认 30，所有时间步长按 1/fps。

## 用到的词

- **活渲**：卡片在舞台里当场一帧帧算出来、画上去。
- **轻卡、重卡**：当场画得过来的卡是轻卡，直接活渲；画不过来的是重卡，事先渲好、播放时贴上去。哪张轻哪张重靠实测，同一张卡在项目的不同位置可以不同。
- **快照**：某张卡某一帧的画面，事先渲好存下，暂停和拖动时贴上去。
- **实体框**：卡片实际画出内容的最小矩形。
- **兜底顺序**：画面来不及时，按从好到差的顺序找能用的画面顶上；都没有才显示占位符。

## 舞台

- 给人看的画面在舞台里渲染。舞台和编辑界面分属不同进程，舞台卡住时编辑界面不卡。

## 播放

- **按帧走，慢帧就等。** 舞台每渲完一帧才推进 1/fps，并报告当前时刻；某一帧慢了就把后续整体后移，不追、不跳帧。
- **播放头跟随舞台。** 编辑界面的播放头跟随舞台报告的时刻。
- **看不到推帧过程。** 拖动或点击时间轴随机跳转时，用户看不到推帧卡被推进的中间过程。
- **停下就精确。** 暂停、点击时间轴、拖动时间轴后松开，以及播放到头停下，所有卡都回到精确的活渲。低内存档除外（见 `platforms.md` 的「面向的平台」）。
- **音频跟随画面。** 画面落后应到时刻太多时暂停音频；恢复时对齐到当前时刻。

## 轻卡与重卡

### 测量

- 每次打开项目，在加载遮罩下把所有卡测完才进入编辑。之后新加的卡在后台舞台里测。

## 重管线：预渲染

- 重卡离屏预先渲染成预渲染结果。播放和拖动时只贴预渲染结果，拿不到这一帧时按下面的兜底顺序处理，播放头从不为它停。
- 预渲染不限于本机：需要预渲染的卡作为任务发布到文档服务的任务队列，由任意渲染节点（本机 PC、独立渲染主机、纯浏览器）按自身能力认领（见 `document-service.md` 的「渲染任务队列」、`platforms.md` 的「渲染节点」）。连不上文档服务时本机照常自己做。
- **不同环境的结果不混用**：不同硬件渲的连续帧拼在一起会闪，所以同一层里的帧只出自一种环境，画面不闪。
- 预渲染结果生成后一律推送到素材服务，素材服务就在本机时也一样，见 `asset-service.md` 的「预渲染的产物」。预渲染进程经素材服务的接口推送产物、读取素材，不直接读写素材服务的存储目录。
- **两档**：**预渲染原尺寸**按项目分辨率渲出，导出和电脑上的预览用；**预渲染小尺寸**由原尺寸直接缩小得到，不重渲，低内存档的预览用。渲染节点产出原尺寸后一并生成小尺寸，两档都推送到素材服务。
- 暂停后，重卡追到精确活渲。

### 兜底顺序

- 只有两种情况退到占位符：该层所有兜底都超出预算；或该层还没有任何预渲染结果。
- 占位符：在该卡的实体框位置显示「沙漏 + 噪点」，表示系统正在加载；量不到实体框时只在位置框中心显示一个小沙漏徽标，不铺噪点。它继承该层的坐标、旋转、缩放和层级，自身几乎不占算力（不跑脚本、不逐帧重绘，动画只动合成属性；同屏多个时只有一个沙漏在转）。
- 其它来不及的时刻也用占位符，不透明：快照还没到、不可见地追帧、等后台舞台补跑后互换。
- 来不及的状态很短时不显示占位符，避免闪烁。
- 占位符只出现在编辑界面的预览里；导出、预渲染、Agent 看到的画面和后台舞台永远没有它。
- 更好的结果到货后自动替换，不等用户操作：新快照在下一拍换上；稀疏段换成满帧段在下一个分段起换上（两种编码的差分帧不能接续）。
- 这台设备渲染不了的卡（在线浏览器模式下的用户卡、图卡，见 `platforms.md`）不走兜底顺序：常驻显示「电脑 + 离线」图标和「需要本地 PC 渲染辅助」，不显示沙漏。它同样只出现在预览里，位置和层级规则与占位符相同。
- 停下就撤兜底：暂停、点击或拖动松开时，兜底画面一律撤下、追到精确活渲；之后不再盖回去，直到下一次跳转或播放。

## canvas 卡的共享 WebGL 渲染器

- canvas 卡的渲染路线有两条，项目选项可切换：桌面默认每个舞台各用一套，低内存档默认两个舞台共用一套。

## 查询渲染与预渲染进程

- 查询渲染的结果从渲染所在的位置直接回传给 Agent，不经过素材服务。
- **Agent 优先只是插队**：Agent 的查询不霸占渲染，用户总能等到预渲染。
- **AI 栏的操作预览可以插队**：它由用户触发，排到普通预渲染队列所有待办任务之前，不打断正在跑的那一批，也不占用 Agent 的专用实例。

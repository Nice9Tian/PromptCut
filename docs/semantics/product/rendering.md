# 渲染

展开 `../architecture.md` 的「成片渲染」「即时渲染」两个角色。从属于 `architecture.md`，与它冲突时以它为准。卡片的分类见 `cards.md`。本册写产品功能（二级）；怎么做到见 `../mechanism/rendering.md`。

## 总规则

- **交互不等渲染。** 用户交互不允许任何卡顿：舞台渲染和用户交互互相异步，交互永远不等渲染。画面来不及时，只允许按「兜底顺序」（见「重管线：预渲染」）退化：先用低帧率或旧的预渲染结果顶上；只有算力预算装不下、或没有任何可用的预渲染结果时，才在该层显示占位符。预览里任何一层都不无提示地透明。打开项目时的测量遮罩是唯一的例外。
- **同一时刻同一帧。** 预览、导出、Agent 看到的画面用同一份卡片代码、同一套钉时间的方法，同一时刻渲染出同一帧。
- **帧率。** 最高 60 fps。项目可选 24、25、30、60，新项目默认 30，所有时间步长按 1/fps。

## 用到的词

- **活渲**：卡片在舞台里当场一帧帧算出来、画上去。
- **轻卡、重卡**：当场画得过来的卡是轻卡，直接活渲；画不过来的是重卡，事先渲好、播放时贴上去。哪张轻哪张重靠实测，同一张卡在项目的不同位置可以不同。
- **剪辑段里的卡和没有剪辑段时一样**：轻卡活渲，重卡各自走轨道流，没流时显示占位（2026-10-21 用户定：「剪辑卡其实里面也是卡片，只是用看到的是"剪辑卡"，实际轨道流里面还是拆分成多个卡片。也就是说剪辑卡的轻卡还是照常能出。重卡走轨道流，和没有剪辑段的情况下，是一回事。」）。2026-10-22 用户重申：毛玻璃这类依赖下层的卡带着下层一起产轨道流（原话「毛玻璃卡带着下层一起产轨道流。不是不产轨道流。」）；在线浏览器也替剪辑段里的重卡产流（原话「剪辑卡就是在时间轴中的卡片。所以重卡也产流。」）。**后半（在线浏览器替剪辑段里的重卡产流）2026-10-23 已做到。前半（毛玻璃带下层产流）2026-10-23 尝试后退回，目前做不到**：唯一已知的做法要给剪辑段的嵌套场景挂 `clip-path: inset(0)`，那会让段里的毛玻璃不再透过段模糊段外的层——用户看得见，用户当日审〔裁〕时推翻（原话「那条裁定我推翻，把 clip-path 那一行拿掉，R01 按做不通处理并返工」）。所以这一句前半仍是用户要的目标，但现在没有实现：这类卡回到没有流、在嵌套场景里活渲。要重新做，先得找到不改变段外模糊行为的办法。
- **轨道流**：重卡事先渲好的带透明的视频，播放、暂停、拖动时贴上去。先有隔一段截一张的稀疏版，再补成每帧都有的满密度版。
- **实体框**：卡片实际画出内容的最小矩形。
- **兜底顺序**：画面来不及时，按从好到差的顺序找能用的画面顶上；都没有才显示占位符。

## 舞台

- 给人看的画面在舞台里渲染。在线浏览器的所有舞台一律跨源隔离，撤掉退回同源单舞台的路，别人同步来的用户卡、素材效果卡在任何舞台都能执行；桌面版舞台里的卡片代码同样不许调本机编辑器进程与预渲染进程的接口，按哈希读素材只放行当前项目（2026-10-14 用户定）。舞台和编辑界面分属不同进程/源，舞台卡住时编辑界面不卡。

## 播放

- **按帧走，慢帧就等。** 舞台每渲完一帧才推进 1/fps，并报告当前时刻；某一帧慢了就把后续整体后移，不追、不跳帧。
- **播放头跟随舞台。** 编辑界面的播放头跟随舞台报告的时刻。
- **看不到推帧过程。** 拖动或点击时间轴随机跳转时，用户看不到推帧卡被推进的中间过程。
- **停下就精确。** 暂停、点击时间轴、拖动时间轴后松开，以及播放到头停下，所有卡都回到精确的活渲。
- **音频跟随画面。** 画面落后应到时刻太多时暂停音频；恢复时对齐到当前时刻。

## 轻卡与重卡

### 测量

- 每次打开项目，在加载遮罩下把所有卡测完，并给判重的卡产一套稀疏的轨道流，才进入编辑；产得久的到时限就先进编辑，剩下的闲时接着产。之后新加的卡在后台舞台里测。

## 重管线：预渲染

- 重卡离屏预先渲染成预渲染结果。播放和拖动时只贴预渲染结果，拿不到这一帧时按下面的兜底顺序处理，播放头从不为它停。
- 预渲染不限于本机：需要预渲染的卡作为任务发布到文档服务的任务队列，由任意渲染节点（本机 PC、独立渲染主机、纯浏览器）按自身能力认领（见 `document-service.md` 的「渲染任务队列」、`platforms.md` 的「渲染节点」）。连不上文档服务时本机照常自己做。
- **不同环境的结果不混用**：不同硬件渲的连续帧拼在一起会闪，所以同一层里的帧只出自一种环境，画面不闪。
- 预渲染结果生成后一律推送到素材服务，素材服务就在本机时也一样，见 `asset-service.md` 的「预渲染的产物」。预渲染进程经素材服务的接口推送产物、读取素材，不直接读写素材服务的存储目录。
- 预渲染结果只有按项目分辨率渲出的轨道流一档。原来的**预渲染小尺寸**是从每张卡的快照缩出来的，快照作废以后停产（2026-10-13）；在线浏览器性能不足时改贴轨道流的稀疏版（见 `platforms.md` 的「在线浏览器」）。
- **先稀疏后满密度**：重卡的轨道流先产稀疏版，把整段铺满，再补成满密度版。之后要补的只在暂停时产，播放时不产；稀疏版排在满密度版前面。
- **谁产流与托管方开关**（2026-10-14 用户定）：「生成轨道流」关着时，托管方的渲染节点完全不为这个项目产流（稀疏版和满密度版都不产）；播放时用成员设备各自生成的轨道流。这个开关只管为成员预览产流，云端 Agent 的看画面等查看请求不受它影响，照常由托管方的渲染节点渲（2026-10-21 用户定）。开启「生成轨道流」设权限分组：只有在权限分组内的创建者账号能打开，不在组内时开关置灰并提示「你的账号没有开启这一项的权限，请联系托管方。」；托管方有后台管理网页增删分组内账号。手机、平板打开项目时也为当前页要播放的重卡产稀疏版（先测浏览器是否支持 H.264，只产稀疏版，不产满密度版）。
- **切分长度与强设备抢占**（2026-10-14 用户定）：motion 式的卡产流任务拆分至少管 30 秒（30fps 下 900 帧，比 30 秒短的卡整张一口气做完）；remotion 式卡保持 8 个分段（4 秒 / 120 帧）一个任务。算力强的设备做完自己的活可以抢算力弱的设备正领着的产流任务（优先级：桌面版 > 托管渲染服务 > 浏览器）；浏览器手里的任务被接走后停下，已上传的分段保留；拖动时自己浏览器在产的流不被抢。
- 暂停后，重卡追到精确活渲。

### 兜底顺序

- 只有两种情况退到占位符：该层所有兜底都超出预算；或该层还没有任何预渲染结果。
- 占位符：在该卡的实体框位置显示「沙漏 + 噪点」，表示系统正在加载；量不到实体框时只在位置框中心显示一个小沙漏徽标，不铺噪点。它继承该层的坐标、旋转、缩放和层级，自身几乎不占算力（不跑脚本、不逐帧重绘，动画只动合成属性；同屏多个时只有一个沙漏在转）。
- 其它来不及的时刻也用占位符，不透明：轨道流的这一帧还没到、不可见地追帧、等后台舞台补跑后互换。
- 来不及的状态很短时不显示占位符，避免闪烁。
- 占位符只出现在编辑界面的预览里；导出、预渲染、Agent 看到的画面和后台舞台永远没有它。
- 更好的结果到货后自动替换，不等用户操作：稀疏段换成满帧段在下一个分段起换上（两种编码的差分帧不能接续）；暂停着的时候原地换上（向左对齐，只取不晚于当前帧的画面，属于兜底规则，不影响「停下就精确」；2026-10-14 用户定）。
- 这台设备运行不了的卡（在线浏览器下转译失败、引用了页面里没有的模块、图形能力不够的用户卡与素材效果卡，见 `platforms.md`）同样照兜底顺序贴预渲染结果；这一帧没有预渲染结果时显示占位符（沙漏），由渲染节点渲，结果到了自动换上。没有「需要本地 PC 渲染辅助」这种提示：暂停时渲染出精确的帧，只有播放时没有轨道流才用沙漏占位（2026-10-21 用户定，原话「无论哪种都不存在『本地PC辅助渲染』这个情况」）。
- 停下就撤兜底：暂停、点击或拖动松开时，兜底画面一律撤下、追到精确活渲；之后不再盖回去，直到下一次跳转或播放。最低一档停下后保留已有预渲染画面，没有结果先显示占位，再逐层尝试渲当前帧，渲好一层换一层，不设时限（见 `platforms.md`「在线浏览器」）。

## canvas 卡的共享 WebGL 渲染器

- canvas 卡的渲染路线有两条，项目选项可切换：缺省每个舞台各用一套；在线浏览器性能不足时回退到两个舞台共用一套。
- **画布卡产流一律直取像素**（2026-10-14 用户定）：画布卡（canvas 卡）产轨道流一律直接从画布取像素交给编码器，不再每段实测对比。

## 即时渲染与预渲染进程

- 即时渲染的结果从渲染所在的位置直接回传给请求方（Agent 等），不经过素材服务。
- **渲染服务的两种模式**（2026-10-16 用户定）：
  - **单项目模式**：只为一个项目干活，整个项目装进来一直留着，这个项目之后的请求都在装好的项目上做。桌面版的预渲染进程用它。
  - **多项目模式**：同时为多个项目干活，不装整个项目，也不让哪个项目占着。每个请求只记下哪个项目、哪一版、哪几帧（或哪张卡的哪一段），排进同一条队列：看画面先于产流，同一类里各项目轮流，同一项目内先来先做。轮到时把这几帧展开成用到的卡片、这些卡依赖的卡和素材，只加载这些，做完就放下。0.7.19 起托管方的渲染服务和独立渲染主机用它。
  - 两种模式出的画面相同（「同一时刻同一帧」）。不同项目的卡不在同一个页面里执行，素材只能读本项目的（见 `asset-service.md`）。
- **0.7.18 暂行：云端 Agent 按轮占用**（2026-10-16 用户定；0.7.19 起由多项目模式取代）：
  - 托管方的渲染服务主要给云端 Agent 看画面用，其次替性能不够的在线浏览器产流。0.7.18 它一次只装一个带用户卡的项目，整个项目（内置卡、用户卡、素材）都在里面渲。
  - 用到它的项目，云端 Agent 这一轮第一次要画面时占住它，到这一轮收尾（说完话，它发起的后台作业也做完）或被叫停才放开。别的项目的 Agent 按先后排队。同一项目同时跑的几轮共用；有别的项目在排队时，这个项目新开的一轮排到它们后面。
  - 没有 Agent 在用时，才为「生成轨道流」打开的项目产流；有 Agent 来排队，做完手里这一个产流任务就让出。没人排队时，装着的项目要等流产满、而且有一阵没被修改，才关掉。几个项目都要产流时，有真人成员在线的项目先产；两个以上这样的项目轮流产，否则装着的那个一直产到满。
- **Agent 优先只是插队**：Agent 的即时渲染不霸占渲染，用户总能等到预渲染。
- **AI 栏的操作预览可以插队**：它由用户触发，排到普通预渲染队列所有待办任务之前，不打断正在跑的那一批，也不占用 Agent 的专用实例。
- **单卡画面（bake_card 与 3D 视图贴图）**（2026-10-14 用户定）：播放时取卡片自己的轨道流（稀疏版也可，向左对齐；无流先占位；打开 3D 模式时轻卡也产轨道流，贴图随播放时间动）；暂停时当场渲当前帧（和 2D 预览「停下就精确」一致）；导出时逐帧高清活渲，不从流里取。单张卡片出图统一称为「PNG 快照」。

## 导出

- 桌面版导出照常由预渲染进程逐帧导出。
- **在线浏览器导出在跨源隔离舞台里整帧渲染**（2026-10-14 用户定）：保留「快速导出 / 完整导出」（快速导出命中的满密度流贴进舞台，完整导出逐帧活渲）。在线浏览器导出时由跨源隔离的舞台把每一帧的完整画面（内置卡片、同步来的用户卡与素材效果卡、视频与图片素材）整帧活渲到画布上，像素交给导出页编码压视频。所有本页能运行的卡（含同步来的用户卡与素材效果卡）都在隔离舞台内直接活渲，不再因「同源导出页不执行同步卡」去等渲染节点；只有本页真正无法运行的卡才走渲染节点逐帧出无损 PNG 位图的退路。

## 有声动效卡

- 画面与声音属于同一片段，共用源时钟。持久音频产物替代该片段的实时合成播放源，不能同时播放两份。
- 预览时，未生成、缺失或过期的声音必须提示。声音继续沿用本册「音频跟随画面」的规则。
- **导出时自动生成声音**（2026-10-06 用户定）：导出开始时，先把所有未生成、缺失或过期的声音生成好，再开始出画面。生成进度算进导出进度，取消导出同时取消生成。只有某段声音确实生成不出来时导出才失败，并说明是哪个片段；导出不得悄悄省略声音。桌面导出与在线浏览器导出都照此办，在线浏览器能合成哪些声音见 `platforms.md` 的「卡片声音的平台边界」。

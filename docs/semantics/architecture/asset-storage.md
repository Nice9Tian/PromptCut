# 素材服务

展开 `../architecture.md` 的「素材服务」角色。从属于 `architecture.md`，与它冲突时以它为准。本角色旧称「素材存储」「素材云」。

## 职责

- 素材服务是字节的唯一读写入口，没有项目语义：原视频、素材、预渲染的产物都经它的接口存取。
- 它与位置无关：本地素材服务是本机的守护进程，走本机磁盘；远程素材服务部署在局域网里的另一台机器（如 NAS）或远程服务器上。它的位置和文档服务的位置互不相干（见 `document-service.md` 的「部署组合」）。无论连的是哪一个，读写都经它的接口，入库这一步不能省，任何一方不得绕过它直接读写字节。
- Agent 进程和预渲染进程也一样：它们像外部客户端一样经素材服务的接口读写素材和产物，哪怕和素材服务在同一台机器上，也绝不直接读它的存储目录。
- 必须允许局域网访问：素材服务允许跨源访问，局域网里的其它设备能直接访问本机的素材服务。设备之间怎么找到对方，见 `document-service.md` 的「连接发现」。
- 所有内容按内容哈希寻址，写入后不可变，天然去重。
- **同步状态只问素材服务**：某份内容的分片收了哪些、是否传完，一律向当前连接的素材服务查询，这是唯一事实来源。本机的临时缓存不作判决依据，项目文档里也不记同步状态。

## 两档素材

- 同一份素材有两档：**小版**是缩到 800×600 以内的 H.264；**原片**保持原编码。
- 小版由上传方在自己的机器上转码，素材服务不转码。没有本机转码能力的客户端（如纯浏览器）导入的素材只有原片一档。
- 导出和像素级检查只用原片；原片还没到时提示等待上传方，不拿小版代替导出。
- 原片是浏览器放不了的编码时，预览一直用小版，导出仍用原片。

## 上传

- 分片上传，支持断点续传：中断后只补缺的分片，全件校验通过才算这一档上传完成。
- **逐个素材上传**：同一份素材先传小版、再传原片，两档都传完才轮到下一份素材。
- 上传在后台低优先级进行，不挡编辑。

## 预渲染的产物

- 渲染生成的所有预渲染产物（HTML 快照、PNG、MOV、轨道流等像素产物），生成后都无条件推送到素材服务，素材服务就在本机时也一样。
- 理由：局域网里没有渲染能力的弱设备（如 iPad 浏览器）靠它们预览；Agent 在没有渲染能力的环境里审阅成片也靠它们。
- 从文档服务的任务队列认领任务的渲染节点，先把产物推送到这里、确认收全，再向文档服务报完成（见 `document-service.md` 的「渲染任务队列」）。

## 拉取

- 素材服务里已有小版时，先拉小版显示，再拉原片替换它；换档时画面不跳、播放位置不变。
- 还没有小版时直接拉原片。

## 本地内容库

- 每台设备有一份本地内容库，按哈希存字节，它是素材服务在该设备上的存储或缓存：连本地素材服务时它是本地素材服务的存储；连远程素材服务时它是该设备上的缓存兼上传队列，作为缓存时不作「是否传完」的判据。其它角色都经素材服务的接口读写它，不直接读写。
- 离线交换用打包文件（`.procp`）：项目加原片，小版可再生、不进包。

# 素材存储

展开 `../02-architecture.md` 的「素材存储」角色。从属于 02，与它冲突时以 02 为准。

## 职责

- 素材存储只存字节，没有项目语义：原视频、素材、预渲染的产物。
- 所有内容按内容哈希寻址，写入后不可变，天然去重。
- 本地模式下不经过素材存储，素材直接读本机的本地内容库（见 `document-service.md` 的两种模式）。

## 两档素材

- 同一份素材有两档：**小版**是缩到 800×600 以内的 H.264；**原片**保持原编码。
- 小版由上传方在自己的机器上转码，素材存储不转码。没有本机转码能力的客户端（如纯浏览器）导入的素材只有原片一档。
- 导出和像素级检查只用原片；原片还没到时提示等待上传方，不拿小版代替导出。
- 原片是浏览器放不了的编码时，预览一直用小版，导出仍用原片。

## 上传

- 分片上传，支持断点续传：中断后只补缺的分片，全件校验通过才算这一档上传完成。
- **逐个素材上传**：同一份素材先传小版、再传原片，两档都传完才轮到下一份素材。
- 上传在后台低优先级进行，不挡编辑。

## 拉取

- 素材存储里已有小版时，先拉小版显示，再拉原片替换它；换档时画面不跳、播放位置不变。
- 还没有小版时直接拉原片。

## 本地内容库

- 每台设备有一份本地内容库，按哈希存素材字节。本地模式下它是素材的真身；云端模式下它是素材存储的本地缓存兼上传队列。
- 离线交换用打包文件（`.procp`）：项目加原片，小版可再生、不进包。

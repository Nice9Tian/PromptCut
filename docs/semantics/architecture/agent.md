# Agent

展开 `../02-architecture.md` 的「Agent」角色。从属于 02，与它冲突时以 02 为准。用户怎么选接入方式、创造力等级、多 Agent 和保护规则，见 `../03-user-workflow.md`。

## 接入

- 所有 Agent 通过同一套工具接口操作项目，不论它是 AI 栏里经命令行或 API 接入的，还是桌面 APP 经 MCP 接入的。
- 每个 Agent 会话有自己的身份。文档服务、通知、多 Agent 协调都按这个身份区分。

## 工具

- **写**：Agent 的写操作经文档服务落地，和编辑界面的操作一样排序、记版本、通知。
- **读**：项目、素材、卡片清单、布局等从项目副本读。
- **看**：看画面走查询渲染，见 `rendering.md` 的「查询渲染与预渲染进程」。
- 只读页面独有状态（当前选中、播放头交互、面板界面）的工具在编辑界面里执行。
- 工具的清单和参数由卡片定义等数据自动生成，加卡片不需要改工具。

## 看到的卡片

Agent 看的、改的卡片是卡片的约定封装，见 `cards.md`。

## 汇报

- Agent 的文字回复不直接展示给用户。它通过结构化的进度汇报交代做了什么、还有什么没做、遇到了什么问题。
- 桌面 APP 的 Agent 按 SKILL 提示词约定的结构化方法汇报。

## 运行位置

- Agent 默认在用户本机运行。
- 项目方提供的云端 Agent 是愿景：它在云端有自己的运行环境、本地内容库和只做查询的渲染进程，从文档服务拉项目，从素材存储拉素材。

# 卡片

展开 `../architecture.md`。从属于 `architecture.md`，与它冲突时以它为准。

## 卡片是什么

- 画面上的特效和动效都是卡片。每张卡片本质上是一段代码。
- 卡片只用网页前端的标准技术编写，不用 Python，不用 After Effects 脚本，以保证在任何设备上都能运行。它由两类技术组成：
  - **页面结构与前端框架**（HTML、JavaScript、React、Motion 等）：负责排版、界面动画、文字动效。
  - **图形加速**（WebGL、WebGPU 及着色器）：负责逐像素的图像处理、调色、三维材质。
- 同一时刻必须渲染出同一帧：卡片的画面只由时间和参数决定，不依赖真实时间。建卡时的具体写法限制见 `server/card-authoring-guide.md`。
- Agent 对卡片能改到多深，由对话的创造力等级决定，见 `../user-workflow.md`。

## 卡片的形态

| 形态 | 是什么 |
|---|---|
| **DOM 卡** | 一个 React 组件，在舞台上渲染成 DOM |
| **图卡** | 按时间产出一份 GPU 描述或一段音频采样，由宿主执行；用于滤镜、转场、强调、音频 |
| **组合卡** | 用部件库里的部件搭成的一棵实例树，每个部件有自己的框、参数和进场时机 |
| **素材封装卡** | 把 Lottie 动画、粒子配置翻译成的卡，参数是翻译好的旋钮 |

## 约定封装

一张卡对外唯一的样子是它的约定封装：卡片与生命周期（进场多久落定、之后停住 / 循环 / 持续变化、支持的退场）、时间、框、混合、运动、部件、参数。Agent 和编辑界面的代码页看的、改的是同一份封装，不是卡片的原始数据，也不是组件源码。

## 三个划分轴

每张卡片在三个轴上各有一个取值。渲染按这三个取值决定怎么渲、怎么预渲染、预渲染结果何时失效。

### 轴一：帧怎么得到

| 类别 | 含义 | 典型例子 |
|---|---|---|
| **随机访问卡** | 按时间 t 直接算出画面，跳到任意帧的代价相同 | 按 t 求值的 React 组件 |
| **可定位的推帧卡** | 有状态，但本质是文档时间线上的动画，能把动画时间直接钉到目标帧，一步到位 | CSS 关键帧与过渡、WAAPI、Motion 的 transform / opacity 动画 |
| **只能逐帧推的卡** | 自己累积状态，只能从起点一帧帧推到目标 | Motion 的弹簧与布局动画、AnimatePresence、粒子、自己累积状态的 JS |

**可定位的判法**：从第 0 帧逐帧推到第 8 帧，生成该卡的快照（HTML，含内联的计算样式）；复位后把它的子树一步钉到第 8 帧，再生成一次快照。两份快照的标签、属性、文本逐字相同，样式里的数值相对误差不超过 1e-6，即判为可定位。

### 轴二：画在什么上

- **DOM 卡**。
- **canvas 卡**：2D canvas，或 three.js 等 WebGL。

### 轴三：依不依赖下层

| 类别 | 含义 | 预渲染结果何时失效 |
|---|---|---|
| **独立卡** | 只画自己 | 只随自身变化失效；可单独预渲染、上云共享 |
| **源依赖卡** | 画面由上游输入决定，如滤镜、转场 | 向上追溯的整条依赖链上，任一控件的参数哈希变化 |
| **下层依赖卡** | 画面采样同一时刻的下层，如毛玻璃 | 同一时刻下层任一控件的参数哈希变化 |

### 分类以审阅表为准

- 每张卡在三个轴上的取值以审阅表为准，不以卡片源码里的声明为准。
- 审阅表没有覆盖到的卡，一律按下层依赖卡处理。

# 架构

本文只写最抽象的一层：系统里有哪些角色、每个角色默认跑在哪个位置、角色之间流什么。将来的扩展一般是把某个角色搬到另一个位置；角色可以增加，但增加角色必须改本文。具体机制在 `architecture/` 分册。

## 角色

| 角色 | 负责什么 |
|---|---|
| **编辑界面** | 用户看和操作的地方 |
| **文档服务** | 项目文档的唯一修改入口：接收人和 Agent 的操作，排序、记版本、通知各方。各方手里的项目都是它的副本。它是通用的文本 / JSON 调度分发中心，预渲染的任务队列是挂在它上面的模块之一：只记账，不分配（见 `architecture/document-service.md` 的「职责」「渲染任务队列」） |
| **素材服务（Asset Service）** | 字节的唯一读写入口：原视频、素材、预渲染的产物都经它存取。只管字节，没有项目语义 |
| **成片渲染** | 把项目渲染成给人看的画面 |
| **查询渲染** | 按 Agent 的要求渲染指定时刻的画面，供 Agent 观察 |
| **云端托管服务** | 常驻云端，所有多用户协作项目的公共入口：牵线与中继。与云端文档服务、云端素材服务独立部署（见 `product/hosting.md`） |
| **Agent** | 读项目、发出修改、查询渲染结果。可替换：本地模型、用户自己的服务、项目方的服务，对其它角色是同一种角色；由谁提供决定是否由项目方计费 |

## 默认位置（最小配置）

```
用户设备                          本机、局域网或远程
┌──────────────────────┐        ┌──────────────┐
│ 编辑界面             │ 操作 → │ 文档服务     │
│ 成片渲染             │ ← 通知 │              │
│ 查询渲染             │        ├──────────────┤
│ Agent                │ 字节 ↔ │ 素材服务     │
└──────────────────────┘        └──────────────┘
```

- **用户设备**：编辑界面、成片渲染、查询渲染、Agent。
- **服务**：文档服务和素材服务是两个分开的服务，都与位置无关：既可以作为本地守护进程跑在用户设备上，也可以部署在局域网里的另一台机器（如 NAS）或远程服务器上。编辑界面、浏览器、Agent 只认服务的接口，不关心它部署在哪。
- **部署不设限**：两个服务各自独立选位置，本机或云端，可以任意组合。只要遵守标准的接口契约，用户可以自由部署；无论怎么组合，数据流不变。按所连服务的位置分别称「本地文档服务」「云端文档服务」「本地素材服务」「云端素材服务」。
- **局域网访问**：素材服务必须允许局域网里的其它设备跨源访问，局域网里的设备要能直接访问本机的素材服务。
- **连接发现**：素材服务 URL 的动态下发作为基础设施发现功能提前引入，由文档服务把素材服务的地址下发给各方。设备间直连所需的地址交换由云端托管服务牵线（预留）。文档服务只做地址下发，不承担素材传输流量；成员直连不到主机时的转发由云端托管服务中继。

没有渲染能力的设备也是用户设备：它只跑编辑界面，成片渲染和查询渲染不在它上面，它靠素材服务里预渲染的产物看结果。

## 数据流

- **操作和通知**只走文档服务。编辑界面和 Agent 都向它提交操作、从它收别人的操作。任何一方不得绕过它改项目。
- **字节**只走素材服务。原视频、素材、预渲染的产物的一切读写都经素材服务的接口，不经过文档服务；素材服务在本机时也一样，任何一方不得绕过它直接读写字节。预渲染的产物生成后一律推送到素材服务。成员直连不到主机时，字节经云端托管服务中继到主机的素材服务，中继不落盘，读写的端点仍是素材服务。
- **预渲染任务**的发布、认领和完成通知走文档服务，只传小消息；任务的输入（项目、素材）和产物都按上一条走素材服务。
- **Agent 看画面**有两条通道：
  - 实时查询渲染的结果从渲染所在的位置直接回传给 Agent，不经过素材服务。
  - 审阅成片，或在没有渲染能力的环境里看结果时，经素材服务拉取预渲染的产物。

协作规则：**最后写的赢；发生覆盖时，覆盖方和被覆盖方都要知道。** 不做多人同时编辑的实时合并。

## 扩展点

| 搬什么 | 搬到哪 | 状态 |
|---|---|---|
| Agent | 项目方服务器 | 愿景 |
| 成片渲染 | 渲染服务器 | 预留 |
| 成片渲染 | 不在本设备（无渲染能力的设备） | 预留 |
| 预渲染 | 任意渲染节点（本机、独立渲染主机、浏览器）经文档服务的任务队列认领 | 预留 |

搬动的前提：角色之间只靠上面三条数据流说话，不依赖同一台机器。

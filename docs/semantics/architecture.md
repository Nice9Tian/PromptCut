# 架构

本文只写最抽象的一层：系统里有哪些角色、每个角色默认跑在哪个位置、角色之间流什么。将来的扩展一般是把某个角色搬到另一个位置；角色可以增加，但增加角色必须改本文。产品功能在 `product/` 分册，具体机制在 `mechanism/` 分册。

## 角色

| 角色 | 负责什么 |
|---|---|
| **编辑界面** | 用户看和操作的地方 |
| **文档服务** | 项目文档的唯一修改入口：接收人和 Agent 的操作，排序、记版本、通知各方。各方手里的项目都是它的副本。它是通用的文本 / JSON 调度分发中心，预渲染的任务队列是挂在它上面的模块之一：只记账，不分配（见 `product/document-service.md` 的「职责」「渲染任务队列」） |
| **账号服务** | VisuHive 仓库中的网站账号服务：账号、密码、账号会话及改密/退出事件。云端文档服务记录云端项目存在状态、创建者、成员和禁入；网站项目列表向它查询，账号服务不另建一套可独立修改的项目记录（2026-10-08 用户明确） |
| **素材服务（Asset Service）** | 字节的唯一读写入口：原视频、素材、预渲染的产物都经它存取。只管字节，没有项目语义 |
| **成片渲染** | 把项目渲染成给人看的画面 |
| **即时渲染** | 按需渲染指定时刻的画面直接交给请求方（如 Agent），供其观察或使用；不经过素材服务（取代旧名「查询渲染」） |
| **云端托管服务** | 常驻云端，所有多用户协作项目的公共入口：牵线与中继。与云端文档服务、云端素材服务独立部署（见 `product/hosting.md`） |
| **Agent** | 读项目、发出修改、请求即时渲染。可替换：本地模型、用户自己的服务、托管方的云端 Agent 服务，对其它角色是同一种角色；由谁提供决定用量记在谁名下 |

## 默认位置（最小配置）

```
用户设备                          本机、局域网或远程
┌──────────────────────┐        ┌──────────────┐
│ 编辑界面             │ 操作 → │ 文档服务     │
│ 成片渲染             │ ← 通知 │              │
│ 即时渲染             │        ├──────────────┤
│ Agent                │ 字节 ↔ │ 素材服务     │
└──────────────────────┘        └──────────────┘
```

- **用户设备**：编辑界面、成片渲染、即时渲染、Agent。
- **服务**：文档服务和素材服务是两个分开的服务，都与位置无关：既可以作为本地守护进程跑在用户设备上，也可以部署在云端。编辑界面、浏览器、Agent 只认服务的接口，不关心它部署在哪。
- **部署不设限**：两个服务各自独立选位置，本机或云端，可以任意组合。只要遵守标准的接口契约，用户可以自由部署；无论怎么组合，数据流不变。按所连服务的位置分别称「本地文档服务」「云端文档服务」「本地素材服务」「云端素材服务」。
- **局域网访问**：素材服务必须允许局域网里的其它设备跨源访问，局域网里的设备要能直接访问本机的素材服务。
- **连接发现**：素材服务 URL 的动态下发作为基础设施发现功能提前引入，由文档服务把素材服务的地址下发给各方。设备间直连所需的地址交换由云端托管服务牵线（预留）。文档服务只做地址下发，不承担素材传输流量；成员直连不到主机时的转发由云端托管服务中继。

没有渲染能力的设备也是用户设备：它只跑编辑界面，成片渲染和即时渲染不在它上面，它靠素材服务里预渲染的产物看结果。

## 数据流

- **操作和通知**只走文档服务。编辑界面和 Agent 都向它提交操作、从它收别人的操作。任何一方不得绕过它改项目。
- **字节**只走素材服务。原视频、素材、预渲染的产物的一切读写都经素材服务的接口，不经过文档服务；素材服务在本机时也一样，任何一方不得绕过它直接读写字节。预渲染的产物生成后一律推送到素材服务。成员直连不到主机时，字节经云端托管服务中继到主机的素材服务，中继不落盘，读写的端点仍是素材服务。
- **预渲染任务**的发布、认领和完成通知走文档服务，只传小消息；任务的输入（项目、素材）和产物都按上一条走素材服务。
- **Agent 看画面**有两条通道：
  - 实时看画面走即时渲染，结果从渲染所在的位置直接回传给 Agent，不经过素材服务。
  - 审阅成片，或在没有渲染能力的环境里看结果时，经素材服务拉取预渲染的产物。
- **云端 Agent** 与文档服务之间只走文档服务的会话；页面（在线页面，或选了「云端」的桌面版）与云端 Agent 服务之间只传对话（消息、过程的事件流、停止），不传项目内容与素材字节。云端 Agent 的改动引出的预渲染任务由 Agent 服务经文档服务的任务队列发布，由云节点的渲染节点认领。

协作规则：**最后写的赢；发生覆盖时，覆盖方和被覆盖方都要知道。** 不做多人同时编辑的实时合并。暂时离线改动重入须按基准与历史核对，并对冲突提供可视化处理；延迟退出旧凭证后的修改按修改项逐条核对后撤回或保留；两者都不能套用“最后写的赢”静默覆盖，见 `product/document-service.md`（2026-10-08 用户定）。

## 扩展点

| 搬什么 | 搬到哪 | 状态 |
|---|---|---|
| Agent | 托管方的云节点（云端 Agent 服务） | 已做：在线浏览器模式的 AI 栏使用；项目放云端时桌面版可选，缺省仍是本机 Agent |
| 成片渲染 | 渲染服务器 | 预留 |
| 成片渲染 | 不在本设备（无渲染能力的设备） | 预留 |
| 预渲染 | 任意渲染节点（本机、独立渲染主机、浏览器）经文档服务的任务队列认领 | 预留 |

搬动的前提：角色之间只靠上面三条数据流说话，不依赖同一台机器。

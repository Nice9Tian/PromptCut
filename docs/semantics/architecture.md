# 架构

本文只写最抽象的一层：系统里有哪些角色、每个角色默认跑在哪个位置、角色之间流什么。将来的扩展都是把某个角色搬到另一个位置，不新增角色。具体机制在 `architecture/` 分册。

## 角色

| 角色 | 负责什么 |
|---|---|
| **编辑界面** | 用户看和操作的地方 |
| **文档服务** | 项目文档的唯一修改入口：接收人和 Agent 的操作，排序、记版本、通知各方。各方手里的项目都是它的副本 |
| **素材存储** | 存字节：原视频、素材、预渲染的产物。只存，没有项目语义 |
| **成片渲染** | 把项目渲染成给人看的画面 |
| **查询渲染** | 按 Agent 的要求渲染指定时刻的画面，供 Agent 观察 |
| **Agent** | 读项目、发出修改、查询渲染结果。可替换：本地模型、用户自己的服务、项目方的服务，对其它角色是同一种角色；由谁提供决定是否由项目方计费 |

## 默认位置（最小配置）

```
用户设备                          云端
┌──────────────────────┐        ┌──────────────┐
│ 编辑界面             │ 操作 → │ 文档服务     │
│ 成片渲染             │ ← 通知 │              │
│ 查询渲染             │        ├──────────────┤
│ Agent                │ 字节 ↔ │ 素材存储     │
└──────────────────────┘        └──────────────┘
```

- **用户设备**：编辑界面、成片渲染、查询渲染、Agent。
- **云端**：文档服务和素材存储。文档服务是服务，素材存储是存储，两者分开部署。

没有渲染能力的设备也是用户设备：它只跑编辑界面，成片渲染和查询渲染不在它上面，它靠素材存储里预渲染的产物看结果。

## 数据流

- **操作和通知**只走文档服务。编辑界面和 Agent 都向它提交操作、从它收别人的操作。任何一方不得绕过它改项目。
- **字节**只走素材存储。原视频、素材、预渲染的产物在这里上传和下载，不经过文档服务。
- **查询渲染的结果**从渲染所在的位置直接给 Agent，不经过云端。

协作规则：**最后写的赢；发生覆盖时，覆盖方和被覆盖方都要知道。** 不做多人同时编辑的实时合并。

## 扩展点

| 搬什么 | 搬到哪 | 状态 |
|---|---|---|
| Agent | 项目方服务器 | 愿景 |
| 成片渲染 | 渲染服务器 | 预留 |
| 成片渲染 | 不在本设备（无渲染能力的设备） | 预留 |

搬动的前提：角色之间只靠上面三条数据流说话，不依赖同一台机器。

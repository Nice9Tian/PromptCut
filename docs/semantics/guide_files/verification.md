# 验证

展开 `suggested_agent_behavior.md` 的「验证」一节。索引见 `../developer_guide.md`。

## 基线

| 项 | 命令 | 通过标准 | 什么时候必跑 |
|---|---|---|---|
| 类型检查 | `npx tsc -b --force` | 零错误 | 每次 |
| 全量测试 | `npm test` | 零失败 | 每次 |
| 导出确定性 | `node scripts/verify-determinism.mjs --url "http://127.0.0.1:5203/?export=1"` | 同一段导两遍，逐像素相同 | 改到画面：渲染管线、导出取帧、卡片的画面（见下「按改动范围验证」） |
| 导出与快照重放一致 | `node scripts/verify-unified-frames.mjs` | 整条通过 | 改到快照、预渲染、渲染 |
| 画面 | 看图，或跑 `scripts/probes/` 下对应的探针（用法见各脚本文件头） | 画面正确、探针全过 | 改到用户看得见的画面 |

## 按改动范围验证（2026-10-06 用户定）

- 渲染附加项（导出确定性、快照重放、与 main 的像素比对、预渲染探针，即主计划第 8 节的 G0-R）只在改到**画面**时跑：渲染管线、舞台、快照与预渲染、导出的取帧，或某张卡、某个部件的画面。
- 只改声音（混音、声音生成、音频素材、静音状态、卡片的 `audio()`）、或只改不出画面的逻辑时，不跑渲染附加项，改跑**覆盖自己范围的探针**，并验**浏览器端**：桌面版与在线浏览器里能不能听到、能不能导出有声成片。改动所属领域还没有自己的探针，就先补探针，验收标准写在探针文件头。
- 一次改动里夹着某张现有卡或部件的画面变化，只对**那几张卡**做改前改后逐帧比对（选能覆盖它全部参数分支的测试项目），不跑全量渲染附加项。像素基线的演示项目里没有这张卡时，全量比对测不到它，跑了也不算数。
- 拿不准算不算改到画面，按改到办。

## 子分支与集成分支各跑什么（2026-10-01 用户定）

- **子分支**（子 Agent 的工作分支）：类型检查与全量测试每次都跑；渲染附加项和探针**按改动范围挑**——改到渲染、预渲染、导出、卡片才跑 G0-R；探针只跑与改动直接相关的那几个，主会话派任务时点名，子 Agent 不自行扩到全套。
- **集成分支合入 main 前**：整套只跑这一次——G0、G0-R、全部探针（主计划第 8 节的门槛表）。
- **集成分支挂了某一项**：先把挂的那一项在各子分支上单独跑一遍定位到哪一支，回到那一支修、重新合流；三支都单独过、合起来挂，才当交互问题在集成分支上查。
- 每个子分支都跑整套的代价太大（每套约两小时），所以不再要求；集成分支那一遍是硬要求，不得省。

## 耗时只记录，不当闸门（原「性能基准机」，2026-10-07 用户改定）

- **耗时不再决定过不过。** 验收项里的时间数字（编码耗时、加载与换档用时、握手用时、往返时延等）只记录，不作通过条件。原先「带耗时门槛的项以笔记本为基准机、在笔记本上过才算过、PC 上标待笔记本复核」的规则，以及同日早些时候定的「渲染五项在 PC 上限 4 核跑」，一并作废。
- **跟着发版记录。** 每次发版，把这些项在发版提交上跑一遍，把机器配置和各项耗时记进 `docs/reports/release-timings.md`，一个版本一节：版本号与提交、机器（哪台、处理器、核数、内存、显卡、系统）、各项的耗时数字。在哪台机器上跑都行，写明是哪台。
- **不看时间的断言照旧是通过条件**：功能对不对、黑帧数、透明拍数、长任务数、帧误差这类。
- **探针里的等待时限只为防卡死**：放宽到不会因机器快慢而误报；等到了头仍没有结果算这一项没跑出来，按不过处理。
- 别处文档里的「带耗时门槛」「待笔记本复核」「性能基准机」都按本节办。笔记本不再是任何一项通过的前提。
- 相邻两版之间某项耗时明显变差，在发版汇报里指出来，由用户决定要不要查；不挡发版。

## 本地验证与真实网络验证（2026-10-07 用户定）

验证分两级。

- **本地验证**：服务全在本机（需要托管端的用本机隔离的托管组合），几个角色用不同的凭证与浏览器配置文件扮演，不必是几台机器。验功能对不对：谁能认领、谁被拒、改动署谁的名、隔离有没有漏。合入 main 前跑的就是这一级，过了即可合入、发版。
- **真实网络验证**：服务在托管节点上，客户端经公网连过去。只验真网络才有的东西：nginx 与证书、延迟与断线重连、部署出来的几样服务是不是同一个提交、节点环境缺不缺东西，以及任务书点名要在节点上走通的体验验收。它不是合入 main 的前提。
- **真实网络验证只在两种时候跑**：一、往节点部署时，部署完跑一遍；不部署就不跑。二、改到网络这一层时（连接、重连、中继、票据、nginx 配置、部署脚本），本地验不出来，要上真网络。只改界面、卡片、声音、渲染这类，本地过了就够。
- 因此合入 main 可以早于真实网络验证。部署时在节点上不过：停掉那一样的进程或把在线页面退回上一版，其余保留，写明原因，告诉用户。
- 真实网络验证动的是在用的生产环境：只用测试房间与测试凭证、验完删掉；改动前备份；重启托管服务前先确认没有正在写入的客户端。
- 「跨机」不再单独成项（原 `m7-contract.md` 的 W7）：角色之间不直接通信，都是各自连文档服务与素材服务，所以两个角色在不在同一台机器上不影响结论。功能部分归本地验证，网络部分归真实网络验证。

## 证据

- 每一项的结果（命令、通过数或退出码、看过的图）直接出现在对话里，汇报时引用。
- 没跑的项要写明没跑、为什么。

## 验证环境

- 验证用 `.claude/launch.json` 的 `dev-test`（5203）。不用 5190～5192：5190（`npm run dev`）通常是用户在用的，5191、5192 是它的舞台端口。
- 每台 dev server 另占「端口 +1」「端口 +2」当舞台端口，三个连号都要空着。
- **Windows 验证静默运行**（2026-10-04 用户定）：会话启动的测试、构建、探针和辅助进程，以及它们继续启动的命令行子进程，一律在后台静默运行，不把 CMD、PowerShell 或终端窗口弹到桌面前台。Node 启动子进程时设置 `windowsHide: true`；PowerShell 的 `Start-Process` 设置 `-WindowStyle Hidden`。检查整条子进程链，不能只隐藏最外层。用户明确要求查看的交互窗口除外。
- 已经弹出的测试命令窗口及时清理：只处理能够确认由本会话启动的窗口。验证仍在运行时先隐藏或最小化，完成后按测试清理流程关闭；不误关用户自己的终端，不结束其他任务或用户进程，不修改宿主机全局终端设置来代替进程隔离。

## 会造成真实损失的操作

- **删含 junction 的目录**：先在 PowerShell 里用 `[System.IO.Directory]::Delete('<junction 路径>')` 只拆链接，用 `Test-Path` 确认没了再删，确认失败就中止。不要在 Git Bash 里用 `cmd //c rmdir`。
- **有 Agent 会话在跑时不装补丁**：补丁会整棵覆盖桌面版的运行时副本，会话里浏览器侧的工具会集体超时几分钟。

# 解法表

展开 `suggested_agent_behavior.md`「对齐」里的「穷尽解法」。索引见 `../developer_guide.md`。

按现有语义做不下去时用。显而易见的两条路都试过仍不过，或者开始考虑改语义，就建表；小报错不建。卡点按出现顺序编号（卡点 1、卡点 2……），每个卡点一张表，写在子 Agent 报告或阶段报告里。

## 做法

1. **写卡点和尺子。** 一行写清三样：要满足哪一条（语义条目或计划里的步骤）；现在观察到什么（错误信息、差异像素数、探针的失败项）；还差多远、怎么量。尺子必须是一条能跑的命令（探针的失败数、差异像素数、耗时）。卡点变了就改这一行，表里的分数跟着重估，旧的留着。
2. **列候选，分两层。**
   - **三级层**：用户看不出区别的改法。实现方式、参数、顺序、缓存、键与格式；需要改 `mechanism/` 的也在这一层。
   - **二级层**：用户看得到区别的改法。改 `product/` 的承诺、默认值、分阶段、改计划里已定的做法。
   - 说不出「它通过什么因果消掉观察到的失败」的剪掉，标「无机制」；碰一级的剪掉，标「禁止」；要用户才能做的（费用、物理操作）标「待用户」，进表不试。
   - 不要求一次列全。一轮里有几条就行。
3. **打分，取 f 最小的试。** g 是已付和要付的代价，子候选累加父候选的 g；h 是试完预计还剩多少缺口，用第 1 步的尺子估。两个都只分 1～5 档，一句话，不做实验，不为打分花时间。f = g + h。只在当前这一层状态为「开放」的行里取 f 最小的。**二级层的行在三级层扫空之前锁住，不参与排序。**
4. **看结果。**
   - 通过：记下来。改了 `mechanism/` 或 `product/` 的，在被改的那一条末尾标〔裁〕，指向「卡点几的第几行」；二级的当场用 `task-announce` 播报（没有 task-announce 的机器在对话里明确说明）。只改实现、不改语义文档的不用标。
   - 部分改善：它成为新起点，往下派生子候选（同方向再进一步、和相邻的一条组合）。
   - 没改善：状态改成「关闭·无改善」，写下学到了什么；学到的东西否定了整个方向，就把那个方向的行都标「关闭·剪（方向已关）」。
   - 暂时性故障（断网、远端重启、超时、端口被占、对端无应答）不是结果：重试加退避，不关行。
   - 一条路的子候选全失败，回到状态为「开放」的行，取 f 最小的。
5. **顾问。** 思路顾问是 Gemini：每一层扫空时请它给新假设。攻坚顾问是 codex：三级层自己的候选试完仍不过时，交它在独立 worktree 里上网查、自己改、自己跑尺子，直到通过或报「思路穷尽」；它的推理档由主会话按难度选（不低于 high），在一档上报穷尽就换高一档再交一次，到 max 仍穷尽才算攻坚顾问穷尽。两者的结果都记进表里，调用也记进报告的「顾问调用记录」。
6. **一层扫空的判据。** 没有状态为「开放」的行、思路顾问给不出新假设、攻坚顾问报思路穷尽，三条都成立。看的是思路，不以失败次数或耗时作为停下的条件。
   - 三级层扫空：解锁二级层，回到第 3 步。
   - 二级层也扫空：这一条标「未达成」，在报告里写明没做到、记待用户项，**接着做下一项**。
7. **什么时候停。** 只有一种情况停下问用户：这一条未达成，后面的工作就没法选型或没法开工（例如渲染不出来，导出就做不了）。这时先把不依赖它的项都做完，再停下报告，附解法表。其余一律不停。

## 维度提示

帮忙想候选，不是必填。

- 三级层：参数与阈值；算法与实现；依赖与接口；数据与格式（键、快照、契约字段）；顺序与时机（重试、缓存、同步改异步）；运行环境（进程、端口、隔离）。
- 二级层：缩小这一步的范围、把它挪到后面的步骤（都不许挪出终点）；等价的做法；分阶段；默认值与开关。

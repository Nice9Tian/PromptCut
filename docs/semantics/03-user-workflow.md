# 用户工作流程

本文是指导层：用户有哪几种工作方式、主线分几步、人和 Agent 协作时守哪些规则。每一步的功能清单在 `workflow/` 分册。分册从属于本文，与本文冲突时以本文为准。

## 工作方式

用户在同一个项目上可随时切换两种方式，切换不丢状态。两种方式都是人与 Agent 协作，区别在 Agent 从哪里接入、编辑界面是否打开。

| 方式 | 界面 | 谁在动手 |
|---|---|---|
| **传统式** | 打开编辑界面 | 用户和 AI 栏里的 Agent |
| **SKILL** | 默认关闭编辑界面，软件转入后台运行 | 桌面 APP 里的 Agent；用户可随时打开界面一起改 |

**后台运行**：关闭编辑界面不退出软件，软件转为托盘图标和悬浮窗继续运行；点击托盘图标或悬浮窗重新打开编辑界面；只有在托盘图标或悬浮窗上右键选择关闭，软件才退出。

## 主线

| 步 | 做什么 | 主体 | 分册 |
|---|---|---|---|
| 0. 开始 | 新建或打开项目 | 用户 | `workflow/project.md` |
| 1. 前期准备 | 把素材放进项目，并让系统理解素材 | 用户和 Agent | `workflow/materials.md` |
| 2. 核心制作 | 用户发送指令，Agent 执行 | 用户、Agent | `workflow/production.md` |
| 3. 用户实时查看 | 用户看画面，看 Agent 的进度 | 用户 | `workflow/editing.md` |
| 4. 用户交互修正 | 用户再发一条指令，或自己动手改 | 用户 | `workflow/editing.md` |
| 5. 交付 | 导出成片，保存项目 | 用户 | `workflow/project.md` |

第 2 到 4 步是循环，直到用户满意再交付。

## 人机协作规则

### Agent 接入方式

| 类别 | 是什么 | 在哪对话 | 对应的工作方式 |
|---|---|---|---|
| **CLI** | 本机的命令行 Agent | AI 栏 | 传统式 |
| **API** | 直连模型接口 | AI 栏 | 传统式 |
| **桌面 APP** | 本机的桌面 Agent 应用 | 桌面 APP 自己的窗口 | SKILL |

桌面 APP 的 Agent：

- 通过 MCP 接入本软件，权限与 AI 栏里的 Agent 相同。
- 桌面 APP 的每个会话是一个独立的 Agent。打开编辑界面时，每个会话在 AI 栏里单独显示，标明所属厂商和正在进行的操作。
- 用户手动修改时，它和 AI 栏里的 Agent 一样收到通知。

### 创造力等级

每个对话各一档，默认「高」。它决定该对话的 Agent 能改到多深，同时约束卡片、效果和测量：

| 等级 | 允许 |
|---|---|
| **低** | 只用已有的卡片和效果，只改参数；测量只用内置方法 |
| **中** | 在已有卡片和效果的基础上，可以改它们的代码或表达式，但不新建 |
| **高** | 可以新建任意卡片和效果，可以写自定义测量代码 |

### 多 Agent

- 用户可以同时开多个 Agent，每个 Agent 一个对话。
- 一个主 Agent 可以拉起其它 Agent 并给它们分派任务，拉起时可以给它们附加预设的角色。
- 各 Agent 声明各自的改动范围，互发消息协调。

### 保护

- 破坏性操作有门槛：删除片段、序列、效果时要说明理由，理由对用户可见。
- Agent 之间不悄悄互相覆盖：一个 Agent 改到别的 Agent 正在改或刚改过的内容时，双方都要知道。
- 用户正在编辑的内容要让 Agent 知道：Agent 看或改用户正在编辑的内容时，系统在返回里直接标出「用户正在编辑」，避免它覆盖用户的编辑。这是提示，不是禁止，因为用户可能正是在这个位置给 Agent 下指令。
- Agent 需要用户做事或回答时，停下并说明，不继续改。
- Agent 不能绕过工具直接改项目。

### 进度可见

- Agent 的文字回复不显示给用户。用户看到的是 Agent 交上来的进度条目（做了、待办、问题）和操作详细预览。
- 桌面 APP 的 Agent 的文字输出本软件拿不到。它按 SKILL 提示词约定的结构化方法汇报进度，显示方式与 AI 栏里 Agent 的进度条目相同。

## 分册的性质

分册里的功能清单是系统至少要提供的能力和默认方法，不是封闭的清单。分册只列能力，不重复本文的规则；涉及规则的地方引用本文。

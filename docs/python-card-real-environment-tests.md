# 自定义卡片：真实环境测试清单

整理日期：2026-09-13。本文件核对已有脚本、日志、截图和产物，没有重新启动测试或增加第六轮构建。

“真实”分为两层：安装后的桌面软件与真实项目端到端测试；开发服务连接真实 Windows LPAC/Python、Chrome/WebGL、音频混合器的集成测试。后者使用小型测试项目，不能等同于真实安装版完整验收。1,189 项单元测试另外统计。

## 1. 真实安装版与东京项目

环境：Windows 本机，安装后的 `C:\Users\admin\AppData\Local\PromptCut\PromptCut.exe`。项目为桌面 `《九箭旅行社·东京7日深度游》4.proc` 的独立副本，88.7 秒、1920×1080、30 fps、原始 17 轨。每轮副本单独保存并核对原文件哈希。

| --- | --- | --- |

## 2. 安装版 Rust/Python 隔离与并发

这些测试直接启动安装目录内的真实 Rust EXE 和 Python，没有模拟进程回复。

| 测试 | 实际做法 | 结果与证据 |
| --- | --- | --- |
| 作用域打开不阻塞已有卡片 | 实际 Windows 命名权限锁被另一进程占用五秒，同时执行已有卡片 | 约 30 ms 返回 |
| 作用域关闭不阻塞已有卡片 | 另一个作用域正在清理时执行已有卡片 | 约 31 ms 返回 |
| 重复、未就绪与容量限制 | 重复打开、打开未完成时关闭、第五个作用域申请 | 及时拒绝，符合错误码与容量断言 |
| 输入结束清理 | 发送有效打开请求后关闭 stdin，等待退出并检查该运行器的 Python 子进程 | 退出 0，子进程数 0 |
| 工作进程崩溃恢复 | Python 主动异常退出，同时排队健康请求 | 崩溃收到 `worker_exited`；后续请求由替代进程完成 |
| 取消与队列恢复 | 取消活动和排队任务，然后提交健康任务 | 取消返回明确错误，后续执行成功 |
| NumPy 与内存 | 实际分配并计算三张 1080p RGBA float 数组 | 约 99.5 MB 数组数据，私有内存约 116 MiB；512 MiB 限制没有放宽 |
| 共享运行时 ACL | 第四轮安装版的两个独立运行器并发，各做三轮打开、崩溃恢复、输入写入拒绝、关闭 | 通过；写只读输入实际收到 PermissionError |

第五轮证据为 `lpac-lifecycle-responsive.log`、`lpac-recovery.log`、`lpac-memory.log`。两运行器并发证据在 `work/installed-card-cycle-4/lpac-concurrency.log`。开发运行器另做过两个运行器各八轮并发测试并通过。

保留的失败：四个独立运行器同时初始化时，曾触发 30 秒 ACL 获取超时。这不能写成“四进程压力测试通过”。这些测试也不是完整的安全渗透审计。

## 3. 开发服务连接真实 Python/Chrome 的功能集成

使用本机 Vite 服务、实际隔离 Python 和真实 Chrome 截图，主要是 64×64 小型测试项目。最终独立集成运行通过，日志为 `work/card-integration/cycle5-final-integration-isolated.log`，脚本为 `scripts/verify-python-cards.mjs`。

| 项目 | 实际检查 |
| --- | --- |
| GLSL 注册 | Python 返回可注册的着色器和符号时间表达式 |
| 时间随机访问 | 不按顺序请求两个时间，检查截图像素分别匹配时间 |
| 任意 Python/Pillow | 实际生成图像并检查 RGBA，时间区间返回三帧 |
| 双输入转场 | 两路输入混合后，检查不同时间的实际颜色比例 |
| 输入像素读取 | Python 读取上游素材像素并改变颜色，验证最终像素 |
| 混合节点链 | Python 消费上游 GLSL 经浏览器物化的像素 |
| 旧 Chrome 输入 | Python 接收旧 Chrome 卡片的实际截图，比较像素差异 |
| Agent 片段看帧 | 实际 HTTP 看帧接口保留被选片段所需的素材及图依赖 |
| 状态推进与透明度 | 计数型状态卡推进后，核对输出为 `[40,0,0,128]` |
| 不完整结果 | 用户请求得到 `incomplete` 和缺失片段 ID；Agent 请求得到真实完整像素 |
| 后台缓存 | 启动实际预渲染并等待 MOV 生成完成 |
| 风格和源码修改 | 修改风格后的颜色更新，编辑源码后执行结果反映新源码 |
| 序列化 | JSON 序列化重建后继续编辑并执行；它与安装版实际保存重开测试分别记录 |

缓存测试的边界：该真实集成脚本主要断言预渲染最终产生 MOV，并非对所有调度时序、抢占边界和每一种失效路径进行完整运行轨迹验证。详细的优先级、失效和错误分支还有单元测试覆盖，不能全部归入真实项目端到端测试。

曾在同时运行故意争用权限锁的测试时出现冷 Chrome 预览超时；独立重跑通过。两次结果均保留。

## 4. 真实 WebGL、旧卡片和音频

- **WebGL 像素与资源测试**：实际浏览器测试 Alpha、时间求值、纹理输入、节点串联、方向、替换源和资源释放计数；错误着色器返回真实编译日志。最终日志 `cycle5-gpu.log` 的 renderer 是 ANGLE/SwiftShader，即真实 WebGL API 的软件后端。它不证明物理显卡加速或显卡性能已通过。
- **编译错误传输**：实际 LPAC → 浏览器 → vision HTTP 请求执行未声明变量的 GLSL，返回 HTTP 500，错误中包含变量名与 `undeclared identifier`。这是负向用例通过，不是渲染成功。证据 `cycle5-gpu-diagnostics.log`。
- **旧 React 随机访问**：640×360 项目，`caption-track` 访问第 18、3、18 帧，两次第 18 帧 PNG 完全一致。
- **旧状态卡回放**：真实 Motion/CSS/rAF 卡片访问第 15、8、15 帧，两次第 15 帧 PNG 完全一致。
- **背景依赖场景**：玻璃卡在有、无下层彩色内容时实际截图，得到 99,754 个变化像素，验证没有把下层上下文完全丢掉。它不是对所有玻璃卡每一像素的设计正确性证明。旧卡证据为 `work/card-legacy/evidence.json`。
- **音频块接口**：真实 NumPy 产生双声道音频块，通过 HTTP 读取 WAV，检查样本数量与数值。
- **音频混合输出**：真实 Python 卡 → Chrome `OfflineAudioContext` → `mix.wav`，检查一秒、48 kHz、双声道、48,000 帧，首对样本为 0.25/0.75。产物 `work/card-audio/export-card-audio-verify/audio/mix.wav`，证据 `work/card-audio/evidence.json`。这是数值及文件链路测试，没有进行扬声器试听。

## 最终选的算法规则

一句话：**先取主轨上的视频 / 图片 / 剪辑段（加被它们溶解过去的后一段），再把从 0 到结尾之间没盖住、长于 0.5 秒的空档，用其余没隐藏的序列上的可见段按时间补上，每一刻挑最长的（一样长挑更靠下的），补进来的只取落在空档里的那一截。**

和任务书建议的区别与理由：

1. **触发条件**：任务书建议「空档超过某个比例才补」。我改成「每一处长于门槛的空档都补」。理由：按比例触发时，一段 0.4 秒的开场卡或结尾卡占比太小不会触发，验收 2「开始与结尾都有缩略图」就做不到；按空档逐处补，规则更短，也保证两端有块。门槛是 0.5 秒，整条很短时取整条的 5%（两者取小），0.2 秒的单卡项目也补得上。
2. **补进来的段剪成落在空档里的那一截**（任务书只说「同一时刻只留一个」）。理由：不剪的话，一段垫在底下的长背景卡会和视频块时间重叠，缩略卡等宽排开后，按住拖动时时间会往回跳（验收 4）。剪了之后块与块的时间先后不交叉。视频段剪掉开头时入点跟着后移，缩略图取的是那一截开头那一帧。
3. **同一段可以补进几处空档**（例如背景卡 0～12 秒、视频在 2～5 与 7～10：背景卡补 0～2、5～7、10～12 三截）。理由：否则后面的空档（包括结尾）补不上。为此 `ThumbStrip.tsx` 的键从 `c.id` 改成 `c.id@c.start`。

阈值写在 `mainContent.ts` 的常量 `GAP_MIN` / `GAP_FRAC` 旁，规则在该文件文件头和 `mechanism/platforms.md` 新的那一节，没有散落别处。

### 二级（请主会话打印给用户）

下面这几条用户看得到区别，但用户没有明说。第 1、2、4 条的做法随上面那条三级〔裁〕写在 `mechanism/platforms.md` 里，用户推翻哪条，改 `mainContent.ts` 对应的几行即可；第 3 条是 `MobileEditor.tsx` 现有判断带出来的副作用。

1. **有视频的项目，空档里的卡片段也会出现在缩略时间轴上**。用户定的是「没有视频 / 图片 / 剪辑段时卡片段也显示」和「开始与结尾都有缩略图」。为了守住后一条，我把规则做成「主轨上每处长于 0.5 秒的空档都用别的序列上的段补」，所以视频项目里开头的片头卡、两段视频之间垫着的卡片、结尾的片尾卡也会成块出现（以前不出现）。不这么做，「片头卡 + 视频」这种项目的起点没有缩略图。
2. **补进来的段在缩略时间轴上不能长按换顺序**：拖它会提示「这几段不都在主轨上，在时间轴分页里调整位置。」它们的位置由别的序列决定，`planReorder` 只会挪主轨。主轨上的段照旧可以换。
3. **补进来的段，「靠头 / 靠尾」对齐也用不了**：`MobileEditor.tsx` 的 `align` 对所有主要内容都提示「主要内容的位置由顺序决定……」。这是 `MobileEditor.tsx` 现有的判断，按任务书不能改那个文件，所以没动。如果要让补进来的卡片还能对齐，需要在 `MobileEditor.tsx` 里把判断改成「只拦主轨上的段」，大约一行，留给主会话解冲突时决定。
4. **补进来、又被剪掉一截的段，卡上的时长是那一截的长度**（例如垫底背景卡在两段视频之间只显示「00:02」），标题行的总时长也按这些截相加，不会重复计算。

# C10a 手机在线快照恢复与素材地址竞态

工作区 `.worktrees/c10a-r2`，分支 `claude/c10a-r2`，起点 `5263329`。C10a 是在线浏览器模式演示。本次不提交、不推送。

## 根因与修法

R2 的现场没有保留请求级日志，无法把那次 900 秒失活唯一归因到一条请求；集成报告第 9.4 节只证实内容库新键下的清单和小位图齐全，手机层表键未换。代码里确定存在一条能造成同样结果的路径：`OnlineSnapshotSource.tick()` 在本轮 `content.get` 返回后才安排下一轮定时器。一次永久悬挂会让 `running` 一直占着，后续 `kick()` 只能标记 `again`，层表和清单都不再轮询。原连接实现有 10 秒超时，但来源自身没有兜底；连接替换、测试注入或非标准传输若不结算 Promise，就会触发这条路径。现在来源给每次内容库请求加 12 秒兜底超时，超时后释放轮询并立刻允许重取层表。小位图的票据、网络和读体过程也加 15 秒兜底超时与中断，释放四个并发槽，下一轮可重取。

本次最初一轮探针发现另一个上游失活：手机修改确实以修订 2 写进文档服务，但预渲染节点的诊断仅有修订 1 的计划；临时内容库在 15 分钟内没有新层表，所以那一轮无法用于检验手机是否换键。`prerenderPreload.ts` 的单飞请求原先也无超时，永久悬挂会把 `inFlight` 留为真，后续编辑和空闲事件不再发请求。现在 6 分钟兜底取消并重试，丢弃迟到结果。该轮没有抓到创建者页面的请求栈，无法断言它正是这条路径；后续探针用调试口观察。

第二轮真浏览器诊断还看到手机来源已缓存 64 张小位图、就绪层表已有 120 帧，但舞台仍无小尺寸节点。`snapshotFeed` 原来在 `setSnapshots` 回包前把新键写进投递基线；活着的 iframe 若丢了回包，后续按基线判“已贴好”，暂停态也没有新帧事件补投。现在 `setSnapshots` / `setTime` 的 RPC 有 8 秒界限；失败时基线作废并主动重投。在线页可见时每 5 秒核一次舞台，强制带 reset 重投，覆盖“回包虽到了、舞台随后被 setTime 覆盖”的顺序。低内存档不追暂停态活渲，所以迟到的 `settled` 事件也不再抑制该档的小尺寸选帧。

404 有两条路径：在线构建初始 `mediaTier` 策略在远程地址未就绪时可能给浏览器 `/@media/<哈希>`；此外 `chooseTier()` 的后台可播性探测绕开可见素材的等待分支，用原片相对地址发起一次隐形 `<video>` 请求。现在初始策略明确在线，远程地址未就绪时哈希素材不给 URL、后台探测也不启动；地址就绪后自动使用远程绝对地址。舞台也在父页 RPC 前设置在线策略。

### 2. 创建者页面为什么在第 1 步整页重载

**根因**：开发服务里 Tailwind v4 的 Vite 插件会静默整页重载；触发它的，是有人在跑探针期间往这个工作区里写文件。

- **机制**：`@tailwindcss/vite`（4.3.3）自动扫描项目里的文件找类名，扫到的文件挂在 CSS 模块下当 asset。它的 `hotUpdate` 碰到「改动的文件只对应 asset、扩展名又不是模块」的情况（`.md` 等）就直接发 `full-reload`，不打日志。所以 codex 那份编辑器日志里只有 `hmr update /src/index.css`，找不到「page reload」。
- **证据一**：诊断轮 D1 用的是 `3f68116` 起的探针，它会记下页面导航。
  - 创建者页面在 `2026-09-27T09:42:41.925Z` 整页重载。
  - 同一刻我提交了 `docs/reports/AGENT-c10a-r2.md`：git 规范化换行时重写了这个文件，mtime 是 `18:42:41.883 +0900`，两者相差 42 ms。
  - 5 分钟前改过的 `src/render/stageRpc.ts` 是模块，走 HMR 边界，没有引起重载。
- **证据二**：对照实验，只带 Tailwind 插件的 Vite 开发服务，根是本工作区，端口 5587。
  - 页面载入 `src/index.css` 后，原样重写已有的 `docs/reports/AGENT-c10a-r2.md`，页面整页重载 1 次，服务端日志里没有任何「page reload」。
  - 新建一个 `.md` 不重载，因为启动时没扫描到它。
- **排除了**：
  - 依赖预构建：`node_modules/.vite/deps` 从 16:51 起没动过，日志里也没有 optimized 字样；
  - 探针自己的导航：只 `goto` 一次；
  - 改卡或写检出目录：`cards.sync` 的 keys 为 0。
- **codex 那两轮的重载**：codex 一边跑探针，一边在同一个工作区里改源码和报告。集成方 R2 那一轮很可能同理：集成报告 9.3 节 R3 一行写着「排障改动未提交」，说明他们也是边跑边改。R2 本身没留下导航记录，没法坐实。
- **开发服务里怎么避开**：跑探针期间不改工作区里的文件。探针文件头写明了这一条；结果里 `creatorPage` 记下创建者页面每次顶层导航，以及意外重载的次数。我没有改 `vite.config.ts`，也没有改 Tailwind 的 `@source`：收窄扫描范围可能漏掉 `server/catalog` 等处的类名，改变画面，留给主会话定（第 6 节）。
- **产品上**：用户自己刷新页面，同样会掉出共享项目。
  - 桌面版 `?editor` 页面刷新后，接回本机的一份新空项目。
  - 走开始页进来的，刷新后回到开始页，要重新加入。
  - 在线页面刷新后，邀请链接的 `#` 片段早已清掉；凭邀请码进来的手机成员不知道项目密码，就进不去了。
  - 创建者掉出去之后，没人替手机的改动发布新计划。这是「改一处之后手机层表不换」的一条路，但不是唯一一条：集成方 R2 里内容库已经有了新键，是手机那边没取到，对应 codex 修的在线来源悬挂与投递丢失。

### 3. 修法：刷新后回到刷新前打开的共享项目（`a15955c`）

语义里没写刷新之后怎样，这里按「对用户最小意外」做，**待主会话定级**（建议一级，写进 `workflow/project.md`「多用户协作」）。

- **记什么**：进入共享项目成功时，在 `sessionStorage` 记下候选（项目号、地址、名字、进入方式）、身份、用户名，以及派生出的 `K`（`buildAuthProtocols` 的 `onKey`，照 `server/auth/client.mjs` 的注释「缓存 K，不缓存口令」）。不存口令，不存邀请码。
  - `sessionStorage` 只属于这个标签页，关掉就没了；浏览器「复制标签页」会一并复制。
- **什么时候清**：主动离开（取消多用户协作）、被踢、被移出、项目被删、在这个标签页换开别的项目、顶栏回开始页。
- **回不去时**：离线、限速、设备信息没取到，都留着记录，下次刷新再试；凭证不对、项目没了、被踢过，就清掉。
- **在哪接**：
  - 开始页（`Shell.tsx`）启动时有记录，就照「加入别人的项目」那样先换一份空项目再进，进去了直接进编辑器；
  - 打开的是邀请链接（`#invite=`）时，以链接为准，不回旧项目；
  - `?editor` 直接进编辑器的页面，由 `Editor.tsx` 在接上本机之后调 `resumeShared`；
  - 适用于创建者和成员、放云端和放本机（局域网）、桌面版和在线浏览器模式。
- **没做单测**：`syncManager` 没有单测骨架（要 WebSocket 与 sessionStorage）。改由演示探针新加的第 1b 步验：创建者刷新页面后，回到同一份项目文档、仍是创建者。

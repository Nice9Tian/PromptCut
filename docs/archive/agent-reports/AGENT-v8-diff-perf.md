# AGENT-v8-diff-perf 报告

分支 `claude/v8-diff-perf`（从 main `8a5d6ff` 建），worktree `.worktrees/v8-diff-perf`。
任务：把 `src/kernel/diffProject.ts` 对「整份深拷贝」输入的差异计算做快，让 V8（`docs/plan/c65-design.md` 验收表里的性能项：1000 个片段的项目，单次差异计算 ≤ 5 ms）有足够余量。输出必须与现在逐字节等价，不改门槛与量法。来由见 `docs/archive/agent-reports/AGENT-flaky-timing.md` 第 2、4 节（主会话选了那里的方向 b）。

结论先说：

- **「整份深拷贝后改一处」在 V8 测试里的中位数从约 2.00 ms 降到约 0.70 ms**（空闲，这台 PC 连跑 20 次），是原来的 35%，达到「降到一半以下」。单独基准里是 1.22 → 0.60 ms。
- **加 4 个忙循环连跑 20 次：20 过**；加 28 个忙循环（把 28 个线程全占满）连跑 10 次：10 过，深拷贝项 0.90～0.96 ms。
- **输出与提速前逐字节等价**：提速前的实现原样留在测试里当参照，随机与手写输入共 20330 组对拍，操作列表的条数、顺序、每条的 op / path / index 全同，value 连引用都相同，JSON 也逐字节相同。另做了变异测试确认对拍拦得住错改。
- 没动 V8 的门槛、判据和量法；`diffProject.test.mjs` 一字未改。

## 1. 现状（改之前）

机器：Intel i7-14700KF，28 个逻辑处理器。开量前总 CPU 占用 2%～5%。

**`node --experimental-test-module-mocks --test src/kernel/diffProject.test.mjs`，空闲，5 次**：全过；深拷贝项中位数 1.999、2.005、1.989、1.992、2.007 ms（都只量 1 批）。

**同上，加 4 个 `node -e "for(;;){}"`，10 次**：10 过；深拷贝项中位数 1.978～2.038 ms。量完按 pid 结束，查过没有残留。28 线程的机器上 4 个忙循环几乎挤不到这一项，所以和空闲时差不多。

**单独基准**（脚本在会话临时目录，照 V8 的六种输入造数据，每批 40 次取中位数、量 10 批，下表是 10 批中位数的中位数，5 次运行）：

| 项 | 中位数 ms |
|---|---|
| 拖动一个片段 | 0.021～0.022 |
| 改一个参数 | 0.019～0.020 |
| 删一个片段 | 0.017～0.028 |
| 加一个片段 | 0.021～0.034 |
| 所有序列重建但片段对象不变 | 0.202～0.206 |
| 整份深拷贝后改一处 | 1.211～1.226 |

测试里（约 2.0 ms）比单独基准里（约 1.2 ms）慢，是因为同一进程里前面的 V1 用例拿各种形状的随机项目跑过 diffProject，属性访问变成多态，优化代码慢一些。下面的判断都以测试里的数为准。

另外：`deepEqual(prev, 整份深拷贝)` 只要 0.44 ms，而 diffProject 要 1.2 ms，说明大头不是「逐个比」，是差异计算为每个节点拼路径、对每个带 id 的数组建 Set / Map、算最长递增子序列这些开销，在整份深拷贝时对 1000 个片段全做了一遍，其实绝大部分都不出操作。

## 2. 做了什么

只改了 `src/kernel/diffProject.ts`，新增测试 `src/kernel/diffProjectEquiv.test.mjs`。没有新增依赖，kernel 没引用任何上层模块。

### 改法

在 `diffIdArray` 第 3 步（两边都有的元素逐个递归）里，身份不同的元素先过一道 `noOpsBetween(before, e)`：它返回 true 时跳过这个元素的 `diffValue`。

`noOpsBetween(prev, next)` 的约定是：**返回 true 时，`diffValue(prev, next)` 保证一条操作也不出**；拿不准就返回 false，交给 `diffValue` 照常算。所以它只可能少做无用功，不可能改变输出。它逐分支照着 `diffValue` / `diffObject` / `diffIdArray` 的判断走：

- 不都是对象：`diffValue` 落到 `deepEqual`，不 `===` 时必为 false，返回 false。
- 一边数组一边不是：`deepEqual` 必为 false。
- 两边普通对象：`noOpsObject`。快路是两边 `Object.keys` 逐位相同（深拷贝和 `{ ...o, k: v }` 都保持键序），这时 `has(o, k)` 就等于 `o[k] !== undefined`，两个循环合成一个，也省掉 for-in 里对另一个对象逐键 `hasOwnProperty`（剖析显示这是新写法第一版的大头）。键不同或键序不同时，照 `diffObject` 原样走两遍。
- 两边数组：`noOpsArray`。长度不同返回 false；prev 不全是带非空字符串 id 的普通对象，说明 prev 不是带 id 的数组，`diffValue` 用 `deepEqual` 判，这里也用 `deepEqual`；两边 id 逐位对齐才继续，否则返回 false；逐个元素递归判；最后确认 id 不重复（重复就两边都不是带 id 的数组，改用 `deepEqual`）。
- 其余（非普通对象，如类实例、Date）：`diffValue` 用 `deepEqual` 判，这里也用 `deepEqual`。

只在带 id 数组的元素这一层调它（片段、序列、剪辑、部件这些实体），不在每一层都调：每层都调的话，改动所在路径上前面的兄弟会被各层祖先反复扫。现在最多多扫一遍改动所在那个实体里、改动之前的部分。

### 顺带的效果

「所有序列重建但片段对象不变」也快了（0.20 → 0.05 ms）：每条序列的 clips 数组身份变了、元素身份没变，以前要为每条序列建 Map、算最长递增子序列，现在 id 对齐加逐个 `===` 就判完了。

几项本来就只有 0.02 ms 的（拖动、改参数）多了约 0.003 ms：改到的那个元素会先被 `noOpsBetween` 判一次（很快就遇到不同、返回 false），再照常算差异。

## 3. 改之后的数字

**`diffProject.test.mjs` 空闲连跑 20 次**：20 过；深拷贝项中位数 0.684～0.810 ms（19 次在 0.684～0.708，1 次 0.810），都只量 1 批。

**加 4 个忙循环连跑 20 次**（`loaded.ps1 -Runs 20 -Busy 4`，量完按 pid 结束忙循环，再用 `Get-CimInstance Win32_Process` 查命令行含 `for(;;)` 的 node 进程：无残留）：**20 过 / 0 挂**；深拷贝项中位数 0.690～0.761 ms。

**加 28 个忙循环（占满全部逻辑处理器）连跑 10 次**：**10 过 / 0 挂**；深拷贝项中位数 0.895～0.957 ms，p90 1.03～1.29 ms。同样查过无残留。

**单独基准，空闲，提速前后交替各 3 次**：

| 项 | 提速前 ms | 提速后 ms |
|---|---|---|
| 拖动一个片段 | 0.021 | 0.024～0.025 |
| 改一个参数 | 0.019～0.020 | 0.021～0.022 |
| 删一个片段 | 0.028 | 0.017～0.018 |
| 加一个片段 | 0.021 | 0.031 |

**单独基准，加 28 个忙循环，各 3 次**：深拷贝项提速前 1.547～2.011 ms，提速后 0.794～0.820 ms。

**全量 `npm test` 里（几十个进程并行）的深拷贝项**：提速前 2.761 ms（p90 4.613 ms，把原实现临时放回来跑的一次，跑完已还原），提速后 0.995 ms 与 1.377 ms（两次）。

余量：这台 PC 上从约 2.5 倍（5 / 2.0）拉到约 7 倍（5 / 0.70）；全量并行下从约 1.8 倍拉到约 3.6～5 倍。笔记本上没有量（任务只要求这台 PC），按同样比例估，笔记本空闲时约 0.7～1.0 ms、`AGENT-flaky-timing.md` 里那种 66%～85% 后台负载下约 1.5～2.5 ms，未实测。

### 参照实现是不是真的等于旧实现

把 main `8a5d6ff` 的 `diffProject.ts` 临时放回 worktree，跑同一份对拍：9 过 0 挂（跑完用 `git checkout` 还原）。说明测试里的参照与旧实现在这 20330 组上逐条一致。

### 对拍拦不拦得住错改（变异测试）

对 `diffProject.ts` 逐个做一处错改，跑对拍，再还原：

| 错改 | 结果 |
|---|---|
| M1 `noOpsArray` 不确认 id 不重复，直接当没有操作 | 随机部分全过，只有 V8B-8 拦住 |
| M3 `noOpsObject` 快路只比键数、不比键名 | V8B-6、V8B-7 拦住 |
| M5 慢路去掉 remove 那一遍 | V8B-1、3、4、6、7 拦住 |
| M6 非普通对象一律当没有操作 | V8B-6、V8B-7 拦住 |
| M7 `noOpsArray` 不判 id 对齐 | 随机部分全过，只有 V8B-8 拦住 |
| M8 prev 不是带 id 的数组时直接当没有操作 | V8B-1、3、4、6、7 拦住 |

M1、M7 只在「不可枚举属性」这种项目数据里不会出现的输入上才和正确写法不同，随机生成器很难碰巧造出来，所以补了 V8B-8 的两条手写用例专门拦它们（提交 `362c3d2`）。

### 等价性的边界

「任何输入」指普通数据：对象、数组、标量，允许无原型对象、类实例、Date、不可枚举属性、稀疏数组。**带 getter 的访问器属性不在保证范围内**：新旧两版读属性的次数不同，getter 有副作用或每次返回不同值时结果可能不同。项目数据来自 JSON 和不可变更新，不会有访问器。

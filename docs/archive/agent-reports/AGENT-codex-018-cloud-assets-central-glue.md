## 当前明确阻断与最小 owner

1. **同一实例权威的 observed 认证**：`doc-agent-assembly` 目前不导出当前 registry/私有 subject 到 A；A 不能用另建的 instanceAuthority 或 asset body 自报的 `authenticationId`。G 独占该文件增加只供 `createRunAssets` 的窄认证 callback，A owner只确认其现有签名输入与cap释放；真实 asset mTLS、Agent→asset TLS exporter/服务 key/instance generation 要同请求一致。缺此 callback，A 构造 503。
2. **当前 asset registry 与恢复见证**：`combo/main` 尚无 pin 后 `resolveObserver` 和 asset 当前实例世代的可信来源；B 的 `verifyLifecycle` 也不能用新进程空 Map、`recoveryFence` 文件存在或 self-report `complete:true` 替代旧 OS/cgroup 空证明。G 的 combo/main/asset-runtime owner只接经现 serviceRegistry、asset lifecycle 与固定实例登记可核的身份；若需新增历史 witness API，先向 root 报精确 `asset-lifecycle` 租约及证据格式。未知就 `runAssetsReady:false`/503，控制 ACK pending。
3. **lease/控制真实关闭**：A 的 `verifyLeaseClosure/verifyControlReceipt/verifyRecoveryClosure` 仍是必需 callback。B 的 `prepareClosure` 在真实 TCP close 后 fsync 本地记录，但 G doc 不能仅核 receipt 里 `complete:true`；需通过当前 asset 证书/同 observer socket、精确 leaseId/assetInstanceId/持久 B receipt 与已关闭资源事件作可信见证，必要时 B owner补只读内部状态查询；历史 unknown 还需 root 的旧实例外部见证。`docAgentAssembly.deliver` 当前只记 doc transport/operation 的 pending，G 将 asset participant 的真实回执并入原 control 完成条件，不能直接给真 ACK。
4. **双 head 与撤销夹缝**：B `createAssetRunAccess` 每请求先同步 human access 与 run outbox；`status` 现仅 run head，`asset-runtime.status` 现仅 access head。G 的 assetRuntime/asset-ready status 组合两者，Agent 数据入口同步齐头后方可开；access 通知先 pause run lease，独立 doc 请求重验合法 retained 后续读，private/stop/off/服务撤销实际 close 后才 ACK。失联或 gap 不按 TTL 缓存开口。
5. **媒体历史与工具登记分离**：ProjectAssets.import 的 `{state:'stored'}` 只说明素材字节完整；doc `exec.mutate addMedia` 仍是另一成功点，必须用当前 run actor 与预期项目版本，经 doc 接受后才说项目含此素材。`openRead` 的 selector 必须从已接受项目 history 查，而非直接读 path/hash。这个界面与 runner/tool 路径不在本轮租约；缺正式接入 503。
6. **部署闭包与公开状态**：doc `HOSTED_DEPLOY_DIRS` 已含 `server/account`，asset literal 清单未含 A/B 新源码；Agent 的 `main` 还未收 ProjectAssets 可信配置。G stage 不能把主仓库向上 import 成功当独立服务可部署；无各服务自己证书/配置仍不 ready。当前 `runTicket` 在 `doc-agent-assembly.mjs` 明确返回 `run-data-proof-unavailable` 503，G 不借资产签名放开它；普通 `auth.ticket` 的 accountMode 禁令同样保留。private 对话里的 visual/snap/px ACL 另包，不借本 media 票据。

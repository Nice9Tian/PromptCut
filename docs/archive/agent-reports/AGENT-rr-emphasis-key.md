# AGENT 报告：rr-emphasis-key（输出节点带上游时，预渲染结果的内容键不含上游）

分支 `claude/rr-emphasis-key`，从 main `84f4bb68` 分出，交活前按主会话的要求把 main（`80bd5435`，已含「甲二」）合了进来，最后一遍验证都在合并之后跑。端口段 27840～27859。

## 先说结论：今天会不会真的贴错

**会。没有被别的条件挡住。** 在改之前的 main 上，用一个四个片段的最小项目经真的预渲染管线跑一遍，预览里两张不同的卡贴出了同一张画面。

- 片段挂了强调以后，卡片图给它的输出节点是外面的强调节点（`@clip/<片段 id>/emphasis`），卡片自己在它的 `inputs.source` 后面。这个节点的能力表是从上游推出来的：里面是一张有状态的独立卡时，它就是「要预渲染、独立」。于是这种片段判成**共享档**（同一张卡多个片段共用一份预渲染结果的那一档）、能单独预渲染、按声明进预渲染集合、能进单卡流。
- `server/card-cache.mjs` 的 `CardFrameCache.plan` 算共享快照的内容键和单卡流的成员键时，把输出节点的 `inputs` 剥掉、`inputKeys` 传空对象。所以键里只有强调的参数加时长、相位、框宽高、画幅这些，**里面是哪张卡、什么参数、哪一版源码都不在键里**。
- 后果有三处，都实测到了：
  1. **流**：两个片段入点相同时流键相同，生产者把后一个当成「同一张卡两个片段共用一条流」并到前一条上，就绪索引给两个片段发同一个键的层。预览里金句药丸（文字 AAA）的位置贴出来的是人物聚焦卡的画面。
  2. **快照**：只要强调、时长、相位、框宽高相同，入点不同也同键。四个片段的快照键是同一个，读出来全是人物聚焦卡的 HTML。
  3. **经队列**（没有起队列，只照 `planForQueue` 的拼法调了 `splitPlan`）：切分按任务 id 去重，三个同键的片段只有第一个出任务，另两个一个任务都没有，靠同一个键取到第一个片段的产物。浏览器节点那一份照出（见「查出的别的事」第 1 条）。
- 撞键要的条件并不苛刻：两个片段挂同样参数的强调（面板上的缺省值就是同样的）、时长相同、入点都落在整帧上、框一样大（都不设框就是）。快照只要这些；流另外要入点在同一帧。
- 带外观的缓存键（`key`、`cacheContentKey`，组流和旧的整帧通道用）一直是对的，它走 `cardNodeIdentities`，带着上游。导出不用这些键，不受影响。

改了以后同一个项目再跑，四个片段各是各的画面；里外都相同的两个片段仍然共用一份快照。

## 做了什么

1. **坐实成单测**：`server/test/card-cache-upstream-key.test.mjs`，22 条。每种情形构造「外面的节点相同、里面不同、时长和采样相位相同」的两个片段，经 `projectCardGraph` 摊图、`CardFrameCache.plan` 出键、`planStreams` 出流，断言共享快照的内容键 `contentKey`、单卡流的成员键 `streamMemberKey`、结果键 `snapshotKey` 不相同，能进单卡流的再断言流的内容键和流键不相同。情形：
   - 强调：里面两张不同的卡；同一张卡参数不同；同卡同参数、源码版本不同。
   - 滤镜（输出节点是 `@clip/<id>/filter`）：两张不同的卡；同一张卡参数不同。
   - 声音效果（输出节点是 `@clip/<id>/audioFx`，卡片段上挂了声音效果时也套一层）：两张不同的卡。
   - 滤镜外面再挂强调（两层上游）：最里面的卡不同；中间那层滤镜的参数不同。
   - 素材段挂强调：素材不同；同一个素材入点不同。
   - 素材效果卡（输出节点是卡自己，素材在它的 `inputs` 后面）：接的素材不同；输入的时间映射不同；串两层时中间那张卡的参数不同；有一个输入指向已删的片段。
   - 反方向 5 条：里外都相同的两个片段键相同（强调、滤镜加强调、素材段、素材效果卡）；入点不同相位相同的快照键相同、位置和不透明度不进键；挂和没挂强调的同一张卡不同键（原来就是这样）。
   - 对照 2 条：没有上游的 8 个片段，三个键和原来的算法（测试里逐字照抄了改之前那两处调用）相同；一份手写的图的成员键和带外观的缓存键等于在改之前的 main 上算出来记下的定值。
   - `cardSnapshotInputKeys` 自己 1 条。
2. **查清产品里的后果**：新探针 `scripts/probes/emphasis-key-probe.mjs`，自己起 dev server，本进程里起一个 `FramePipeline`（和预渲染进程同一份代码），灌四个片段的项目，记下每个片段的档位、键、流、层，读快照，再用一个舞台 iframe 照父页的做法贴流截图，和同一帧活渲的截图比。改前改后各跑一遍，见下节。
3. **修**（两个文件）：
   - `server/card-identity.mjs` 新增 `cardSnapshotInputKeys(graph, { style, environment, sourceVersions })`，回 `节点 id → { 输入名: { key, offset, rate } }`。上游节点的身份和 `cardNodeIdentities` 同一个结构，只是多剥一个 `clipId`，它自己的上游照同样的办法一层层算上去。没有上游的节点这一栏是 `{}`。
   - `server/card-cache.mjs` 的 `plan` 里对每个输出节点取这一栏，交给原来那两处 `cardSnapshotIdentity` 的 `inputKeys`（原来写死 `{}`）。`cardSnapshotIdentity` 和 `cardNodeIdentities` 本身没动，`below` 那一支没碰。
4. **对照探针** `scripts/probes/card-plan-key-compare.mjs`：同一份输入在 main 和当前工作区各跑一遍 `plan`，逐片段比六个键。`card-table-digest-compare.mjs` 比的是直接调 `cardSnapshotIdentity` 的结果，比不到 `plan` 这一层，所以补了这一支。

## 查出的别的事（没有动手）

1. **挂了强调、滤镜的片段，经队列时卡片 id 是空的。** `server/frame-pipeline.mjs` 的 `planForQueue` 给每个控件补 `cardId` 时用的是输出节点的 `cardId`，外面套了一层的片段输出节点没有 `cardId`，补出来是 `null`。`split.mjs` 靠它判三件事，于是都判错：
   - Lottie 素材卡本来不给浏览器节点，挂了强调就给了（用 `out/rr-emphasis-key/split-check.mjs` 照 `planForQueue` 的拼法调 `splitPlan` 实测：不挂强调的 Lottie 片段浏览器 0 份，挂了的快照 2 份、流 1 份）；
   - 用户卡挂了强调以后不算用户卡，任务的 `requires.cardSources` 是空的，手里没有这张卡代码的节点也能认领；
   - 任务的 `input.cardId` 是 `null`。
   这不是键的问题，改键之前就在；改键之后每个片段都有自己的任务了，受影响的任务比以前多。文件不在我的清单里。改法：补 `cardId` 时顺着 `inputs.source` 找到里面那张卡。
2. **已经写进云端层表的旧行。** 改之前桌面给挂强调的片段写的层表行，指的可能是别的卡的流。升级后桌面按新键重写，新行排在最前；但页面那一侧「输入签名没过期就照播」，新键的流产出来之前，旧行可能还会被播一小段。本机的预览不受影响（就绪索引只认当前的键）。
3. 这种片段的输出节点没有写法这一栏（`frameMode` 是空的），产流时一律按有状态处理、从挂载帧回放；里面是 remotion 式的卡时多回放了，画面不会错。
4. 人物聚焦卡画出框外的部分，贴流时只留框外 30 来像素，活渲时全画出来（截图里右下那张卡两种画法大小不同）。改前改后都这样，和这次无关；探针只比框内那一块。
5. 后台产共享档快照很慢：90 帧的一张卡约 5 分钟。只是记录。

## 没做成的及原因

- 挂滤镜、挂声音效果的卡片段，素材效果卡的本地档，没有经管线端到端跑，只有单测。
- 上游是**别的片段**的节点时（转场接两段素材），那个片段相对这一个的入点没有进键。`cardNodeIdentities` 也不带。源依赖卡今天不单独预渲染、不进单卡流，所以没有后果；以后要放行时这一处得一起补。写在 `cardSnapshotInputKeys` 的注释里了。

## 裁定〔裁〕

没有改语义文档。

1. 〔裁〕上游的身份照 `cardNodeIdentities` 的结构算，多剥一个 `clipId`，递归到底；放进原来就留着的 `inputKeys` 一栏，形状是 `{ 输入名: { key, offset, rate } }`。没有另加版本号：没有上游的节点这一栏还是 `{}`，摘要的输入和原来逐字相同。
2. 〔裁〕外面那一层的参数（强调的颜色粗细、滤镜的定义和参数）照旧在键里。实际上强调是包裹层加的，不在快照和流里，所以「同一张卡挂不同的强调」「挂和不挂」的产物相同却不共用，多产一份，不会贴错。要共用得改成按里面的卡出键，还得逐种确认外面那一层确实不在产物里，这次不做。
3. 〔裁〕这一栏对每个输出节点都算，不分档位：本地档的素材效果卡也跟着带上了素材的身份。
4. 〔裁〕没有动流的代码版本号。带上游的片段换了新键，旧键下的产物不会再被本机取到。

## 对任务书或语义的更正建议

- `docs/semantics/mechanism/cards.md`「轴三」那张表后面建议补一句：片段挂了强调、滤镜时，它的预渲染结果的键带着里面那张卡的身份（参数、源码版本）和链上每一层的参数；同一张卡的两个片段里外都相同才共用一份。
- 页面一侧以后要产「输出节点不是卡片自己」的片段的流时，要跟着改 `src/online/pageStreamPlan.ts` 的 **`streamMemberKey`**：它现在写死 `inputs: {}`，要改成收这个节点的上游那一栏（`cardSnapshotInputKeys` 的页面版，上游节点剥 `id`、`inputs`、`definitionId`、`clipId` 后逐层摘要），并把 `PAGE_STREAM_CODE_VERSION` 跟上；同一个文件里 `pageStreamBlock` 的 `wrapped-node` 那道闸也要放开。对拍单测是 `server/test/page-stream-plan.test.mjs` 的 PSP-03。今天页面不产这类片段的流，所以不用动。

## 哪些卡的键变了

- 内置卡：0 张（101 张逐张相同）。卡片的源码版本、声音不受影响。
- 变的只有**输出节点带上游的片段**：挂了强调、滤镜、声音效果的卡片段，挂了强调或滤镜的素材段，接素材的素材效果卡。它们的共享快照内容键、结果键、单卡流的成员键（连带流键）换一次，已有的快照和单卡流要重产一遍。带外观的缓存键、组流的键、成本键不变。

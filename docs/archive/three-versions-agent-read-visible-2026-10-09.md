# 云端对话读取撤回与助手展示：小阶段验收

2026-10-09，主会话收回。固定共同源码为 `ba2d7753390196edbb004248d458211d5f1b8990`。本阶段只交付读取失权后的真实关闭与界面清理，以及持久助手事件的实际展示；生产 Agent 尚未部署，完整编辑器的真实模型和工具执行另做。

## 做成了什么

- 文档服务给同一个 Agent 进程下发读取撤回，Agent 先同步禁止继续写出，再关闭实际请求、响应和 socket，等待尚未结束的分派结束，持久保存收口记录后才回确认。新实例不能替旧实例证明关闭；没有真实证据时仍返回未完成。
- 普通成员原来正在看的共有对话被开对话者切成私有后，旧事件连接真正关闭，当前正文自行清空，重新打开历史时服务端和界面都不再列出该对话。创建者仍能只读查看，不能发言。
- 账号事件流断开后清除原读取授权下的正文、队列、发言者和附件关联，从新授权下重新完整读取。页面工具请求保留已执行编号，避免断线重放时执行两次；局域网模式保留原来的续读行为。
- 云端助手记录绑定原消息、运行、发起账号、项目、对话及实例代次；实际服务的持久事件流可以显示助手文字和工具结果，重新读取不产生重复气泡。执行器结束后仍显示等待关闭与结算，不把 HTTP 成功或模型驱动结束算成整个任务完成。

## 首次失败及修正

两项失败分别为新增真实 mTLS 测试和事件流测试并行占用同一个 6640 端口，以及旧页面工具守门把完整函数调用字面写死，不能容纳新增账号模式参数。原作者提交窄修：两份测试让系统分配端口并读回实际端口，实际浏览器的专用默认端口保留；守门显式核对账号模式参数，同时保留唯一事件流入口、委托票据和无 Cookie 检查。没有串行化全量、自动重试或删除断言。修正后才进行上表的新一轮复验，首次失败仍在证据目录。

助手展示此前两轮真实窗口也失败：第一轮缺少 fixture 授权回调，在实际 POST 之前停住；第二轮 POST 202、事件流 200，但持久用户记录向界面投影时没有带项目与对话，因而没有助手气泡。修正可信记录投影后实际第三轮 7/7，随后主会话在共同候选再验 7/7。各轮结果与失败截图均归档。

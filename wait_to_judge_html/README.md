# 待审清单页面（〔裁〕总审的模板）

〔裁〕是会话在执行中自己定下、要你事后审的做法。这个目录把「〔裁〕总审」那一页做成模板：条目写在 Markdown 里，跑一次 `build.py` 生成 HTML。页面能按状态、级别、有没有截图筛选，点开每条看详情和建议，在页面上选「维持 / 推翻 / 改成 / 先不定」，最后复制成一段回复贴回对话。

## 生成

```bash
python wait_to_judge_html/build.py
```

- `out/index.html`：本机双击打开就能看，截图在 `out/shots/`。
- `out/artifact.html`：发布成 claude.ai 链接用的版本，截图已经内嵌，一个文件就够。
- 加 `--inline`：`index.html` 的截图也内嵌，得到能单独发给别人的一个文件。
- `out/` 不进仓库（根目录 `.gitignore` 里的 `out` 已经盖住），每次生成都会覆盖。

只用 Python 标准库，3.8 及以上都行。跑完会打印条目数、待审的二级条目、缺建议的条目，以及要注意的地方：编号重复、截图文件找不到、决定对不上编号、编号前缀不在分区表里等。

## 目录

| 路径 | 是什么 |
|---|---|
| `build.py` | 生成器 |
| `template.html` | 页面的样式和交互；页面标题和条目数据由 `build.py` 填进去 |
| `source/report.md` | 页头：大标题、导语、分区表、页脚的「范围与做法」 |
| `source/items/*.md` | 条目，一个文件可以放很多条；文件名随意，按文件名顺序读 |
| `source/verdicts.md` | 你已经回过的决定 |
| `source/shots.md`、`source/shots/` | 截图清单和图片 |

## 平时怎么更新

1. **你回了决定**：把回复贴进 `source/verdicts.md`，放在当天日期的 `## 2026-10-22` 这样的标题下，一行一条，例如 `- A07 改成：……`。生成后这几条变成「已审」，单条页显示你的原话。同一条回过两次，按日期晚的算。
2. **有新的〔裁〕**：照下面「条目的写法」加进 `source/items/` 里对应分区的文件，或者新建一个文件。编号不能和已有的重复，重复了生成时会提示。
3. **补截图**：图片放进 `source/shots/`，在 `source/shots.md` 加一节 `### 编号 文件名`，下面一段写图说：红框框的是什么、什么时候在哪截的。一条只配一张图，同一张图可以给几条用。
4. **重新生成**，再打开 `out/index.html` 看。要更新已经发出去的链接，让 Claude 用 Artifact 工具把 `out/artifact.html` 发布到原来的链接（上一次发布在 https://claude.ai/artifact/QSFG5yubCUpEmdYzogvRbB ）。

页面上点的选择只存在那台浏览器里。发布到同一个链接，选择会留着；换了链接、换了浏览器就看不到了。

## 条目的写法

```markdown
### A07 回复被截断时的处理
- 状态：待审
- 级别：二级
- 涉及：在线浏览器 / 云端 Agent
- 出处：`docs/semantics/mechanism/agent.md:40`
- 裁定原文：「……」
- 是什么：……
- 为什么当时这样定：……
- 现状：……
- 修改前 → 修改后：原句「……」 → 现句「……」
- 用户看得到的差别：……
- 选项：甲 维持；乙 推翻（返工：……）
- 建议：甲。……
- 截图：不需要。
```

- 一条从 `### 编号 标题` 开始，到下一个标题或分隔线 `---` 为止。编号是一个大写字母加两三位数字，字母决定它排在哪个分区。
- `- 字段名：值` 开一个字段。值可以写好几行：后面不以字段名开头的行都算这个字段的。页面上每行是一段，以 `- ` 开头的行连成列表。
- 字段都可以不写，写了才显示。单条页里的顺序固定：是什么、当时为什么这样定、现在代码怎么做（即「现状」）、修改前 → 修改后、你看得到的差别、选项、截图、裁定原文、出处；「建议」放在最上面的决定框里。
- **状态**：以「待审」「已审」「已失效」开头，后面可以带括号写依据，例如「已审（2026-10-18 用户定）」。不写按待审。已审、已失效的条目没写建议时，建议框里显示括号里的依据。
- **级别**：写「二级」或「三级」。一级按二级算，都是你看得出区别的那一档。
- **修改前 → 修改后**：用「 → 」（箭头前后各一个空格）分成两栏；以「语义未改」「新增」「无」开头的，整段照原样显示。
- **截图**：`shots.md` 没给这一条登记图时，这里的文字显示在「截图」一段，比如为什么没截。
- 清单里标题下面那行小字，取「是什么」的第一句（没写就取建议）。
- 行内可以用 `` `代码` `` 和 `**加粗**`。`<!-- -->` 里的内容不进页面。

条目以外的前言、统计、附录不进页面，可以照常写。

## 页头 report.md

```markdown
# 〔裁〕总审

- 页面标题：PromptCut 裁定总审
- 眉题：PROMPTCUT · 语义文档里的会话裁定
- 调研日期：2026-10-21
- 存储键：pc-cai-verdicts-v1

## 导语
……

## 分区
| 前缀 | 名称 | 收哪些 |
|---|---|---|
| A | Agent | …… |

## 范围与做法
- ……
```

- `# ` 那行是页面上的大标题，〔〕用强调色。页面标题是浏览器标签和链接列表里的名字；眉题是大标题上面那行小字；调研日期写在页脚。
- 分区表的顺序就是页面上的顺序。编号前缀不在表里的条目归到最后的「其他」，生成时会提示。
- 存储键是页面把你的选择存在浏览器里用的名字。同一批条目更新时别改；拿模板做一批全新的、编号会和旧的重复的条目时换一个，免得旧选择串进来。

## 拿它做别的总审

复制一份 `source/`，换上新的条目，用 `--source` 和 `--out` 指过去：

```bash
python wait_to_judge_html/build.py --source 新目录 --out 新目录/out
```

页面上的四个按钮（维持、推翻、改成、先不定）和「怎么回复」那段话写在 `template.html` 里，要换就改那里。

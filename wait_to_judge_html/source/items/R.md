### R01 剪辑段里毛玻璃与新写的卡不走流
- 状态：待审
- 级别：二级
- 涉及：桌面版 / 在线浏览器 / 渲染节点
- 出处：

- 裁定原文：「剪辑段里依赖下层、源依赖、没审阅过的卡，以及挂着素材效果卡节点的片段，暂时不产流、不抑制，照旧在嵌套场景里活渲（v1）。」
- 是什么：剪辑段里有几类卡现在不能事先渲成视频流，只能一直现场画。
  - 剪辑段是 2026-10-20 的新功能；2026-10-21 用户定：剪辑段里的卡「和没有剪辑段时一样」，轻卡活渲，重卡各自走轨道流。会话照这句话做了，但只做通了「独立卡」（画面只靠自己、不依赖下面或上游的卡）这一类。
  - 没做通的是：毛玻璃这类要采样下面画面的卡；转场、套在视频上的素材效果卡；挂了素材效果卡的片段；以及**所有没进内置登记表的卡**（用户或 Agent 新写的卡一律算「没审阅过」；在剪辑段外面，系统按最保守的「依赖下层」给它们产流，在剪辑段里却不产）。
  - 同一张卡放在剪辑段外面能产流，放进剪辑段里就一直现场画，既不产流，也不显示占位符。
- 为什么当时这样定：依赖下层的卡产流要按舞台坐标画，还要把「段外面的下层加段里面的下层」一起算进去；而剪辑段是整块缩放、可能旋转的，流贴回去时盖不住段里更高的层。转场和素材效果卡节点的输入按原片段 id 引用，摊平后 id 会悬空。实现的会话列了解法表：行 1、2（让这些卡真的走流）是三级大工程，要同时改分派、预渲染进程、舞台三端；行 3「判重时显示占位符」是二级，用户看得出，留给用户定。

- 用户看得到的差别：有。剪辑段里的这几类卡播放时一直是现场画：画面是对的，但卡比较重时预览会按「慢帧就等」变慢（整体后移，不跳帧）。同一张卡放在剪辑段外面，会走轨道流，播放更顺。

### R03 剪辑段的透明度与淡入淡出按整体算
- 状态：待审
- 级别：二级
- 涉及：桌面版 / 在线浏览器 / 导出 / 云端 Agent
- 出处：
  - `docs/semantics/mechanism/rendering.md:130`（「画面走嵌套场景」）、`:128`（〔裁〕标记）
  - `docs/archive/agent-reports/AGENT-cut-nesting.md`「〔裁〕清单」第 10、11 条、「没做成的与原因」第 8 条

- 裁定原文：「所以不透明度、淡入淡出作用在合成好的整帧上（组不透明度），不是逐层相乘。」
- 是什么：给剪辑段设不透明度或淡入淡出时，系统先把里面所有层合成一整张画面，再整体变淡；不是里面每一层各自变淡再叠起来。
  - 区别只在里面有「叠在一起的多层」时：整体变淡，下层不会透过上层露出来；逐层变淡则会。
  - 预览、导出、预渲染、Agent 看画面都是同一份代码，所以几处一致。
- 为什么当时这样定：为了让预览、导出、Agent 看画面出同一帧，剪辑段画成「一个带框的卡」，里面挂一个嵌套场景，先在项目画幅里合成、再整块缩放进段的框。跨源舞台每拍做离屏位图做不到 30 帧，所以不是离屏位图，而是舞台里整块合成。整块合成之后再乘不透明度，自然就是整体变淡。会话把它记成〔裁〕，是因为任务书只写了「整帧合成」，没有点名透明度怎么算。
- 现状：代码就是这样做的。`src/render/Stage.tsx:299-303`（段的不透明度、淡入淡出放在剪辑段那一层包裹层上，淡入从段真正露出来的起点算）；`src/render/CutSegmentScene.tsx:78-88`（里面是一个嵌套场景）。
- 修改前 → 修改后：新增（用户 2026-10-20 的原句只说「画面是被引用剪辑在对应时刻的整帧合成」；「整体变淡」这一步是会话推出来写进三级的）。
- 用户看得到的差别：有，但只在里面有叠层、且剪辑段设了不透明度或淡入淡出时：整体变淡，看不到下层透出来。多数用户的预期就是这种（和嵌套序列的常见做法一致）。
- 选项：
  - 甲 维持整体变淡（与「整帧合成」一致，也是剪辑软件里嵌套序列的常规）。
  - 乙 改成逐层相乘：返工中等，嵌套场景要把段的不透明度分发给里面每个片段，且预渲染、导出的口径都要重新过一遍像素基线。
- 建议：甲。这是用户 10-20 那句「整帧合成」的直接结果，也是最少让人意外的做法；改成逐层相乘反而会让叠层透出来。

### R04 剪辑段贴开头时首 0.2 秒略不同
- 状态：待审
- 级别：二级
- 涉及：桌面版 / 在线浏览器 / 导出
- 出处：
  - `docs/semantics/mechanism/rendering.md:132`（「预卷」）、`:128`
  - `docs/archive/agent-reports/AGENT-cut-nesting.md`「可行性探针」用例 B、「没做成的与原因」第 3 条、「〔裁〕清单」第 10 条
  - 源码：`src/kernel/cutSegments.ts:379-389`
- 裁定原文：「挪不到 0 之前：段贴着时间轴开头、预卷不够时截到段起点为止，那几张卡开头约 0.2 秒和单独渲染不一样（探针用例 B，6 帧）。」
- 是什么：剪辑段从被引用剪辑的中间开始、又紧贴整条时间轴开头时，里面有的动画卡开头约 0.2 秒和单独播放那条剪辑时画面不同。
  - 背景：有的动画卡（motion 式）必须从它自己的起点一帧帧推过来才对得上。剪辑段从被引用剪辑的第 N 秒开始时，这类卡在第 N 秒可能已经演到一半，所以系统把这一段的起点往前挪一截（预卷），让它们先推一遍，再露出画面。
  - 但时间轴不能有负的时间：段紧贴开头时预卷不够，只能截到 0 秒为止。
- 为什么当时这样定：没法在 0 秒之前再推；另一条路（让整条时间轴多出一段缓冲）改动面太大。会话只在探针里量了一个用例：起点 1 秒、偏移 2 秒、预卷只够 1 秒，174/180 帧和平铺等价物逐字节相同，前 6 帧不同。
- 现状：代码就是这样做的。`src/kernel/cutSegments.ts:383-389`：预卷取 `min(需要的预卷, 段起点)`。
- 修改前 → 修改后：新增（`product/rendering.md:8` 的「同一时刻同一帧」没有写这个例外）。
- 用户看得到的差别：有，但很边缘：只有「剪辑段紧贴时间轴开头、从被引用剪辑中间开始、里面有按历史推进的动画卡且恰好演到一半」时，段开头约 0.2 秒的画面和单独播放那条剪辑时不同。
- 选项：
  - 甲 维持这个已知近似，在语义里补一句例外。不用返工。
  - 乙 补齐：要么让时间轴允许负起点，要么在后台舞台把这几帧预先补跑再换上。返工中等偏大，要过像素基线。
- 建议：甲。边缘情形、只差约 0.2 秒；用户把剪辑段往后挪一点或把偏移改小就避开了。
- 截图：不需要（6 帧的差别静态图看不出来）。

### R05 剪辑段里丢了文件的独立音效导出时不自动补
- 状态：待审
- 级别：二级
- 涉及：导出 / 桌面版 / 在线浏览器
- 出处：
  - `docs/semantics/mechanism/rendering.md:142`（「声音走平移展开」末句）
  - `docs/archive/agent-reports/AGENT-cut-segment-followups.md`「做了什么」第 3 节、「没做成的与原因」第 3 条、「〔裁〕清单」第 1 条
  - 对照的二级句：`docs/semantics/product/rendering.md:90`（「导出时自动生成声音」，2026-10-06 用户定）
  - 源码：`src/editor/io/exportSounds.ts:172-174`
- 裁定原文：「被引用剪辑里缺了文件的独立音效不在导出前补，导出失败并说明要打开那条剪辑重新生成。」
- 是什么：被引用的剪辑里有一段独立音效（提示音、键盘声）的声音文件丢了，导出会失败，要用户自己打开那条剪辑重新生成。
  - 导出前系统会自动把「未生成、缺失或过期」的声音都生成好。剪辑段里的有声动效卡已经做到会自动生成（任意深度）。
  - 唯独「独立音效丢了文件」这一种，补回要把新文件写进那条剪辑，而写入动作只认当前打开的剪辑，没做；所以导出失败并提示：「这段音效在被引用的剪辑里,请打开那条剪辑重新生成后再导出」。
- 为什么当时这样定：不让导出悄悄省略声音（用户 10-06 的规矩），同时补回要让 `commitSoundEffect` 认停放的剪辑，超出当次任务范围，所以选择「明说失败」。
- 现状：代码就是这样做的。`src/editor/io/exportSounds.ts:172-174`：`need.kind === "effect"` 且在被引用剪辑里时直接抛错。
- 修改前 → 修改后：`product/rendering.md:90`：导出开始时先把所有未生成、缺失或过期的声音生成好，只有确实生成不出来才失败 → `mechanism/rendering.md:142`：被引用剪辑里缺了文件的独立音效不在导出前补，导出失败并说明要打开那条剪辑重新生成。
- 用户看得到的差别：有，但只在这一种罕见情形：导出弹出失败提示，而不是自动补好。其余声音规则都没变：段的音量、独立静音、淡入淡出都是「被引用剪辑里的片段音量 × 每层剪辑段的音量」，任何一层静音就静音，成片已用电平探针核过（误差 0.01 dB 以内）。
- 选项：

  - 键的毛病：片段上挂了强调（阴影、描边）或滤镜时，预渲染结果的键里没有里面那张卡的身份，所以改了里面卡的参数，旧结果还会被接着贴；两张不同的卡只要强调参数、框、时长相同，还会共用一份、互相贴到对方的画面。修法：键里带上里面卡的身份和每一层的参数；外面那一层（强调、滤镜）的参数照旧在键里，所以「挂和不挂」的同一张卡不共用（多产一份，不会贴错）。
  - 派活的毛病：片段套了不止一层，或里面不止一张卡（转场接两段）时，经任务队列派活这一步认不出里面是哪张卡。修法：顺着输入走到底按最里面那张卡办；里面有多张时，任务里的卡片 id 留空、要这一版全部定制卡的代码、只要有一张是用户卡就算用户卡、浏览器节点不做。

- 修改前 → 修改后：新增（`mechanism/cards.md:40`）。

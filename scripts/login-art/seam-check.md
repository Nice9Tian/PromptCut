# 循环接缝怎么验的

登录页左栏那段预渲染的循环，要能一遍遍播而看不出接头。这里记下**怎么做到的**和**实测的读数**，
以后改了着色器或循环长度，照同一个办法再验一次。

## 做到的办法：时间走一个闭合的圈

原来四项域扭曲都是 `p + t * k` 这种一直往前漂，时间轴上不闭合，截一段来循环会在接缝处跳一下。

现在每一项的偏移都是 `uLoop`（0→1）的周期函数：基频加二次谐波的一条闭合曲线
（正圆看着像在原地打转，叠个二次谐波之后走的路更长、更不像转圈，周期还是 1）。
`uLoop` 走满一圈回到出发点，所以**第 0 帧和第 N 帧是同一个输入**，算出来必然一样。

每一项还减去了 `loopAng = 0` 时的值，所以 `uLoop = 0` 这一帧和改成周期之前完全一样 ——
当初在调参台上试出来的那组数照旧能用。

卡片里：`uLoop = (t / loopSeconds)` 的小数部分；`loopSeconds` 和视频长度相等。

## 实测（2026-10-24）

把项目拉到 **49** 秒（比循环长 1 秒），好让第 1152 帧（`t = 48.0`，正是循环走满一圈）存在，
然后**单独**导第 0 帧和第 1152 帧：

```
node scripts/export-e2e.mjs --project scripts/login-art/project-seam.json --id seam-a --frames 0-0
node scripts/export-e2e.mjs --project scripts/login-art/project-seam.json --id seam-b --frames 1152-1152
```

读数：

```
A=000000.png  B=001152.png
e22dd3724c85b1eb59ac7480788cceb2ef4adec45c8d90c28df27f056f8d31d4
e22dd3724c85b1eb59ac7480788cceb2ef4adec45c8d90c28df27f056f8d31d4
尺寸 880x1080  不同的字节数 0  最大差值 0
```

两张 **SHA-256 完全相同、逐字节零差异** —— 循环点看不出来。

## 要注意的两件事

1. **`loopSeconds` 必须和视频实际长度相等。** 视频短了或长了，播到头那一下就不是「走满一圈」，接缝会跳。
   `render-all.mjs` 里 `LOOP_SECONDS` 同时决定项目时长和卡片参数，两边是同一个数，不会对不上。
2. **压到视频之后接缝是「视觉上」无缝，不是逐字节无缝** —— 有损编码的第 0 帧和最后一帧不会逐字节相同。
   逐字节那一条只在导出的 PNG 上成立，也只需要在那里成立：源头对了，编码出来的循环点就看不出来。

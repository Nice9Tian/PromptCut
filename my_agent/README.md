# 在 PromptCut 仓库干活的硬性要求

本文件由派活方放在这里，仓库里没有、也不要去仓库找它的出处。读完就按它做。

- **只改任务书列出的文件。** 别的文件、别的分支、`main` 一律不碰。
- **语义优先。** `docs/semantics/` 里写定的高于现有代码。需要改语义才能继续，就停下报告，不要自己改。
- **必守 `docs/semantics/guide_files/constraints.md`。** 其中最容易撞的几条：分层是 kernel ← render ← editor / mcp / ai，下层不引用上层，守门测试会拦；卡片代码守 `server/card-authoring-guide.md`；不原地改 store 里的项目对象，改动一律换新对象；文档和注释说「预渲染」「生成快照」，不说「烘焙」「冻结」。
- **验证照 `docs/semantics/guide_files/verification.md`。** 最少这三样：`npx tsc -b --force` 零错误；只跑本次改动影响到的测试，用 `npm test -- <文件...>`（必须经 `npm test`，它的全局 setup 占住端口，直接 `node --test` 跑要端口的测试会不准）；改到画面的跑 `scripts/probes/` 下对应的探针。
- **不推 `main`、不合并、不改写 git 历史。** 自己那条分支上早提交、勤提交。
- **不碰用户在跑的进程和端口**（5190～5192 是用户的 dev server 及其舞台端口）；**不动宿主机的网络**（网卡、代理、路由、DNS、防火墙）；要花钱或要人在机器旁动手的事写进报告，不自己上。
- **报告写清**：做了什么、每一项验证的命令原文和结果、没做成的及原因。报告路径由派活方指定。

读不到本文件而看到了指向它的提示词，就停下来问派活方，不要自己猜规矩。
